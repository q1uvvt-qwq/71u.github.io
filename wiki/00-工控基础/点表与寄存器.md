## 一句话概括

点表是工控系统的地址簿：它把寄存器地址、IOA 点号翻译成"这是什么量、什么单位、能不能写、安全范围是多少"。没有点表，通信链路是通的但没人知道在控什么；有了点表，攻击者才知道写哪个地址能把风机停下来。

## 原理

### 一、点表是什么

定义：点表（Point List / Tag List）就是一张映射表，回答六个问题：

```text
1. 这个点的名字（Tag）叫什么
2. 它在设备里的地址是多少（寄存器偏移 / IOA）
3. 它的数据类型和量纲是什么（Float/Int/Bool，x10、0.01kWh）
4. 它的读写权限是什么（R / RW）
5. 它的正常范围/安全范围是多少
6. 它走什么协议、属于哪台设备
```

点名（Tag）在真实风电场里有一套统一规范，靶场采用"区域.设备.对象.测点"四段式（出自风电场点表与数据模型设计.md）：

```text
WF.WT01.GEN.ActivePower          风电场.1号风机.发电机.有功功率
WF.WT01.CTRL.PowerLimitSet       风电场.1号风机.控制.功率设定
WF.CB01.LINE01.CurrentA          风电场.1号箱变.1回集电线.电流A相
WF.MET01.WIND.Speed              风电场.气象站.风.风速
WF.IED01.XCBR1.Pos               风电场.1号IED.断路器1.位置
WF.RTU.YC.TotalActivePower       风电场.远动.遥测.总有功
```

每个点还统一带四个元数据字段：

| 字段 | 含义 |
|---|---|
| value | 当前值 |
| quality | 数据质量：Good / Bad / Stale / Manual / Simulated |
| ts | 数据时间戳 |
| source | 数据来源：OPCUA、MODBUS、IEC61850、API |

`quality` 这个字段在攻击链里很关键：平原链的校验节点就是靠"手动覆盖标志 + 数值合理性 + 签名"判定数据被篡改的。

### 二、权限 R / RW：点表里最要命的一列

权限列直接决定了一个点是"只能看"还是"能动手"：

```text
permission=R   只读，通常是遥测/遥信：功率、风速、温度、断路器位置、告警码
permission=RW  可读写，通常是控制点：启停命令、功率设定、限功率百分比、告警复位
```

一条通用经验（也写进了靶场设计要求）：只读点远多于可写点，可写点的地址必须连续、可被单独保护。靶场对 Modbus 的约定是：

```text
HR0-HR89   只读
HR90-HR94  可写
```

好处是：工业防火墙可以只放行对 HR90-HR94 的写，把对 HR0-HR89 的写直接拒绝。点表同时是防火墙白名单的依据。

### 三、量纲与系数：x10、0.01kWh

工控设备为了省通信带宽，通常不传浮点数，而传一个放大后的整数，由点表规定怎么还原：

| 场景 | 寄存器原值 | 点表里的缩放 | 真实含义 |
|---|---|---|---|
| 风速 | 85 | value/10 | 8.5 m/s |
| 逆变器温度 | 730 | value/10 | 73.0 °C |
| 有功功率 | 1500 | value | 1500 kW |
| 发电量（32 位） | HR98=1、HR97=34464 | 0x000186A0 × 0.01 | 1000.00 kWh |
| 限功率百分比 | 100 | value | 100 % |

平原链里的两个例子：

```text
HR92 = WindSpeedOverrideX10   寄存器值 300 表示 30.0 m/s（×10）
HR97/HR98 = 发电量，高字 HR98 + 低字 HR97 组成 32 位，单位 0.01kWh
            目标 1000.00 kWh = 100000 = 0x000186A0
            高字 HR98 = 1，低字 HR97 = 0x86A0 = 34464
```

这也是猜寄存器行不通的原因：同样的数值 34464，在别的设备上可能是完全不同的物理量，量纲和系数只存在于点表里。

### 四、量程与安全范围

点表还有一列常被忽略但很关键：`safe_range`（安全范围）。它是保护逻辑和校验逻辑的共同输入：

| 点名 | 类型 | 单位 | 权限 | 正常范围 |
|---|---|---|---|---|
| WF.WTxx.Environment.WindSpeed | Float | m/s | R | 0~25 |
| WF.WTxx.Generator.ActivePower | Float | kW | R | 0~3000 |
| WF.WTxx.Generator.GridFrequency | Float | Hz | R | 49.5~50.5 |
| WF.CB01.TR.OilTemperature | Float | degC | R | 20~95 |
| WF.WTxx.Control.PowerLimitSet | Float | kW | W | 0~3000 |

风电场点表与数据模型设计.md 还给出了控制保护规则，它们可以看成点表的下游约束：

```text
1. 风速过高时不允许启动
2. EmergencyStop 为 true 时不允许 StartCommand
3. PowerLimitSet 超过额定值时拒绝
4. MaintenanceMode 为 true 时 AGC 不应下发功率指令
5. 控制点写入必须产生操作日志
```

```csv
WT-RTU,Modbus TCP,1,HR,zero_based_pdu,94,HR94,RW,AlarmReset,0-1
```

逐列拆解：

| 列 | 值 | 含义 |
|---|---|---|
| register_area | HR | Holding Register，保持寄存器，Modbus 里最常承载过程值/设定值/控制参数 |
| addressing | zero_based_pdu | 协议帧里的地址直接用 register_offset，即 HR93 就是 PDU offset 93 |
| register_offset | 90~94 | 可写区间 |
| permission | R / RW | 只读 / 可读写 |
| safe_range | 0-100 | 保护与校验的依据 |
| hmi_label | HR93 | HMI 页面上显示的名字 |

HR0-HR9 是遥测只读，HR90-HR94 是控制可写，点表权限模型在这里就是最简单的形态。

## 在攻击链里的位置

成因：点表同时泄露了地址、权限、语义、量程四样东西，攻击者必须先拿到它。

```text
只有地址没有语义 -> 知道要写 93，但不知道写它会限功率
只有语义没有地址 -> 知道要限功率，但不知道写哪个寄存器
只有地址语义没有量程 -> 写了 0 却不知道这是"合法的 0%"而不是非法值
只有这些没有权限 -> 不知道 HR0-HR9 写了也没用（只读）
```

平原链把这四样东西串得非常清楚：

```text
1. 报表系统 SQL 注入 -> 读到 scada_datasource：plain_scada_gateway / modbus_gateway / 200-500
2. IDOR 遍历 /api/reports/export?id=200..500 -> 命中 id=387
   下载 scada_gateway_backup_202607.zip
3. 解压得到 gateway.conf / rtu_targets.csv / pointmap.csv / route_note.txt / gateway_diag_key.pem
4. 从 pointmap.csv 得到：HR93 = ActivePowerLimitPercent，RW，安全范围 0-100
5. 用备份里的诊断私钥 SSH 进 10.0.6.8，作为 Modbus Master 写 HR93=0
6. HMI（10.0.8.3）显示总有功归零、告警 POWER_LIMIT_ZERO
```

山区链同理：攻击者从 pcap 里读出 `TypeID=45 C_SC_NA_1、CA=3、IOA=10490`，再结合日志知道 IOA=10490 对应 `WT08_STOP_CMD`。IOA 就是 IEC104 世界的寄存器地址，日志就是 IEC104 世界的点表。

## 安全视角

典型薄弱点：

- 点表文件泄露。点表常跟着工程包、网关备份、SCD/CID 文件一起被打包下载（`pointmap.csv` 就在 SCADA 网关备份里）。
- 点表通过页面泄露。前端 HTML 里直接写死 API、导出 ID、点表字段。
- 可写区间过大。如果 HR0-HR89 也可写，一个误写就能篡改遥测而不仅仅是控制量。
- 缺少范围校验。写 HR93=0 是合法范围，写 HR92=3000（300 m/s 风速）就应触发 RANGE_WIND；如果设备端不做校验，就只能靠旁路校验节点发现。
- 控制点没有操作日志。事后无法区分调度下发的和攻击者写的。

防护要点：

- 点表按最小必要授权管理，低权限账号只能看摘要，不能看全量路由与点表。
- 工程包/网关备份不放在 Web 可下载目录，下载接口必须做对象级归属校验（修掉 IDOR）。
- 可写寄存器区间要尽可能小，并在设备侧与网关侧同时做上下限校验。
- 所有控制点写入记录操作来源、身份、入参、执行结果，并同步到 Historian 与安全监测。
- 关键遥测做完整性保护（源端 HMAC + 时间戳新鲜度），让改了值但签名对不上能被发现。
