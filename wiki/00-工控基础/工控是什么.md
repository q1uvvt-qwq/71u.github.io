## 一句话概括

工控（OT，Operational Technology）是用计算机和网络操作物理世界的一类技术：传感器读到的电压、风速、温度变成控制指令，再去驱动断路器、变桨电机和风机。它和办公网（IT）的区别在于，另一头连着的机器会转、会发电，也会伤人。

## 原理

### 一、OT 与 IT 的六条差异

定义：两者差异不在技术新旧，而在安全目标的排序。工控把可用性放在第一位。

| 维度 | IT（办公/互联网） | OT（工业控制） |
|---|---|---|
| 首要目标 | 机密性优先，数据别泄露 | 可用性优先，机器别停 |
| 设备生命周期 | 3~5 年一换代 | 10~25 年不换，固件不敢升 |
| 通信协议 | HTTPS/TLS、认证加密成为默认 | Modbus、IEC 104 明文无认证；IEC 61850 有 IEC 62351，现场常不启用 |
| 与物理过程 | 无耦合，宕机只是刷新不了页面 | 强耦合，一条指令直接改变物理状态 |
| 补丁与重启 | 随时打补丁、随时重启 | 停机窗口以年计，补丁要等检修 |
| 谁负责 | IT 部门 | 生产/运检部门，IT 常常插不上手 |

可用性优先落到现场，变成三个具体的决定：

1. SCADA 服务器可能因为"加固会停机"而继续用弱口令。
2. 早期出厂的风机主控 PLC 早已停更固件，只能靠网络隔离保护。
3. "重启一下就好了"在这里不成立：重启 HMI 没事，重启一台并网发电的主控系统可能要报事故。

### 二、协议里没有"你是谁"这个字段

定义：Modbus 与 IEC 104 的访问控制完全由网络可达性决定，只要 TCP 可达服务端口，就自动获得主站的全部权力。

靶场里的实际值（来自平原链攻击链指南）：

```text
WT01-RTU  10.0.5.6:502   Modbus TCP，Unit ID = 1
WT02-RTU  10.0.5.4:502
WT03-RTU  10.0.5.5:502
HR93 = ActivePowerLimitPercent，权限 RW，安全范围 0-100
HR94 = AlarmReset，权限 RW
```

Modbus 报文里没有"我是谁""我有没有权限"这类字段。只要能连上 502，就能用 FC06 把 HR93 从 100 改成 0。协议能拒绝的只有地址越界、功能码不支持这类语法错误（异常码 01、02），没有基于身份的拒绝。

成因：协议成形时 RTU 挂在物理可控的串行总线上，身份校验被算作物理层的责任，报文层没留字段。接进 IP 网络后，这层假设失效。

IEC 104 同样如此（来自山区攻击链指南）：

```text
10.0.4.2 (frontend3-lower) -> 10.0.4.5:2404 (conpot RTU)
TypeID=45 C_SC_NA_1, CA=3, IOA=10490 = WT08_STOP_CMD
COT=activation, Test=1, SBO=Select -> Execute, SCS=0
```

一个 C_SC_NA_1 单点遥控报文，把 Test bit 从 1 改成 0，就是一条语法合法的停机命令。协议层看不出"调度员发的"和"抓包后改的"的区别。

注意：IEC 61850 不同，它的 MMS 可以套 TLS（IEC 62351-4），只是现场启用率很低。说"工控协议都没有加密"并不准确。

### 三、为什么不能照搬 IT 安全思路

- "加个认证就行"走不通：老 PLC/RTU 的协议栈写死在固件里，现场改不了。
- "上杀毒软件"不行：会误杀组态软件，白名单加固要先停机。
- "先全网扫一遍资产"不可行：主动扫描可能把老 PLC 扫挂。
- "以围堵为主"不适用：OT 靠分区、边界、纵深。
- 成败标准不同：IT 看有没有拿到 shell，OT 看物理过程有没有被改变。平原链的落点是 HMI 上"场站总有功功率归零"和 POWER_LIMIT_ZERO 告警。

### 四、工控安全的三个目标

定义：三个安全目标的排序与 IT 相反。

| 目标 | IT 排序 | OT 排序 | 含义 |
|---|---|---|---|
| 可用性 Availability | 最低 | 最高 | 控制系统必须在需要时可用；不能因为安全措施导致停机 |
| 完整性 Integrity | 中 | 中 | 遥测/遥控/点表/程序不被篡改 |
| 机密性 Confidentiality | 最高 | 最低 | 泄露点表、拓扑很严重，但一般不直接导致物理后果 |

- 一个"会导致停机 10 分钟"的加固方案往往会被否决，哪怕它能防住一个高危漏洞。
- 攻击者最想要的效果也是可用性：让风机停、让功率归零。
- 这也是 MITRE ATT&CK for ICS 把 Inhibit Response Function（阻止响应）、Impair Process Control（破坏过程控制）单列的原因。

## 事件对照：两边各自看什么

```text
IT 视角的事件：一次登录失败、一次 SQL 注入、一次 webshell 落地

OT 视角的事件（出自风电场点表与数据模型设计.md 的安全监测数据模型）：
  MODBUS_WRITE_CONTROL      对关键寄存器写入
  IEC104_REMOTE_CONTROL     遥控/遥调命令出现
  IEC61850_BREAKER_CHANGE   断路器状态变化
  OPCUA_BAD_WRITE           非授权 OPC UA 写入
  TIME_SYNC_LOST            设备对时失败，影响事件可信性
```

OT 侧这几类事件都带业务语义，"关键"要靠点表界定；IT 侧日志拿到同一件事，只会记成一次普通写操作。

## 在攻击链里的位置

```text
平原链：报表系统 SQL 注入 / IDOR -> SCADA 网关备份 -> Modbus 写 HR93=0 -> 风机有功归零
山区链：工单系统存储型 XSS   -> 维护工作站 -> IEC104 ARP MITM + Rogue Master -> Conpot RTU IOA=10490 -> WT08 停机
海上链：趋势门户 SSRF -> JWT Secret 泄露 -> 伪造 JWT -> 维护工作站 -> OPC UA Method Call -> Turbine08 保护停机
```

三条链都是"从 IT 入口进，到 OT 物理效果收尾"，落点一致：停机、脱网、功率归零和告警。

## 安全视角

典型薄弱点：

- IT 的 Web 漏洞（SQL 注入、IDOR、XSS、SSRF）被当成"只是网站问题"，在靶场里它们是进入 OT 的第一跳。
- 配置备份、点表文件、诊断私钥放在能被下载的地方（平原链的 `scada_gateway_backup_202607.zip`）。
- 运维通道（SSH、Web Terminal、厂商远程维护）缺最小权限与审计。
- 认为"协议没认证所以没办法"。防护重点是分区与边界，不是改协议。

防护要点：

- 遵循"安全分区、网络专用、横向隔离、纵向认证"，用正/反向隔离装置和工业防火墙把 IT 与 OT 隔开。
- 关键控制点（HR90-HR94、IEC104 遥控点）做权限控制、二次确认、全量操作日志。
- 遥测加完整性校验（HMAC 签名、时间戳新鲜度、范围、跳变、一致性）；平原链的 `10.0.5.7:8080` 是这类旁路校验的演示。
- 任何安全措施落地前先做停机影响评估。这条最容易被跳过，也最容易让方案在评审会上被否。
