## 一句话概括

威胁模型是用一套标准语言描述"攻击者会怎么一步步打进来"的框架。工控领域最通用的是 MITRE ATT&CK for ICS：它把攻击行为归到十几个战术（Tactic）里，让每条攻击链都能说清这一步是初始访问、这一步是横向移动、这一步才是真正破坏过程控制。

## 原理

### 一、为什么工控需要单独的 ATT&CK

普通 ATT&CK 的终点是拿到数据/权限，ATT&CK for ICS 的终点是改变物理过程，因此多了两类 IT 里没有的战术：

```text
Inhibit Response Function（阻止响应）：让防御方和操作员看不见异常
Impair Process Control（破坏过程控制）：真正去改工业过程
```

这也解释了为什么工控靶场的评分标准是 HMI 上有没有出现停机/脱网/功率归零/告警，而不是有没有 shell。

### 二、战术链与风电靶场的对应行为

| 战术 | 含义 | 风电靶场里的对应行为 |
|---|---|---|
| Initial Access 初始访问 | 攻击者如何进入工业环境 | 平原链：报表门户 `/api/reports` 的 SQL 注入进入；山区链：工单系统评论区的存储型 XSS；海上链：边缘门户 `/api/trend/preview?source_url=` 的 SSRF |
| Execution 执行 | 进入后执行代码 | 在维护工作站上运行 `modpoll`、`arpspoof`、`tcpdump`，或通过 Web Terminal 的 PTY API 执行命令 |
| Persistence 持久化 | 下次还能回来 | 植入远程控制程序、修改自启动项；靶场里体现为"用泄露的长期凭据（诊断私钥 / SSH 密码）反复进入" |
| Discovery 发现 | 侦察环境 | `nmap -sT -p 502 10.0.5.6/5.4/5.5`、`ip -br addr`、`ls -la ~`、读 `gateway.conf` / `remote-link.yaml`，枚举网段与协议端口 |
| Lateral Movement 横向移动 | 跨区移动 | 平原链：报表机 -> 通信系统1 -> 三台 RTU；山区链：工单系统 -> 维护工作站 -> 前置机/RTU 链路；海上链：边缘门户 -> 维护网关 -> 维护工作站 -> OPC UA 网关 |
| Collection 收集 | 收集工业信息 | 点表识别（Point & Tag Identification）：读 `pointmap.csv` 得到 HR93 语义；从 pcap 读出 IOA=10490 = WT08_STOP_CMD；Browse OPC UA 资产树找到 Protection 方法 |
| Command and Control 命令控制 | 控制已入侵设备 | 用 HTTP/WebSocket/自定义协议维持对维护工作站的操控；平原链里 SSH 会话本身就是 C2 通道 |
| Inhibit Response Function 阻止响应 | 让防御方看不到异常 | 见下方子技术 |
| Impair Process Control 破坏过程控制 | 真正改变工业过程 | 见下方子技术 |

### 三、Inhibit Response Function：让报警消失

| 子技术 | 含义 | 靶场对应 |
|---|---|---|
| Alarm Suppression 报警抑制 | 关掉报警，操作员不知道 | 通过写 HR94=AlarmReset 做复归，或让告警中心不再产生告警 |
| Modify Alarm Settings 修改报警参数 | 改报警阈值，设备已经危险但不报 | 海上链：把 Turbine08 的 `temperature_limit` 从 95.0 改成 40.0，风机保护动作后页面上的阈值本身就已经是攻击者写进去的值 |

海上链是这类战术的典型：攻击者没有关掉任何告警，而是改了判断告警的门槛。结果系统一切正常，因为风机确实按新阈值忠实执行了自己的保护逻辑。

### 四、Impair Process Control：真正改变过程

| 子技术 | 含义 | 靶场对应 |
|---|---|---|
| Modify Parameter 修改参数 | 改设定值/阈值 | 海上链：`SetTemperatureLimit(40.0)` -> OPC UA Server 把新阈值写入 Modbus HR96 -> 温度 73.0 > 40.0 -> `PROTECTION_STOP` |
| Manipulate I/O Image 操纵 IO 映像 | 改 PLC 看到的输入/输出 | 平原链：写 HR91=ManualOverrideEnable 打开手动覆盖，再写 HR92（风速）、HR95（电压）、HR97/98（发电量），让 PLC/SCADA 看到的是被篡改的 IO 映像 |
| Unauthorized Message 未授权报文 | 直接向设备发非法控制消息 | 平原链：在通信系统1上用 `modpoll` 作为 Rogue Modbus Master 写 HR93=0；山区链：自写 IEC104 Rogue Master 发 `C_SC_NA_1 / IOA=10490` |

三条链分别对应这三条子技术。

## 事件对照：一次 ICS 攻击链的战术标注

以平原链为例，把每一步标上 ATT&CK 战术：

```text
步骤                                            战术
--------------------------------------------------------------------
1. 打开报表系统 10.0.7.10:8080 看页面 HTML       Discovery
2. /api/reports?turbine_id=WT-01'                 Initial Access（SQL 注入）
3. 枚举 information_schema / scada_datasource    Collection（点表与数据源识别）
4. IDOR 遍历 export?id=200..500，命中 387        Collection / Initial Access
5. 解压 scada_gateway_backup_202607.zip          Collection（拿到 routing + pointmap + key）
6. ssh -i gateway_diag_key.pem plain_diag@10.0.6.8  Lateral Movement
7. nmap -sT -p 502 10.0.5.6/5.4/5.5              Discovery（Remote System Discovery）
8. modpoll ... -r 93 读取当前值 100               Collection
9. modpoll ... -r 93 写入 0                       Impair Process Control（Unauthorized Message）
10. HMI 10.0.8.3 总有功归零、告警 POWER_LIMIT_ZERO  业务影响（可验证的最终效果）
```

## 在攻击链里的位置

三条链的战术分布可以直接对比：

| 战术 | 平原链 | 山区链 | 海上链 |
|---|---|---|---|
| Initial Access | SQL 注入 | 存储型 XSS | SSRF |
| Discovery | SQL 元数据枚举、nmap | nmap 2404、读链路日志 | SSRF 探内网服务、Browse 资产树 |
| Lateral Movement | 报表 -> 网关 -> RTU | 工单 -> 维护站 -> 二层 MITM | 门户 -> 网关 -> 维护站 -> OPC UA |
| Collection | pointmap.csv、route_note.txt | pcap 里的 TypeID/IOA/COT | profile 里的 endpoint、资产树 |
| Impair Process Control | 写 HR93=0（Unauthorized Message） | 发 C_SC_NA_1（Unauthorized Message） | SetTemperatureLimit（Modify Parameter） |
| 最终效果 | 三台风机功率归零 | WT08 停机 | Turbine08 保护停机 + 脱网 |
| 校验/取证 | 校验节点 10.0.5.7 判定"被篡改" | 维护工作站日志、pcap | HMI 的 `/api/state` |

## 安全视角

典型薄弱点：

- Web 层的 IT 漏洞被当成低危。三条链的 Initial Access 全是 Web 漏洞，却决定了整条链能否成立。
- 配置与凭据的暴露面过大。备份包、profile 文件、前端 JS 泄露的内部服务名和路径，把 Discovery 的成本降到几乎为零。
- 参数修改缺少边界校验。温度阈值被改成 40.0 时，没有"新阈值是否低于当前温度"的合理性检查。
- 没有 IO 映像与遥测的完整性保护。手动覆盖标志（HR91）本身是合法功能，但没有机制要求"进入覆盖模式必须授权并记录"。
- 缺少跨战术的检测点。只有登录日志，没有 MODBUS_WRITE_CONTROL、IEC104_REMOTE_CONTROL、OPCUA_BAD_WRITE、IEC61850_BREAKER_CHANGE 这类工控语义告警。

防护要点：

- 用 ATT&CK 战术链做检测覆盖度检查：每个战术至少有一种可发现的手段。
- 在设备侧、网关侧、SCADA 侧三个位置部署工控语义告警，而不是只看网络层。
- 对关键控制点做双人授权 + 二次确认 + 全量日志，让 Unauthorized Message 无处藏身。
- 对参数类修改（阈值、定值、量程）单独建审计项，它比发停机命令更隐蔽。
- ICS 攻击链的终点是物理效果，所以验证与取证也必须在物理/过程层完成（HMI 状态、告警码、事件记录）。
