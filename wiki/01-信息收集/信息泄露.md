## 一句话概括

信息泄露的共同点是文件或数据本来就该藏好，却因为部署时的一个疏忽直接暴露在 Web 目录下。这里面危害最大的两类是 `.git` 目录和配置文件，前者能还原出整套源码，后者往往直接写着账号密码。

## 常见类型

git 泄露：网站目录下的 `.git` 文件夹可以被直接访问，攻击者用 `githack` 之类的工具就能重建完整的源代码仓库，其中包含密钥、数据库连接字符串和密码。

原因是在把代码部署到生产服务器时，直接把整个开发目录（包含 `.git`）传到了 Web 目录下，或者配置错误没有禁止访问。

配置文件泄露：常见的配置文件如 `.env`（环境变量）、`config.php`、`web.config` 等被直接下载。

日志文件泄露：应用程序的访问日志、错误日志、调试日志文件可被下载。

目录遍历：Web 服务器被错误配置，当客户端（如浏览器）请求的 URL 对应一个物理目录、且该目录中没有默认文档（如 `index.html`、`index.php`）时，服务器不返回错误页面（如 403 Forbidden），而是返回一个列出该目录下所有文件和子目录的清单页面。

错误信息页泄露：Web 应用未关闭调试模式，出现错误（如 SQL 语句报错）时，把详细的错误信息（堆栈跟踪、数据库结构、SQL 查询片段）直接返回给用户。

备份文件泄露：编辑器自动生成的备份文件（如 `index.php.bak`、`.index.php.swp`）被留在 Web 目录下，可直接下载。

用户信息泄露：由于系统漏洞、攻击事件或内部管理不善，导致用户的个人身份信息（PII）被未授权方访问、获取、披露或窃取。可能原因出现在所有程序中，比如网站未使用 HTTPS、SQL 注入、服务器配置错误等。

AK 泄露：关键的访问密钥意外暴露给了未经授权的人或实体。

webpack 泄露：把用于开发的 `.map` 文件错误地部署到了生产环境，并且该文件可以被外界公开访问。
