## 一句话概括

题目只给一个包含点和一个「flag 在 `flag.php`」的提示。要打通它，除了会写 `php://filter` 的 payload，还得**分清 `/var/www/html/`（网站根目录）和 `/`（文件系统根目录）** —— 这两个「根」混了，路径就会写错。

## 本题情景与解题手法

### 题目形态

页面/源码里透出的信息很零散，但拼起来是完整的：

- 存在 `include` 点，参数是 `?file=`；
- 提示「上传」、`?file=1` 这类探测用的值；
- 明确告诉你 **flag 在 `flag.php` 里**。

```text
include
?
上传/?file=1
在flag.php中
```

### 第一步：先确认包含点能不能读文件

拿一个**肯定存在**的文件当探针（不要直接上 flag，先把链路跑通）：

```http
GET /?file=/etc/passwd HTTP/1.1
Host: 靶机地址
```

能回显 `root:x:0:0:...` → 包含点可用，且是个**本地文件包含**（不是命令执行）。

### 第二步：用 `php://filter` 读 `flag.php`

`flag.php` 是 PHP 文件，直接 `?file=flag.php` 只会**执行**它，看不到源码。要让内容「不可执行」才能被原样吐出，于是用 `php://filter` 加 Base64 编码：

```http
GET /?file=php://filter/convert.base64-encode/resource=/var/www/html/flag.php HTTP/1.1
Host: 靶机地址
```

响应是一串 Base64，解码即得 `flag.php` 的内容。

> **为什么不用相对路径？** 直接写 `?file=flag.php` 依赖「当前工作目录正好是网站根目录」，而 Web 服务器的工作目录不一定是脚本所在目录（可能是 `/`、`/var/www` 或配置指定的其他位置）。**用完整绝对路径最稳。**

### 第三步：`/var/www/html/` 这个路径是怎么来的

这不是凭空猜的，而是 Web 部署的**通用惯例**：

- `var` = **var**iable data（可变数据）
- `www` = **W**orld **W**ide **W**eb（万维网）
- `html` = **HTML** 文件

Apache 的默认站点配置里就写着这个根目录：

```apache
<VirtualHost *:80>
    DocumentRoot /var/www/html    # ← 这里定义了网站根目录
</VirtualHost>
```

**Web 服务器的视角**：外部访问的 URL 路径，会被映射到 `DocumentRoot` 之下：

| 浏览器访问 | Web 服务器实际读取的文件 |
|---|---|
| `http://example.com/` | `/var/www/html/index.php` |
| `http://example.com/images/logo.png` | `/var/www/html/images/logo.png` |
| `http://example.com/flag.php` | `/var/www/html/flag.php` |

所以「`flag.php` 在网站里」等价于「`flag.php` 大概率在 `/var/www/html/` 下」。

> 不同发行版 / 服务器可能是 `/var/www/`、`/usr/share/nginx/html/`、`/home/www/` 等。**先用 `/etc/passwd` 这类文件确认包含可用，再逐个试这些常见根目录**（黑盒推断的完整方法见 `01-信息收集\目录遍历.md`）。

### 第四步：`cat /flag` 里的 `/` 又是哪个根

原笔记在这里追问：「使用 `cat /flag` 的 `/` 表示根目录，也与其有关吗？」

**有关，但那是另一个「根」。** `cat /flag` 里的 `/` 是 **Linux 文件系统根目录**，而 `/var/www/html/` 只是它的一个子目录：

| | **文件系统根目录** | **网站根目录** |
|---|---|---|
| 表示符号 | `/` | `/var/www/html/` |
| 作用 | 整个 Linux 文件系统的起点 | Web 服务器对外提供文件的起点 |
| 示例 | `cat /flag`、`ls /` | `http://site.com/index.php` |
| 两者关系 | —— | `/var/www/html/` 是 `/` 的子目录 |

**绝对路径 vs 相对路径**（同一件事的两种说法）：

```bash
# 绝对路径 —— 从 / 开始，指向唯一确定的位置
cat /flag                      # 读文件系统根目录下的 flag
cat /var/www/html/index.php    # 读网站目录下的文件

# 相对路径 —— 从「当前目录」开始，换个位置就失效
cat flag                       # 读当前目录下的 flag
cat ./flag                     # 同上（./ 表示当前目录）
cat ../flag                    # 读上一级目录下的 flag
```

**这就是为什么找 flag 要用 `cat /flag` 而不是 `cat flag`**：后者依赖当前工作目录，前者明确指向文件系统的根。文件包含场景下同理 —— **能写绝对路径就写绝对路径**。

### 解题手法一句话总结

> **`/etc/passwd` 探针确认包含可用** → 用 `php://filter/convert.base64-encode/resource=/var/www/html/flag.php` 读源码（Base64 保证内容不可执行、有回显）→ 解码得 flag。**路径一律用「从 `/` 开始的完整绝对路径」**，并牢记 `/var/www/html/` 是网站根、`/` 是文件系统根。

## 原理

### 1. 为什么读源码必须用 `php://filter`

`include` 的职责是「执行」，它没有「只显示不执行」的开关。要让服务端把文件内容交出来，就得先让内容**天然不可执行** —— 把 `<?php ... ?>` 变成一串纯 ASCII。这与 `00-基础\编码-为什么要Base64.md` 讲的是同一件事，此处不重复。

### 2. 为什么目标文件要有明确路径

`include` / `php://filter` 的 `resource=` 最终都要交给文件系统去解析。文件系统只认路径规则，不认「你以为的相对位置」：

| 你写的 | 实际含义 | 风险 |
|---|---|---|
| `flag.php` | 当前工作目录下的 `flag.php` | cwd 不确定 → 可能读不到 |
| `./flag.php` | 同上（显式写当前目录） | 同样依赖 cwd |
| `/var/www/html/flag.php` | 文件系统里唯一确定的位置 | **最可靠** |

「网站根目录 ≠ 文件系统根目录」这一点，也是 `01-信息收集\目录遍历.md` 里 `../` 层数推断的基础。本文只保留它与文件包含相关的部分。

## Payload 速查

| 目的 | Payload |
|---|---|
| 探针：确认包含可用 | `?file=/etc/passwd` |
| 读网站根目录下的 flag（推荐） | `?file=php://filter/convert.base64-encode/resource=/var/www/html/flag.php` |
| 读相对路径下的 flag | `?file=php://filter/convert.base64-encode/resource=flag.php` |
| 常见网站根目录清单 | `/var/www/html/`、`/var/www/`、`/usr/share/nginx/html/`、`/home/www/` |
| 解码回 Base64 | `echo "PD9waHA..." \| base64 -d` |

## 踩坑与备注

- **别一上来就怼 flag**：先用 `/etc/passwd` 确认包含链路是通的，否则会把「路径写错」误判成「包含点不可用」。
- **`/var/www/html/` 只是惯例，不是定律**：拿不到就挨个试 `/var/www/`、`/usr/share/nginx/html/`、`/home/www/`，或者先用路径遍历读 `/etc/nginx/sites-enabled/default`、`/etc/apache2/sites-enabled/000-default.conf` 里的 `DocumentRoot` 拿到真实值。
- **前端看到的 URL 路径与物理路径不是一回事**：`http://site/flag.php` 不等于物理路径 `/flag.php`，而是 `<DocumentRoot>/flag.php`。把这两者混起来，就会去猜 `/flag.php` 这种不存在的路径。
- **原笔记里「上传/」的提示**：说明题目环境可能还有一个上传目录，flag 也可能放在网站根目录之外（如 `/` 或 `/tmp`）。**绝对路径逐个试**比纠结相对层级更快。
- 原文中的靶场域名与题号属于一次性信息，本文统一抽象。
