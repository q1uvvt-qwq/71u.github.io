## 一句话概括
商业欺骗防御产品的主线是企业内网诱捕、身份与凭据诱饵、横向移动检测和低误报告警，能力和运营成熟，但多数不是围绕新曝 CVE 生成高仿真漏洞蜜罐。

## 定位
这一类产品被 04 归为商业方案调研，04 调研了六家：Thinkst Canary、Fortinet FortiDeceptor、CounterCraft、Acalvio ShadowPlex、SentinelOne Singularity Hologram / Attivo、Tracebit。06 的商业竞品矩阵在同一组里还列了 Proofpoint Illusive / ITDR、Zscaler Deception、Fidelis Deception。

它们的共同特点是：更适合企业落地和长期运营，强调低误报、高置信和告警联动，在诱饵资产、凭据、Token、身份、云、OT、横向移动上能力成熟，通常具备较好的控制台、部署、集成、权限和安全治理。

## 能力清单

### Thinkst Canary
- 定位：成熟的商业诱捕/欺骗防御产品，强调快速部署、低误报，既有硬件、虚拟、云 Canary，也有大量 Canarytoken 类型
- 支持硬件、虚拟、云 Canary 部署
- 支持 Canarytokens，例如文档、URL、API Key、云凭据、Web Bug 等
- 支持自定义 Webroot，用于上传自定义 Web 页面
- 支持 Custom TCP Service，用于添加未内置的 TCP 服务
- 支持 Cloned Website Canarytoken，用于发现被克隆的登录页/门户页
- 判断：CVE/Profile 生成未发现支持；高仿真 Web 指纹间接支持，Custom Webroot 可模拟页面，但未发现面向 CVE 的 Profile 化生成；HTTP 流量采集间接支持，Canary 会告警，公开资料未体现完整漏洞 Payload 分析管道；Payload/IOC 未发现针对漏洞 Payload 的深度分析能力；检测规则输出未发现支持；安全隔离明确支持成熟部署模型，细节由产品托管
- 对比矩阵评分：精准 高、高仿真 中、流量侧 中、Payload/IOC 弱
- 评价：企业诱捕和低误报告警很成熟，适合快速部署诱饵资产和 Token，但核心不是新漏洞出现后自动生成高仿真漏洞蜜罐并分析 Payload

### Fortinet FortiDeceptor
- 定位：Fortinet 的企业级欺骗防御产品，面向内网攻击、横向移动、凭据滥用、MITM、勒索等场景，通过 Decoy VM、Deception OS、Tokens/Lures 构建诱捕环境
- 支持 Windows、Linux、SCADA、IoT 等 Decoy VM
- 支持部署 Decoy VM 网络，用于诱捕和监控攻击者活动
- 支持 Deception Token，把诱饵线索放到真实端点上引导攻击者进入 Decoy
- 支持 FortiGuard Outbreak Alerts 相关的 Deception/Outbreak 能力，官方文档中出现 Outbreakv1 Deception OS 和与 FortiGuard Outbreak 漏洞相关的 Decoy 描述
- 官方社区文章中有针对 Microsoft Exchange、WordPress 插件 CVE 的 FortiDeceptor 检测案例
- 判断：CVE/Profile 生成间接支持，FortiGuard Outbreak 方向与漏洞诱捕接近，但公开资料未显示用户可自定义通用 CVE Profile 生成流程；高仿真 Web 指纹间接支持；HTTP 流量采集间接支持，公开资料未聚焦完整 HTTP Payload 数据管道；Payload/IOC 间接支持，Fortinet 生态有威胁情报联动，但未说明开放的 Payload 分析机制；检测规则输出未发现直接支持用户导出 Sigma、Suricata、WAF 规则的公开说明；安全隔离明确支持企业产品级 Decoy/隔离部署
- 对比矩阵评分：精准 高、高仿真 高、流量侧 中、Payload/IOC 中
- 评价：商业产品中最接近漏洞专项方向的竞品，优势建立在 Fortinet 生态、FortiGuard 情报和产品化 Decoy 体系上，公开资料没有证明其具备开放的、用户可控的任意新 CVE 到高仿真蜜罐到 Payload/IOC/规则输出流程

### CounterCraft
- 定位：deception-powered threat intelligence 平台，强调构建接近真实环境的欺骗环境、数字孪生、主动情报采集和攻击者行为观测
- 构建与真实架构相似的欺骗环境，部署 realistic decoy systems
- 将攻击者交互转化为实时威胁情报
- 面向云、边界设备、国家安全、OT 等场景
- 公开资料强调完整攻击遥测、TTP 可见性和威胁情报输出
- 判断：CVE/Profile 生成未发现支持；高仿真 Web 指纹间接支持，digital twin 与 realistic decoy 方向与高仿真接近；HTTP 流量采集间接支持，强调 attack telemetry，但未发现针对 Web CVE Payload 的公开细节；Payload/IOC 间接支持，具体字段和规则输出未知；检测规则输出未发现支持；安全隔离间接支持，欺骗环境隔离是产品基础，公开细节有限
- 对比矩阵评分：精准 高、高仿真 高、流量侧 中、Payload/IOC 中
- 评价：在高仿真欺骗环境和威胁情报上与漏洞蜜罐方向相关性明显，但公开资料更偏企业级欺骗和攻击者行为情报，适合作为高仿真和情报化方向的竞品参考

### Acalvio ShadowPlex
- 定位：企业级 360 Deception / Preemptive Cybersecurity 平台，强调 agentless、AI-powered、Fluid Deception、Deception Farms，覆盖身份、云、OT、端点
- Agentless deception across identity、cloud、network、endpoints、OT/ICS
- 动态欺骗和 HoneyPaths
- 通过 Deception Farms/Fluid Deception 扩展轻量化 Decoy 和 Honeytoken
- 与 SIEM、SOAR、EDR、XDR、ITSM 集成
- 强调根据环境生成真实感更强的 Decoy 和 Honeytoken
- 判断：CVE/Profile 生成未发现支持；高仿真 Web 指纹间接支持，强调真实感和动态欺骗，但不是漏洞专项 Web Profile；HTTP 流量采集未发现明确支持；Payload/IOC 间接支持，威胁检测和情报能力存在，细节非公开；检测规则输出未发现支持；安全隔离明确支持企业级部署和集成方向
- 对比矩阵评分：精准 高、高仿真 中高、流量侧 中、Payload/IOC 中
- 评价：强项是企业范围的大规模自动化欺骗、身份/云/OT 覆盖和动态欺骗，不是公开可见的 CVE 专项 Web 蜜罐生成。最有价值的参考是自动化生成、环境贴合、低运维成本的产品思路

### SentinelOne Singularity Hologram / Attivo
- 定位：SentinelOne 把 Attivo 的身份和欺骗能力整合进 Singularity/XDR 体系，Hologram 更偏身份欺骗、网络欺骗、AD/云身份安全和横向移动检测
- 诱导网络和内部威胁参与 Decoy
- 使用 Decoy credentials、data cloaking、misdirection、identity deception
- 与 XDR/Identity Security 联动
- 记录攻击者与 Decoy 的交互，支撑调查和 adversary intelligence
- 判断：CVE/Profile 生成未发现支持；高仿真 Web 指纹未发现支持；HTTP 流量采集未发现明确支持；Payload/IOC 间接支持，产品可支撑调查，但不是漏洞 Payload 管道；检测规则输出未发现支持；安全隔离明确支持企业产品级欺骗部署
- 对比矩阵评分：精准 高、高仿真 中、流量侧 弱、Payload/IOC 中
- 评价：重点是身份与横向移动欺骗，对高仿真 Web 漏洞蜜罐不是直接竞品，可作为企业级欺骗防御和 XDR 集成参考

### Tracebit
- 定位：云原生 Canary/Deception 平台，重点在 AWS、Azure、GCP、Kubernetes、身份、CI/CD、工作站等环境部署 realistic canary resources 和 credentials
- 云基础设施 Canary、Kubernetes Canary、Okta/身份类 Canary
- Perimeter Sensors / decoy services
- 文件、凭据、密钥、CI/CD 诱饵
- SIEM/SOAR 集成
- 研究 AI agent 攻击与 Canary 防御
- 判断：CVE/Profile 生成未发现支持；高仿真 Web 指纹未发现明确支持；HTTP 流量采集间接支持，Perimeter Sensors 可能相关，公开细节不够；Payload/IOC 间接支持，更偏 Canary 触发与上下文；检测规则输出未发现支持；安全隔离明确支持安全 Canary 资源和非生产诱饵
- 对比矩阵评分：精准 高、高仿真 中、流量侧 中、Payload/IOC 中
- 评价：强项是云、Kubernetes、CI/CD 和身份侧的 Canary 资源，不是 Web CVE 专项蜜罐。启发是自动化部署、低噪声、高上下文、云原生覆盖

### Proofpoint Illusive / ITDR
- 定位：身份威胁检测响应
- 最适用场景：身份安全、凭据滥用、AD 攻击路径
- 侧重点是身份风险、凭据和攻击路径
- 对比矩阵评分：精准 高、高仿真 中、流量侧 弱、Payload/IOC 中
- 可吸收：身份欺骗和凭据诱饵

### Zscaler Deception
- 定位：云安全/零信任欺骗
- 最适用场景：互联网暴露诱饵、云/端点/身份诱捕
- 与零信任和云安全体系结合
- 对比矩阵评分：精准 高、高仿真 中、流量侧 中、Payload/IOC 中
- 可吸收：互联网诱饵、云安全集成

### Fidelis Deception
- 定位：商业欺骗防御
- 最适用场景：网络诱捕、凭据诱饵、横向移动检测
- 企业网络和端点欺骗能力
- 对比矩阵评分：精准 高、高仿真 中、流量侧 中、Payload/IOC 中
- 可吸收：企业部署、告警联动

## 局限
- 多数产品主线不是新 CVE 出现后快速生成漏洞蜜罐
- 高仿真更多指环境/资产真实感，不一定指具体 Web 漏洞路径和框架行为仿真
- 公开资料中很少展示完整 HTTP Body/Payload 留存、解码、IOC 提取、规则输出流程
- 能力偏黑盒，不利于研究型自定义和快速迭代
- 新 CVE 快速 Profile 化能力不透明：公开资料中很少看到用户输入一个 CVE 后自动生成漏洞蜜罐的开放流程
- Web 漏洞专项流量采集不是主叙事：多数产品强调内网攻击、身份欺骗、横向移动、云资源诱饵
- Payload/IOC 输出细节不足：更多强调告警和调查，不强调 HTTP Body/Payload 解析、IOC 归一化和规则生成
- 用户可控性有限，不适合做研究型原型和定制化 CVE 分析
- 检测规则沉淀不突出：未发现多数产品直接将蜜罐 Payload 转成 Sigma/Suricata/WAF 规则的公开能力

## 素材中的不确定处
- Nextrap 在 04、05、06 三份源文件里都没有出现，本笔记未收录。
- 素材的分组把 Tracebit 同时列在商业欺骗防御平台和诱饵 Token/云原生诱捕两组里，两处归类重复。
- 商业矩阵比商业方案调研多出 Proofpoint Illusive、Zscaler Deception、Fidelis Deception 三家，调研未对这三家做能力判断，本篇只保留矩阵里的信息。
