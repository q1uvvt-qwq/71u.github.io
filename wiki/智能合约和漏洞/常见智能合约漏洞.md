## 常见智能合约漏洞

智能合约漏洞通常意味着：

> 攻击者使用合约允许的交易入口和有效签名，让合约进入开发者没有预料到的状态。

节点和EVM可能完全正常，只是忠实执行了存在缺陷的代码。



## 1. 重入攻击

重入发生在合约调用外部地址时，外部地址在原函数完成之前再次调用该合约。

```
// 存在重入风险
function withdraw() external {
    uint256 balance = userBalances[msg.sender];
    require(balance > 0);

    // 外部合约可能在这里回调withdraw
    (bool success, ) = msg.sender.call{value: balance}("");
    require(success);

    // 状态更新得太晚
    userBalances[msg.sender] = 0;
}
```

攻击过程：

```
调用withdraw
→ 合约发送ETH
→ 恶意接收合约再次调用withdraw
→ 原余额尚未清零
→ 重复提款
```

常见防护包括：

```
// Checks-Effects-Interactions
function withdraw() external {
    uint256 balance = userBalances[msg.sender];
    require(balance > 0);

    userBalances[msg.sender] = 0;

    (bool success, ) = msg.sender.call{value: balance}("");
    require(success);
}
```

还可以使用重入锁。需要注意，重入也可能跨函数、跨合约，甚至发生在读取暂时不一致状态的过程中。

## 2. 整数溢出、下溢与精度错误

在旧版Solidity中，整数超过类型范围后可能发生环绕：

```
uint8最大值为255
255 + 1 → 0

uint8最小值为0
0 - 1 → 255
```

Solidity 0.8及以上默认会在算术溢出或下溢时回滚，因此一般不再需要SafeMath实现同类检查；`unchecked`代码块仍可恢复环绕行为。[Solidity文档](https://docs.soliditylang.org/en/latest/control-structures.html)明确规定了这两种算术模式。

现代合约更常见的计算风险包括：

- `unchecked`使用错误；
- 小整数类型转换时截断；
- 先除后乘导致精度丢失；
- 代币小数位不同；
- 舍入方向错误；
- 首次存款时分母过小；
- 份额、利息和抵押率计算错误。

编译器可以检查部分溢出，但无法判断业务公式是否正确。

## 3. 短地址攻击

短地址攻击是一个历史问题。早期工具如果没有正确检查参数长度，可能对不足的数据补零，造成后续参数错位，最终错误解释转账金额。

现代Solidity ABI解码器、节点和钱包通常会拒绝格式错误的参数，因此它已不是当前审计中的主要风险。

目前更应关注：

- 自定义汇编如何读取`calldata`；
- 是否手动解析字节数据；
- 动态参数边界是否正确；
- 签名内容与实际解码内容是否一致。

## 4. 时间戳与不安全随机数

`block.timestamp`可以用来表示时间条件，例如“到期后允许提款”，但不应单独作为高价值随机数。

以下数据通常具有可预测性或一定影响空间：

```
block.timestamp
block.number
blockhash
prevrandao
msg.sender
交易哈希
```

在当前以太坊PoS中，时间戳与时隙规则绑定，区块提议者的任意选择空间比早期PoW场景更小；但时间戳仍然公开且可预测，不能因此变成安全随机源。

高价值随机场景可以采用：

- 提交后揭示；
- 多方随机输入；
- 可验证随机函数；
- 延迟多个区块确定结果。

## 5. 权限控制不当

提款、铸币、暂停、升级和修改预言机等函数必须限制调用者。

```
// 缺少权限检查
function mint(address to, uint256 amount) external {
    _mint(to, amount);
}
```

常见问题包括：

- 敏感函数没有权限修饰；
- 把角色授予错误地址；
- 初始化函数可以重复调用；
- 默认管理员权限过大；
- 所有权转移不完整；
- 使用`tx.origin`鉴权；
- 升级权限由单个热钱包控制。

可以使用经过广泛测试的`Ownable`或`AccessControl`组件，但仍需正确配置。OpenZeppelin Contracts 5.x中的`Ownable`构造函数需要显式提供`initialOwner`。[OpenZeppelin访问控制文档](https://docs.openzeppelin.com/contracts/5.x/access-control)也建议对高权限角色使用多签、延迟和更严格的管理规则。

## 6. 未检查的外部调用

低级调用可能返回`false`而不自动让调用者回滚：

```
(bool success, ) = target.call(data);

// 如果不检查success，后续逻辑可能继续执行
```

可能造成：

```
外部转账实际失败
→ 内部账本记录为成功
→ 资产和账目不一致
```

合约应检查调用结果和返回数据，并把外部合约视为不可信对象。代币调用还要考虑不返回布尔值、转账扣费、余额自动变化等非标准行为。

## 7. `tx.origin`钓鱼

`tx.origin`表示整条调用链最初发起交易的外部账户，`msg.sender`表示当前这一层的直接调用者。

```
外部账户
  ↓
恶意合约
  ↓
目标合约

目标合约中：
tx.origin  = 外部账户
msg.sender = 恶意合约
```

如果目标合约用`tx.origin`判断权限，恶意合约可能诱导有权限的账户发起交易，然后借用其身份调用目标合约。权限判断通常应基于明确的`msg.sender`和角色体系。

## 8. 输入验证与拒绝服务

合约需要检查金额、地址、数组、期限和状态。否则可能出现零地址转账、重复领取、错误状态转换或超额操作。

拒绝服务常见形式包括：

- 遍历不断增长的用户数组；
- 单个接收地址回滚导致整批付款失败；
- 攻击者创建大量状态记录；
- Gas消耗超过区块限制；
- 某个必须依赖的外部合约永久失败。

常见防护包括分页处理、限制输入规模、由用户分别领取，以及避免让一个外部调用阻断所有用户。

## 9. 业务逻辑漏洞

业务逻辑漏洞是合约规则本身存在缺陷，例如：

- 同一奖励可以重复领取；
- 少量存款获得过多份额；
- 借款后债务没有正确增加；
- 清算后抵押品没有正确减少；
- 多个单独安全的函数组合后可以超额提款；
- 状态转换可以跳过必要步骤。

这类漏洞通常没有固定代码特征。审计时需要先定义不变量：

```
用户不能提取超过自己权益的资产
总负债不能无故超过总资产
同一奖励只能领取一次
普通用户不能获得管理员权限
```

然后尝试通过不同调用顺序和极端输入破坏这些不变量。

# DeFi与系统级风险

## 10. 闪电贷与价格操纵

闪电贷允许在一笔交易中借入大量资产，只要在交易结束前归还。它本身是一种金融工具，常被用于放大已有漏洞。

典型攻击链是：

```
闪电贷获得临时资金
→ 大额交易改变薄流动性市场价格
→ 协议读取被操纵的价格
→ 超额借款或错误清算
→ 恢复价格并归还闪电贷
```

防护重点包括多源预言机、足够窗口的时间加权价格、价格偏差限制、熔断机制，以及针对极端流动性的属性测试。以太坊安全资料也将“可操纵的即时价格”视为预言机风险的核心来源。[以太坊智能合约安全说明](https://ethereum.org/developers/docs/smart-contracts/security)

## 11. MEV与交易排序

MEV来自交易排序、插入或排除带来的额外收益，常见形式包括：

- 抢跑；
- 尾随；
- 夹子交易；
- 抢先清算；
- 抢先领取有限奖励。

MEV不是单一合约漏洞。有些行为利用公开内存池和排序权，有些则利用合约缺少滑点、截止时间或公平竞价机制。

PBS和相关区块构建基础设施尝试分离“构造区块”和“提议区块”的角色，但不能消除应用层全部排序风险。

## 12. 跨链桥攻击

跨链桥同时依赖多个系统，常见攻击面包括：

- 多签验证者密钥；
- 跨链消息验证；
- 轻客户端验证；
- 锁定与铸造数量对应关系；
- 重放保护；
- 合约升级权限；
- 链重组和最终性判断。

桥合约通常锁定大量资产，一个消息验证错误就可能导致跨链资产被无抵押铸造。多签只能降低部分密钥风险，无法替代正确的消息和状态验证。

## 13. 治理攻击

攻击者可能通过借入或临时获得治理权，推动恶意提案：

```
取得治理代币或投票权
→ 提交并通过恶意提案
→ 调用金库、升级或参数修改权限
```

防护措施包括：

- 使用历史区块快照确定投票权；
- 设置提案门槛；
- 投票权锁定；
- 执行时间锁；
- 对紧急高风险操作设置额外审查；
- 限制治理能够直接执行的权限。

# 风险分类

需要区分真正的漏洞和攻击条件：

| 情况               | 更准确的分类       |
| ------------------ | ------------------ |
| 重入导致重复提款   | 合约代码漏洞       |
| 缺少权限检查       | 访问控制漏洞       |
| 错误份额计算       | 业务逻辑漏洞       |
| 闪电贷提供临时资金 | 攻击放大工具       |
| MEV重新排列交易    | 排序和经济机制风险 |
| 管理员主动恶意升级 | 权限与治理风险     |
| 管理员私钥被盗     | 密钥管理事件       |
| 跨链消息验证错误   | 跨系统协议漏洞     |

当前OWASP智能合约风险分类也把访问控制、预言机操纵、逻辑错误、输入验证、重入和未检查外部调用列为主要风险类别。[OWASP Smart Contract Top 10](https://scs.owasp.org/sctop10/archive/2025/Top10%3A2025/)

## 本章要点

分析智能合约漏洞时，不要只寻找某段“危险代码”。需要还原：

```
攻击入口
→ 调用顺序
→ 外部依赖
→ 状态变化
→ 被破坏的不变量
→ 最终资产流向
```
