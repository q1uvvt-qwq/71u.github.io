## 智能合约与代币

智能合约可以持有资产、记录数据并执行规则。大量区块链攻击并没有破坏以太坊共识，而是利用了智能合约代码或业务逻辑中的问题。



### 智能合约定义

**智能合约是部署在区块链上、由节点按照相同规则执行的程序。**

一个合约通常包含：

```
程序代码
+ 持久化数据
+ 合约地址
+ 持有的原生资产
```

合约可以实现：

- 发行和管理代币；
- 保存用户余额；
- 处理兑换和借贷；
- 锁定或分配资产；
- 检查访问权限；
- 调用其他智能合约；
- 根据输入修改链上状态。



### 普通账户与合约账户

以太坊中可以先区分两种账户：

| 类型            | 控制方式 | 能否主动发起交易 |
| --------------- | -------- | ---------------- |
| **外部账户EOA** | 私钥     | 可以             |
| **合约账户**    | 合约代码 | 不能独立主动发起 |

普通账户拥有私钥。合约账户通常没有可供某个人直接使用的私钥，它的行为由代码决定。

合约需要先被外部交易或其他合约调用，才会执行代码：

```
外部账户签署交易
       ↓
调用合约A
       ↓
合约A执行代码
       ↓
合约A可以调用合约B
```

智能合约不会因为时间到了就自行启动。定时任务通常需要外部机器人或服务发送交易来触发。



### EVM

**EVM是以太坊虚拟机，是所有以太坊节点执行智能合约代码的统一运行环境。**

开发者通常使用Solidity等语言编写合约：

```
Solidity源代码
      ↓ 编译
EVM字节码
      ↓ 部署
以太坊合约
```

节点收到调用合约的交易后，会在自己的EVM中执行同一份字节码。为了让所有节点得到相同结果，合约执行必须具有确定性：

```
相同的交易
+ 相同的执行前状态
+ 相同的协议规则
= 相同的执行结果
```

如果节点执行结果不同，网络就无法对新的链上状态达成一致。



### 部署合约

部署合约本身也是一笔交易。部署交易通常包含：

- 编译后的合约字节码；
- 构造函数参数；
- Gas设置；
- 部署者签名；
- 可选的ETH金额。

交易成功后，网络会：

```
创建合约地址
      ↓
执行构造或初始化逻辑
      ↓
保存合约运行代码
      ↓
写入初始状态
```

部署需要Gas，因为节点需要执行代码并保存数据。

普通合约部署后，代码通常不能直接修改。可升级合约会通过代理结构把调用转发到另一份实现代码，具体风险在下一章讲解。



### 合约地址

每个已部署合约都有链上地址，例如：

```
0x1234...ABCD
```

向这个地址发送交易时：

- 如果携带ETH，合约可能收到ETH；
- 如果携带交易数据，EVM会尝试调用相应函数；
- 如果函数不存在，可能触发备用函数或执行失败；
- 合约怎样处理资产由代码决定。

合约地址可以公开，但名称和图标不是可靠身份。判断一个合约时，需要核对网络和完整合约地址。

### 合约组成

可以把智能合约分成两部分：

**代码**

定义合约可以执行哪些操作，例如：

```
转账
存款
提款
兑换
设置管理员
暂停服务
```

**状态**

保存合约当前的数据，例如：

```
地址余额
授权额度
管理员地址
抵押品数量
当前价格
是否暂停
```

代码决定数据怎样变化，状态表示当前结果。



## 本章要点

**智能合约是部署在区块链上的程序，由节点在EVM中执行。代码规定操作规则，状态保存当前数据，交易触发函数，Gas限制计算成本。**

代币本质上是智能合约维护的余额或所有权记录。分析链上安全时，需要同时查看交易入口、完整调用链、状态变化和最终资产流向。
