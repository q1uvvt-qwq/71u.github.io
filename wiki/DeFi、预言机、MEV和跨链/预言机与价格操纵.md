# 预言机与价格操纵

> **智能合约怎样知道某种资产现在值多少钱？**

答案通常是：通过**预言机（Oracle）**获得价格。



## 预言机

智能合约只能直接读取链上已经存在的数据，例如：

- 某个地址的代币余额；
- 某个交易的发送者；
- 当前区块编号和时间戳；
- 某个流动性池中的代币数量；
- 其他合约公开的状态。

但智能合约天然不知道链外世界的信息，例如：

- ETH 当前价值多少美元；
- 某只股票的市场价格；
- 某地今天是否下雨；
- 某场比赛的结果；
- 某个航班是否延误。

因此，需要有一个系统把这些信息传递给智能合约。

**预言机不是预测未来的机器，而是给智能合约提供外部数据的机制。**

可以把过程简化为：

```
外部市场或链上交易市场
          ↓
    数据采集与计算
          ↓
       预言机
          ↓
   智能合约读取价格
          ↓
借贷、清算、交易等业务逻辑
```

在区块链安全中，我们最常讨论的是**价格预言机**。



## 预言机角色承担

“预言机”不是某个固定的硬件，也不一定是一个人。

它可能是：

- 一个智能合约；
- 一组链下服务器；
- 多个独立数据提供者；
- 多个节点组成的数据网络；
- 协议自己编写的价格计算模块；
- 直接读取某个去中心化交易所价格的合约。

从逻辑上看，预言机通常包含两个部分：

```
数据来源 → 数据传输和聚合 → 链上价格合约
```

安全分析时，不能只看最后那个合约，还要继续追问：

1. 原始价格从哪里来？
2. 谁负责提交价格？
3. 使用了几个数据来源？
4. 数据如何聚合？
5. 多久更新一次？
6. 价格异常时怎么办？
7. 谁有权更换数据源？



## 常见的价格来源

### 1. 中心化价格源

由某个服务器或管理员提交价格：

```
服务器读取市场价格
        ↓
服务器签名或发送交易
        ↓
链上合约保存价格
```

优点：

- 实现简单；
- 更新速度快；
- 成本较低。

风险：

- 服务器被攻击；
- 私钥泄露；
- 管理员作恶；
- 服务中断；
- 数据来源本身发生故障。

如果一个协议完全相信单个地址提交的价格，那么控制这个地址就可能控制整个协议的价格。

这属于**单点故障**。

------

### 2. 多数据源预言机

多个节点从不同交易市场采集价格，然后进行聚合。

例如，多个节点分别报告：

```
节点 A：2,001 美元
节点 B：1,998 美元
节点 C：2,500 美元
节点 D：2,002 美元
节点 E：1,999 美元
```

如果系统采用中位数，排序后为：

```
1,998
1,999
2,001
2,002
2,500
```

最终价格为：

```
2,001 美元
```

单个异常值 `2,500` 不会直接控制结果。

这种模式减少了对单一服务器和单一市场的依赖，但仍然需要分析：

- 节点是否真正独立；
- 多个节点是否使用了相同的数据来源；
- 攻击者需要控制多少节点；
- 聚合算法是否合理；
- 更新是否及时；
- 管理权限是否过大。

“有很多节点”不一定意味着真正去中心化。十个节点如果都读取同一个交易所的数据，那个交易所仍然是共同的单点风险。

------

### 3. 链上即时价格

协议直接读取某个去中心化交易所流动性池的当前状态。

例如，一个池中有：

```
100 ETH
200,000 USDC
```

粗略计算：

```
1 ETH = 200,000 ÷ 100 = 2,000 USDC
```

这种当前时刻的价格通常称为：

> **现货价格（Spot Price）**

它的优点是完全来自链上，智能合约可以立即读取。

但它也非常危险，因为攻击者可能通过大额交易，暂时改变池中两种资产的数量。



## 价格操纵过程

假设一个简化的 AMM 池中有：

```
100 ETH
200,000 USDC
```

池内价格大致是：

```
1 ETH = 2,000 USDC
```

如果攻击者用大量 USDC 买入 ETH：

- 池里的 ETH 变少；
- 池里的 USDC 变多；
- ETH 在这个池里的价格会上升。

交易结束后，池子可能变成：

```
50 ETH
400,000 USDC
```

此时用余额比例粗略观察：

```
1 ETH = 8,000 USDC
```

这个价格不代表整个市场上的 ETH 都值 8,000 美元，只代表这个流动性池在被大额交易影响后的短暂状态。

如果借贷协议直接相信这个价格，攻击者可以：

```
1. 在流动性池中大量买入 ETH
2. 将池内 ETH 价格暂时推高
3. 借贷协议读取被推高的价格
4. 协议高估攻击者的 ETH 抵押物
5. 攻击者借走大量其他资产
6. 攻击者反向交易，使价格恢复
7. 攻击者不偿还贷款
8. 借贷协议留下坏账
```

关键问题不是攻击者永久改变了市场价格，而是：

> **攻击者只需要在协议读取价格的那一刻改变价格。**



## 流动性决定操纵成本

流动性可以理解为一个市场承受大额交易的能力。

**深度较高的市场**

池中资产很多：

```
100,000 ETH
200,000,000 USDC
```

一笔普通交易只占池子很小的比例，因此难以大幅改变价格。

**流动性较薄的市场**

池中资产很少：

```
10 ETH
20,000 USDC
```

一笔较大的交易就可能显著改变池内比例和价格。

因此：

```
流动性越薄
    ↓
改变价格所需资金通常越少
    ↓
预言机操纵风险通常越高
```

审计时不能只看到“价格来自某个 DEX”，还必须检查：

- 具体是哪个交易池；
- 池中有多少真实流动性；
- 流动性是否可能瞬间撤走；
- 交易量是否真实；
- 攻击者改变价格需要多少成本；
- 攻击收益是否高于操纵成本。



## 预言机操纵的主要类型

| 类型         | 核心问题                 | 可能后果                 |
| ------------ | ------------------------ | ------------------------ |
| 现货价格操纵 | 直接读取单个池的即时价格 | 超额借款、错误清算       |
| 薄流动性操纵 | 改变价格所需资金很少     | 低成本制造异常价格       |
| 闪电贷放大   | 临时获得巨额资金         | 在单笔交易内完成操纵     |
| 价格过期     | 长时间没有更新           | 使用已经失真的市场价格   |
| 单一数据源   | 完全依赖一个节点或市场   | 单点被攻破即可控制价格   |
| 小数位错误   | 单位或精度处理错误       | 资产价值被放大或缩小     |
| 价格方向错误 | 混淆 A/B 与 B/A          | 抵押价值计算严重错误     |
| 权限泄露     | 管理员可随意修改价格源   | 恶意替换预言机或提交价格 |
| 聚合失效     | 多个节点并不真正独立     | 看似分散，实际共同失效   |
| 跨链延迟     | 不同链上的价格更新不同步 | 使用滞后或不一致的价格   |
