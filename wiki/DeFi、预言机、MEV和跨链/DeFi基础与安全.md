## DeFi基础与安全

**DeFi（Decentralized Finance）是通过智能合约实现的链上金融系统。**

它可以提供兑换、借贷、抵押、清算和收益分配等功能。用户通常通过钱包直接与合约交互，资产和规则主要记录在区块链上。

DeFi安全的关键是理解：

```
资产存在哪里？
价格从哪里来？
收益由谁支付？
什么时候会清算？
谁可以修改规则？
```



### 基本结构

一个DeFi应用通常包含：

```
用户钱包
   ↓
应用前端
   ↓
智能合约
   ├─ 保存资产
   ├─ 记录份额和债务
   ├─ 执行业务规则
   └─ 调用其他合约
          ↓
      代币、预言机、其他协议
```

前端只是操作入口。真正控制资产和执行规则的是链上的合约，以及合约依赖的管理员、预言机和其他协议。



### DEX去中心化交易所

去中心化交易所简称DEX。用户通过智能合约交换代币，不需要把资产充值到中心化交易所账户。

常见DEX模式包括：

| 类型              | 价格形成方式                  |
| ----------------- | ----------------------------- |
| **订单簿**        | 买单和卖单相互匹配            |
| **自动做市商AMM** | 根据流动性池资产比例计算价格  |
| **聚合器**        | 在多个DEX和路径中寻找兑换结果 |

以太坊上的很多DEX使用AMM。



### 流动性池

流动性池是由智能合约持有的两种或多种资产，例如：

```
ETH/USDC流动性池

100 ETH
200,000 USDC
```

用户兑换时，不是等待另一个用户提交相反订单，而是直接与流动性池合约交易。

向池中提供资产的一方称为**流动性提供者（LP）**。LP通常获得：

- 代表池中份额的凭证；
- 交易手续费；
- 某些协议额外发放的激励代币。



### AMM计算价格

一种基础AMM使用恒定乘积公式：

```
x × y = k
```

其中：

- `x`是池中资产A的数量；
- `y`是池中资产B的数量；
- `k`在一次不考虑手续费的兑换过程中保持不变。

假设池中有：

```
100 ETH × 200,000 USDC
k = 20,000,000
```

此时一个ETH的近似池内价格为：

```
200,000 ÷ 100 = 2,000 USDC
```

当交易者从池中买走ETH时，池中ETH减少、USDC增加，ETH的池内价格随之上升。



### 价格影响与滑点

**价格影响**来自交易本身改变了流动性池的资产比例。交易量相对池子越大，价格影响通常越明显。

**滑点**表示最终成交结果与用户预期结果之间的差异。用户通常设置最低接收数量：

```
预计获得：1000个代币
最低接受：990个代币
```

执行结果低于990时，交易回滚。

滑点设置过高会给价格变化和夹子交易留下更大空间；设置过低则可能导致正常交易频繁失败。



### 无常损失

当池中两种资产的外部市场价格发生变化时，套利交易会调整池内比例。LP取回的资产组合可能比单纯持有两种资产价值更低，这种差额称为**无常损失**。

“无常”表示价格恢复时差额可能缩小，并不表示损失一定会恢复。退出流动性池后，差额就会体现在实际结果中。

LP获得的手续费可能抵消无常损失，也可能不足以抵消。



### DeFi借贷

DeFi借贷通常使用超额抵押：

```
存入抵押品
    ↓
协议根据抵押品价值计算借款上限
    ↓
借出另一种资产
    ↓
持续计算利息和抵押率
```

例如：

```
抵押品价值：2,000美元
最高贷款价值比：75%
理论最大借款：1,500美元
```

实际借到最高额度会非常接近清算边界。抵押品价格下跌或债务利息增加，都可能触发清算。



### 贷款价值比与健康度

**贷款价值比（LTV）**可以简化表示为：

```
LTV = 债务价值 ÷ 抵押品价值
```

假设：

```
抵押品价值：2,000美元
债务价值：1,000美元

LTV = 50%
```

如果抵押品价格下跌到1,250美元：

```
LTV = 1,000 ÷ 1,250 = 80%
```

当LTV超过协议规定的清算阈值时，仓位可能被清算。

有些协议使用健康因子表示风险：

```
健康因子 > 1：通常仍安全
健康因子 ≤ 1：可能允许清算
```

具体公式由协议决定。



### 清算

清算是协议处理高风险债务的机制。清算者偿还借款人的部分债务，并以折扣获得抵押品：

```
仓位达到清算条件
      ↓
清算者偿还部分债务
      ↓
协议把部分抵押品交给清算者
      ↓
借款人的债务和抵押品减少
```

给予清算者折扣或奖励，是为了让外部参与者及时处理风险仓位。

如果抵押品价格下降过快、预言机延迟或链上拥堵，抵押品可能不足以偿还债务，形成**坏账**。



### 利息

借款人支付利息，存款人获得其中一部分。利率通常会根据资金利用率变化：

```
利用率较低
→ 可借资金充足
→ 利率通常较低

利用率较高
→ 可借资金不足
→ 利率通常上升
```

存款收益通常低于借款利率，因为协议可能保留一部分费用或风险准备金。



### 收益

DeFi收益可能来自：

| 收益来源   | 实际支付者     |
| ---------- | -------------- |
| 交易手续费 | 进行兑换的用户 |
| 借贷利息   | 借款人         |
| 清算奖励   | 被清算仓位     |
| 质押奖励   | 区块链协议     |
| 激励代币   | 项目新增发行   |
| 套利收益   | 市场价格差异   |

高收益如果主要来自新增代币发行，就依赖代币价格和后续需求，不代表协议产生了等额真实收入。

分析收益产品时，应追踪收益最终由谁承担。



### 凭证代币与份额

存入DeFi协议后，用户可能获得凭证代币或份额：

```
存入100个资产
      ↓
获得100份凭证
      ↓
凭证代表对协议资产的索取权
```

随着利息积累，每份凭证可兑换的底层资产可能增加。

份额计算是重要攻击面：

```
份额 = 存入资产 × 总份额 ÷ 协议总资产
```

首次存款、直接向合约转账、舍入方向和资产捐赠，都可能影响份额价格。如果公式设计错误，攻击者可能用少量资产获得过多份额。



### 稳定币

稳定币试图维持与某种资产的固定关系，例如与美元保持接近1:1。

常见类型包括：

| 类型               | 主要支撑                   |
| ------------------ | -------------------------- |
| **法币储备型**     | 银行账户中的现金或短期资产 |
| **加密资产抵押型** | 链上超额抵押资产           |
| **算法调节型**     | 铸造、销毁和市场激励机制   |
| **混合型**         | 同时使用储备、抵押和算法   |

稳定币可能发生脱锚。原因包括储备不足、抵押品下跌、赎回受限、合约漏洞、银行风险或市场信心下降。

其他协议把稳定币视为“一美元”时，脱锚可能引发连锁清算和坏账。



### 闪电贷

闪电贷允许在同一笔交易中：

```
借入资产
→ 使用资产执行多个操作
→ 归还本金和费用
```

如果交易结束前没有归还，整笔交易回滚。

闪电贷可以用于正常套利和清算，也可以放大：

- 价格操纵；
- 份额计算漏洞；
- 治理攻击；
- 清算逻辑错误；
- 流动性不足造成的价格偏移。

安全协议应假设任何人都能在一笔交易中暂时获得大量资金。



## 本章要点

DeFi把交易、借贷和清算规则写入智能合约。理解DeFi安全，需要追踪四条线：

```
资产流向
份额和债务记录
价格来源
权限与外部依赖
```
