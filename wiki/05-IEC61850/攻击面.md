## 一句话概括

GOOSE 为了快，放弃了认证、加密和连接。任何能接入间隔层/过程层网络的设备都能伪造一条"低电压保护动作、断路器分闸"的报文；靶场海上链还叠上两个更现实的应用层缺陷：测试通道边界校验不严、联锁确认不校验来源与角色。

## 原理

IEC 61850 的安全问题可以分成三层来看，越往下越难用传统手段防护：

```text
应用层    授权模型、测试边界、联锁确认、压板与远方控制权限
         -> 靠实现正确性，IEC 61850 本身不提供，必须自建

协议层    MMS 的认证与访问控制、报告与文件服务的权限
         -> IEC 62351 提供了增强思路，但需要额外配置与设备支持

链路层    GOOSE / SV 的二层组播，无认证、无加密、广播可达
         -> 协议层面几乎无法解决，只能靠网络隔离与准入控制
```

定义：链路层的问题落在协议设计本身，GOOSE 的设计目标里就没有"来源可信"这一项；应用层和协议层的问题则都出在实现上。

## 结构

下面按链路层 → 协议层 → 应用层三层归类；配置文件与资料泄露不落在这三层上，单列在最后。

### 链路层

#### 弱点一：GOOSE 无认证、无加密、广播可达

这是 GOOSE 的固有属性，与具体实现无关：

```text
无连接      没有握手，没有会话，接收方无法确认发布者是谁
无认证      帧里没有签名、没有 MAC 校验（消息认证码）、没有证书
无加密      明文，allData 里的布尔量直接可读
组播广播    同一 VLAN 内所有设备都能收到，也都能发送
```

直接后果：

```text
1. 任意接入网络的设备都能伪装成某台 IED 发布 GOOSE
2. 报文内容可离线解析，保护动作与开关位置一目了然
3. 伪造报文与真实报文在接收方看来没有区别
4. 传统的"按端口放行"失效：GOOSE 没有端口
```

网络位置决定了谁能利用这一点：

```text
接入间隔层/过程层交换机  -> 可伪造保护事件
接入站控层               -> 通常收不到 GOOSE，但可打 MMS
从站外接入               -> 若边界没有 VLAN 与控制，风险直接落到一次设备
```

#### 弱点二：序列号可伪造（重放 / 欺骗）

GOOSE 用 `stNum` / `sqNum` 表达新鲜度，机制本身有效，但校验要由接收方自己做，协议不强制：

```text
接收方应校验      stNum 单调递增、不回退、不重复
                状态变化帧 sqNum = 0
                同 stNum 下 sqNum 不回退
                超时未收到下一帧应告警（timeAllowedToLive）
```

如果实现里缺了这些校验，攻击手法就成立了：

```text
重放  录下历史的一条"保护动作"帧，原样重发
      -> 接收方认为是新的状态变化，执行联锁
欺骗  按已知 gocbRef / datSet / 数据集顺序构造一条新帧
      -> 把 PTUV1.Op.general 置 true、XCBR1.Pos.stVal 置 open
      -> 接收方执行分闸逻辑
```

注意：`timeAllowedToLive` 设得太小，订阅者会因超时告警暴露异常；设得与真实流量一致，则更难被发现。这个字段既是可用性参数，也是伪装参数。

海上链把校验规则显式写进了验收口径，这本身就是防护示范：

```text
序列要求：stNum > 41，sqNum = 0
```

含义是"只接受状态号比既有基线更大、且是新状态第一帧的事件"，攻击者重放旧帧时 `stNum` 不满足大于 41 就会被拒。

### 协议层

#### 弱点三：MMS 越权读写

MMS 侧的越权形式比较常规，但影响不小：

```text
102 暴露在可达网段            -> 任何主机都能尝试建 MMS 关联
弱口令 / 默认账户             -> 直接获得合法身份
读写权限未按角色分离          -> 只读账号能写控制对象
报告控制块可被改写            -> 改 TrgOps/DatSet 改变上送行为，制造盲区
文件服务权限过宽              -> 读走定值、配置、录波，甚至删改记录
远方控制未受压板约束          -> 直接下发分合闸
```

这些和 OPC UA 侧的问题同源：协议提供了权限模型，实现里没有把它用起来。

### 应用层

#### 弱点四：test 位被忽略

`test=true` 表示"这帧只在试验/仿真，不反映真实一次设备状态"。正确处理是双向的：

```text
正常模式的订阅者  应忽略 test=true 的帧
测试模式的订阅者  应忽略 test=false 的帧
ndsCom=true       一律拒绝（装置未组态完成，数据不可信）
```

海上链的第一个漏洞点正是单向校验：

```text
正常逻辑：保护测试通道只能接受 test=true 的 GOOSE 回放事件。
缺陷逻辑：AGC/AVC3 只校验 test_ticket，未阻止 test=false 正式保护事件进入下游链路。
结果：正式 GOOSE 保护事件被前置机1转发到 SCADA系统5。
```

翻译成一句话：测试通道收了不该收的正式事件，把仿真环境的入口变成了生产链路的入口。问题出在边界规则只校验"有没有票"，没校验"票对不对类型"，与 GOOSE 协议本身无关。

对应防护就是记录里那句：

```text
test=true 只模拟，test=false 不应通过测试通道进入生产链路
```

#### 弱点五：联锁确认授权缺陷

海上链的第二个漏洞点：

```text
正常逻辑：断路器联锁确认应由 SCADA系统3/HMI 授权操作员完成。
缺陷逻辑：HMI 只校验 interlock_id 与事件内容，未校验请求来源、角色和测试通道边界。
结果：AGC/AVC3 的 interlock-test 测试接口可触发真实联锁确认。
```

这里有两个"只校验内容、不校验主体"的错误：

```text
校验了   事件内容对不对（interlock_id 与 event_id 匹配吗）
没校验   谁在请求（来源主机、身份、角色）
没校验   走的是哪条通道（测试通道还是生产通道）
```

对比 OPC UA 侧的缺陷"只校验登录、不校验方法级权限"，两者形态一致，说明这类问题在协议栈里是通用盲区。

#### 弱点六：保护压板与远方控制权限不清

压板（硬压板 / 软压板）本应是"能不能出口"的最终开关：跳闸出口压板决定保护动作能否真正跳开断路器，远方/就地切换决定是否接受监控主机的控制，联锁投退压板决定联锁逻辑是否生效。

这些若不纳入严格的权限管理，仅靠一条协议报文就可能完成真实出口动作。靶场把 `XCBR1.Pos.stVal=open -> CTRL.GRID_ENABLE -> HR93=0` 串起来是为了让影响可见；真实系统里这一路应当有多道确认。

### 资料面

#### 弱点七：保护定值与配置文件泄露

SCD / CID / ICD 这类 SCL 文件里包含：

```text
全站 IED 清单与通信参数
每个 IED 的逻辑设备与逻辑节点实例
GOOSE 控制块定义：gocbRef、datSet、APPID、组播 MAC、confRev
数据集内容与顺序（allData 的构成）
保护联锁关系（哪个保护动作触发哪个开关）
```

再加上 MMS 文件服务可读的录波、动作报告、事件日志、装置参数文件，泄露面扩大到"保护定值与动作行为"。

拿到这些资料的价值排序很清晰：

```text
1. 知道有哪些设备、怎么编号           -> 资产测绘
2. 知道 GOOSE 帧该长什么样             -> 伪造的前提
3. 知道保护联锁关系                    -> 知道伪造哪条事件最有效
4. 知道保护定值与录波                  -> 反推保护逻辑，评估动作边界
```

这是"信息泄露直接放大攻击能力"的典型案例：不需要任何协议漏洞，只要配置文件和文件服务可读，伪造 GOOSE 帧的参数就齐了。

## 报文/字段对照

| 弱点 | 协议层可观测点 | 应做的校验 |
|---|---|---|
| GOOSE 无认证 | 帧内无签名 / 无 MAC 校验字段 | 网络层准入 + 工业防火墙按组播 MAC、APPID 白名单放行 |
| 序列号可伪造 | `stNum` / `sqNum` | `stNum` 单调递增、变化帧 `sqNum=0`、同 `stNum` 下不回退 |
| 时效性可伪造 | `timeAllowedToLive` / `t` | 超时告警；必要时对时标做时效性判断 |
| 配置被篡改 | `confRev` | 与 SCD 记录比对，不一致应拒绝并告警 |
| test 位被忽略 | `test` / `ndsCom` | 双向模式一致校验；`ndsCom=true` 拒绝 |
| 定值/配置泄露 | SCL 文件、MMS 文件服务 | 文件服务只对授权角色开放，读取留痕，重要文件做完整性校验 |
| MMS 越权 | 102 会话、MMS `Write` 服务、RCB 属性 | 按角色分离读写；RCB 变更单独审计 |
| 联锁确认越权 | 联锁接口的来源、角色、通道 | 三者全校验，不能只校验事件内容 |
| 压板与远方控制 | 控制类数据对象的写操作 | 压板状态与权限双重确认，操作全程留痕 |

## 实测过程

```text
attack-offshore
  -> AGC/AVC3 IEC61850 GOOSE 保护测试        <- 漏洞点 1：只校验 test_ticket
  -> 前置机1
  -> SCADA系统5 生成 PENDING_CONFIRM
  -> AGC/AVC3 回执通道读取 event_id / interlock_id
  -> AGC/AVC3 interlock-test 联锁确认        <- 漏洞点 2：不校验来源与角色
  -> SCADA系统3/HMI
  -> PLC3 HR93=0
  -> OFF_GRID / GRID_DISCONNECT
```

工控协议点：

```text
协议：IEC61850 GOOSE
事件：PTUV1.Op.general=true
设备对象：XCBR1.Pos.stVal=open
序列要求：stNum > 41，sqNum = 0
测试边界：test=true 只模拟，test=false 不应通过测试通道进入生产链路
控制映射：XCBR1.Pos.stVal=open -> CTRL.GRID_ENABLE -> HR93=0
业务影响：PLC3 OFF_GRID，功率归零，告警 GRID_DISCONNECT
```

实测行为：

```text
GET  /api/protection/sample          返回 GOOSE 样例、字段说明和 HR93 映射
POST /api/protection/replay          test=true  -> SIMULATION_ONLY（正确拒绝进入生产）
                                     test=false -> PENDING_CONFIRM（本应被测试通道拒绝）
GET  /api/protection/test-result     event_id     = EVT-PTUV1-20260712-001
                                     interlock_id = INT-XCBR1-20260712-001
POST /api/protection/interlock-test  确认后 PLC3：status/grid_state = OFF_GRID
                                     active_power_kw = 0，alarm = GRID_DISCONNECT
```

旧的海上直控入口 `POST AGC/AVC3 /api/dispatch` 已禁用，返回 `LEGACY_DISPATCH_DISABLED`。验收后执行 reset，PLC3 恢复 `RUNNING / GRID_CONNECTED`。

再次强调实现方式：这段链路用 HTTP 接口模拟 GOOSE 事件的回放与联锁确认，校验的是事件要素（事件类型、设备对象、`stNum`/`sqNum`、`test` 位），并不是在二层真实收发 GOOSE 帧。素材中没有 GOOSE 或 MMS 的 pcap，本篇不提供抓包字节。它适合讲清"序列号校验、测试边界、授权边界"三类问题；讲帧级伪造与重放需要真实 IED 或 GOOSE 仿真器配合抓包。

## 安全视角

- 站控层隔离 + VLAN 划分。站控层与办公网、管理信息区彻底隔离，MMS（TCP 102）只允许 SCADA、网关、保护信息子站等指定主机访问；三层各自成 VLAN，禁止跨 VLAN 的 GOOSE/SV 泛洪，把"谁能发 GOOSE"从物理接入收敛到逻辑分区。
- 工业防火墙只放行授权 IED 的 GOOSE 组播。按组播 MAC 与 APPID 建立白名单，阻断非授权发布者，这是链路层唯一有效的控制手段。
- 序列号新鲜度校验。接收端必须校验 `stNum` 单调递增、状态变化帧 `sqNum=0`、同 `stNum` 下序号不回退，并结合 `timeAllowedToLive` 做超时告警。海上链把 `stNum > 41、sqNum = 0` 写成硬性序列要求，就是这个思路。
- 测试边界双向执行。`test=true` 不进生产链路、`test=false` 不进测试链路、`ndsCom=true` 一律拒绝。测试通道的设计要"默认拒绝"，而不是"校验票据后放行"。
- 保护压板与远方控制权限管理。跳闸出口压板、远方/就地切换、联锁投退必须纳入权限体系，控制类操作要求来源、角色、压板状态三重确认，全程留痕。
- 配置文件与文件服务管控。SCD/CID/定值单按敏感工程资料管理；MMS 文件服务只对保护信息子站、SCADA、工程师站开放，读取行为记日志，重要文件做完整性校验。
- 监控与取证。持续记录 GOOSE 发布者 MAC、APPID、`stNum` 变化与 `confRev`，对 102 会话、MMS `Write`、RCB 属性变更做审计。异常发布者或异常序列应告警，这是事后区分"真实保护动作"与"伪造事件"的关键证据。
- 建立纵深防御的心智模型。链路层挡不住时，应用层的授权与测试边界必须兜住；应用层被绕过时，压板与人工确认必须兜住。海上链的价值就是把"单点校验失效会导致什么"演示清楚。
- 定位说明：本篇面向授权靶场与教学环境做弱点与防护整理，所用事件要素、接口行为与返回值均来自靶场实测记录，不对应真实生产系统的可利用操作；真实系统的测试必须经过书面授权。
