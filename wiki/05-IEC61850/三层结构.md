## 一句话概括

IEC 61850 先用"站控层 / 间隔层 / 过程层"把变电站的网络和设备分成三层，再用"逻辑节点 LN → 数据对象 DO → 数据属性 DA"把每台设备的功能拆成标准化的数据点，最后用 MMS、GOOSE、SV 三种通信把它们连起来。理解了这套分层与命名，才看得懂 `PTUV1.Op.general` 为什么会引出 `XCBR1.Pos.stVal`。

## 原理

### 它要解决什么问题

升压站/变电站里设备型号极多：保护装置、测控装置、合并单元、智能终端、监控主机、远动网关，来自不同厂家。如果每家的点表命名、通信方式都不同，站控层每接一台设备就要改一次代码，保护联锁这种跨设备配合更难以实现。

IEC 61850 的思路是：先把信息模型统一，再把通信映射统一。

```text
信息模型层：规定"断路器位置""低电压保护动作"应该叫什么、怎么组织
通信映射层：规定这些数据用 MMS / GOOSE / SV 哪条通道传、怎么传
工程配置层：用 SCL 文件把上面两层具体化，形成全站唯一的配置描述
```

### 三层结构

```text
站控层（Station Level）
  监控主机 / SCADA 操作员站 / 工程师站 / 远动网关（通信网关，上送调度）
  职责：全站监视、集中控制、事件记录、与调度主站通信（常经 IEC 104 上送）
  通信：MMS（对间隔层 IED 读写与报告）、文件服务（读录波与报告）
        ↓ 站控层网络（MMS 走 TCP/IP）
间隔层（Bay Level）
  保护 IED、测控 IED、计量 IED（保护、测控、合并单元等）
  职责：本间隔的保护判断、测量、控制、联锁
  通信：MMS（对站控层）、GOOSE（IED 之间）、SV（接收采样）
        ↓ 过程层网络（GOOSE / SV 走二层以太网）
过程层（Process Level）
  合并单元 MU / 智能终端 / 电子式互感器 / 断路器与隔离开关本体
  职责：一次设备侧的采样与开关执行
  通信：SV（电流电压采样值）、GOOSE（跳合闸与位置回传）
```

关于"合并单元到底算哪一层"：标准分层里 MU 属于过程层（物理位置和职责都在一次设备侧），但早期教材和部分工程习惯也把 MU 称作间隔层 IED 的一种形态（它确实是一台智能电子设备），两种说法都能见到。判断依据看职责：负责一次侧采样与就地执行的归过程层，负责本间隔保护测量逻辑的归间隔层。

三层结构带来两条重要的网络边界：

```text
站控层 ↔ 间隔层：走 MMS，TCP/IP，可被防火墙按端口和会话管控
间隔层 ↔ 过程层：走 GOOSE / SV，二层组播，传统防火墙难以按端口管控
```

后一条边界是 IEC 61850 安全上的特殊之处：GOOSE 不走 TCP/IP，没有端口可以封，只能用 VLAN、组播 MAC 过滤和工业防火墙的深包检测来管。

### 逻辑节点 LN、数据对象 DO、数据属性 DA

定义：从"设备"到"一个具体数值"，中间隔三层。

```text
IED（物理设备，例如某台保护装置）
  └── Logical Device（逻辑设备，通常对应一个间隔，例如 PROT / MEAS）
        └── Logical Node 逻辑节点（功能单元，例如 XCBR、PTUV、MMXU）
              └── Data Object 数据对象（例如 Pos、Op）
                    └── Data Attribute 数据属性（例如 stVal、general）

完整引用写法：LDName/LNName.DO.Attribute
例如：PROT/XCBR1.Pos.stVal
```

- LN 逻辑节点：一类功能的抽象。同一个 LN 类可以在不同间隔里实例化多次，用前缀和实例号区分：`XCBR1`、`XCBR2`、`PTUV1`。
- DO 数据对象：LN 里的一个数据集合，例如断路器位置 `Pos`、保护动作 `Op`。
- DA 数据属性：DO 里真正带值的字段，例如 `Pos` 下的 `stVal`（状态值）和 `q`（品质）、`t`（时标）。

这种"类 + 实例 + 前缀"的命名法让全站数据具备确定性：只要知道 LN 类和实例号，在任何厂家的设备上都能定位到同一个语义点。

常用的 LN 类与关键数据点：

| LN | 含义 | 关键 DO/DA | 说明 |
|---|---|---|---|
| `XCBR` | 断路器（Circuit Breaker） | `Pos.stVal` | 开关位置：`open`（分）/ `intermediate` / `closed`（合）/ `bad` |
| `PTUV` | 低电压保护（Protection, Time, Under Voltage） | `Op.general` | 保护动作总信号：`true` 表示动作 |
| `MMXU` | 测量单元（Measurement） | `TotW` / `TotVAr` / `A` / `PhV` / `Hz` | 有功/无功/电流/相电压/频率 |
| `CSWI` | 开关控制器 | `Pos` / `OpOpn` / `OpCls` | 接收控制命令、控制开关 |
| `PTOC` | 过流保护 | `Op.general` | 过流动作总信号 |
| `GGIO` | 通用 I/O | `Ind` / `SPCSO` | 硬接点与通用状态量 |

### 功能约束 FC

DA 不只是有名字，还带一个功能约束（Functional Constraint），说明这个属性属于哪一类用途。常用取值：

| FC | 全称 | 含义 | 典型例子 |
|---|---|---|---|
| `ST` | Status Information | 状态信息 | `XCBR1.Pos.stVal`（断路器位置）、`PTUV1.Op.general`（保护动作） |
| `MX` | Measurands | 测量值 | `MMXU1.TotW.mag`（有功功率）、`MMXU1.A.phsA.cVal.mag`（A 相电流） |
| `CO` | Control | 控制量 | 断路器分合闸控制、调节命令 |
| `CF` | Configuration | 配置信息 | 定值组、量程、时间参数 |
| `SP` | Setpoint | 设定值 | 保护定值、功率设定值 |
| `DC` | Description | 描述信息 | 设备铭牌、描述文本 |
| `SG` | Setting Group | 定值组 | 定值区切换 |
| `EX` | Extended Definition | 扩展定义 | 厂商扩展属性 |

FC 的实用价值在于：它把"读状态""读测量""下发控制""改定值"从语义上分了类，正是天然的四类不同权限。看到 `ST` 就知道这是遥信类只读量，看到 `CO` 就知道这可能落到开关动作上。

### SCL 配置文件

SCL（Substation Configuration description Language）是基于 XML 的工程配置语言，用一组不同用途的文件描述全站配置：

| 文件 | 全称 | 用途 | 谁产出 |
|---|---|---|---|
| `ICD` | IED Capability Description | 装置的固有能力描述，厂家提供 | 装置厂家 |
| `CID` | Configured IED Description | 下装到具体装置的、已实例化的配置 | 系统集成 |
| `SCD` | Substation Configuration Description | 全站唯一配置：所有 IED、通信参数、GOOSE 连线、保护联锁关系 | 系统集成 |
| `SSD` | System Specification Description | 一次系统（单线图、间隔）描述 | 设计院/集成 |
| `IID` | Instantiated IED Description | 单个 IED 的实例化描述 | 集成调试 |

SCD 是信息量最大的一份：

```text
全站 IED 清单与 IP
每个 IED 的逻辑设备 / 逻辑节点实例
GOOSE 控制块（gocbRef、datSet、APPID、组播 MAC、confRev）
GOOSE 数据集里包含哪些数据点（allData 的内容与顺序）
保护联锁关系（哪个保护动作触发哪个开关）
MMS 通信参数与报告控制块
```

对安全评估来说，拿到 SCD 就等于拿到全站设备清单、点表、GOOSE 连线关系和联锁逻辑，这也是配置文件泄露会被单独列为一类风险的原因。

## 报文/字段对照

三种通信的服务对象对照：

| 通信 | 承载 | 服务模型 | 服务对象 | 实时性 | 典型用途 |
|---|---|---|---|---|---|
| MMS | TCP/IP，常见 102/tcp | 客户端/服务器 | 站控层与间隔层之间读写数据、报告上送、文件服务 | 毫秒~百毫秒 | SCADA 读取遥测遥信、下发控制、读录波 |
| GOOSE | 二层以太网，以太类型 `0x88B8` | 发布者/订阅者（广播） | IED 之间的快速事件与联锁 | 毫秒级（可到 3~4 ms） | 保护跳闸、闭锁、联锁、位置状态传递 |
| SV | 二层以太网，以太类型 `0x88BA` | 发布者/订阅者（广播） | 合并单元 → 保护/测控的采样值 | 极快，按采样率周期发送 | 电流电压采样值传输 |

海上链实例中出现的两个引用，完整含义是：

```text
PTUV1.Op.general = true
  LN 类 PTUV（低电压保护），实例号 1，数据对象 Op（保护动作），
  数据属性 general（动作总信号）。取值 true 表示该保护已动作。

XCBR1.Pos.stVal = open
  LN 类 XCBR（断路器），实例号 1，数据对象 Pos（位置），
  数据属性 stVal（状态值）。取值 open 表示断路器分位（已断开）。
```

两句连起来是一条完整的保护逻辑：低电压保护动作 → 断路器分闸。这个分闸动作最终被映射到并网控制点上，导致机组脱网。

## 实测过程

2026-07-12 的海上 GOOSE 保护链路把这条逻辑做成了可演练的通道。链路结构：

```text
attack-offshore
  -> AGC/AVC3 IEC61850 GOOSE 保护测试
  -> 前置机1
  -> SCADA系统5 生成 PENDING_CONFIRM
  -> AGC/AVC3 回执通道读取 event_id / interlock_id
  -> AGC/AVC3 interlock-test 联锁确认
  -> SCADA系统3/HMI
  -> PLC3 HR93=0
  -> OFF_GRID / GRID_DISCONNECT
```

对应接口：

```text
GET  /api/protection/sample                       取 GOOSE 样例与字段说明
POST /api/protection/replay                       回放 GOOSE 事件
GET  /api/protection/test-result?id=OFFSHORE-PROT-TEST-20260712
POST /api/protection/interlock-test               联锁确认
```

实测取值：

```text
event_id     = EVT-PTUV1-20260712-001
interlock_id = INT-XCBR1-20260712-001
```

注意：这条链用 HTTP 接口模拟 GOOSE 的事件内容与校验要素（事件类型、设备对象、stNum/sqNum、test 位、联锁确认），并不是真的在二层发 GOOSE 帧，仅适合讲清"信息模型、事件语义、校验缺陷"，做不了逐字节的 GOOSE 帧分析，那需要真实的 IED 或 GOOSE 仿真器。

旧的海上直控入口已禁用：

```text
POST AGC/AVC3 /api/dispatch
返回：LEGACY_DISPATCH_DISABLED
```

控制不再允许"直接下发"，必须走保护事件的通道，这与真实的保护联锁语义更接近。

## 安全视角

- 分层就是分区。三层各是一个安全区，跨区通信必须经过受控的边界设备；MMS 走 TCP/IP 尚可用端口管控，GOOSE/SV 走二层，只能靠 VLAN 与组播过滤。
- 配置文件的敏感度被低估。SCD/CID/ICD 一旦泄露，等于全站设备清单、点表、GOOSE 连线与联锁逻辑全部交出，这类文件应按敏感工程资料管理，不下发到无关主机。
- FC 天然提供了权限分类依据：`ST`/`MX` 属只读观测，`CO` 属控制，`SP`/`CF` 属参数与定值修改。授权模型应沿用这一分类，而不是笼统地给一个"可读写"角色。
- LN 命名带来可预测性，也降低攻击门槛：`XCBR1.Pos.stVal`、`PTUV1.Op.general` 都是全站通用的标准名称，攻击者无需点表即可推断语义。防护要依赖访问控制，而不是"名字不好猜"。
- 联锁关系必须在应用层校验来源与角色。海上链的两个漏洞点都出在这里：测试通道只校验票据、不阻止正式保护事件进入下游；HMI 只校验联锁 ID 与内容、不校验请求来源与角色。协议本身不解决这种越权。
