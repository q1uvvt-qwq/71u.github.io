## 一句话概括

IEC 60870-5-104（简称 IEC 104）是电力系统里场站和调度中心之间传数据、下命令的远动协议，跑在 TCP/IP 上，默认端口 2404，用一条长连接把风电场的遥测、遥信送到调度主站，同时接收下发的遥控、遥调命令。

和 Modbus 的区别一句话说清：Modbus 是设备点对点读寄存器，IEC 104 是厂站与调度之间的业务对话，传的不是寄存器，而是带业务语义（点号 + 原因 + 类型）的信息对象。

## 原理

### 1. 从 101 到 104：同一个标准的两副面孔

```text
IEC 60870-5-101   串行链路（RS-232/485），用于低速远动
IEC 60870-5-104   101 的应用层（ASDU）原样搬到 TCP/IP 上
```

IEC 104 就是把 101 的报文原样套进 TCP，没有重新设计。两个直接结果：

1. ASDU（应用服务数据单元）的结构与 101 完全一致，TypeID、COT、CA、IOA 都来自 101。
2. TCP 之上加了一层链路控制（APCI），负责启动/停止/测试与序号确认。TCP 只管字节可靠，远动要的是明确的链路管理与会话状态，这也是链路异常类攻击的入口，见 `链路异常.md`。

### 2. 真实链路位置

```text
调度主站 / D5000
      │  调度数据网
      ▼
前置机（规约处理与转发）              ← 常配纵向加密认证装置
      │
      │  IEC 104 / TCP 2404          ← 攻击链关注的就是这一段
      ▼
RTU / 远动网关（厂站侧）
      │  内部协议（Modbus / 厂商协议）
      ▼
SCADA / PLC / 风机控制点
```

调度命令不会直接打到 PLC，要经过前置机、RTU、SCADA 层层映射才落到某个控制点。从"发遥控"到"风机停机"之间每一跳都可能有校验，也可能有缺陷，山区链的漏洞点就在这里。

### 3. 四遥：IEC 104 传的四类东西

```text
遥测 = 看数值    连续量：电压、电流、有功、无功、频率、风速
遥信 = 看状态    开关量：断路器分合位、保护动作、告警状态、并网状态
遥控 = 控开关    命令类：分闸、合闸、启停            ← 攻击链的落点
遥调 = 调参数    设定类：有功设定值、无功设定值、电压目标值
```

定义：四遥按方向分两组，遥测、遥信是"往上送"的观测数据，遥控、遥调是"往下打"的控制命令。

### 4. TypeID：报文的"类型标识"

TypeID 是 1 字节的类型标识，告诉对方"这条 ASDU 是什么"。常用值：

| TypeID | 十进制 | 名称 | 含义 | 方向 |
|---|---|---|---|---|
| `0x01` | 1 | M_SP_NA_1 | 单点信息 | 遥信 ↑ |
| `0x03` | 3 | M_DP_NA_1 | 双点信息 | 遥信 ↑ |
| `0x09` | 9 | M_ME_NA_1 | 测量值（归一化） | 遥测 ↑ |
| `0x0B` | 11 | M_ME_NB_1 | 测量值（标度化） | 遥测 ↑ |
| `0x0D` | 13 | M_ME_NC_1 | 测量值（短浮点） | 遥测 ↑ |
| `0x2D` | 45 | C_SC_NA_1 | 单命令（单点遥控） | 遥控 ↓ ★ |
| `0x2E` | 46 | C_DC_NA_1 | 双命令（双点遥控） | 遥控 ↓ |
| `0x30` | 48 | C_SE_NA_1 | 设定值命令（归一化） | 遥调 ↓ |
| `0x31` | 49 | C_SE_NB_1 | 设定值命令（标度化） | 遥调 ↓ |
| `0x32` | 50 | C_SE_NC_1 | 设定值命令（短浮点） | 遥调 ↓ |
| `0x64` | 100 | C_IC_NA_1 | 总召唤 | 请求 ↑ |
| `0x67` | 103 | C_CS_NA_1 | 时钟同步 | 双向 |

山区链用的就是 `C_SC_NA_1`（TypeID=45，单点遥控），一条"单点命令"，值只有 0 或 1。`SCS=0` 表示"分/停"，`SCS=1` 表示"合/启"。

### 5. 三种帧格式：U / S / I

APCI 控制域（4 字节）有三种互斥格式，靠最低位区分：I 帧（Information）`bit0 = 0`，承载应用数据；S 帧（Supervisory）`bit0 = 1`、`bit1 = 0`，只做序号确认，不带数据；U 帧（Unnumbered）`bit0 = 1`、`bit1 = 1`，做链路管理。对应到实操：

- U 帧用来"拉手"：`STARTDT`（启动传输）、`STOPDT`（停止传输）、`TESTFR`（测试链路，保活）。
- S 帧用来"确认"：告诉对方"我已经收到第 N 条 I 帧了"。
- I 帧才真正干活，遥控命令就在 I 帧里。

### 6. 一条真实遥控的完整节奏（山区链实测）

```text
① TCP 三次握手（建立 2404 连接）
② U 帧 STARTDT act   ← 主站请求启动传输
③ U 帧 STARTDT con   ← RTU 确认
④ I 帧 Select        ← 选择（SBO 第一步）
⑤ I 帧 ACT_CON       ← 激活确认
⑥ I 帧 Execute       ← 执行（SBO 第二步）
⑦ I 帧 ACT_CON       ← 激活确认
⑧ I 帧 ACT_TERM      ← 激活终止（命令执行完毕）
```

成因：SBO（先选后控）是电力远动的安全设计。Select 先把目标点上锁，Execute 才真正动作，中间这段窗口留给检查与二次确认。跳过 Select 直接 Execute、或两条命令用不同连接发送，都是异常行为。

逐帧十六进制与字段拆解见 `抓包分析.md`。

## 在攻击链里的位置

### 山区链：借"维护测试通道"落地正式控制

```text
工单系统 D50003（存储型 XSS）
      │  泄露维护工作站凭据
      ▼
维护工作站 10.0.4.6（SSH，且 sudo NOPASSWD）
      │  发现 IEC104 通信对象：前置机 10.0.4.2 ↔ conpot RTU 10.0.4.5:2404
      ▼
ARP MITM + tcpdump 抓包          ← 从真实业务流量里"学到"协议参数
      │  读到 TypeID=45 / CA=3 / IOA=10490 / COT=activation / Test=1 / SBO
      ▼
自写 Rogue Master 脚本           ← 把 Test 位从 1 改成 0，发正式遥控
      │  STARTDT → Select → Execute（同一 TCP 连接）
      ▼
Conpot RTU 执行 IOA=10490 = WT08 停机命令
      ▼
山区 HMI：WT08 停机、功率归零、告警 POWER_LIMIT_ZERO
```

这条链最有教学价值的三个点：

- 参数全部来自证据，不是猜的：CA、IOA、SBO 流程都是从抓包里读出来的，不是遍历出来的，对应"不允许靠猜点号制造难度"的设计原则。
- "测试命令"与"正式命令"只差 COT 里的一个 Test 位。测试通道本应只模拟、不落地，一旦被转发成正式控制就成了漏洞。
- 协议知识是硬门槛。不理解 TypeID / COT / IOA / SBO，抓到包也不知道该改哪个字节。

### 为什么攻击者能抓到包？

维护工作站、前置机、Conpot RTU 三者同在一个二层网段（素材里明确要求这一点，否则 ARP MITM 不成立）。这在真实世界很常见：生产流量与维护终端没做二层隔离。

## 安全视角

IEC 104 的固有风险与 Modbus 同源，但后果更重，因为它直接面向调度控制：

```text
原生缺少强认证        任何能连 2404 的主站都能发遥控
通信可能明文          点号、命令、值在链路上可读可改
2404 端口暴露         扫描到 2404 基本就能判定是远动链路
遥控/遥调可被伪造     直接改变现场设备状态
历史命令可被重放      见 链路异常.md
遥测可被篡改          调度侧看到假数据，做出错误决策
```

对应的防护：

```text
调度数据网隔离 + 纵向加密认证装置    ← 电力行业标准做法
只允许调度主站访问 2404（白名单）
工业防火墙做深度解析：只放行指定 TypeID / COT / IOA
对 COT=test 的命令强制"只模拟不落地"
遥控双人确认 + 操作审计（谁、何时、哪个 IOA、什么值）
遥测签名与时间戳新鲜度校验
```
