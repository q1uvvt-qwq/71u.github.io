## 一句话概括

IEC 104 一帧里六七个字段，决定命令能不能打到目标设备的只有四个：`CA`（打哪个厂站）、`IOA`（打哪个点）、`SCS`（打成什么样）、`COT`（算正式命令还是测试命令）。其余字段（TypeID、VSQ、OA、SBO 位、序号）决定协议栈收不收。抓到一个包，弄清"哪个字段负责哪件事"，立刻就能判断该改哪里。

## 原理

### 1. 字段职责总表

| 字段 | 长度 | 它决定什么 | 一句话判据 |
|---|---|---|---|
| 起始符 | 1 | 是否是 IEC 104 帧 | 恒为 `0x68` |
| 长度 | 1 | 帧边界 | = 4 + ASDU 长度，解析器的第一道校验 |
| 控制域 | 4 | 帧种类（I/S/U）+ 收发序号 | `bit0` 判别 I 帧，序号决定链路是否被接受 |
| TypeID | 1 | 业务类型 | `0x2D` = 单点遥控，打错类型对方不认 |
| VSQ | 1 | 对象个数与地址连续性 | 遥控恒为 `0x01` |
| COT | 1 | 命令性质（含 Test 位） | `0x86` 测试 / `0x06` 正式，只差 bit7 |
| OA | 1 | 命令发起者（级联场景） | 实测恒为 `0x00` |
| CA | 2 | 打哪个厂站 | 小端，实测 `03 00` = 3 |
| IOA | 3 | 打哪个点 | 小端，实测 `f8 28 00` = 10488 |
| SCO | 1 | 打成什么样（选择/执行 + 状态） | `bit7` 选执行、`bit0` 定 0/1 |

### 2. TypeID：决定对方拿什么逻辑解释后续字节

```text
TypeID = 0x2D  C_SC_NA_1   后面跟 1 字节 SCO        ← 遥控
TypeID = 0x2E  C_DC_NA_1   后面跟 1 字节 DCO        ← 双点遥控（分/合两位表示）
TypeID = 0x30  C_SE_NA_1   后面跟 1 字节 + 2 字节设定值  ← 遥调
TypeID = 0x01  M_SP_NA_1   后面跟 1 字节品质描述词   ← 遥信（反方向）
TypeID = 0x0D  M_ME_NC_1   后面跟 4 字节浮点 + 品质   ← 遥测（反方向）
```

抓包时先看 TypeID，才知道这条 ASDU 的信息元素怎么切。山区链用的 `0x2D`（十进制 45）就是"值只有 0/1 的单点命令"。

### 3. COT：决定"这条命令算不算数"

COT（1 字节）的 `bit7` 是 Test 测试标志（攻击链只改这一位），`bit6` 是 P/N 肯定/否定确认，`bit5..0` 是传送原因值，它是整条攻击链里最便宜也最致命的改动点。改动前后的实测字节：

```text
0x86 = 1000 0110  Test=1, COT=6(激活)   ← 维护测试通道发的原包
0x06 = 0000 0110  Test=0, COT=6(激活)   ← 把最高位清掉，变成正式控制
```

COT 里的 Test 位在规范里是"允许的"：规范只定义了它，没规定收到 Test=1 该怎么处理，所以"测试命令会不会落地"由实现决定，这正是这类漏洞的来源。防护上必须在转发组件里显式拒绝 Test=1 的命令进入生产链路，只校验"有没有凭据"不够。

COT 值还区分命令的生命周期：

```text
COT=6   激活           主站下发
COT=7   激活确认       从站表示"收到且接受"
COT=10  激活终止       从站表示"执行完毕"
```

一条遥控如果只有 `6` 没有 `7`，说明从站没接受（点号错/被拒）；有 `6` `7` 没有 `10`，说明命令还在执行中或中途失败。

### 4. CA：厂站过滤的第一道墙

CA（公共地址，2 字节小端）是厂站级地址。每个厂站有独立的 CA，命令的 CA 与设备自身配置不符时，设备会忽略或回 "未知公共地址"（COT=46）。

```text
CA = 03 00（小端） = 3     山区链目标厂站
```

成因：CA 是地址字段，不是认证字段，它只提供最粗粒度的一道隔离。打错 CA 的命令根本进不了目标厂站的业务逻辑，但知道厂站编号的人都能填对。

### 5. IOA：打哪个点（最需要确认的字段）

IOA（信息对象地址，3 字节小端）就是 IEC 104 里的"点号"，等价于 Modbus 的寄存器地址，也是攻击链里最需要确认的字段：打错点号，命令就会落到别的设备上或被拒。实测 WT07 的停机命令点写作 `f8 28 00`，小端还原为 `0x00 28 f8` = 10488，同厂站的另两台是：

```text
WT07 = f8 28 00 = 10488
WT08 = fa 28 00 = 10490
WT09 = fc 28 00 = 10492
```

三个点号是连续的（10488/10490/10492），间隔为 2，这是设计上的规律：一台风机占连续两个点号（可能是"停机命令"与"启机命令"成对）。抓到其中一个就能推出全厂映射。

> 字节序陷阱：IEC 104 的 IOA 是小端 3 字节。但素材里手册给的单行测试命令写作 `...00030000 28fa 80`，把 IOA 写成了 `00 28 fa`（大端读法）。同一个点号 10490，小端是 `fa 28 00`，大端是 `00 28 fa`。实测 pcap 用的是小端。遇到不确定时以抓包为准，不要照抄文档里的字节串。

### 6. SCO：打成什么样

遥控的信息元素只有 1 字节，叫 SCO：`bit7` 是 S/E（Select/Execute，1 = 选择，0 = 执行），`bit6` 是限定词 QU（通常 0），`bit5..1` 保留，`bit0` 是 SCS（Single Command State，0 = 分/停，1 = 合/启）。实测（WT07 停机）：

```text
Select  SCO = 0x80 = 1000 0000   S/E=1（选择）、SCS=0（停）
Execute SCO = 0x00 = 0000 0000   S/E=0（执行）、SCS=0（停）
```

注意：Select 与 Execute 的 SCS 必须相同。先选"停"再执行"停"，才是一次完整遥控；先选"停"再执行"启"，是异常行为（多数实现会拒绝或告警）。

### 7. SBO（Select Before Operate）：流程字段，不是独立字段

定义：SBO 不是某个字段，而是用 SCO 的 bit7 拉出来的一个两段式流程：

```text
① Select  SCO=0x80  → 从站 ACT_CON 回显 0x80   ← 目标点被"上锁"
② Execute SCO=0x00  → 从站 ACT_CON 回显 0x00   ← 真正动作
                    → 从站 ACT_TERM 0x00      ← 命令闭环
```

跳过 Select 直接 Execute、两条命令走不同 TCP 连接、或者 Select 与 Execute 的 IOA 不一致，都是异常行为，也是检测的重点。

### 8. VSQ 与 OA：为什么它们"不用管"

| 字段 | 遥控场景取值 | 原因 |
|---|---|---|
| VSQ | `0x01` | SQ=0（每个对象带 IOA）+ 对象个数 1。一条遥控永远只操作一个点 |
| OA | `0x00` | 单主站直连场景不需要源发站标识；级联/多主站才用 |

这两个字段在山区链里是常量，看到非 `0x01` / 非 `0x00` 的值，反而说明是陌生实现或异常构造。

## 报文/字段对照：一条命令里"谁改了会怎样"

以 WT07 停机（CA=3 / IOA=10488 / SCS=0）为例，逐字段做"改动实验"：

| 改动 | 报文变化 | 预期结果 |
|---|---|---|
| 不动（原包） | `...2d 01 86 00 0300 f82800 00` | 正常执行（Test 位被实现当作测试处理） |
| 清 Test 位 | `...2d 01 06 00 0300 f82800 00` | 命令正式落地（山区链的攻击动作） |
| IOA 改 10490 | `...2d 01 06 00 0300 fa2800 00` | 打到 WT08，不是 WT07 |
| CA 改 2 | `...2d 01 06 00 0200 f82800 00` | 报"未知公共地址"，命令不落地 |
| TypeID 改 0x2E | `...2e ...` | 解释方式变了（双点命令），信息元素可能被误读 |
| SCS 改 1 | `...2d 01 06 00 0300 f82800 01` | 变成"启机"而不是"停机" |
| VSQ 改 0x02 | `...2d 02 ...` | 声明 2 个对象但只给了 1 个，解析异常 |

这张表说明了为什么"抓到包≠会利用"：必须同时改对 COT 的 Test 位、保留正确的 CA/IOA/SCS、保持长度字段一致，命令才又生效又不畸形。

## 安全视角

- "哪个字段能被猜"决定了防护重点。TypeID（0x2D）、VSQ（0x01）、OA（0x00）几乎是行业常量，猜得到；CA/IOA/SCS 场景相关，必须从证据（点表、日志、HMI 变量名）里得到。一旦发现有人在遍历 IOA，就说明攻击者手里没有证据、正在探测，高频 IOA 扫描是很强的告警信号。
- COT 的 Test 位是设计缺陷级的问题，不是配置问题。它不该靠"运维规范"来保证，而应在转发组件里硬编码拒绝：任何 `COT & 0x80` 的命令都不得进入生产控制通道。
- SBO 只防误操作，不防恶意。攻击者完全可以按规范先 Select 再 Execute，SBO 拦不住他，只能让行为"看起来正常"。它的价值在于做异常检测的基线：没有 Select 的 Execute、跨连接的 Execute、Select/Execute 值不一致，这三类可以直接判定为攻击。
- CA 提供的是分区，不是认证。多厂站部署时，应把 CA 与网络分区（纵向加密装置、工业防火墙）绑定起来，做到"即使知道 CA，也进不了那段网络"。
- 字段级白名单是最有效的工业防火墙策略。只放行 `TypeID=0x2D ∧ COT∈{6,7,10} ∧ 不含 Test 位 ∧ CA=3 ∧ IOA∈{10488,10490,10492}` 的命令，能把攻击面压缩到"只能对这三台风机做规范遥控"。注意：这种策略要在能看到应用层内容的设备上做，交换机 ACL 做不到。
