## 一句话概括

SSTI 练习环境有两条路：**用现成的 Docker 镜像**（`mcc0624/flask_ssti`）一键拉起，或**在 venv 里手写一个带漏洞的 `demo.py`**。踩得最多的坑是镜像名拼错、脚本语法报错、以及端口 / 锁文件占用。

## 环境准备：Docker 拉取镜像

```bash
# 先开代理（镜像拉取受限时需要）
cd /etc/docker
vim daemon.json          # 原笔记记为 docker.json，用于配置拉取镜像的代理

# 拉取 SSTI 靶场镜像
docker pull mcc0624/flask_ssti:last

# 生成 / 启动容器（<CONTAINER ID> 换成容器 ID）
docker start <CONTAINER ID>
```

启动后访问靶场（原笔记用的是本机靶场地址，此处统一写作 `靶场地址`）：

```text
http://靶场地址/
```

> 注意：镜像标签写的是 `last`，标准写法是 `latest` —— 见下方排错。

## 启动靶场：venv + demo.py

不想用镜像时，在本机建一个虚拟环境手写服务：

```bash
cd /opt/flask1
source ./bin/activate     # 激活 venv
vim demo.py               # 写/改服务代码
python3 demo.py           # 运行
```

退出方式：

```bash
quit()                    # 退出 python3 交互
deactivate                # 退出 venv
```

### demo.py 内容（自带 SSTI 漏洞）

```python
from flask import Flask, request, render_template_string

app = Flask(__name__)

@app.route('/')
def index():
    name = request.args.get('name', '')
    template = '''
    <h1>Hello {}</h1>
    <form>
        <input type="text" name="name" placeholder="Enter name">
        <input type="submit" value="Submit">
    </form>
    '''.format(name)                       # 用户输入被拼进模板
    return render_template_string(template)  # 再当模板渲染 → 存在 SSTI

if __name__ == '__main__':
    app.run(debug=True, host='0.0.0.0', port=5000)
```

两个关键参数：

| 参数 | 作用 |
|---|---|
| `debug=True` | 显示错误的具体位置（**仅用于开发，不要用于生产**），且改代码后**自动重启** |
| `host='0.0.0.0'` | 允许所有 IP 访问，此时同网段的物理机也能访问该地址 |

### Flask 变量规则

路由可以写固定路径，也可以带变量：

| 规则写法 | 访问示例 | 含义 |
|---|---|---|
| `@app.route('/hello')` | `/hello` | **固定格式**，路径必须完全一致 |
| `@app.route('/user/<name>')` | `/user/benben` | 默认按**字符串**取，变量名要与函数参数同名 |
| `@app.route('/user/<int:id>')` | `/user/1` | 按**整数**匹配 |
| `@app.route('/f/<float:f>')` | `/f/1.5` | 浮点数 |
| `@app.route('/p/<path:p>')` | `/p/a/b/c` | 可含斜杠的路径 |

要点（原笔记）：**变量添加的规则是一致的，但不同类型严格区分，知一求三** —— 路径里的占位符决定了能匹配什么形态的 URL，类型不同写法就不同。

> 此处原为「Flask 变量规则 / 多结果 / 整形」的截图，要点即上表：路径变量必须与视图函数参数名一致，类型转换器（`int` / `float` / `path`）决定入参格式。

## Flask 最小应用与三种路由

上面 `demo.py` 已经能跑，但要看懂它，得先知道 Flask 最小应用长什么样。一个只收 POST 的登录接口：

```python
from flask import Flask, request

app = Flask(__name__)                          # 创建 Flask Web 应用

@app.route('/login', methods=['POST'])         # 装饰器：把 URL 路径映射到视图函数
def login():                                   # 该路径只接受 POST 请求
    username = request.form['ben']             # 从请求体的表单里取字段 ben
    return f"欢迎 {username}!"
```

一条 `@app.route(...)` 对应一个视图函数；`methods` 限定该路由收哪些请求方法（不写默认只收 GET）。`request` 负责解析 HTTP 请求数据。

### 完整示例：app.py（三种路由）

原笔记把下面三个路由归纳为「三种写法」，代码在 `app.py`：

```python
from flask import Flask, redirect, url_for, request, render_template

app = Flask(__name__)

@app.route('/')                                    # 路由一：直指根目录，渲染表单页
def index():
    return render_template('index.html')

@app.route('/success/<name>')                      # 路由二：把用户名拼进欢迎语
def success(name):
    return 'welcome %s' % name

@app.route('/login', methods=['POST', 'GET'])      # 路由三：同时接受 GET 与 POST
def login():
    if request.method == 'POST':
        user = request.form['ben']                 # POST：从请求体的表单取 ben
        return redirect(url_for('success', name=user))   # 302 → /success/<user>
    else:
        user = request.args.get('ben')             # GET：从 URL 查询串取 ben
        return redirect(url_for('success', name=user))

if __name__ == '__main__':
    app.run(host='0.0.0.0', debug=True, port=8081)
```

三个路由各自的作用：

| 路由 | 方法 | 作用 |
|---|---|---|
| `/` | GET | 渲染 `templates/index.html` 表单页 |
| `/success/<name>` | GET | 把 `<name>` 拼进 `welcome ...` 返回 |
| `/login` | GET / POST | POST 取 `request.form['ben']`，GET 取 `request.args.get('ben')`，再 `redirect` 到 `/success/<name>` |

`url_for('success', name=user)` 按视图函数名反查 URL，拼出 `/success/<user>`；`redirect` 返回 302，浏览器随后对目标地址再发一次 GET —— 这一步就是「重定向」。

### 配套模板：templates/index.html

Flask 默认在 `templates/` 目录下找模板，该表单把内容 POST 到 `/login`：

```html
<html>
<body>
    <form action="http://127.0.0.1:8081/login" method="post">
        <p>Enter Name:</p>
        <p><input type="text" name="ben" /></p>
        <p><input type="submit" value="submit" /></p>
    </form>
</body>
</html>
```

注意表单字段名 `name="ben"` 必须和视图函数里的 `request.form['ben']` 一致，否则取不到值会直接 `KeyError`。

## 主机 / 虚拟机联调排错

这套环境是「主机跑服务、虚拟机当客户机」：

- **主机**：开发环境（PyCharm、Python、Flask），负责编写并运行代码
- **虚拟机**：干净的测试环境（只有浏览器），用来模拟真实用户来访问

在虚拟机浏览器里访问主机上的服务，地址填的是**主机的局域网 IP**：

```text
http://主机地址:8081/
```

链路是：`虚拟机浏览器 → 主机局域网 IP（主机地址）→ 主机的 8081 端口上的 Flask`。

### 127.0.0.1 与主机 IP 的区别

| 写法 | 在虚拟机里代表谁 | 结果 |
|---|---|---|
| `127.0.0.1` | **虚拟机自己** | 访问虚拟机本机的 8081，主机上的 Flask 访问不到 |
| `主机地址`（局域网 IP） | **主机** | 命中主机上监听的 Flask 服务 |

`127.0.0.1` 是回环（loopback）地址，**永远指「发起请求的那台机器自己」**，不会因为你想访问外部的服务就变成外部地址。所以虚拟机里访问 `127.0.0.1:8081`，请求根本没走出虚拟机，找的是虚拟机自己 8081 上的服务 —— 主机上的服务不是这么访问的。

要让虚拟机连上主机，主机端还必须监听对的网卡：`app.run` 默认只绑 `127.0.0.1`，只有主机自己能连；改成 `host='0.0.0.0'` 才会绑定本机所有网卡（含局域网网卡），这时虚拟机才能通过主机局域网 IP 访问到。

### 现象：首页能开、表单 POST 报错，而 GET 正常

虚拟机里的实际现象（**同一份代码在主机上正常**）：

```text
1. 访问 http://主机地址:8081/                            ✅ 能打开表单页
2. 表单输入 benben 点击提交                              ❌ 报错
3. 直接访问 http://主机地址:8081/login?ben=testuser      ✅ 返回 welcometotestuser
```

也就是说：**表单的 POST 有问题，但 GET 正常**。原笔记据此排除了「重定向」的嫌疑，理由是：

- `redirect` 发生在服务器成功处理完请求之后（`POST /login → Flask 处理 → 302 去 /success/benben → 浏览器再 GET`）。
- 如果重定向这段逻辑本身有问题，那么走同一条 `redirect` 的 **GET** 分支也应该一起失败。
- 但 GET 分支能正常返回 `welcome ...`，说明 `login` 逻辑、`redirect`、`success` 路由都是通的。
- 再加上同一份代码在主机上一切正常，代码逻辑本身也被排除。

于是嫌疑被缩小到 **POST 这条链路**、以及**表单到底提交到了哪个地址**上 —— 而不是重定向。

顺着这条线，一个明显的可疑点是模板里把提交地址写死了：

```html
<form action="http://127.0.0.1:8081/login" method="post">
```

按上面的解释，`127.0.0.1` 在虚拟机里指向虚拟机自身，而不是运行 Flask 的主机；而直接在地址栏敲主机 IP 的 GET 请求却能成功。**原笔记止步于此，没有进一步验证这一点，未定位到最终根因** —— 这里如实保留为待查线索，不做定论。

## 常见报错与排错

### 1. `pull access denied for mcc8624/flask_ssti`

```text
docker run -d --name ssti_test mcc8624/flask_ssti:last
→ pull access denied for mcc8624/flask_ssti
```

四种可能（原笔记归纳）：

1. **镜像不存在** —— 用户名或镜像名写错
2. **标签错误** —— 例如 `last` 应为 `latest`
3. **需要登录** —— 私有仓库需要认证
4. **拼写错误** —— 镜像名 / 标签拼错

本题实际是**第 4 种**：用 `docker search flask_ssti` 一搜，发现正确用户名是 **`mcc0624`**（不是 `mcc8624`）。更正后即可拉取：

```bash
docker search flask_ssti
docker pull mcc0624/flask_ssti
```

### 2. `SyntaxError: unmatched ')'`

启动 `demo.py` 报错，提示括号不匹配。一开始还以为是容器没开，实际问题出在**代码本身多写了一个 `)`**（或括号不成对）。删掉多余的括号即可。

> 排查顺序：Python 语法报错优先看**报错行号附近的括号 / 引号配对**，不要先怀疑环境。

### 3. 端口被占用 / lck 锁文件

现象：提示已有程序占用端口，**用管理员身份结束进程仍然打不开**。

原笔记的解法：**删除 kali 目录下 `lck` 后缀的临时文件即可**。

```bash
# 锁文件（.lck 临时文件）残留会导致程序无法启动，删掉它
rm -f /path/to/*.lck
```

### 4. 文件"被销毁"

原笔记另有一次启动失败，推测原因为**文件被销毁**（编辑 / 保存过程异常导致文件异常），重新写入 `demo.py` 后恢复。

## 踩坑与备注

- **镜像名先 search 再 pull**：`mcc8624` 与 `mcc0624` 只差一个字符，肉眼极易看错；`docker search` 是定位正确镜像名最快的一步。
- **标签 `last` ≠ `latest`**：写错标签会报 `pull access denied`（看着像权限问题，其实只是标签不存在）。
- **`debug=True` 会暴露源码**：Flask 调试模式在报错页里会展示代码片段，本身也是一个信息泄露点；CTF 靶场里这是"送信息"，生产环境必须关掉。
- **`host='0.0.0.0'` 才允许外部访问**：只写默认的 `127.0.0.1` 时，同网段的物理机访问不到。
- **虚拟环境别忘激活**：`source ./bin/activate` 之后再 `python3 demo.py`；退出用 `deactivate`，退出 Python 交互用 `quit()`，三个动作别混。
- **改完 `demo.py` 若没自动重启**：`debug=True` 才会自动重载；否则手动重启进程，或检查是否有旧进程 / 锁文件残留。
- **虚拟机里的 `127.0.0.1` 不是主机**：回环地址永远指「本机自己」，跨机器访问必须用对方的局域网 IP（见上文「主机 / 虚拟机联调排错」）。
- **表单 `action` 别写死 `127.0.0.1`**：一旦页面被别的机器打开，POST 就会提交到那台机器自己而不是服务端；用相对路径如 `/login` 更稳。
- 原文中的靶机 IP 与主机局域网 IP 均属一次性环境地址，本文统一写作 `靶场地址` / `靶机地址` / `主机地址`。
