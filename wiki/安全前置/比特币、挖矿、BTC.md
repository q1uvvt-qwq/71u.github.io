# 比特币、挖矿、BTC

## 比特币

### 定义

**比特币（Bitcoin）是一个去中心化的电子货币系统，也是一套由许多节点共同维护的区块链网络。**

它允许用户在没有银行等中央记账机构的情况下，直接通过网络转移比特币。网络中的节点按照同一套规则验证交易、保存账本并确认比特币的归属。



### 比特币作用

传统电子支付通常由银行或支付平台维护账本。账户余额、转账是否有效，都由这些机构判断。

比特币尝试让一组互不信任的参与者，在没有中央记账机构的情况下，共同确认：

- 哪些BTC可以被使用；
- 谁有权使用这些BTC；
- 一笔BTC是否已经被花掉；
- 哪些交易应当进入正式账本；
- 新BTC按照什么规则发行。

其中一个关键问题是**双花**：同一笔数字资产是否会被重复花费。比特币通过交易验证、工作量证明和区块链上的交易顺序解决这个问题。



### 比特币交易记录内容

比特币使用一种叫作 **UTXO** 的记账方式。UTXO可以理解为：

> 一笔以前产生、现在还没有被花掉的交易输出。

比特币钱包显示的余额，实际是由多个属于该钱包控制范围的UTXO相加得到的。

假设某个地址可以控制两个UTXO：

```
UTXO 1：0.3 BTC
UTXO 2：0.8 BTC
总计：1.1 BTC
```

现在需要支付0.5 BTC，可以使用0.8 BTC的UTXO，并创建两个新的输出：

```
收款输出：0.5 BTC
找零输出：0.299 BTC
手续费：0.001 BTC
```

原来的0.8 BTC UTXO被完整花掉，随后产生新的收款和找零UTXO。

这与现金支付有些相似：使用一张面额较大的纸币付款，然后收到找零。但UTXO只是帮助理解的记账概念，并不是实际存在的电子硬币。



### 比特币交易

一笔比特币交易通常经过以下过程：

**选择UTXO → 创建输出 → 签名 → 广播 → 节点验证 → 矿工打包 → 获得确认**

1. **选择UTXO**
   钱包选择足以支付转账金额和手续费的未花费输出。
2. **创建输出**
   交易规定哪些BTC交给收款方，剩余部分交给哪个找零地址。
3. **数字签名**
   钱包使用对应私钥生成签名，证明这些UTXO的花费条件已经满足。私钥本身不会发送给网络。
4. **广播交易**
   已签名的交易被发送给比特币节点，并在网络中传播。
5. **节点验证**
   节点检查签名、输入、输出和金额等是否符合规则，也会确认相关UTXO尚未被花费。
6. **矿工打包**
   矿工从待处理交易中选择交易，尝试把它们写入新区块。
7. **获得确认**
   交易所在区块之后继续出现新区块时，交易获得更多确认，被撤销的难度通常也随之增加。

### 比特币使用者

比特币没有一家统一控制整个网络的公司。不同参与者承担不同作用：

| 参与者             | 作用                                     |
| ------------------ | ---------------------------------------- |
| **用户**           | 持有密钥并发起交易                       |
| **钱包软件**       | 创建交易、管理密钥、展示链上信息         |
| **节点**           | 验证并传播交易和区块                     |
| **矿工**           | 通过工作量证明竞争提出新区块             |
| **开发者**         | 研究和编写软件，但不能强迫节点接受新规则 |
| **商家与交易平台** | 自行决定接受哪些交易和需要多少确认       |

比特币的运行结果来自这些参与者在协议规则下的共同作用。

### 安全依赖

比特币安全主要依赖四个部分：

**密钥与签名**

只有满足对应花费条件的一方才能使用某个UTXO。最常见的条件是提供有效数字签名。私钥一旦泄露，攻击者就可能生成有效交易。

**节点独立验证**

节点自行检查交易和区块，不需要直接相信矿工或其他节点提供的结果。

**工作量证明**

修改历史记录需要重新完成大量计算，并追赶或超过正常网络持续增长的工作量。

**确认数量**

刚刚进入区块的交易仍可能受到短期区块重组影响。后续区块越多，修改这笔交易所在历史记录通常越困难。

因此，**比特币的安全不是单纯依靠“区块连接在一起”，而是同时依赖密码学、验证规则、网络节点和工作量证*明。**

### 安全风险

学习比特币安全时，需要关注：

- 私钥或助记词泄露；
- 钱包软件被植入恶意代码；
- 收款地址被替换；
- 钓鱼网站和虚假投资平台；
- 交易所被攻击或限制提现；
- 交易确认不足导致双花风险；
- 地址复用导致隐私泄露；
- 找零地址处理错误；
- 多签和托管权限配置错误；
- 用户把BTC转到错误地址或错误网络。

## 挖矿

### 定义

挖矿是比特币网络用来**产生新区块、排列交易顺序、发行新BTC并保护历史记录**的机制。它不是单纯“制造比特币”，更核心的作用是让没有中央管理者的网络决定：下一批交易由谁写入账本。

### 与比特币的关系

网络中可能同时出现大量交易，甚至出现相互冲突的交易。比特币需要解决两个问题：

- 下一批交易由谁写入区块；
- 出现多个账本版本时，节点选择哪一个。

如果任何人都能零成本创建区块，攻击者就可以伪造大量身份，不断制造冲突。比特币要求区块提出者完成有现实成本的计算工作，这就是**工作量证明（Proof of Work，PoW）**。

### 完整过程

**1. 收集交易**

节点接收用户广播的交易，检查签名、UTXO和金额等基本规则。暂未写入区块的有效交易通常保存在**内存池（mempool）**中。

**2. 组装候选区块**

矿工从内存池选择交易，一般优先选择手续费率较高的交易，并决定交易在区块中的顺序。

区块中的第一笔交易叫作**Coinbase交易**。它不是交易所Coinbase，而是一种特殊交易，用来领取区块补贴和交易手续费。

**3. 构造区块头**

矿工把交易整理为Merkle树，并把Merkle根写入区块头。比特币区块头主要包含：

| 字段             | 作用                                 |
| ---------------- | ------------------------------------ |
| 前一个区块的哈希 | 把当前区块连接到历史区块             |
| Merkle根         | 代表当前区块包含的全部交易           |
| 时间戳           | 记录区块的大致时间                   |
| 难度目标         | 规定什么样的哈希结果才有效           |
| nonce            | 矿工反复修改、用于尝试不同哈希的数字 |

**4. 反复计算哈希**

矿工对区块头进行哈希计算。结果无法提前预测，只能不断尝试不同的nonce或调整区块中的其他内容。

只有当结果小于或等于网络规定的**目标值**时，这个工作量证明才合格。目标越小，找到合格结果越困难。某个矿工率先找到结果带有很强的随机性，但长期来看，获得区块的概率大致与其算力占比成正比。

**5. 广播并接受验证**

找到结果的矿工把完整区块广播给网络。全节点会重新检查：

- 工作量证明是否合格；
- 区块是否连接到已知区块；
- 所有交易是否合法；
- 是否存在双花；
- Coinbase交易是否领取了超额奖励。

全部符合规则，节点才接受该区块。**矿工负责提出区块，全节点负责判断区块是否有效。**矿工即使拥有很高算力，也不能要求正常节点接受违反规则的区块。[比特币区块链技术说明](https://developer.bitcoin.org/devguide/block_chain.html)明确区分了挖矿和全节点验证。

### 难度变化

比特币希望平均约每10分钟产生一个区块，但单个区块可能几秒出现，也可能等待很久。

如果全网算力增加，区块会暂时产生得更快；如果算力减少，则会变慢。协议每经过2016个区块调整一次难度，目标是让这2016个区块总体约用两周完成。

因此，“十分钟一个区块”是长期平均目标，不是固定计时器。

### 矿工收入

矿工成功产生有效区块后，收入由两部分构成：

| 收入           | 来源                               |
| -------------- | ---------------------------------- |
| **区块补贴**   | 协议允许产生的新BTC                |
| **交易手续费** | 区块内交易输入总额与输出总额的差额 |

区块补贴最初是50 BTC，每经过210,000个区块减半一次，大约四年一次。2024年减半后，每个区块的补贴为3.125 BTC。随着补贴持续降低，交易手续费在矿工收入中的作用会越来越大。

Coinbase交易产生的奖励需要等待100个区块后才能花费，以降低区块后来成为废弃分支时带来的问题。[比特币区块规范](https://developer.bitcoin.org/reference/block_chain.html)规定了补贴、手续费和Coinbase交易的约束。

### 目标条件

目标条件不是矿工或矿池随意设定的，而是由比特币协议根据过去一段时间的出块速度自动计算。所有全节点都独立计算相同结果，并拒绝使用错误目标值的区块。

**基本形式**

比特币把区块头进行两次SHA-256哈希，然后将结果看作一个256位整数：

```
区块头哈希值 ≤ 当前目标值 Target
```

满足条件，工作量证明有效；不满足，矿工继续尝试。

**决定因素**

当前目标值由三部分共同决定：

1. 比特币协议规定的计算公式；
2. 上一个难度周期使用的目标值；
3. 上一个周期实际花费的时间。

每个区块头中都有一个名为`nBits`的字段，用紧凑格式记录当前目标值。矿工会把它写进区块头，但全节点会自行计算正确值并核对。

```
矿工提交的nBits = 节点计算出的正确值
                  ↓
                可以继续验证

矿工提交的nBits ≠ 节点计算出的正确值
                  ↓
                 拒绝区块
```

**计算方法**

简化后的公式是：

```
新目标值 = 旧目标值 × 实际用时 ÷ 目标用时
```

其中：

```
目标用时 = 14天
```

因为难度与目标值成反比：

- 实际用时少于14天，说明出块太快，需要降低目标值、提高难度；
- 实际用时超过14天，说明出块太慢，需要提高目标值、降低难度。

### 矿工、节点和矿池区别

| 角色         | 主要工作                     |
| ------------ | ---------------------------- |
| **普通用户** | 创建并签署交易               |
| **全节点**   | 验证交易和区块，执行共识规则 |
| **矿工**     | 组装候选区块并进行哈希计算   |
| **矿池**     | 协调许多矿工的算力并分配收益 |

单独挖矿可能很久都找不到一个区块，所以大量矿工加入矿池。矿池把计算任务分配给参与者，通过难度较低的“份额”统计各自贡献，再按规则分配收益。[比特币挖矿说明](https://developer.bitcoin.org/devguide/mining.html)将其分为独立挖矿和矿池挖矿。





## BTC

### BTC产生

新BTC通过区块奖励按照协议规则发行。区块奖励会定期减半，因此新BTC的发行速度会逐渐下降。

按照当前协议规则，BTC的总量上限约为：

```
21,000,000 BTC
```

这不是因为所有BTC在系统启动时一次性生成，而是因为发行奖励不断减半，累计发行量会逐渐接近这个上限。

协议规则也可以通过软件更新被提出修改，但节点需要主动采用相应规则。单个开发者、矿工或公司不能独自随意增加所有正常节点认可的BTC数量。
