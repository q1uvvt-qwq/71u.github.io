## 资产与余额

这一章解决四个问题：

- 区块链资产究竟记录在哪里；
- 原生资产和代币有什么区别；
- 地址余额是怎样计算出来的；
- 账户模型和UTXO模型有什么区别。

### 区块链资产存放

区块链资产并不是某个存放在钱包里的电子文件。链上保存的是一组记录，用来表示：

```
哪些资产存在
谁有权控制这些资产
这些资产已经被怎样转移
```

钱包负责管理密钥、创建交易并读取链上记录。删除钱包软件不会直接删除链上资产；只要仍然掌握相应密钥，就可以使用其他兼容钱包恢复控制权。

所以，“钱包里有10 ETH”更准确的含义是：

> 以太坊当前状态记录某个地址拥有10 ETH，而钱包掌握或调用了控制该地址的方法。

### 原生资产

**原生资产是由区块链协议本身定义和管理的资产。**

| 区块链 | 原生资产 | 主要用途                           |
| ------ | -------- | ---------------------------------- |
| 比特币 | BTC      | 转账、支付矿工手续费、提供挖矿奖励 |
| 以太坊 | ETH      | 转账、支付Gas、参与质押和验证      |

原生资产的发行和转移规则写在区块链协议中。例如：

- BTC通过区块补贴按照协议规则发行；
- ETH通过以太坊权益证明规则发行；
- 节点直接理解BTC或ETH的余额和转移规则。

原生资产通常也称为“币”。

### 代币

**代币是通过智能合约或链上程序定义的资产。**

在以太坊中，代币合约会记录：

```
代币名称
代币符号
发行数量
各地址余额
转账规则
授权规则
是否允许增发、销毁、冻结或暂停
```

常见代币包括：

| 类型                | 特点                                       |
| ------------------- | ------------------------------------------ |
| **同质化代币**      | 每一单位可以互换，例如多数稳定币           |
| **非同质化代币NFT** | 每个代币具有独立编号和所有权记录           |
| **治理代币**        | 可能用于协议投票或治理                     |
| **包装代币**        | 在一条链上表示另一种资产或被锁定资产的凭证 |

ETH是以太坊原生资产；以太坊上的USDT、USDC等是智能合约代币。发送这些代币时，实际执行的是代币合约中的转账函数。



### 原生资产与代币的关系

在以太坊上转移代币，需要节点执行代币合约代码。执行交易要支付Gas，因此账户通常仍然需要ETH。

```
转移100个代币
      ↓
调用代币合约
      ↓
合约修改双方的代币余额
      ↓
发送方使用ETH支付Gas
```

所以，地址可能拥有很多代币，却因为没有ETH而无法发送这些代币。

某些特殊钱包或应用可以代付手续费，但底层仍然有人以原生资产承担网络成本。



### 账户余额模型

以太坊主要采用**账户模型**。可以把当前链上状态理解为一张不断更新的账户表：

| 地址      | ETH余额 | 交易序号 | 合约代码与数据 |
| --------- | ------- | -------- | -------------- |
| 地址A     | 10 ETH  | 5        | 无             |
| 地址B     | 3 ETH   | 2        | 无             |
| 合约地址C | 20 ETH  | 8        | 有             |

如果地址A向地址B转出3 ETH，并支付0.001 ETH手续费，执行后的状态大致是：

```
地址A：10 - 3 - 0.001 = 6.999 ETH
地址B：3 + 3 = 6 ETH
```

节点验证交易后直接更新相关账户状态。这里的余额是以太坊协议直接记录的ETH余额。





### 代币余额

以太坊协议只直接认识ETH。代币余额通常保存在对应智能合约的数据中。

代币合约内部可以维护类似这样的关系：

```
地址A → 500个代币
地址B → 200个代币
地址C → 0个代币
```

当发生代币转账时，合约修改这些数据：

```
地址A：500 → 400
地址B：200 → 300
```

钱包要显示代币余额，需要查询相应代币合约。钱包界面没有显示某种代币，不一定代表链上余额不存在；反过来，钱包显示了某个代币，也不代表它具有真实价值或可信来源。



### UTXO模型

比特币使用**未花费交易输出模型**，简称UTXO。

比特币账本通常不直接保存“某地址余额为多少”。它保存哪些交易输出尚未被花费，钱包再把自己可以控制的UTXO加起来。

假设某个钱包可以使用三个UTXO：

```
UTXO 1：0.2 BTC
UTXO 2：0.5 BTC
UTXO 3：0.8 BTC

可用余额：1.5 BTC
```

需要支付0.6 BTC时，可以选择0.8 BTC的UTXO，并产生新的输出：

```
收款输出：0.6 BTC
找零输出：0.199 BTC
交易手续费：0.001 BTC
```

原来的0.8 BTC UTXO会被完整消耗，随后产生0.6 BTC和0.199 BTC两个新UTXO。



### 账户模型和UTXO模型的区别

| 比较项       | 账户模型                       | UTXO模型                   |
| ------------ | ------------------------------ | -------------------------- |
| 典型区块链   | 以太坊                         | 比特币                     |
| 资产记录     | 直接记录账户当前余额           | 记录尚未花费的交易输出     |
| 转账方式     | 从发送账户扣减并给接收账户增加 | 消耗旧UTXO并创建新UTXO     |
| 找零         | 通常不需要单独的找零输出       | 经常需要找零输出           |
| 防止重复交易 | 使用账户nonce等机制            | 检查UTXO是否已经被花费     |
| 智能合约状态 | 适合维护复杂共享状态           | 脚本能力和状态表达相对受限 |
| 余额计算     | 读取账户当前状态               | 汇总可控制的UTXO           |

## 本章要点

**区块链记录的是资产归属和使用条件，钱包负责读取记录并管理控制方式。BTC使用UTXO表示可花费资产；ETH使用账户余额；以太坊代币则由智能合约保存余额和转移规则。**
