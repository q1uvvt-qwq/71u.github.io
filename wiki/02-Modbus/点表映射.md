## 一句话概括

点表（Point Map）是工控系统的"地址簿"：它规定每个寄存器偏移对应的业务量、单位、读写属性与合理值域。对攻击者来说，拿到点表等于拿到地图，知道该敲哪一扇门；对防守方来说，`permission` 与 `safe_range` 就是最后一道业务防线。

## 原理

### 1. 点表为什么必须存在

Modbus 帧里只有裸数字：地址 93、值 100。"93 是什么、100 意味着什么"完全由点表定义。设备侧、SCADA 侧、报表侧各持同一份点表的副本，整个系统才"看懂"同一件事。

所以工控里有条铁律：不看点表就无法理解 Modbus 流量。攻击链设计里对应的原则是：不能让玩家靠猜寄存器，寄存器含义必须能从业内证据（点表 CSV、工程包、HMI 变量名、审计日志）里得到。

### 3. 逐字段读懂这张表

| 列 | 含义 | 为什么重要 |
|---|---|---|
| `device` | 设备类型（WT-RTU 风机远动终端） | 一份点表可能覆盖多种设备 |
| `protocol` | Modbus TCP | 同一系统里可能有多种协议，点表要标明 |
| `unit_id` | `1` | 请求帧里必须填对，否则超时或异常 |
| `register_area` | `HR` = Holding Register 保持寄存器 | Modbus 四个区之一 |
| `addressing` | `zero_based_pdu` | 帧里的地址直接用 offset，不加 1、不写 4xxxx |
| `register_offset` | 0, 1, …, 93, 94 | 就是 PDU 地址 |
| `hmi_label` | HR0 … HR94 | HMI 上显示的名字，用于跨材料对齐 |
| `permission` | `R` 只读 / `RW` 读写 | 安全的关键分级 |
| `meaning` | ActivePowerKW、WindSpeed_x10… | 业务语义 |
| `safe_range` | 0-3000、0-100… | 合法值域，业务层应做校验 |

### 4. 三组寄存器：遥测 / 状态 / 控制

点表按用途分三段，名称与量程见 §2 的 CSV：

```text
HR0  - HR9    只读遥测与状态     ← SCADA 轮询读取，攻击者用来侦察与伪造
HR90 - HR94   可写控制区        ← 攻击链的落点
```

设计原则（来自点表设计文档）：HR0-HR89 只读、HR90-HR94 可写。可写区间刻意做得极窄，把攻击者能触碰的面收到最小。

### 5. 量纲与系数：为什么值是"100"而不是"10.0"

工控设备用整数寄存器传物理量，靠系数还原小数：

| 寄存器 | 原始值 | 系数 | 物理量 |
|---|---|---|---|
| HR2 WindSpeed_x10 | 85 | ÷10 | 8.5 m/s |
| HR93 ActivePowerLimitPercent | 100 | 直接就是百分比 | 100% |
| （发电量） | 100000 | ÷100 | 1000.00 kWh |

`_x10` 后缀就是"寄存器值 = 实际值 × 10"。量纲搞错会导致攻击"看起来成功但没效果"：把 8.5 m/s 当成 8 写下去，实际风速就变成 0.8 m/s。

### 6. 状态量是枚举，不是连续值

`RunStatus`、`GridState`、`AlarmCode` 这类寄存器的值是枚举码，读点表才能翻译（枚举定义见 §2 的 CSV）。平原链攻击后 HMI 上出现的 `POWER_LIMIT_ZERO`，就是 `AlarmCode=10`。

HMI 上的文字就是从这些码翻译出来的。所以"改一个寄存器 → HMI 上多一条告警"这件事，中间的逻辑并不神秘。

### 7. 32 位量：高低字拼装

超过 16 位的量（发电量、累计电量）要占两个连续寄存器：

```text
目标 1000.00 kWh = 100000（单位 0.01kWh）= 0x000186A0
        高 16 位 = 0x0001 → HR98 写 1
        低 16 位 = 0x86A0 → HR97 写 34464
```

写的时候顺序不能错（有的设备是低字在前），这也是点表/工程文档必须写清的地方。

### 8. 签名寄存器：让篡改留下痕迹

平原链的扩展环节里，RTU 对关键遥测计算 HMAC-SHA256，通过 `HR21-HR24` 随遥测上报，由旁路校验节点验签。攻击者改了值签名就对不上，校验节点即可判定"数据在来源端或传输中被改动"。

这引出一个设计观念：Modbus 本身不提供完整性保护，只能在应用层自己加。

## 在攻击链里的位置

### 核心控制点：HR93

```text
寄存器    HR93 / PDU offset 93
业务含义  ActivePowerLimitPercent（有功功率限制百分比）
权限      RW
安全范围  0-100
攻击动作  写 0 → 场站有功功率限制为 0%
```

为什么选它，而不是 `HR90 RunCommand`（直接启停）？

- 它是"参数"不是"开关"。写 HR90=0 是"停机"，业务上是明显的大动作；写 HR93=0 是"把限功率调到 0"，属于合法的运行参数调整，更贴近真实攻击者的偏好。
- 它是可恢复的。验收后写 `HR94=1` 触发告警复位，三台 RTU 就会恢复 HR93=100、HMI 回到 RUNNING。这对反复验题很关键。
- 它必须能影响可见业务。HMI 的总有功功率 = 三台风机功率之和，每台功率又受 HR93 约束，所以三台都写 0 才能让"场站总功率归零"。

### 从点表出发的攻击链下游

```text
pointmap.csv（HR93 是什么）
      │
      ├─► gateway.conf  write_range=HR90-HR94 / target_control=HR93
      │
      ├─► modpoll -r 93 读 100   → 确认未限功率
      │
      └─► modpoll -r 93 ... 0 写 → 限功率 0%
                                    │
                                    └─► HMI 总有功 0 / 告警 POWER_LIMIT_ZERO
```

注意：点表不是终点，是起点。攻击链要求"寄存器含义来自场景证据"，证据链正是 `scada_datasource` 表 → 导出任务 ID 范围 → IDOR 拿到备份包 → 里面同时有 `gateway.conf`、`rtu_targets.csv`、`pointmap.csv`。三者互相对齐（配置文件说 `target_control=HR93`，点表说 HR93 是 ActivePowerLimitPercent，csv 说三台 RTU 的地址），攻击者才能确信自己打的是对的点。

## 安全视角

- 点表泄露是链路起点，不是终点。单有点表不足以控制设备，还需要可达路径与凭据。防护上要同时收紧：备份包不要暴露在 Web 可枚举的 ID 上、导出对象要做归属校验、诊断私钥不要随备份外发。
- `permission` 列必须在设备/网关侧强制。点表写 `R` 而设备实际接受写入，点表就只是文档而不是控制。正确做法是在 RTU 与工业防火墙两层同时拒绝越界写入。
- `safe_range` 是业务层防线。HR93 允许 0-100，写 0 是"合法但危险"的操作。这里要的是变更审计 + 变化率/联动校验（例如"限功率从 100 直接跳到 0 且无调度指令"应触发告警）。
- 枚举与量纲是排错钥匙。忘了 ÷10、把枚举码当数值，都会让攻击/验题结果与预期不符。抓包看到 `RunStatus=0` 却说"还在跑"，那就是读错了寄存器。
- 完整性只能自己加。HR21-HR24 的 HMAC 是这个靶场给出的正确答案，但要注意：签名密钥一旦和点表一起泄露，签名就形同虚设。密钥与点表必须分域存放。
