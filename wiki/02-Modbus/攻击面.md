## 一句话概括

Modbus 的攻击面可以一句话说清：任何能连上 502 端口的机器，都可以是一个"合法主站"，读走全部数据、写掉任何存在的寄存器。它没有认证、没有加密、没有权限、没有审计，攻击与防护都发生在网络边界、点表校验与变更审计上，不在协议里。

> 本篇只讨论授权靶场与教学环境下的协议弱点与防护思路，不提供可直接用于真实生产系统的攻击操作。

## 原理

### 1. 五类典型弱点

#### ① 未授权访问：Rogue Master（伪造主站）

Modbus 是主从模型，但"谁是主站"没有任何身份校验。任何主机只要 TCP 可达、Unit ID 与地址填对，就是功能完整的主站。

```text
合法：SCADA / 通信网关  ──FC06 写 HR93──►  RTU
攻击：攻击者的 modpoll  ──FC06 写 HR93──►  RTU   ← 设备无法区分
```

平原链里，攻击者正是借用通信系统1这个"唯一被允许访问 RTU 的节点"当跳板，用 `modpoll` 作主站。设备侧看到的是同一个源 IP、同一种请求，没有任何异常信号。

防护：

- 网络层白名单，只允许 SCADA/网关的 IP 连 502。
- 工业防火墙深度解析，只允许 FC03/FC04，禁止 FC05/06/15/16（若业务允许）。

#### ② 功能码滥用：写操作不设限

如果网关或设备放行了 FC06/FC16 又不限制地址范围，攻击者可以直接改控制参数：

```text
HR90 RunCommand            0-1    启停
HR91 ManualOverrideEnable  0-1    手动覆盖（绕过采集端校验的开关）
HR92 WindSpeedOverrideX10  0-300  伪造风速
HR93 ActivePowerLimitPercent 0-100 限功率   ★核心落点
HR94 AlarmReset            0-1    告警复位（可用来"擦掉"告警痕迹）
```

HR94 要单独说一句：它本意是"复位告警"，但攻击者先写 HR93=0 造成 `POWER_LIMIT_ZERO`，再写 HR94=1 复位，告警就被清掉，这是一种典型的"抑制响应"（Inhibit Response Function）行为。

防护：

- 写入范围白名单，只允许 HR90-HR94。
- 值域校验。
- 对 HR91/HR94 这类"敏感开关"单独加权限。

#### ③ 寄存器范围不校验：任意探点

设备或网关不校验地址，攻击者就能扫描式读取把点表反推出来（靠响应正常还是异常码 `02` 区分有效地址）：

```text
读 93  → 正常返回        → 93 是有效寄存器
读 300 → 异常码 02       → 无效
```

防护：

- 未定义地址统一返回 `02 Illegal Data Address`。
- 在网关层阻断高频扫描。
- 用速率限制检测"连续地址扫描"模式。

#### ④ 数据篡改：伪造遥测

Modbus 上行数据同样没有签名，所以篡改不只发生在下行。平原链的扩展环节演示了四类：

| 手法 | 操作 | 校验节点判定 |
|---|---|---|
| 伪造过程量 | HR91=1 开手动覆盖，再写 HR92 风速 / HR95 电压 | `SOURCE_OVERRIDE` / `RANGE_WIND` / `RANGE_VOLTAGE` |
| 伪造统计量 | 写 HR97/HR98 拼出假的发电量 | 值超出合理性区间 |
| 删除注入 | 让采集端丢弃上报 | `NO_DATA` / 断档 |
| 延迟注入 | 重放旧报文 | `STALE` / 过期 |

防护：

- RTU 侧对关键遥测计算 HMAC 签名（靶场里放在 HR21-HR24），由旁路校验节点验签。
- 叠加范围校验、变化率校验、P=V·I 一致性校验、时间戳新鲜度校验。
- 单纯数值合理性检查挡不住精心构造的假值，签名才能证明"数据来自设备且未被改动"。

#### ⑤ 无审计：事后无法回溯

Modbus 设备不记录"谁在什么时候写了什么"。攻击完成后，设备侧没有任何痕迹。

防护：

- 审计只能在 SCADA/网关/工业防火墙做。
- 记录功能码、源 IP、地址、旧值、新值、时间戳。

#### 速查表：弱点与防护对照

| 弱点 | 直接后果 | 主要防护手段 |
|---|---|---|
| 无身份认证 | 任何主机都是合法主站 | 网络白名单、工业防火墙源 IP 约束 |
| 无加密 | 点表与值在链路上明文可读 | 分区隔离、端口安全、隧道封装（非协议内） |
| 无权限模型 | 能连就能写 | 功能码白名单 + 寄存器范围白名单 |
| 无范围校验 | 任意地址可读写 | 未定义地址返回异常码、写入值域校验 |
| 无完整性保护 | 遥测可被篡改 | 应用层 HMAC/签名 + 旁路校验节点 |
| 无审计 | 无法追溯 | 网关/防火墙/SCADA 侧记录变更日志 |
| 危险默认值 | 覆盖开关、告警复位被滥用 | 敏感寄存器单独授权、变化率告警 |

## 在攻击链里的位置

平原链把 Modbus 的弱点串成了一条完整链路：

```text
Web 层（SQL 注入 + IDOR）           ← 拿到 SCADA 网关备份包
      │
      ▼
备份包内证据                        ← gateway.conf / rtu_targets.csv /
      │                                pointmap.csv / gateway_diag_key.pem
      ▼
SSH 进通信系统1                     ← 借用合法主站位置（弱点①）
      │
      ▼
modpoll FC03 读 HR93 = 100          ← 侦察
      │
      ▼
modpoll FC06 写 HR93 = 0            ← 落点（弱点②）
      │
      ▼
HMI 总有功归零 / POWER_LIMIT_ZERO    ← 业务影响
      │
      └─（扩展）HR91/92/95/97/98 伪造遥测 → 校验节点报 SOURCE_OVERRIDE
```

注意链路的设计逻辑：攻击者并没有"直接连 502"这条路，得先通过 Web 漏洞拿到证据与凭据，再借合法节点当主站。这是真实世界的访问边界，现场 502 端口对办公网、攻击机都不可达（`route_note.txt` 里的 `deny src=any dst=10.0.5.4-10.0.5.6 tcp/502`）。

## 靶场设计的"防非预期"约束

协议攻击点布设模板对 Modbus 场景规定了明确边界，这些约束本身就是最好的防护清单：

```text
1. 不把 PLC simulator 的 502 端口直接映射给玩家（除非题目就是考直接 Modbus）。
2. HR0-HR89 只读。
3. HR90-HR94 可写。
4. 写入值范围有限制。
5. 错误寄存器不会影响全局系统。
6. 参数（Unit ID、寄存器、值）必须来自场景证据，不能靠猜。
```

## 安全视角

### 检测思路

| 检测点 | 规则 |
|---|---|
| 写入源异常 | 非 SCADA/网关 IP 发出 FC06/FC16 |
| 写入频率异常 | 短时间内对 HR93/HR91 反复写入 |
| 值跳变异常 | HR93 从 100 直接到 0 且无对应调度指令 |
| 覆盖开关 | HR91=1（手动覆盖）出现在非调试时段 |
| 告警被清 | HR94=1 紧跟在一次异常写入之后 |
| 地址扫描 | 大量非连续地址读取、频繁触发异常码 02 |
| 遥测签名 | HMAC 不匹配 / 时间戳超龄 |

### 设计观念

- 协议保护不了自己，边界才行。Modbus 的安全等于"谁能到 502" + "放行哪些功能码"。
- 可写区间要窄，而且每个寄存器都要有存在的理由。HR90-HR94 只有 5 个，每个都有明确业务用途：写范围越窄，攻击面越小。
- "合法但危险"的操作需要额外校验。写 0 到 HR93 在协议与点表上都合法，只能靠业务规则（联动校验、变化率、指令来源核对）拦住。
- 审计是唯一的事后答案。设备不记事，网关必须记事。
