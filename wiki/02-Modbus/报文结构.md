## 一句话概括

Modbus TCP 的一帧 = 7 字节 MBAP 头 + PDU。MBAP 管"这帧是谁发的、发给谁、有多长"，PDU 管"要干什么、在哪个地址、什么值"。没有校验和、没有签名、没有认证字段，7+5=12 个字节就是全部。

> 说明：本篇帧示例按 Modbus 应用层协议规范，结合靶场实测参数（Unit ID=1、PDU offset 93、值 100/0）推导。素材中没有 Modbus 的 pcap 文件，实测抓包见 `抓包分析.md` 里 modpoll 的真实输出。

## 原理

### 1. 整体结构

```text
┌──────────────────────── MBAP 头（7 字节）───────────────────────┐┌── PDU ──┐
│ 事务标识 ID │ 协议标识 │  长度  │ 单元标识 │  功能码  │   数据    │
│   2 字节    │  2 字节  │ 2 字节 │  1 字节  │  1 字节  │   N 字节  │
└─────────────┴──────────┴────────┴──────────┴──────────┴──────────┘
   高 低        固定 00 00   后续字节数   Unit ID      动词       地址/值
```

| 字段 | 长度 | 说明 |
|---|---|---|
| 事务标识 Transaction ID | 2 | 主站自己维护的计数，请求和响应必须相同，用来配对 |
| 协议标识 Protocol ID | 2 | Modbus 固定为 `00 00`；其它值表示不是 Modbus |
| 长度 Length | 2 | 从"单元标识"起算的字节数 = 1 + PDU 长度 |
| 单元标识 Unit ID | 1 | 从站地址，直连 RTU 通常为 `1` |
| 功能码 Function Code | 1 | FC03 读 / FC06 写 … |
| 数据 Data | N | 地址、数量、值，或响应里的字节数与数据 |

整个 TCP 载荷里没有一字节用于认证或完整性校验，这是理解 Modbus 攻击面的起点。

### 2. 读保持寄存器（FC03）：`modpoll -r 93 -c 1 -t 4`

请求 = 7 字节 MBAP + 5 字节 PDU = 12 字节：

```text
00 01 00 00 00 06 01 | 03 00 5D 00 01
│     │     │     │    │  │     └── 数量 = 1 个寄存器
│     │     │     │    │  └──────── 起始地址 = 0x005D = 93  (PDU offset)
│     │     │     │    └─────────── 功能码 = 03 读保持寄存器
│     │     │     └──────────────── Unit ID = 01
│     │     └────────────────────── 长度 = 6  (1 字节 Unit ID + 5 字节 PDU)
│     └──────────────────────────── 协议标识 = 0 (Modbus)
└────────────────────────────────── 事务标识 = 1
```

响应 = 7 字节 MBAP + 4 字节 PDU = 11 字节（读回 HR93=100）：

```text
00 01 00 00 00 05 01 | 03 02 00 64
│     │     │     │    │  │  └──── 寄存器值 = 0x0064 = 100
│     │     │     │    │  └─────── 字节数 = 2（1 个寄存器 = 2 字节）
│     │     │     │    └────────── 功能码 = 03（与请求一致）
│     │     │     └─────────────── 长度 = 5 (1 + 4)
└─────┴─────┴─────┴──────────────── 事务标识/协议标识与请求相同
```

注意：寄存器值是大端（高字节在前）；读一个寄存器返回 2 字节，`-c 3` 就会得到字节数 `06` 与 6 字节数据。

### 3. 写单个保持寄存器（FC06）：`modpoll -r 93 -c 1 -t 4 -1 10.0.5.6 0`

请求 = 7 + 5 = 12 字节：

```text
00 02 00 00 00 06 01 | 06 00 5D 00 00
                         │  │     └── 写入值 = 0  （HR93 = ActivePowerLimitPercent = 0）
                         │  └──────── 目标地址 = 93
                         └─────────── 功能码 = 06 写单个保持寄存器
```

响应是原样回显（这是 FC06 的规范行为）：

```text
00 02 00 00 00 06 01 | 06 00 5D 00 00
```

> 回显意味着"我收到了、也照做了"，但不表示"我有权限"，协议层根本没有权限检查。所以攻击链第 16 步"再次读取 HR93 确认写入成功"是必要的：读回才是真正验证设备侧生效。

### 4. 写多个寄存器（FC16）：`0x10`

```text
00 03 00 00 00 0B 01 | 10 00 5A 00 02 04 00 00 00 00
                         │  │     │  │  └── 4 字节数据：两个寄存器都写 0
                         │  │     │  └───── 字节数 = 4
                         │  │     └──────── 数量 = 2 个寄存器
                         │  └────────────── 起始地址 = 0x005A = 90
                         └───────────────── 功能码 = 16
```

### 5. 异常响应：功能码最高位置 1

从站遇到不存在的地址、非法数量或非法值时，把功能码 + 0x80 作为响应码，后跟 1 字节异常码：

| 异常码 | 名称 | 常见原因 |
|---|---|---|
| `01` | Illegal Function | 该从站不支持这个功能码 |
| `02` | Illegal Data Address | 地址不存在或超出允许范围（防守方最常用的一招） |
| `03` | Illegal Data Value | 数量或值超出允许范围 |
| `04` | Server Device Failure | 设备侧故障 |

```text
请求： 00 04 00 00 00 06 01 | 03 75 30 00 01     （读一个不存在的地址 0x7530 = 30000）
响应： 00 04 00 00 00 03 01 | 83 02               （FC03|0x80 = 0x83，异常码 02）
```

异常码是防守方的抓手：靶场和真实系统都可以利用"点表里没有的地址一律返回 `02`"来防止攻击者盲扫寄存器。

## 报文/字段对照：读 vs 写

| 项目 | FC03 读 | FC06 写 |
|---|---|---|
| 请求 PDU 长度 | 5 字节 | 5 字节 |
| 请求内容 | 功能码 + 起始地址(2) + 数量(2) | 功能码 + 地址(2) + 值(2) |
| 响应 PDU | 功能码 + 字节数(1) + 值(N×2) | 功能码 + 地址(2) + 值(2)（回显） |
| 是否改变设备状态 | 否 | 是 |
| 攻击链中的作用 | 侦察（读 HR93 当前值） | 落点（写 HR93=0） |

## 在攻击链里的位置

平原链把"读"和"写"分成了两步，这个顺序是有意设计的：

1. 先读（第 14 步）：`modpoll -m tcp -p 502 -a 1 -0 -r 93 -c 1 -t 4 -1 <ip>` → `[93]: 100`。确认三台 RTU 的 HR93 当前值都是 100（未被限功率），也确认了通信可达、Unit ID 与地址口径正确。
2. 再写（第 15 步）：同一条命令在末尾加 `0` → `Protocol configuration: MODBUS/TCP, FC6` / `Written 1 reference.`。
3. 回读验证（第 16 步）：重复第 14 步，`[93]: 0`，证明协议层写入成功。
4. 看业务（第 17 步）：HMI 场站总有功归零、告警 `POWER_LIMIT_ZERO`，证明业务层生效。

这四步对应工控安全里的一条经验：协议层成功 ≠ 业务层生效，两者都要有证据。

## 安全视角

报文结构本身就说明了 Modbus 的弱点：

- MBAP 里没有版本、没有 nonce、没有时间戳、没有签名，除长度外没有任何结构约束。抓到一个合法帧，改掉地址或值再发出去，就是一个合法帧。
- 功能码是唯一的"意图声明"。读用 3、写用 6，只要防火墙不放行 FC06/FC16，就能挡住绝大多数写攻击，这也是工业防火墙做深度协议解析的意义。
- Unit ID 是弱标识，只区分设备，不区分用户。同一网段里任何主机都可以声明自己是 Unit ID 1 的主站。
- 异常码会暴露实现细节：攻击者用异常码 `02` 与正常响应就能把有效地址区间"扫"出来，反推出点表。防守方要么统一返回同样的错误，要么在网关层阻断扫描。
