## 一句话概括

Modbus 是工业设备之间最简单、最常见的"读写数据"协议：一台主站（Master）主动发起请求，一台或多台从站（Slave）应答，主站问什么、从站答什么。它极简单，因此也格外脆弱：原生没有认证、没有加密、没有权限、没有审计。

风电场景里，SCADA 或通信网关作主站，按周期轮询每台风机 RTU 的保持寄存器，把风速、功率、状态取回 HMI 显示；需要控制时，主站就往控制区的寄存器写一个值。

## 原理

### 1. 主从模型：谁说话、谁只能应答

定义：Modbus 是主从轮询协议，通信永远由主站发起，从站只应答。

```text
主站 (Master / Client)              从站 (Slave / Server)
   Modbus TCP 502                        Modbus TCP 502
        │                                     │
        │──── 请求 Request（功能码+地址+数量）──►│
        │◄─── 响应 Response（功能码+数据）─────│
        │                                     │
   SCADA / 通信网关 / 攻击者            RTU / PLC / 电表 / 箱变
```

- 从站从不主动发消息。"设备主动上报"在 Modbus 里不存在，只能靠主站轮询。
- 一次请求一次响应，一问一答。请求与响应通过 MBAP 头里的事务标识（Transaction ID）配对。
- 一个主站可以轮询多个从站，但在 TCP 上通常是一对一连接，靠 Unit ID 区分同一个网关后面的多台设备。

### 2. 四个数据区：Modbus 的"内存地图"

从站内部数据划成四个区，各有固定的编号前缀与读写属性：

| 区名 | 常见编号写法 | 数据宽度 | 读写属性 | 在工控里通常表示 |
|---|---|---|---|---|
| Coil 线圈 | `0x0001` / `00001` | 1 bit | 读写 | 开关量输出、启停命令 |
| Discrete Input 离散输入 | `1x0001` / `10001` | 1 bit | 只读 | 开关量输入、限位、故障接点 |
| Input Register 输入寄存器 | `3x0001` / `30001` | 16 bit | 只读 | 只读模拟量、测量值 |
| Holding Register 保持寄存器 | `4x0001` / `40001` | 16 bit | 读写 | 设定值、控制参数、可写模拟量 |

> 风电场里的落点几乎全在保持寄存器上。见 `点表映射.md`：遥测（功率、风速、温度）放在 HR0-HR9 只读，控制量（启停、限功率、告警复位）放在 HR90-HR94 可写。

### 3. 功能码：请求的"动词"

| 功能码 | 十六进制 | 作用 | 教学价值 |
|---|---|---|---|
| FC01 | `0x01` | 读线圈 | 读开关量状态 |
| FC02 | `0x02` | 读离散输入 | 读只读开关量 |
| FC03 | `0x03` | 读保持寄存器 | 轮询遥测的主用功能码 |
| FC04 | `0x04` | 读输入寄存器 | 读只读模拟量 |
| FC05 | `0x05` | 写单个线圈 | 开关量控制 |
| FC06 | `0x06` | 写单个保持寄存器 | 写控制参数（攻击链落点） |
| FC15 | `0x0F` | 写多个线圈 | 批量开关量控制 |
| FC16 | `0x10` | 写多个保持寄存器 | 批量参数下发 |

在攻击链里，`modpoll ... -c 1 -t 4` 读寄存器触发的是 FC03，末尾带一个写值时触发的是 FC06。读和写的区别只体现在功能码上，协议层没有任何"你有没有权限写"的检查。

### 4. Unit ID：一个连接后面的多台设备

定义：Unit ID 是 Modbus TCP 的 MBAP 头里保留的 1 字节从站地址（Slave ID / Unit Identifier）。

成因：Modbus 最早跑在 RS-485 串行总线上，一条总线挂多台设备，靠从站地址区分；搬到 TCP 之后，这个字段被保留下来。

- 直连一台 RTU 时，Unit ID 常固定为 `1`。
- 经过 Modbus 网关时，Unit ID 表示"网关后面的第几台设备"。网关把 TCP 请求翻译成串行帧转发给对应从站。

所以点表里的 `unit_id=1` 含义是"这台 RTU 在网关视角下的设备号是 1"。Unit ID 不对，请求会被应答成异常码或直接超时，这是实战排错的第一检查项。

### 5. 地址口径：0-based、1-based 与 4xxxx

同一个寄存器在不同材料里有三种写法，指的是同一个东西：

```text
点表写法         register_offset = 93, addressing = zero_based_pdu
PDU 地址          93      → 帧里填 0x005D
Modicon 传统写法  40094   （4xxxx 前缀 + offset+1）
```

风电靶场的点表明确写了 `addressing=zero_based_pdu`，意思是"协议帧里的地址直接用 register_offset 的值"。

- `HR93` → 帧里写 `0x005D`（93）；
- 不要再加 1，也不要写 40094。

注意：`modpoll` 的 `-0` 参数就是告诉工具用 0-based PDU 地址，与点表口径对齐。

## 在攻击链里的位置

平原链最后两步是纯粹的 Modbus 操作，位置在通信系统1（SCADA 网关）到三台风机 RTU 之间：

```text
攻击机 ──(Web SQL 注入 + IDOR 下载备份)──► 拿到网关配置与诊断私钥
   │
   └─ SSH 进通信系统1 10.0.6.8（唯一被允许访问 RTU 502 的节点）
        │
        ├─ modpoll -m tcp -p 502 -a 1 -0 -r 93 -c 1 -t 4 -1 10.0.5.6   → [93]: 100  （FC03 读）
        └─ modpoll -m tcp -p 502 -a 1 -0 -r 93 -c 1 -t 4 -1 10.0.5.6 0 → 写 HR93=0 （FC06 写）
```

这一步能改变业务，是因为 SCADA HMI 通过通信系统1 周期性轮询三台 RTU，把 HR93 解释为"有功功率限制百分比"。HR93=100 时风机按正常风速算功率，HR93=0 时该台风机有功被限为 0%。HMI 读的是 RTU，所以改寄存器等价于改 HMI 上的数字。

## 安全视角

Modbus 的设计前提是"运行在物理隔离的专有总线上"，当初就没把安全算进去：

| 缺失的能力 | 直接后果 |
|---|---|
| 无身份认证 | 任何能连上 502 的机器都是合法主站 |
| 无加密 | 报文在链路上明文，抓包即得功能码与寄存器值 |
| 无权限模型 | 能写就是能写，没有"只读账号"这种概念 |
| 无操作审计 | 写没写、谁写的、写了几次，设备侧不留痕 |
| 无范围约束 | 只要地址存在，就能写（约不约束全靠实现） |

防护要点：

- 工业防火墙做深度协议解析，只放行 FC03 和特定寄存器区间。
- 用白名单限定哪些源 IP 可以作为主站。
- 在协议网关/SCADA 侧做写入范围与值的双重校验。
- 对控制类写入记录审计日志。
