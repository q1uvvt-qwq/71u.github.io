## 一句话概括

漏洞仿真的目标不是复现真实漏洞，而是安全地模拟攻击者期望看到的行为反馈。攻击者判断一个目标能不能打，靠的是响应差异；蜜罐把这份差异做出来，就能把利用请求留在采集面里。

## 原理

靶场运行真实漏洞组件，攻击者一旦利用成功就拿到真实执行环境；漏洞仿真不加载真实漏洞组件，只按请求特征返回预设响应。

成因：多数漏洞的验证环节里，攻击者只看响应特征：状态码、错误信息、回显内容、是否报出数据库错误、有没有出现请求的文件内容。拿到这些反馈就足以判断可利用性，不需要真的执行命令。

所以仿真要下功夫的是响应模板的选择逻辑：按 Profile、请求特征和风险等级挑模板。可选类型有正常页面响应、静态资源响应、框架错误响应、API JSON 响应、认证/跳转响应和轻量随机化响应。

## 各类漏洞行为要仿真什么

- 弱口令登录仿真：认证流程、失败提示和成功跳转照目标产品给，同时记录用户名与口令尝试。
- 文件读取仿真：对路径穿越、任意文件读取请求返回类似真实系统的文件内容或权限错误。
- 命令执行假响应：不执行命令，返回攻击者期望看到的回显或框架异常。
- SQL 注入差异化响应：按注入特征返回不同的报错、空结果或数据行，制造注入生效的差异。
- 文件上传仿真：返回上传成功或校验失败的结果，记录上传文件名与内容。
- API 越权仿真：对越权访问返回数据或拒绝响应，记录参数与 Token。
- 工控异常读写仿真：对异常读写返回设备风格响应，记录点位与操作序列。

## 三类案例的仿真重点

- Log4Shell 风格：Java Web 服务外观、常见 Header 注入面（User-Agent、X-Forwarded-For、Referer 等）、JNDI/LDAP/DNS/RMI 特征字符串捕获、回连域名与 IP 提取。重点是把注入进 Header、参数、Body 的载荷都留全。
- Confluence RCE 风格：Confluence/Wiki 风格路径、登录页与错误页、关键路径的 200/302/404/500 响应差异、可疑表达式与命令片段捕获、下载与回连 IOC 提取。仿真重点在企业应用指纹。
- Next.js / React RSC 风格：`/_next/static/` 静态资源、Next.js 风格 HTML、RSC/Server Action 请求入口、相关 Header 与 Content-Type、框架错误或流式响应特征、常见 API 路由。

## 安全边界

- 不执行真实危险 Payload。
- 不运行真实漏洞组件，不加载真实受影响版本。
- 不执行真实应用逻辑，不引入真实漏洞框架。
- 不让请求进入真实框架解析链。
- 对利用请求返回框架风格错误或"像失败但可继续尝试"的响应，而不是简单拒绝。
- 响应目标是合理可信，不是完整复刻生产系统。

注意：回连观测是敏感点。可以让蜜罐记录 Payload 中的候选回连地址，但不能让它主动访问攻击者基础设施；需要验证时放到隔离分析环境里人工做。
