## 一句话概括

流量采集是漏洞蜜罐的核心资产层。蜜罐的价值不在"有人访问了"，而在把攻击者的请求、Payload、会话和样本完整留下来，后面的分析、画像和规则全部建立在这层数据上。

## 原理

采集先于响应：请求进来先记录，再决定返回什么，采集不受分析结果影响。

成因：蜜罐告警只说明"有人在打"，漏洞热度期真正稀缺的是攻击流量原文；请求、Header、Body、Payload 没留全，事后补不回来。

流量优先的具体含义：

- 请求可完整采集。
- Body 可受控留存。
- Payload 可解析。
- IOC 可提取。
- 行为可分类。
- 规则可沉淀。

Dashboard、资产管理、多协议扩展这类能力可以后置，采集链路不能后置。

## 采什么

- 网络连接信息，包括来源 IP/端口与目标端口。
- HTTP Header 与 Body。
- 协议会话。
- 登录尝试。
- 命令序列。
- Payload。
- 上传文件。
- 下载链接。
- 样本 Hash。
- PCAP 或关键流量摘要。

## 记录字段

- 时间戳
- Sensor ID
- Profile ID
- 来源 IP/端口
- 目标端口
- HTTP 方法
- Path
- Query
- Header
- Cookie
- Body Hash
- Body Preview
- Body Size
- Raw Body 存储路径
- 响应状态码
- 响应模板 ID
- 命中的 Profile 和规则
- 时间线

## Body 留存策略

```text
小 Body：记录 Preview + Hash + 可选原文
大 Body：记录 Hash + 截断 Preview + 原文文件
超限 Body：拒绝或只记录元数据
疑似敏感字段：脱敏或标记
```

## 存成什么

统一走 JSONL，一条请求一行事件：

```json
{
  "ts": "2026-08-16T10:00:00+08:00",
  "sensor_id": "web-cve-honeypot-001",
  "profile_id": "nextjs-rsc-rce-sim",
  "src_ip": "192.0.2.10",
  "src_port": 54321,
  "dst_port": 8080,
  "method": "POST",
  "path": "/example/action",
  "query": "a=b",
  "headers": {
    "user-agent": "scanner"
  },
  "body_sha256": "sha256...",
  "body_preview": "truncated body",
  "body_size": 1234,
  "raw_body_ref": "bodies/sha256...",
  "matched_profile_rules": ["path", "header", "body_keyword"],
  "classification": "suspected_exploit",
  "risk_score": 70,
  "iocs": {
    "ips": [],
    "domains": [],
    "urls": [],
    "base64": [],
    "commands": []
  },
  "response_status": 500,
  "response_template": "framework-error"
}
```

日志之外还要有 IOC 列表、检测规则样例和分析报告，以及供 SIEM/SOC 对接的字段。

## 采集之后的分析

- 提取 URL、域名、IP、User-Agent、Base64、命令关键词、文件名、下载链接、回连地址、文件 Hash、漏洞特征字符串。
- 攻击行为分类，区分扫描、指纹探测、疑似利用、命令注入、文件读取、下载、回连、后渗透迹象和噪声。
- 去重、打标签、置信度评分，形成按 Profile 聚合的 IOC 列表和高置信事件列表。

## 安全边界

- Body 限制最大记录长度，避免磁盘被打满。
- 原始 Body 单独落文件并记录 Hash。
- 敏感字段脱敏或标记，不保存与研究无关的个人敏感信息。
- 日志目录独立挂载，定期清理日志和样本。
- 分析器只做静态解析和安全解码：不访问 Payload 中的外部 URL，不执行任何命令，不把请求内容传入危险解释器、Shell、模板引擎或反序列化链。

注意：请求 Body 本身可能是恶意样本。留存策略要保证样本被保存下来，但保存动作不能触发它。

## 素材中的不确定处

- 事件日志字段有两个版本：08 记 `raw_body_ref`、`matched_profile_rules`、`risk_score`、`response_template`，03 记 `matched_indicators`，且没有 `raw_body_ref` 与 `risk_score`。
