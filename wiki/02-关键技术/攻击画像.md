## 一句话概括

攻击画像把零散的事件日志聚合成长期视图，分成两个视角：某个产品被怎么打，某个来源 IP 怎么打。日志回答单次事件，画像回答趋势和态势。

## 原理

画像的底座是攻击样本库。同一产品、同一 IP 的请求按时间聚合后，再叠加攻击类型、来源地区、路径等维度做统计，才形成态势。

成因：蜜罐集群长期运行会沉淀大量流量，单条事件无法回答"这类产品最近被利用得最多的是哪个漏洞""这个 IP 一直在扫什么"，只有聚合统计层面才有情报价值。

画像依赖结构化字段而非日志原文。请求需要先被识别出攻击位置、攻击载荷、攻击类型，并映射到具体产品，才能按维度聚合（字段清单见 `情报检索.md`）。

## 产品攻击画像统计什么

- 产品漏洞利用态势。
- 攻击类型统计。
- 高频攻击路径。
- 路径曝光度。
- URL 匹配程度。
- Payload 聚合分析。
- 攻击源地区统计。

## IP 攻击画像统计什么

- 追踪恶意 IP 地址，识别攻击源与攻击特征。
- 攻击 IP 统计。
- 攻击国家统计。
- 识别攻击源与攻击特征。

## Web 攻击分析

实时监测 Web 应用攻击行为，包括注入攻击、XSS 等威胁。

## 平台侧的运营能力

平台通常还提供蜜罐模板市场、我的模板、模板发布与复用、用户私有蜜罐、SaaS 化节点接入、会员等级、权限控制、配额管理、规则管理与工单反馈。

## 安全边界

- 画像结论用于态势判断和线索生成，不直接作为封禁依据。
- IOC 需要人工校验，不能全部直接封禁。
- 画像的聚合结果依赖攻击类型与产品识别，识别错会让统计口径整体偏移。
