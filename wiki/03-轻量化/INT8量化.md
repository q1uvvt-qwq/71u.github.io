## 一句话概括

INT8 量化把权重和激活从 FP32 压到 8 位整数，用更小的位宽换更快的算子，代价是数值不再逐位相等。日志异常检测靠分数排序和阈值下结论，所以量化之后必须重新验证漂移，延迟降了多少只是其中一个指标。

## 量化的数学定义

定义：量化是把一个连续浮点区间映射到有限整数格点的过程，映射由 scale（步长）和 zero-point（零点）两个参数确定，反量化就是逆映射。

非对称量化的形式是 `q = round(x / scale) + zero_point`，反量化 `x' = (q - zero_point) * scale`。zero_point 的作用是让浮点里的 0 精确落在某个整数上，这样 padding 用的 0 不会因为量化偏移变成非零值。对称量化强制 zero_point = 0，整数区间关于 0 对称，实现更简单，适合权重分布本来就近似对称的场合。

scale 由被量化张量的取值范围决定，位宽 b 时 `scale = (max - min) / (2^b - 1)`。范围越窄分辨率越高，误差越小。

粒度分两级。per-tensor 给整个张量算一组 scale/zero-point；per-channel 给每个输出通道各算一组。per-channel 精度通常更好，因为不同通道的数值范围可能差一个数量级，共用一组参数会让小通道的取值被大通道的范围压扁。代价是推理时要多做一层按通道缩放，部分算子内核支持得不好。

## 哪些算子该量化，哪些不该

- 适合：MatMul / Gemm / Linear。权重是常量，可以离线量化；乘加本身整数化收益明确。
- 不适合：LayerNorm、Softmax、GELU、阈值与异常分数逻辑。这几类数值敏感，Softmax 里的 exp 和 LayerNorm 里的方差动态范围都很难塞进 8 位整数。

所以量化 op 的范围要限制在 MatMul/Gemm/Linear，其余保持 FP32。

注意：脚本里请求量化的节点数和最终图里真正生成的整数算子数不是一回事。部分 attention MatMul 不满足动态 INT8 的可量化条件，会被内核跳过。看收益前要先数实际生成了多少个 `DynamicQuantizeLinear` / `MatMulInteger`，否则会把"没量化上"当成"量化了但没用"。

## 动态量化不需要校准集

成因：动态量化在每次前向时现场统计 activation 的 scale 与 zero-point，权重则提前量化好。量化参数从当前这批输入算出来，所以不用预先准备代表数据。ONNX Runtime 的做法是在量化 MatMul 前插入 `DynamicQuantizeLinear`，再用 `MatMulInteger` 加 scale 乘法还原浮点输出。

这条特性直接带出一个容易踩的坑：activation 范围随调用组成变化。

- 一张 flatten 后含多条消息的 tensor，如果与不同的同伴消息拼在一起做动态量化，scale 与 zero-point 会重新估计，舍入结果随之改变。
- 同一批掩码变体按不同 chunk 分组执行，结果不再相等，只有和标定配置一致的 chunk 才逐元素相等。
- 异构 batch 里不同分区拼在一起时，逐元素结果也对不上。
- per-message 缓存路径因此失效：只编码命中之外的消息，等于换了调用组成，embedding 的微小差异传到 ContextScore 会被放大。

一句话收口：量化参数是从这批输入现场算的，输入组成变了参数就变，输出不可能逐位复用。任何建立在"单条消息的 embedding 与它和谁同批无关"之上的复用设计，在动态 INT8 下都不成立。这一点与 Message Embedding 缓存天然冲突（见 [缓存](缓存.md)）。

## 静态量化需要校准集

静态量化先用一批代表数据跑一遍，统计每个 activation 张量的取值范围，把 scale/zero-point 固化成模型常量。推理时不再重算，省掉动态量化那一步开销，理论上更快。

两头都有代价。一是校准集必须覆盖良好，否则固定下来的范围与实际输入对不上；二是范围定死之后对分布漂移不再敏感。校准建议是只用正常日志、覆盖不同服务与时间段、保留独立异常验证集、校准后重新确定阈值。

静态量化理论更快却可能实测更慢。常见原因是 QDQ 格式在 CPU 上引入了额外的量化/反量化节点与 Cast，而动态量化的这条路径会被运行时内核融合掉；校准范围与实际输入偏差大时，整数乘法还可能退化。漂移也不一定更小，因为固定的激活范围未必比现场统计更贴合当前输入。一次失败不能证明所有静态配置都失败，但候选实测跑不过动态量化时，就不该继续作为部署路线。

## 选择性量化

既然全图量化漂移大、静态量化更慢，自然的想法是只量化一部分节点。常见的三个候选：

- FFN INT8：只量化各层的 linear1/linear2
- Attention INT8：只量化 self-attention 的 MatMul/Gemm
- Layers 0-1 INT8：只量化前几层的 attention 加 FFN

三个候选都保留 LayerNorm、Softmax 与控制流节点为 FP32。要点是：只量化局部节点并不能消除动态量化的调用组成敏感性，稳定性验证仍然可能失败。

从收益和敏感度看，FFN Linear 是最有价值的 selective 目标，attention projection 最敏感。数值上如果没有一个能通过稳定性 gate，就都不可部署，收益再好也不能上线。

## 怎么测收益

量化收益要和 Amdahl 一起读。ContextScore 占整链的大头，只量化 MessageEncoder 省下的时间会被它吸收，端到端加速很有限；两个编码器都量化才看得出差别。

还有一部分收益属于副作用，不能算在量化头上。INT8 产生的 embedding 差异有时恰好降低了后续 ContextScore 的计算时间，这部分不随模型结构稳定，换个模型或换批数据就没了。报收益时要区分"算子真的变快了"和"下游恰好算得少了"。

漂移要和收益一起看。全量化漂移最大，混合方案（只量化一侧）漂移小但几乎不加速。这是一个明确的取舍，没有两头都占的配置。

## 体积收效有限

量化的体积压缩比想象中小。原因是动态量化只覆盖 MatMul/Gemm 的权重，而模型里占大头的大词表 embedding 是 Gather 查表，保持 FP32。所以"权重接近 4 倍压缩"这句话只对可量化那部分成立，整体文件大小通常只降几个百分点。

如果部署受体积而不是延迟约束，要另找手段：词表剪枝砍的是 embedding 表，那才是体积的主项。

## 精度掉点之后怎么办

- 先分清误差类型。量化误差随位宽和粒度变化；调用组成误差在 FP32 下不存在，一换组合就出现。两者的修法不同。
- 重校准阈值。分数分布整体平移时，按正常集重新定阈值比动模型便宜。
- 换量化路线。静态 QDQ 用固定激活 scale，可以消掉组成敏感，但要新建 ONNX 资产并走完整验证。
- 上 QAT。训练时模拟量化，让权重适应舍入误差，精度最稳，但要动训练流程，冻结期内不允许。
- SmoothQuant 一类方法把激活的量化难度转移到权重上，同样属于新资产路线。
- 接受现状。把动态 INT8 只当性能参考、准确性优先时退回混合方案，是一个合理的取舍。
