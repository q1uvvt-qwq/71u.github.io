## 一句话概括

工程师站（Engineering Workstation / 运维工作站）是那台"能改东西"的电脑：下装 PLC 程序、改 SCADA 点表、改保护定值、做远程维护。它是典型的高价值跳板，同时具备 IT 能力与 OT 权限：能上网、跑脚本、开终端，也能直连 PLC、RTU、IED、OPC UA 服务器。

## 原理

### 一、工程师站到底在干什么

| 职责 | 具体动作 | 影响面 |
|---|---|---|
| 下装程序 | 把组态/逻辑下载到 PLC、RTU | 改变控制逻辑本身 |
| 改点表 | 新增/删除/改名测点，改量纲系数、改量程 | 改变"数据是什么意思" |
| 改保护定值 | 修改保护阈值、延时、投退 | 改变"什么时候该跳闸" |
| 改配置 | 网关路由、通信参数、报警规则 | 改变"数据往哪流、什么时候报" |
| 远程维护 | SSH、Web Terminal、厂商远程工具 | 改变"谁能进来" |
| 故障处理 | 查日志、抓包、分析录波 | 需要贴近现场的能力 |

风电场系统安全区归属表.md 对它的定位非常谨慎：

```text
engineer-station | 生产控制区 / 安全 II 区，必要时就高按 I 区
理由：工程师站修改点表、配置和控制逻辑，风险高；如可直接修改控制逻辑，应按 I 区加强
灰区：如果直接修改控制逻辑、保护配置或 RTU 点表，应按 I 区保护
安全要求：工程师站访问 I 区设备必须审计
```

定义："就高保护"：一台机器只要具备改控制逻辑的能力，安全等级就不该低于它所能控制的设备。

### 二、为什么它是"高价值跳板"

成因：它同时具备 IT 与 OT 权限，又常与 OT 设备处在同一二层域，跨区防火墙拦不住它，因为它本来就在"里面"。

攻击者拿下办公机只能横向移动；拿下工程师站/运维站，等于同时拿到 IT 与 OT 两样东西：

```text
IT 侧能力                         OT 侧能力
---------------                   ---------------
通用 shell / 脚本语言             直连 PLC / RTU 的 Modbus 502
常见运维工具链                    直连 IED 的 IEC 61850 MMS 102
可下载上传文件                    直连 OPC UA Server 4840
可发起网络连接                    自带厂商工程软件与协议栈
                                  在物理网段内，不受跨区防火墙限制
```

### 三、远程维护通道：便利与风险的一体两面

远程维护是刚需，风机在山上、在海上，不可能每次都派人上去，于是有了这些通道：

| 通道 | 形态 | 靶场实例 |
|---|---|---|
| SSH | 经典远程登录 | 平原链 `ssh -i gateway_diag_key.pem plain_diag@10.0.6.8`；山区链 `ssh remote-maintainer@10.0.4.6` |
| Web Terminal | 浏览器里的终端（PTY API） | 海上链 `/ops/remote-maint/connect` -> 302 -> `/ops/remote-maint/terminal?sid=...`，配套 `/api/pty/write` 与 `/api/pty/read` |
| 维护网关 | 带鉴权与会话管理的入口 | 海上链 `maintenance-gateway`，校验 JWT 的 `maintenance.connect` scope |
| 厂商远程运维 | 设备厂商自己的远程工具/账号 | 威胁模型里的 External Remote Services 战术 |

对应的三类风险：

- 凭据泄露即通道失守。平原链的诊断私钥、山区链的 SSH 密码，都来自"本该内部使用"的资料。
- 会话管理薄弱。海上链的维护网关被伪造 JWT 通过，因为它只校验签名和 scope，而签名密钥已经从 `/actuator/env` 泄露。
- 厂商通道是影子入口。供应商账号泄露 -> 远程连接 -> 进入 OT 网络，这条路径常常绕过企业自己的边界设备。

## 报文/字段对照

海上链的维护门户会话建立流程（出自海上链攻击链指南）：

```text
1. 获取 viewer token
   curl -s http://10.0.11.8:8080/api/auth/viewer-token
   -> payload: scope=[trend.read], role=viewer

2. 用 viewer token 访问维护网关（验证权限不足）
   curl -s -i -H "Authorization: Bearer <viewer_token>" \
        http://10.0.11.8:8080/ops/remote-maint/connect
   -> HTTP 403, WWW-Authenticate: Bearer error="insufficient_scope",
      scope="maintenance.connect"

3. 用泄露的 JWT_SECRET=offshore-secret-2026 自签一个 scope 扩展后的 JWT
   （保留 user=edge-service / role=viewer，只增加 maintenance.connect）

4. 再访问 /connect
   -> HTTP 302 Found
      Set-Cookie: maint_session=OFF-SID-...
      Location: /ops/remote-maint/terminal?sid=OFF-SID-...
```

注意第 3 步：身份没变，只是权限列表里多加了一项，属于权限提升（Scope Escalation）。密钥泄露因此比账号泄露严重得多。

## 在攻击链里的位置

| 链条 | 节点 | 角色 | 怎么被拿下 | 拿下后做了什么 |
|---|---|---|---|---|
| 平原链 | `plain-scada-gateway`（通信系统1，`10.0.6.8`） | 通信网关兼运维入口，装有 `modpoll` | 备份包里的 `gateway_diag_key.pem` + `plain_diag` 账号被 SSH 复用 | 用 `modpoll` 读/写三台 RTU 的 HR93 |
| 山区链 | `mountain-maint-ws`（`10.0.4.6`，部署地址 `10.0.7.50`） | 远动维护工作站，装有 tcpdump / tshark / arpspoof / python3 | 工单系统存储型 XSS 回传 `/api/maintenance/current-session`，泄露 `remote-maintainer` / `remote-maint-2026` | `sudo bash` 提权后 ARP MITM 抓 IEC104，自写 Rogue Master 脚本 |
| 海上链 | `offshore-maint-ws`（`10.0.12.x`） | OT 运维工作站，含 `opcua-profiles/` 与 `opcua-tools/` | SSRF 读 `/actuator/env` 泄露 JWT Secret，伪造带 `maintenance.connect` 的 JWT 进入 Web Terminal | 读 `offshore-gateway.profile` 拿到 `opc.tcp://10.0.12.8:4840/windfarm/offshore/`，调用 Protection 方法 |

三条链的规律一致：先用 IT 漏洞拿到合法身份或凭据，再进工程师站/运维站，最后用站上现成工具碰 OT 设备。

```text
平原链：网关 = 唯一的 Modbus 出口，工程师站性质 → 拿到它 = 拿到对 RTU 的写权限
山区链：维护站 = 唯一能同时看到 IEC104 双向流量的位置 → 拿到它 = 能 MITM、能抓包、能自写 Master
海上链：运维站 = 唯一能到达 10.0.12.0/24 的位置 → 拿到它 = 能读 OPC UA 资产树、能调 Method
```

三条链都在证明同一件事：工程师站/运维站是 IT 与 OT 的接缝处，最容易"两边的防护都不覆盖"。

山区链维护工作站上翻到的东西很说明问题：

```text
config/remote-link.yaml          -> upstream_peer.address = 10.0.4.2（frontend3-lower）
logs/iec104-monitor.log          -> peer=10.0.4.2、peer=10.0.4.5、dport=2404
profiles/site-maint.profile
/var/log/iec104-monitor.log
```

海上链里的：

```text
~/opcua-profiles/offshore-gateway.profile
    endpoint=opc.tcp://10.0.12.8:4840/windfarm/offshore/
~/opcua-tools/
    discover.py / browse.py / read.py / call_method.py
```

## 安全视角

典型薄弱点：

- 诊断私钥放在可下载的备份包里，维护账号密码通过 XSS 就能读出来。
- 一个维护账号在 `sudo -l` 里是 `(root) NOPASSWD: ALL`，直接等于 root。
- `modpoll`、`arpspoof`、`tcpdump`、`tshark`、`python3` 既是运维工具也是攻击工具。
- profile 里的 OPC UA endpoint、链路日志里的对端 IP 与端口，等于把网络拓扑写成文本放在家目录。
- 远程维护通道只校验签名与 scope，不校验会话绑定、来源、时效与一次性。
- Web Terminal 的 `pty/write` / `pty/read` 没有完整记录，事后无法还原操作序列。
- 供应商通道常直连现场，不受本地防火墙与堡垒机约束，绕过了企业边界。

防护要点：

- 运维凭据独立管理、最小权限、可撤销、定期轮换；诊断密钥绝不随工程包/备份包分发。
- 所有远程维护必须经堡垒机（ops-bastion）+ 安全接入区 + 白名单防火墙，禁止直连生产设备。
- 远程维护账号不使用 `NOPASSWD: ALL`；提权操作单独审批与记录。
- 维护会话全量录屏/记录：登录、命令、文件传输、时长，并同步到安全监测平台。
- 工作机上的配置、profile、日志按敏感资料管理，不放易读位置，不写明文 endpoint 与凭据。
- 维护网关的令牌校验要绑定用户、用途、来源和有效期；密钥用 KMS/密钥库管理，禁止放在 `/actuator/env` 这类可被 SSRF 读到的地方。
- 厂商远程运维纳入统一账号与审计体系，不允许存在"影子入口"。
