## 一句话概括

边界设备是安全区之间那道"闸门"：工业防火墙按白名单放行特定协议、功能码和寄存器范围；纵向加密认证装置管住到调度数据网的远动链路；正/反向隔离装置把链路做成单向的，正向只出不进，反向只允许经校验的数据导入。

## 原理

### 一、四类边界设备与它们的位置

```text
风机/采集侧 --FW-ICS-01--> SCADA/站控层
升压站/间隔层 --FW-ICS-02--> SCADA/站控层
安全接入区 --FW-OPS--> 生产控制区
生产控制区 --forward-isolation--> 管理信息区
管理信息区 --reverse-isolation--> 生产控制区（受控导入）
生产控制区 RTU --crypto-gateway-A/B--> 调度数据网 A/B 平面
```

| 设备 VM | 类型 | 所属边界 | 网卡 1 | 网卡 2 |
|---|---|---|---|---|
| `FW-ICS-01` | 工控防火墙 | 风机/场内采集侧 与 站控层 SCADA | 采集侧汇聚交换机 | `SW-SCADA` |
| `FW-ICS-02` | 工控防火墙 | 升压站/间隔层 与 站控层 SCADA | 升压站侧汇聚交换机 | `SW-SCADA` |
| `FW-OPS` | 工控防火墙 | 安全接入区 与 生产控制区 | `SW-OPS` | `SW-SCADA` |
| `FW-MGMT` | 工控防火墙 | 生产控制区 与 管理信息区 | 生产控制区边界交换机 | `SW-MGMT` |
| `forward-isolation` | 正向隔离装置 | 生产控制区 -> 管理信息区 | 生产控制区边界交换机 | `SW-MGMT` |
| `reverse-isolation` | 反向隔离装置 | 管理信息区 -> 生产控制区 | `SW-MGMT` | 生产控制区边界交换机 |
| `crypto-gateway-A/B` | 纵向加密认证装置/加密认证网关 | RTU 与调度数据网 A/B 平面 | 站内远动侧 | `SW-DISP-A/B` |

共同特征：都是双网卡，都不当普通服务器用，而是当边界控制点用。

### 二、工业防火墙：不是"网络防火墙 + 工控标签"

定义：工业防火墙与 IT 防火墙的差别在深度协议解析。

```text
普通防火墙看得懂：  src / dst / port / protocol
工业防火墙还要看懂：功能码（FC03 读 / FC06 写）
                    寄存器地址与范围（HR90-HR94 可写，HR0-HR89 只读）
                    点号（IEC104 的 IOA、IEC 61850 的逻辑节点）
                    方向与语义（遥测上送 vs 遥控下发）
```

这意味着白名单可以写得极细："只允许 SCADA 对 HR90-HR94 执行写操作，禁止对 HR0-HR89 的任何写，禁止任何来源的 FC16 批量写"。这就是"限制数据流"（IEC 62443 FR5）的落地形态，也是点表权限模型生效的地方。

靶场里四台工业防火墙的放行策略摘要：

| 防火墙 | 建议放行 | 默认拒绝 |
|---|---|---|
| `FW-ICS-01` | `data-gateway -> scada-server`（HTTPS/REST）；`scada-server -> data-gateway`（OPC UA 4840 或 REST）；`historian <-> data-gateway`；Syslog 到安全监测 | `hmi-web` 直连风机；`engineer-station` 直连风机；SCADA 绕过网关批量扫风机侧 |
| `FW-ICS-02` | `substation-gw -> scada-server`；`scada-server -> substation-gw`；`substation-gw -> rtu-gateway`；`energy-meter -> historian`；`fault-recorder -> engineer-station`（SFTP/HTTPS） | HMI 直连 IED；管理区直连 IED；绕过 `substation-gw` 批量扫 IED |
| `FW-OPS` | `ops-bastion -> engineer-station`（SSH/SFTP 22）；`ops-bastion -> hmi-web`（HTTPS 443）；`ops-bastion -> scada-server` | 运维区直连风机/IED/RTU；非堡垒机访问生产控制区；运维区横向扫描 |
| `FW-MGMT` | 生产侧日志源 -> `security-monitor`（Syslog 514/6514）；只读副本 -> 管理侧应用（HTTPS 443）；`forecast-server -> reverse-isolation` | 管理区直连 `scada-server` / `agc-avc-control` / `rtu-gateway`；任意交互式连接 |

### 三、纵向加密认证装置

它管的是生产控制区与调度数据网之间的远动链路（依据《电力监控系统安全防护规定》第十一条）：

```text
rtu-gateway -> crypto-gateway-A -> dispatch-network-A -> dispatch-master
核心协议：IEC104，TCP 2404
外层可用 WireGuard / IPsec / TLS 模拟认证与加密
```

它要做四件事：

- 只允许指定的远动链路通过，非 IEC104 业务一律拒绝。
- 对调度链路做认证或加密（对应 IEC 62351 的思路）。
- 记录链路建立、访问、拒绝、异常日志。
- 默认拒绝：非白名单主机访问调度数据网、管理区访问调度数据网、生产区任意 VM 绕过 `rtu-gateway` 接入调度侧。

靶场不必复刻真实商用设备，但必须体现上述四点；A/B 双平面体现调度链路冗余。

### 四、正向隔离与反向隔离：单向才是重点

注意：这两种装置容易被误当成普通路由器，它们只允许指定方向、指定数据类型、指定流程通过。

| 装置 | 方向 | 主要数据 | 实现要求 |
|---|---|---|---|
| 正向隔离 | 只允许生产区向管理区输出 | 运行数据、历史数据、报表数据、告警摘要、安全日志 | 不开普通 IP 转发；不允许管理区主动连接生产区；生产区只能推送到隔离装置的生产侧接口；每次交换记录数据类型、来源、目的、时间、结果 |
| 反向隔离 | 只允许经校验的数据从管理区导入生产区 | 功率预测文件、计划值文件、配置包、受控维护文件 | 不允许管理区直接访问生产区目标 VM；只允许向隔离装置提交文件或结构化数据；检查文件类型、字段、大小、哈希、签名；通过后由生产侧服务主动拉取 |

反向隔离常见的默认拒绝清单：

```text
管理区 SSH 到生产区
管理区 HTTP 直连 SCADA/AGC
管理区直接下发控制命令
未经校验的任意文件导入
```

### 补充：安全接入区

安全接入区不是一个设备而是一个区域，专门收容"从外面来的人"。

```text
外部/跨区运维 --FW-OPS--> 安全接入区（ops-bastion 堡垒机）--> 生产控制区
```

三条铁律：

- 运维不能直接进入 I 区设备。
- 运维会话、命令、文件传输必须记录。
- 对生产控制区的访问按最小权限和白名单控制。

## 报文/字段对照

协议与端口总表（出自安全设备VM部署与边界策略.md）：

| 边界 | 允许协议/端口 | 数据类型 |
|---|---|---|
| 风机/采集侧 -> SCADA | OPC UA TCP 4840、HTTPS/REST 443/自定义端口 | 风机状态、箱变状态、气象数据、告警 |
| 升压站侧 -> SCADA | HTTPS/REST、OPC UA、必要时 TCP 102 | 遥测、遥信、保护告警、录波索引 |
| 运维区 -> 生产区 | SSH/SFTP 22、HTTPS 443 | 运维登录、配置维护、审计访问 |
| 生产区 -> 管理区 | Syslog 514/6514、HTTPS/REST、文件推送 | 历史数据、日志、报表、告警摘要 |
| 管理区 -> 生产区 | HTTPS/SFTP 上传到隔离入口 | 功率预测文件、计划值、配置包 |
| RTU -> 调度数据网 A/B | IEC104 TCP 2404、WireGuard/IPsec/TLS | 遥测、遥信、遥控、遥调 |

与政策依据的对应：

| 安全要求 | 对应设备 |
|---|---|
| 安全分区 | 所有交换机分区、所有安全边界 VM |
| 网络专用 | 生产控制区交换机、调度数据网 A/B 平面 |
| 横向隔离 | `forward-isolation`、`reverse-isolation`、`FW-MGMT` |
| 纵向认证 | `crypto-gateway-A`、`crypto-gateway-B` |
| 访问控制/防火墙 | `FW-ICS-01/02`、`FW-OPS`、`FW-MGMT` |
| 日志与告警 | `security-monitor` 与各安全设备日志 |

一条真实的访问控制（出自平原链 `route_note.txt`）：

```text
allow src=10.0.6.8 dst=10.0.5.6 tcp/502
allow src=10.0.6.8 dst=10.0.5.4 tcp/502
allow src=10.0.6.8 dst=10.0.5.5 tcp/502
deny  src=any      dst=10.0.5.4-10.0.5.6 tcp/502
```

## 在攻击链里的位置

边界设备在三条链里的角色就是"要绕开的那道墙"：

```text
平原链：
  攻击机不在生产控制区，无法直连 10.0.5.4-10.0.5.6:502
  -> 所以必须先拿到通信系统1（10.0.6.8）这个"被白名单信任的源"
  -> 再从 10.0.6.8 发起 Modbus 写操作，走的正是 allow 规则里的那条合法路径
  -> 整条链没有"打破"边界，而是"借用"了边界允许的那条通路

山区链：
  攻击机在交换机11/其他区，无法直连 IEC104 链路
  -> 先经 D50003 工单系统 XSS 拿到维护工作站（在同二层网段内）
  -> 在二层做 ARP MITM，前置机与 RTU 都以为在跟对方说话
  -> 边界是三层设备，管不住同二层域内的欺骗

海上链：
  攻击机在 10.0.11.0/24，OT 维护侧在 10.0.12.0/24，网络隔离
  -> 必须通过维护网关的 Web Terminal 代理才能跨区
  -> 攻击者最终"合法地"穿过了边界，因为凭据和令牌都是伪造得合法的
```

共同结论：边界设备的强度决定攻击者要付出的代价，但一旦凭据/令牌/信任源被攻破，边界反而成了攻击者的合法通道。

## 安全视角

典型薄弱点：

- 防火墙规则写成 `any -> any`、只按端口放行不看功能码、允许 FC16 批量写。
- 开了 `net.ipv4.ip_forward=1`，正向隔离变双向可达，反向隔离变任意访问通道。
- 反向导入只判断文件后缀，不校验文件类型、字段、大小、哈希、签名。
- 纵向加密只做"能通"不做"只允许规定链路"，放行整个 2404，不限制来源主机与业务类型。
- 边界设备不记放行与拒绝日志，事后无法还原攻击路径。
- 图纸上分区清晰，设备上却是"临时放开"的旧规则，被利用的往往就是这条缝。
- 堡垒机被绕过、`FW-OPS` 放行过宽，运维区变成直通生产区的高速路。

防护要点：

- 白名单优先、默认拒绝：每个边界只放行"必要方向 + 必要协议 + 必要端口 + 必要功能码/寄存器范围"。
- 隔离装置默认关闭普通转发，只开放自研数据交换服务或白名单代理，所有交换动作记日志。
- 反向导入做多层校验：文件类型、字段白名单、大小、哈希、签名或口令，通过后由生产侧主动拉取。
- 纵向加密认证装置只放行规定的远动链路，并记录链路建立、访问、拒绝、异常。
- 所有安全设备纳入 syslog 与安全监测平台，日志集中留存，作为"放行/拒绝"两类证据。
- 部署后逐项检查：是否双网卡且接对交换机、是否关闭默认转发、是否启用白名单、是否记录日志、能否阻断非预期访问、能否放行预期业务。
- 定期对账"图纸分区"与"设备策略"，把临时放开的规则当成漏洞来管理。
