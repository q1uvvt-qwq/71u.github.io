## 交易

核心思想：交易是一条请求区块链更新记录的指令。

#### 交易内容

钱包在发送前会准备交易内容。下面是理解一笔以太坊交易最需要认识的信息：

| 信息                  | 它表示什么                                        |
| --------------------- | ------------------------------------------------- |
| **发送地址**          | 从哪个账户发起交易。网络可以通过签名验证这一点。  |
| **接收地址**          | 交易发往哪个地址；该地址也可能是智能合约。        |
| **金额**              | 直接随交易转出的 ETH 数量。                       |
| **交易数据**          | 发送给智能合约的指令。普通 ETH 转账通常不需要它。 |
| **交易序号（nonce）** | 发送账户的交易编号。                              |
| **网络标识**          | 交易针对哪条区块链网络。                          |
| **手续费设置**        | 愿意为处理交易使用多少计算资源、支付多少费用。    |
| **签名**              | 用控制账户的私钥对交易内容作出的授权证明。        |

钱包通常替用户整理这些信息，但**点击签名前看到的收款地址、金额和操作内容仍需核对**。

#### 交易过程

整个过程可以记成：

**准备交易 → 签名 → 广播 → 网络验证 → 收录进区块 → 查看执行和确认结果**

**准备交易。**钱包填写接收地址、金额、网络及手续费等信息。此时交易还没有进入区块链。

**签名。**钱包使用私钥生成签名。正常情况下，网络收到的是签名后的交易，**不需要收到私钥本身**。签名表示相应私钥授权了这条指令。

**广播。**钱包把交易发送给节点，再由节点传播到网络。交易通常会先处于“待处理”状态。**已广播不等于已完成。**

**验证。**节点检查签名、交易序号、余额等是否符合规则。验证不过的交易不能作为有效的账本更新。

**收录和执行。**交易被放入有效区块后，节点按规则执行并核对结果。普通 ETH 转账成功时，相关地址的余额随之改变。

**确认。**区块被收录后，记录会随着网络继续运行而变得更稳定。不同链判断“足够确定”的方式不同，后面学习最终性时再详细解释。

#### 手续费

在以太坊中，处理交易要消耗 **Gas**，可以把它暂时理解为计算和处理工作量的计量单位。手续费由**实际消耗的 Gas**和**每单位 Gas 的实际价格**决定。钱包设置的 Gas 上限是允许使用的工作量上限，并不表示一定会用满。

因此，前面那笔转出 3 ETH 的普通交易成功后：

- 收款地址增加 **3 ETH**；
- 发送地址从 **10 ETH** 中扣除 **3 ETH + 实际手续费**。

与智能合约交互时，交易可能被收录却执行失败；由于网络已经处理了它，**失败的交易也可能产生手续费**。所以“入块”和“执行成功”必须分开看。

#### 交易状态

| 状态         | 应该怎样理解                                         |
| ------------ | ---------------------------------------------------- |
| **已签名**   | 指令获得授权，但可能还没有发往网络。                 |
| **待处理**   | 网络收到交易，尚未将它收录进有效区块。               |
| **已入块**   | 交易被收录；还需要查看执行结果。                     |
| **执行成功** | 交易按规则完成了相应操作。                           |
| **执行失败** | 交易被处理了，但目标操作没有成功；可能仍产生手续费。 |

每笔交易还有一个**交易哈希**，用于查询这笔交易。它相当于查询编号：**有交易哈希，不代表交易已入块或执行成功。**
