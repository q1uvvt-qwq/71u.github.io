## 一句话概括

四个特征量纲不同、分布不同，直接加权求和没有意义。校准要做的就是把它们各自标准化到同一个尺度，再合成一个能跟单一阈值比较的分数。阈值本身只用正常样本定，用分位数换算成目标误报率。

## 标准化：为什么用 median / MAD

```text
robust_z_j = |(feature_j - median_j) / max(mad_j, 1e-9)|
```

`median_j` 是第 j 个特征在正常样本上的中位数，`mad_j` 是中位数绝对偏差（各样本到中位数的距离再取中位数）。`mad` 为 0 时替换成 `1e-9`，避免除以零。

用中位数和 MAD 而不是均值和标准差，理由是稳健性。四个特征里 `point_max` 和 `context_max` 本身就是极值统计量，在正常样本里也会偶尔冒出离群的高分。用均值的时候，这几个离群点会把均值抬高、把标准差撑大，导致真正需要被区分的样本被压到阈值以下。中位数和 MAD 对尾部不敏感，前 50% 的数据决定它们的位置和尺度。

这套标准化在文献里叫 Robust-Z 或修正 Z 分数。它把"偏离正常中心多少个稳健标准差"变成可比量，代价是当分布严重不对称时，中位数两侧的尺度其实不一样，MAD 只能给一个平均的尺度。

## 分数合成与阈值

```text
sequence_score = L2(robust_z)                       # 四个分量平方和开根
threshold      = percentile(sequence_score, 95.0)   # 在正常集上取分位
decision       = sequence_score >= threshold
```

拟合流程是三步：按列算 median / MAD，把特征矩阵转成 robust_z，再取行方向的 L2 范数作为每个窗口的分数，最后在正常分数分布上取分位数当阈值。

用 L2 而不是简单相加，是因为四个分量中任意一个大都值得告警。L2 会放大较大分量的贡献，一个特征严重偏离和四个特征各偏离一点，得到的分数不同，前者更高。这与"最可疑的那个位置说了算"的判据一致。

阈值取正常分数分布的高分位，分位点直接对应误报率：取 95% 分位，意味着 5% 的正常窗口会被判成异常。这是一个业务决策，不是模型能力指标。

## 阈值绑在模型上，不能跨模型套用

阈值不是一个可以复制粘贴的数字。它绑定四样东西：

- 具体模型的分数分布
- 导出产物的版本指纹
- Point reference 集合
- 特征顺序

换其中任何一样，原来的分位点对应的误报率就变了，套用旧阈值等于随机决定误报率。不同模型的分数尺度本来就不一样，两个看起来同为"高分"的数值可能处在完全不同的分布位置上。

## 阈值包的必备内容

一份可用的阈值包不只是那个数字，规范上要能独立复现。至少要记录：

- 校准数据 ID 与参与校准的 host 清单
- 标签语义（用的是哪种正常标签）
- 拟合代码的版本指纹
- 拟合参数（percentile / quantile）
- 目标误报约束
- 冻结时间
- 是否用过测试数据（应当是显式的"未使用"声明）

校准窗口的规模也要写进去。用几百个窗口拟合出来的中位数和 MAD 不稳定，分位点取到尾部时尤其如此。

## 没有冻结阈值时只能出诊断

阈值未冻结、仍处于候选状态时，规范的要求是只能出 `DIAGNOSTIC_ONLY`，不得报告 Accuracy / F1 / Precision / Recall / FPR / 混淆矩阵。

理由很直接：F1、Recall 这些指标全部依赖一个二值判定，判定依赖阈值。没有阈值就没有判定，指标只能靠临时挑一个阈值算出来，那个数字换一个阈值就变一个样，不能当验收结论。

注意：阈值必须按误报率定，不能按 F1 最优点定。在异常检测里正类是少数且金标稀少，F1 最优点往往会挑到一个召回很高但误报也高的位置。运维能否接受，取决于误报的绝对数量而不是 F1 的数值。所以阈值要用分位数来表达目标误报，而不是先算 F1 再反推。

## 阈值必须重校准的场景

- 量化：INT8 会推移分数分布，`Robust-Z` 的 median / MAD 与阈值都要重算（见 [漂移度量](../03-轻量化/漂移度量.md)）
- 换模型变体：不同档位的分数尺度不同，阈值不通用
- 换 tokenizer 或词表：输入表示变了，分数分布跟着变
- 数据漂移：训练日与攻击日分布不同，正常基线本身在移动

重校准必须在独立的正常验证集上做，不能用 TEST，也不能用被量化改动过的那批输出当基准（见 [划分与防泄漏](../01-数据工程/划分与防泄漏.md)）。
