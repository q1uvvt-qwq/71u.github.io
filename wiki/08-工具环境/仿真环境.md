## 一句话概括

靶场仿真环境用一批开源组件分别"扮演"真实工控设备：pymodbus 和 modpoll 演 Modbus 从站与主站，Conpot 演 IEC104 RTU，asyncua/open62541 演 OPC UA Server，Mosquitto 演 MQTT Broker，OpenPLC 演 PLC，FUXA/Grafana 演 HMI；核心纪律是一个协议节点一个独立实例/镜像，并保证 MITM 实验所需的二层可见性。

## 原理

### 为什么要仿真

依据学习方案：

```text
开源组件用于教学仿真，不等同于真实厂家设备。
如果公司后续提供真实风机、PLC 或沙盘接口，应把仿真协议层替换成真实通信适配层，
但监控平台和攻击链结构尽量保持不变。
```

注意：仿真层可替换，攻击链结构与业务语义（点表、控制点、业务影响）应保持稳定。

## 部署对照

### Docker 化部署注意点

| 项 | 要求 | 依据 |
|---|---|---|
| 镜像粒度 | 一个子站 = 一个独立镜像 | 9 个镜像分别构建 |
| 节点粒度 | 一个子站 = 一个独立拓扑节点 | 禁止合并到同一节点 |
| 端口 | 各自暴露本协议端口 | Modbus `502/tcp`、IEC104 `2404/tcp`、OPC UA `4840` |
| 地址 | 每节点独立 IP / 寄存器空间 | 三台子站读数互不相同 |
| 交付 | 统一 tar 包 | `modbus-substation-images_20260725.tar`，约 42 MB |

```text

本地调试端口映射：15027/15028/15029 -> 502/tcp（仅调试用）
```

### Dockerfile 健康检查的坑

素材记录的构建失败：

```text
Dockerfile heredoc 写法会把后续 import 解析成 Dockerfile 指令
-> unknown instruction: import
```

已改为单行：

```dockerfile
HEALTHCHECK --interval=10s --timeout=3s --retries=3 CMD python -c "import os, socket; s = socket.create_connection(('127.0.0.1', int(os.environ.get('MODBUS_LISTEN_PORT', '502'))), timeout=2); s.close()"
```

### MAC 与 ARP 可见性对 MITM 实验的影响

MITM（ARP 欺骗）要求攻击者与目标同处一个二层广播域，且能用自己的 MAC 冒充网关/对端，这对容器化部署提出额外要求：

```text
容器默认使用 bridge 网络，MAC 由 Docker 管理，且容器间东西向流量
可能不经过宿主机的外部网卡，ARP 欺骗不一定能生效。
```

素材中可观察到的事实：

```text
Modbus 子站：已 Docker 化（镜像 + 独立节点）
IEC104 MITM 两端：仍是 VM
  frontend3-lower  = 10.0.7.133（VM）
  conpot-rtu-mnt   = 10.0.7.131（VM）
  维护工作站        = 10.0.4.6（VM）
```

说明：任务说明给出的理由是"Docker 尚未确认能稳定支持独立 MAC 与 ARP 欺骗，因此 IEC104 MITM 两端保留 VM"。素材中未见关于该 Docker MAC/ARP 能力的实测结论，此处按工程约束记录，属于依据不足项，实际部署前需自行验证。

## 用法

### 本地联调与正式平台的区别

```text
本地调试端口 15027/15028/15029 不能作为正式平台地址。
正式平台中三个 Docker 子站应作为拓扑节点接入交换机，并各自暴露 502/tcp。
```

环境变量替换示例（Conpot 桥接到 WT08）：

```text
本地：MOUNTAIN_WT08_MODBUS_HOST=10.0.7.106
      MOUNTAIN_WT08_MODBUS_PORT=15028

正式：MOUNTAIN_WT08_MODBUS_HOST=<平台节点 IP 或服务名>
      MOUNTAIN_WT08_MODBUS_PORT=502
```

其他关键变量：

```text
MOUNTAIN_WT08_MODBUS_UNIT_ID=1
MOUNTAIN_WT08_STOP_REGISTER=93
MOUNTAIN_WT08_STOP_VALUE=0
MOUNTAIN_WT08_RESET_REGISTER=94
MOUNTAIN_WT08_RESET_VALUE=1
MOUNTAIN_WT08_MODBUS_TIMEOUT=2.0
```

### 子站隔离性验证

三个子站必须是独立服务，不能是共享状态的静态页面：

| 子站 | Power HR0 | Wind HR2 | Temp HR6 | RunState HR10 | Alarm HR11 | HR93 |
|---|---:|---:|---:|---:|---:|---:|
| WT07 | 99 | 83 | 28 | 1 | 0 | 100 |
| WT08 | 132 | 87 | 31 | 1 | 0 | 100 |
| WT09 | 121 | 86 | 30 | 1 | 0 | 100 |

对 WT08 写 FC06（HR93=0）后，只有 WT08 变成 `Power=0 / RunState=4 / Alarm=10 / HR93=0`，WT07 与 WT09 不受影响，证明是三个独立 Slave。

### 桥接层的正确性要求

素材强调桥接层不能伪装成功：

```text
Test=1 的测试遥控只记录日志，不写 Modbus，不影响风机。
Test=0 且通过 SBO 检查后，执行真实 Modbus FC06。
如果 Modbus 写入失败，IEC104 桥接层不伪装执行成功，
会记录 MODBUS_WRITE_FAILED 并拒绝 effect。
```

## 安全视角

- 仿真组件不是真实设备。漏洞模式只用于教学，评估真实系统时不能直接套用结论。
- 一节点一镜像 / 一节点一服务是安全边界与仿真真实性的共同要求：共享状态的"假多节点"会让攻击链验证失真（打一台影响三台）。
- 容器网络可见性直接决定实验可行性。做 MITM/抓包实验前先验证攻击者位置的二层可见性与 ARP 生效范围，否则会出现"抓不到包"却误判为"发送端没发"。
- 端口暴露要最小化。`502`/`2404`/`4840` 只应对生产/现场网段内的授权节点开放，不直接暴露给学生入口。
- 测试后必须恢复。素材中每次验证后都执行 reset（如 Conpot 侧 reset、HR94=1），并确认无残留进程、IP 转发已关闭。
