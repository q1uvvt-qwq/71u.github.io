## 一句话概括

OPC UA 跑在 TCP 4840 上，客户端要拿到一个数据必须依次走完"端点发现 → 安全通道 → 会话 → 服务调用"四层；服务端把 SecurityMode 配成 None，这四层里的安全能力就形同虚设，只剩一句"你连上了"。

## 原理

### 为什么是二进制协议

OPC UA 有两条承载路线：传统的 `opc.tcp`（二进制编码，端口 4840），以及把同样服务映射到 HTTP/SOAP 上的旧路线。现在工程上基本只用 `opc.tcp`，原因很直接：

```text
二进制编码体积小、解析快，适合高频数据采集
TCP 长连接，适合订阅和周期上报
端口固定 4840，便于网络规划与放行
```

代价是报文不可读，必须靠 Wireshark 这类带 OPC UA dissector 的工具解析。二进制不等于全加密：SecurityMode=None 时，地址空间里的字符串（`opc.tcp://`、节点名 `SetTemperatureLimit`、用户令牌内容）在报文里仍是明文。

![OPC UA 通信分层与安全通道](../_assets/opcua架构.svg)

### 端点 URL 格式

端点的完整写法是一段 URL，拆开看每一段都有含义：

```text
opc.tcp://10.0.12.8:4840/windfarm/offshore/
   |        |      |      |
   |        |      |      +-- 路径（服务端自定义，用于区分同一服务器上的不同应用）
   |        |      +--------- 端口，OPC UA 二进制默认 4840
   |        +---------------- 主机 / IP
   +------------------------- 协议标识，opc.tcp 表示二进制 TCP 承载
```

海上链的实测值（来自维护工作站上的客户端 profile）：

```text
endpoint=opc.tcp://10.0.12.8:4840/windfarm/offshore/
```

注意：路径 `/windfarm/offshore/` 本身就是信息泄露，把"风电场 / 海上"直接写在 URL 上。部署记录中同一服务在平台侧的目标 IP 写作 `10.0.12.10`，本笔记统一采用攻击链实测的 `10.0.12.8`。

## 结构

### 四层建立过程

定义：四个阶段层层依赖，前一层没建好，后一层无从谈起，从"什么都没有"到"能读到温度值"要依次走完。

第一阶段：GetEndpoints（端点发现）

只交换 URL 和最小信息，客户端问服务端"你支持哪些端点"，服务端返回 EndpointDescription 列表，每项包含：

```text
endpointUrl        该端点的实际地址
securityMode       None / Sign / SignAndEncrypt
securityPolicy     加密套件 URI，例如 Basic256Sha256
serverCertificate  服务端证书（SecurityMode=None 时通常为空）
userIdentityTokens 可接受的用户令牌类型：匿名 / 用户名密码 / 证书
```

客户端必须从这份列表里挑一个端点再连接，服务端只提供 None 端点时客户端想加密也无从谈起。

第二阶段：SecureChannel 建立（安全通道）

客户端与服务端协商建立加密通道：先用非对称加密（RSA）完成握手和密钥交换，再用对称加密（AES）保护业务流量，产物是通道 ID 和一对会话密钥。通道之上，客户端身份（应用实例证书）被双方校验，确认"连过来的是哪个应用程序"。

第三阶段：Session 创建与激活（会话）

通道有了，还要有"谁在用"。CreateSession 请求里携带 UserIdentityToken，服务端据此确定用户身份和角色。三种常见令牌：

```text
AnonymousIdentityToken      匿名，不携带凭据
UserNameIdentityToken       用户名 + 密码
X509IdentityToken           客户端证书
```

会话创建后需 ActivateSession 才可使用，会话本身有超时（默认常见 60 分钟），超时后需要重建。

第四阶段：服务调用

会话激活之后，客户端可以反复调用各类服务，业务数据的读写都发生在这里。

### 服务集

OPC UA 把所有能力定义成一组标准服务，工控场景常用的有：

| 服务 | 方向 | 作用 | 靶场对应 |
|---|---|---|---|
| `Browse` | 客户端→服务端 | 浏览地址空间，逐层展开节点 | `browse.py` 发现 Turbine07/08/09 与 Protection 方法 |
| `Read` | 客户端→服务端 | 读取一个或多个 Variable 节点的值 | `read.py --turbine Turbine08` 读回 temperature=73.0 |
| `Write` | 客户端→服务端 | 写入 Variable 节点 | 直接改 `TemperatureLimit`（靶场刻意未开放此路径） |
| `CreateSubscription` + `CreateMonitoredItems` | 客户端→服务端 | 建立订阅、为指定节点登记监控项，数据变化时服务端主动 Publish 上报 | SCADA/HMI 侧采集趋势的常规做法 |
| `Call` | 客户端→服务端 | 调用 Method 节点，带 InputArguments，返回 OutputArguments | `call_method.py` 触发 `SetTemperatureLimit(40)` |
| `GetEndpoints` | 客户端→服务端 | 端点发现 | 每次连接的固定第一步 |
| `CreateSession` / `ActivateSession` | 客户端→服务端 | 会话建立与激活 | 决定用户身份与权限 |

"订阅 + 监控项"和 `Read` 的区别要单独记一下：Read 是客户端主动轮询，订阅是服务端变化即推送。对攻击者来说订阅也是双刃剑：能持续观察温度、阈值、并网状态的实时变化，不必反复发 Read 请求暴露行为。

### SecurityMode 与 SecurityPolicy

这两个概念经常被混淆，要分开看：

| 概念 | 取值 | 含义 |
|---|---|---|
| SecurityMode | `None` | 不做任何消息安全处理，明文收发 |
| SecurityMode | `Sign` | 消息签名，防篡改、可验证来源，但不加密，内容仍可读 |
| SecurityMode | `SignAndEncrypt` | 签名 + 加密，防篡改且防窃听 |
| SecurityPolicy | `None` | 配合 Mode=None 使用，无算法 |
| SecurityPolicy | `Basic128Rsa15` / `Basic256` | 较老的加密套件，已被认为强度不足 |
| SecurityPolicy | `Basic256Sha256` | 目前主流推荐套件 |
| SecurityPolicy | `Aes128_Sha256_RsaOaep` / `Aes256_Sha256_RsaPss` | 新版套件 |

一句话记法：

```text
SecurityMode  = 要不要做（无 / 只签名 / 签名加加密）
SecurityPolicy = 用什么算法做
```

`SecurityMode=None` 的风险是连锁的：

```text
1. 认证机制不生效：证书不被校验，任何人都能建通道
2. 报文可被离线解析：节点名、用户名令牌、读取值全部明文
3. 可被中间人篡改：Call 请求的入参可以被改成任意值
4. 可被重放：没有新鲜度校验，历史请求可原样复用
```

靶场里的海上链就是典型：端点可达、Browse/Read/Call 一路畅通。没有什么加密被破解，只是没有人把安全机制打开。

## 报文/字段对照

四个阶段与实际使用的服务对照：

| 阶段 | 使用服务 | 关键字段 | 靶场观察点 |
|---|---|---|---|
| 端点发现 | GetEndpoints | `endpointUrl`、`securityMode`、`securityPolicy`、`userIdentityTokens` | 是否只提供 None 端点、是否允许匿名 |
| 通道建立 | OpenSecureChannel | 安全策略、证书、Nonce、通道生命周期 | 是否有证书校验 |
| 会话建立 | CreateSession / ActivateSession | `UserIdentityToken`、会话超时 | 是否接受匿名 / 弱口令 |
| 业务调用 | Browse / Read / Write / Call / 订阅 | `NodeId`、`AttributeId`、`InputArguments` | 低权限是否能 Browse 全树、是否能 Call 方法 |

## 实测过程

海上链从维护工作站到 OPC UA 网关的完整动作序列（材料中为逐条 PTY 命令执行与读取）：

```text
1. 读 profile 得到 endpoint
   cat ~/opcua-profiles/offshore-gateway.profile
   -> endpoint=opc.tcp://10.0.12.8:4840/windfarm/offshore/

2. 端点发现 / 连通性确认
   /opt/windfarm/offshore-maint-ws/venv/bin/python ~/opcua-tools/discover.py
   -> CONNECTED opc.tcp://10.0.12.8:4840/windfarm/offshore/
   -> Namespaces: ns=0 / ns=1 / ns=2

3. Browse 资产树
   browse.py -> WindFarm/Offshore/Turbine07|08|09/Protection/SetTemperatureLimit

4. Read 当前值
   read.py --turbine Turbine08 -> temperature=73.0, temperature_limit=95.0

5. Call 方法
   call_method.py --node "ns=2;s=WindFarm.Offshore.Turbine08.Protection.SetTemperatureLimit" --value 40
   -> StatusCode: Good, action = PROTECTION_STOP
```

## 边界约束：网关的只读 HTTP 端口

网关本身还开放了一个只读 HTTP 端口 8080 用于部署验收和状态查看：

```text
GET http://<gateway>:8080/api/health
-> status=ONLINE, protocol=OPC UA, opcua_port=4840
```

部署记录里对这条边界写得很硬：

```text
8080 只用于部署验收、状态查看和后续 HMI 聚合。
该节点不提供 HTTP 控制接口。
温度阈值修改必须通过真实 OPC UA Method Call 完成。
```

靶场刻意把教学重点固定在"真实协议调用"上，不允许用 HTTP 包装接口抄近路。

## 安全视角

- 端点暴露即入口，4840 不应暴露在边界或办公可达网段。海上链的正确设计是攻击机不能直连网关，必须先穿过维护网关和维护工作站，这条链才有边界穿越含义。
- SecurityMode 必须显式配置为 SignAndEncrypt，不要依赖默认值，很多开源服务端默认就是 None；同时把 `SecurityPolicy=None` 从候选列表移除，避免降级协商。
- 匿名令牌应关闭。靶场里 `discover.py` 毫无阻碍地拿到命名空间表，说明连接阶段没有有效身份约束。
- 服务级授权要与角色绑定。能 Browse 不代表能 Call，能 Call `Read` 类方法不代表能 Call 控制类方法；`Call` 服务必须单独审计并做方法级授权。
- 审计 Call 服务。控制类方法调用应记录时间、会话身份、目标 NodeId、入参、返回值，并与业务侧日志（如 Modbus FC06 写寄存器记录）交叉核对；海上链的 `opcua-control.log` 记录 `OPCUA_METHOD_CALL` 与 `PROTECTION_STOP`，这就是审计应有的最小粒度。
- 依据说明：四层建立流程、服务集划分、SecurityMode / SecurityPolicy 定义来自 OPC UA 规范与学习资料；端点、命名空间表、命令工具与调用结果来自海上链实测输出，素材未提供 pcap，本篇不做逐字节报文分析。
