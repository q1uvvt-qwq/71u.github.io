## 一句话概括

这套日志规范定义漏洞专项蜜罐的事件类型、字段结构、命名约定和 Body 留存策略，第一版输出 JSONL，每行一个事件。核心事件是 HTTP 请求采集事件，围绕它记录命中的 Profile、网络信息、请求与响应上下文、匹配依据、行为分类、IOC 摘要和安全控制状态。字段命名统一 snake_case，时间用 ISO 8601，敏感字段保留字段名但值要脱敏。

## 设计目标

日志和 IOC 规范要支撑三个目标：

1. 精准
   每条日志都能关联到命中的漏洞 Profile、产品指纹、路径规则和行为分类。

2. 高仿真
   记录响应模板、响应状态、仿真路径和匹配依据，便于评估仿真是否有效。

3. 流量侧
   完整记录攻击请求、Header、Body、Payload、IOC 和响应上下文，不只记录告警摘要。

## 日志类型

第一版建议输出 JSONL，每行一个事件。

事件类型：

| 事件类型 | 说明 |
| --- | --- |
| http_request | HTTP 请求原始采集事件 |
| profile_match | 请求命中 Profile 的匹配事件 |
| ioc_extracted | IOC 提取事件 |
| alert | 高风险告警事件 |
| analyzer_summary | 分析汇总事件 |
| safety_event | 安全控制事件，例如 Body 超限、限速、出网阻断 |

MVP 阶段可以先只实现：

- `http_request`
- `ioc_extracted`
- `alert`

## 命名规范

字段命名采用 snake_case。

要求：

- 时间字段使用 ISO 8601。
- IP 字段区分 `src_ip`、`dst_ip`。
- 端口字段区分 `src_port`、`dst_port`。
- Hash 字段明确算法，如 `body_sha256`。
- 原文引用使用 `*_ref`，不直接内嵌大对象。
- 敏感字段保留字段名，但值应脱敏。

## HTTP 请求事件结构

### 顶层结构

```json
{
  "event": {},
  "sensor": {},
  "profile": {},
  "network": {},
  "request": {},
  "body": {},
  "response": {},
  "matching": {},
  "classification": {},
  "iocs": {},
  "storage": {},
  "safety": {},
  "pipeline": {}
}
```

### event 字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| event.id | string | 是 | 事件唯一 ID |
| event.type | string | 是 | http_request/profile_match/ioc_extracted/alert |
| event.ts | string | 是 | 事件时间 |
| event.schema_version | string | 是 | 日志 Schema 版本 |
| event.severity | string | 否 | info/low/medium/high/critical |

### sensor 字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| sensor.id | string | 是 | Sensor ID |
| sensor.name | string | 否 | Sensor 名称 |
| sensor.env | string | 否 | local/lab/dmz/cloud |
| sensor.region | string | 否 | 部署区域 |
| sensor.version | string | 否 | Sensor 版本 |

### profile 字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| profile.id | string | 是 | 命中的 Profile ID |
| profile.name | string | 否 | Profile 名称 |
| profile.version | string | 否 | Profile 版本 |
| profile.family | string | 否 | web-rce/file-read/command-injection 等 |
| profile.severity | string | 否 | Profile 风险等级 |

如果请求未命中具体 Profile，`profile.id` 可为 `unknown`，但必须保留。

### network 字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| network.src_ip | string | 是 | 来源 IP |
| network.src_port | int | 否 | 来源端口 |
| network.dst_ip | string | 否 | 目标 IP |
| network.dst_port | int | 是 | 目标端口 |
| network.protocol | string | 是 | http/https |
| network.tls | bool | 否 | 是否 TLS |
| network.forwarded_for | string/list | 否 | X-Forwarded-For |

注意：

- 如果部署在反向代理后，必须记录真实来源字段和代理字段。
- 不应盲目信任 X-Forwarded-For，只作为参考。

### request 字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| request.method | string | 是 | GET/POST/PUT 等 |
| request.path | string | 是 | URL Path |
| request.query | string/map | 否 | Query |
| request.full_url | string | 否 | 完整 URL |
| request.http_version | string | 否 | HTTP 版本 |
| request.headers | map | 是 | Header，敏感字段脱敏 |
| request.cookies_present | bool | 否 | 是否存在 Cookie |
| request.user_agent | string | 否 | User-Agent |
| request.content_type | string | 否 | Content-Type |
| request.content_length | int | 否 | Content-Length |

### body 字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| body.present | bool | 是 | 是否存在 Body |
| body.size | int | 是 | Body 字节数 |
| body.sha256 | string | 否 | Body SHA256 |
| body.preview | string | 否 | 截断预览 |
| body.preview_truncated | bool | 否 | Preview 是否截断 |
| body.raw_ref | string | 否 | 原始 Body 存储引用 |
| body.encoding_hint | string | 否 | 编码提示 |
| body.redacted | bool | 否 | 是否脱敏 |
| body.redaction_rules | list[string] | 否 | 命中的脱敏规则 |

Body 留存原则：

```text
Hash 必存
Preview 默认存
Raw Body 按 Profile 策略受控保存
超限 Body 只保存元数据和截断 Preview
敏感字段必须脱敏或标记
```

### response 字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| response.status | int | 是 | HTTP 状态码 |
| response.template_id | string | 否 | 响应模板 ID |
| response.headers | map | 否 | 响应 Header |
| response.body_size | int | 否 | 响应体大小 |
| response.delay_ms | int | 否 | 响应耗时 |

该字段用于后续评估高仿真效果。

### matching 字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| matching.profile_hit | bool | 是 | 是否命中 Profile |
| matching.route_id | string | 否 | 命中的路由 ID |
| matching.rules | list[string] | 否 | 命中的匹配规则 |
| matching.indicators | list[string] | 否 | 命中的特征 |
| matching.confidence | string | 否 | low/medium/high |

示例：

```json
"matching": {
  "profile_hit": true,
  "route_id": "catch_post",
  "rules": ["path_prefix", "body_keyword"],
  "indicators": ["external_url", "command_keyword"],
  "confidence": "high"
}
```

### classification 字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| classification.category | string | 是 | scan/fingerprinting/suspected_exploit 等 |
| classification.risk_score | int | 是 | 0-100 |
| classification.risk_level | string | 是 | low/medium/high/critical |
| classification.reasons | list[string] | 否 | 分类依据 |
| classification.attack_stage | string | 否 | scan/probe/exploit/download/callback |

分类枚举：

- scan
- fingerprinting
- credential_attempt
- suspected_exploit
- command_injection
- file_read
- download
- callback
- post_exploitation
- noise

### iocs 字段

日志事件中可内嵌 IOC 摘要：

```json
"iocs": {
  "ips": [],
  "domains": [],
  "urls": [],
  "emails": [],
  "user_agents": [],
  "file_names": [],
  "file_hashes": [],
  "base64_candidates": [],
  "commands": [],
  "callback_hints": []
}
```

注意：

- 事件内 IOC 是摘要。
- 规范化后的 IOC 应单独输出到 IOC 文件或 IOC 事件。

### safety 字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| safety.body_limited | bool | 否 | Body 是否超限 |
| safety.rate_limited | bool | 否 | 是否触发限速 |
| safety.raw_body_saved | bool | 否 | 是否保存原始 Body |
| safety.egress_attempt_blocked | bool | 否 | 是否阻断出网尝试 |
| safety.redaction_applied | bool | 否 | 是否做脱敏 |

### pipeline 字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| pipeline.collector_version | string | 否 | Collector 版本 |
| pipeline.analyzer_version | string | 否 | Analyzer 版本 |
| pipeline.processing_status | string | 是 | collected/analyzed/error |
| pipeline.error | string | 否 | 错误信息 |

## 素材中的不确定处

- matching 字段的示例里 `rules` 取值为 `["path_prefix", "body_keyword"]`，完整 HTTP 事件示例里同一字段写成 `["path", "body_keyword"]`。两处未统一，复现时以完整示例为准。
