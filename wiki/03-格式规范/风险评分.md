## 一句话概括

风险评分把请求行为折算成 0 到 100 的分数，再映射到 low、medium、high、critical 四个等级。分数由命中的特征加分，也可能因为本地测试源、白名单 User-Agent、健康检查路径等条件降分。白名单要谨慎使用，命中记录仍要保留。

## 风险评分

### 风险分数

| 分数 | 等级 | 含义 |
| --- | --- | --- |
| 0-29 | low | 噪声或低风险探测 |
| 30-59 | medium | 可疑探测或弱利用迹象 |
| 60-79 | high | 疑似利用或明显恶意 Payload |
| 80-100 | critical | 高置信利用、下载、回连或后渗透迹象 |

### 加分规则

| 条件 | 分数 |
| --- | --- |
| 命中特定 Profile 路径 | +20 |
| 命中特定 Header 或参数 | +20 |
| Body 中出现命令关键词 | +20 |
| 出现外部 URL/域名 | +15 |
| 出现 Base64 候选 | +10 |
| 出现下载工具关键词 | +15 |
| 出现回连线索 | +20 |
| 同一来源高频访问多个漏洞 Profile | +10 |

### 降分规则

| 条件 | 分数 |
| --- | --- |
| 明确为本地测试源 | -20 |
| 命中白名单 User-Agent | -10 |
| 无 Body 且只访问首页 | -10 |
| 明确为健康检查路径 | -20 |

白名单必须谨慎使用，并且保留匹配记录。
