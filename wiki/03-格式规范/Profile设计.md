## 一句话概括

CVE Profile 是漏洞专项蜜罐的核心配置单元，用来描述面向哪个漏洞或漏洞家族、模拟哪个产品外观、暴露哪些路径与响应、采集哪些请求字段、如何识别扫描利用行为并提取 IOC。它不是漏洞利用代码，而是"漏洞仿真、流量采集和分析规则"的声明式配置。这套设计规范给出 Profile 的设计原则、生命周期和状态流转，使"新漏洞情报 -> 高仿真蜜罐 -> 流量采集 -> IOC/规则输出"的过程可解释、可审核、可复用。适用范围是 Web/HTTP 类漏洞专项蜜罐，传统 SSH/Telnet/数据库协议蜜罐不作为第一版重点。

## 定义

CVE Profile 是漏洞专项蜜罐的核心配置单元。

它用于描述：

- 这个 Profile 面向哪个漏洞或漏洞家族。
- 要模拟哪个产品、框架或应用外观。
- 要暴露哪些路径、Header、响应和错误页。
- 要采集哪些请求字段和 Body。
- 如何识别扫描、探测、疑似利用、下载、回连等行为。
- 如何提取 IOC。
- 如何在不执行真实 Payload 的前提下完成高仿真响应。

一句话：

> CVE Profile 不是漏洞利用代码，而是"漏洞仿真、流量采集和分析规则"的声明式配置。

## 设计原则

### 安全优先

Profile 不允许包含任何会执行攻击者输入的逻辑。

禁止：

- 执行 Shell 命令。
- 访问攻击者提供的 URL。
- 加载真实脆弱组件。
- 将请求内容传入模板引擎、反序列化器或真实框架解析链。
- 在 Profile 中嵌入动态脚本执行逻辑。

### 可解释

Profile 的每个关键字段都应能解释来源：

- 来自官方公告。
- 来自 NVD/CVE。
- 来自 Nuclei 模板。
- 来自 PoC 分析。
- 来自 IDS/WAF 规则。
- 来自威胁情报报告。
- 来自竞品/开源项目设计经验。

不允许出现无法解释来源的关键仿真字段。

### 可审核

Profile 必须支持人工审核。

需要审核：

- 漏洞范围是否准确。
- 仿真路径是否合理。
- 响应模板是否过于明显或过于真实。
- 采集策略是否可能保存敏感信息。
- IOC 提取规则是否容易误报。
- 安全控制是否完整。

### 可复用

同类漏洞应尽量复用基础模板。

例如：

- Next.js/React 类 Web 框架 Profile。
- Java Web RCE 类 Profile。
- 企业应用 RCE 类 Profile。
- 文件读取类 Profile。
- 命令注入类 Profile。

### 低交互高仿真

Profile 的目标是：

```text
外观和响应尽量像真系统
执行逻辑尽量低风险
```

也就是：

- 仿真路径、Header、状态码、错误页、静态资源。
- 采集完整攻击请求。
- 不执行真实漏洞。
- 不做真实后端业务处理。

## 生命周期

### Profile 生成流程

```text
漏洞资料收集
  -> 仿真要素提取
  -> Profile 草稿
  -> Schema 校验
  -> 安全校验
  -> 人工审核
  -> 测试请求验证
  -> 发布启用
  -> 日志反馈
  -> Profile 更新
```

### 状态机

| 状态 | 含义 |
| --- | --- |
| draft | 草稿，未完成校验 |
| review | 待人工审核 |
| testing | 测试中 |
| active | 可启用 |
| deprecated | 已过期，不建议新部署 |
| disabled | 禁用 |
| rejected | 审核不通过 |
