## 一句话概括

词表剪枝是在保留判别能力的前提下砍掉长尾 token，目的是压小 embedding 表、降低参数量、减少稀疏 token 带来的噪声。难点不在砍，在于怎么给每个 token 打一个"它到底有没有用"的分。

## 为什么要给四个基线都跑一遍

正式实验至少要有四个版本对照：

- Baseline A：full vocab
- Baseline B：frequency prune
- Baseline C：random prune
- Baseline D：distinguishability Top-K prune

只交付 Top-K 版本，看不出收益是从哪来的。清洗规则改了、词表砍了、模型换了，三个变量混在一轮里，分数变好也不知道该归功给谁。四组对照的作用是把"剪枝有没有用"和"剪枝是不是还不如随便砍"这两个问题分开。

random prune 这一组容易被当成凑数的。它的价值在于给出下界：如果按可区分度剪枝的效果和随机剪枝差不多，那说明选出来的 token 并不比随便挑的 token 更有判别力，整套打分方法就没有成立。

## 统计单位与样本

默认统计单位是 sequence window，不是单条消息、也不是单个 token 出现次数。

对每个 token 定义：

```text
z_w = 1{w appears in sequence}
y   = train_label
```

`z_w` 是二值的，只问"这个 token 在这个窗口里出现过吗"，不问出现几次。理由是窗口内重复出现的次数受窗口长度和切分方式影响，而"出现过"这个信号更稳。

只用训练集里有标签的样本。没有标签的样本进不了监督统计，用测试集的标签算分数等于把答案写进了词表。

## 三个分数

```text
IG(w)    = H(Y) - H(Y | z_w)
logOR(w) = log( (p1/(1-p1)) / (p0/(1-p0)) )
TFDiff(w)= |tf_pos(w) - tf_neg(w)| * log(N / df(w))
```

其中 `p1 = P(z_w=1 | y=1)`、`p0 = P(z_w=1 | y=0)`。

信息增益：`H(Y)` 是标签本身的熵，`H(Y | z_w)` 是知道这个 token 出没出现之后标签还剩多少不确定性。两者之差就是"知道这个 token 能减少多少关于标签的不确定性"。它的好处是有明确的信息论含义，缺点是偏向取值多的特征；这里 `z_w` 是二值的，所以这个偏差不存在。

优势比：`p1/(1-p1)` 是异常样本里这个 token 出现的几率，`p0/(1-p0)` 是正常样本里的几率，两者相除再取对数。它衡量的是"这个 token 把异常和正常拉开多少倍"。取对数是因为比值可以趋近 0 或无穷，取对数后分布更对称。它的陷阱是低支持 token 会给出极端值：某个 token 在训练集里只出现过几次且全在异常窗口，`p1` 会接近 1、`p0` 接近 0，logOR 数值漂亮但毫无统计意义。这正是要单列支持度约束的原因。

TFDiff 是三项里最接近 TF-IDF 直觉的。`|tf_pos - tf_neg|` 是同一个 token 在正负两侧词频之差的绝对值，`log(N / df(w))` 是 IDF 项。IDF 在这里惩罚的是"到处都是"的 token：不管哪个窗口都有它，`df(w)` 接近 N，`log(N/df(w))` 接近 0，整项被压没。反过来一个只在一部分窗口出现的 token，IDF 项会把它抬起来。文档频率低的 token 才有区分价值，这是 IDF 在文本检索里的一贯含义，放到异常检测上依然成立。

三项合成：

```text
score(w) = 0.5 * z(IG) + 0.3 * z(|logOR|) + 0.2 * z(TFDiff)
```

`z()` 是分区内归一化，因为三项量纲不同：IG 是比特，logOR 是对数几率，TFDiff 是词频差乘对数。不归一化就直接加权，权重会被量纲大的那项吃掉。`|logOR|` 取绝对值是因为区分度关心的是偏离程度，一个 token 只出现在正常窗口里同样有判别力，只是方向相反。

所有权重的比例项都必须做 Laplace smoothing。分子加一、分母加二，避免某个格子的计数为零导致比值为 0 或未定义。这是计数类比例的标准做法，代价是低支持 token 的估计被拉向 0.5，恰好也抑制了上面说的极端值问题。

## 支持度约束

高区分度不等于高覆盖率。一个 token 分数再高，如果它只在三个窗口里出现过，砍掉它的损失很小，留下它的收益也很小，但它对统计量的扰动很大。每个 token 必须记录：

- `tf_pos` / `tf_neg`：正负样本中的词频
- `df_pos` / `df_neg` / `df_total`：正负样本中出现的窗口数
- `coverage`：覆盖的窗口比例
- `score` / `rank` / `kept`

配套的硬约束是：低支持 token 不得只凭极端 OR 进入主词表。最小支持度阈值由训练集与验证集确定，并写入 manifest 留档。

## K 值与质量门槛

候选配置：

```text
full vocab / 50% / 25% / 10%
K = 50, 150, 300, 750, 1500, 3000
```

只运行不超过完整词表大小的配置。主线初始建议取中间档。不得根据测试集指标选 K，理由和划分那一节一样：用测试集挑超参数，测试集就不再是留出集。

剪枝质量用 UNK 率验收：

- train `unk_ratio <= 0.30`
- validation / test `unk_ratio <= 0.40`
- positive-window `unk_ratio <= 0.50`
- special token ID 不变

UNK 率是剪枝最直接的副作用指标。词表砍得太狠，正文里大量 token 落进 `[UNK]`，模型看到的不再是内容而是一串占位符。三档门槛里正样本窗口的门槛最宽松，因为异常窗口本身就更可能包含罕见 token，对它要求同样的 UNK 率等于逼着词表保留长尾。

若小 K 超过门槛，回退到更大的一档，把词表放大再验一次。
