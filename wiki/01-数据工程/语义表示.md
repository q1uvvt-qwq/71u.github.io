## 一句话概括

语义表示要把一条标准事件转成模型能吃的文本或 token，同时保住区分正常与异常所需的那些细节。它夹在两个方向中间：表示得越具体，信息保留越多，但词表越膨胀、泛化越差；表示得越抽象，词表越小，但攻击特征可能被一起抽象掉。

## 模板化与 parser-free 的分岔

定义：日志模板解析指把日志按词位置比对和变量槽聚类，抽出一条模板（例如"用户 X 从 IP Y 登录"），再用模板 ID 代替原文。

模板化在系统日志上很有效。系统日志由固定格式串产出，同一条打印语句生成的文本只在少数槽位上变化，聚类后模板数量远小于日志条数，序列建模也简单。Drain、Spell 这类解析器就是按这个假设工作的：先按 token 数量分组，再在组内按位置比对，位置一致的 token 当作模板骨架，位置不同的当作变量槽。

这套假设在 EDR 日志上不成立。主机行为日志不是固定格式串的产物，命令行、路径、哈希、IP 全是自由文本，而模板化想丢掉的变量槽，恰好就是判断异常的凭据。一条"powershell 启动"的模板对异常检测几乎没有信息量，信号全在它后面跟的那串编码参数里。

所以面向主机日志的表示方案里，不用传统模板 ID 代替完整消息是一条基本原则。裁剪也不得把整条消息退化成单一模板 ID。

## canonical_message

canonical_message 是供 parser-free message encoder 使用的规范文本，它把变量替换成语义类别，同时保留句法骨架。

七条原则：

- 保留事件动作
- 保留主体和对象类别
- 保留安全相关变量语义
- 同语义生成同文本
- 不包含标签、split、异常分数
- 不使用传统模板 ID 代替完整消息
- 截断时保留 [TRUNCATED]

推荐格式是 `<subject> <action> <object> <semantic_attributes>`。几个例子：

```text
powershell.exe process_create child=cmd.exe parent=office_process flags=HAS_ENCODED_FLAG
powershell.exe network_connect destination=IP_PUBLIC port=PORT_OTHER
powershell.exe file_write path=PATH_USER_TEMP type=FILE_EXECUTABLE
registry_modify key=REG_RUNKEY process=powershell.exe
```

"同语义生成同文本"是缓存和统计的前提。同样的行为每次生成不同文本，缓存键命中率会掉到零，token 频率统计也会被同义变体摊薄。

"不包含标签、split、异常分数"这一条的用意更直接。canonical_message 是模型输入，标签进去就是标签泄漏，split 进去模型能直接看出这条样本属于哪个集合，异常分数进去等于自己给自己打分。

截断有五步：先删低价值冗余字段，再做字符或 token 截断，保留头部和尾部，加 `[TRUNCATED]` 标记，最后报告截断率和被截断字段分布。保留尾部是专门为命令行设计的，下载地址和编码载荷往往在命令末尾，只留头部会把最关键的一段切掉。

## 类别化与打码的区别

变量替换有两种做法。一种是把变量打成无差别的占位符，IP 就是 `[IP]`，路径就是 `[PATH]`；另一种是把变量归类，IP 分成内网、公网、回环，路径分成系统、用户临时、下载目录。

可行的做法是后者。把所有路径统一替换为 `[PATH]`、把全部参数替换成 `[ARGS]` 这类打码方式要避免。

成因：打码把"这个值是什么"压缩成了"这里有一个值"，所有 IP 塌缩成一个符号。归类只压缩取值空间，不压缩语义维度。powershell 连内网和连公网，打码之后文本完全相同；归类之后一个是 NET_CONNECT_INTERNAL_*，一个是 NET_CONNECT_EXTERNAL_*，模型一眼能分开。攻击行为大量体现为"不该出现的类别组合"，比如办公进程连公网、系统目录里落地可执行文件，这些区分只有在类别还保留时才存在。

几个常用的类别表：

- IP：IP_PRIVATE、IP_PUBLIC、IP_LOOPBACK、IP_LINK_LOCAL、IP_MULTICAST、IP_INVALID
- 端口：PORT_WEB、PORT_DNS、PORT_MAIL、PORT_SMB、PORT_RDP、PORT_DATABASE、PORT_EPHEMERAL、PORT_OTHER、PORT_INVALID
- 域名：DOMAIN_INTERNAL、DOMAIN_PUBLIC、DOMAIN_ALLOWLISTED、DOMAIN_UNKNOWN、DOMAIN_INVALID
- 路径：PATH_SYSTEM、PATH_PROGRAM_FILES、PATH_USER_PROFILE、PATH_USER_TEMP、PATH_DOWNLOADS、PATH_STARTUP、PATH_NETWORK_SHARE、PATH_OTHER
- 注册表：REG_RUNKEY、REG_SERVICE、REG_SECURITY_POLICY、REG_FIREWALL、REG_STARTUP、REG_CREDENTIAL、REG_OTHER

端口表里 PORT_EPHEMERAL 单列一格，因为高频临时端口本身是扫描或批量外联的迹象。PATH_STARTUP 和 REG_RUNKEY 单列，因为它们是持久化落点。REG_CREDENTIAL 单列，因为它直接对应凭据访问。

分类粒度由两个约束夹出来。类别太粗（所有 IP 归一类），区分度丢失；类别太细（每个 IP 一个类别），词表爆炸、泛化丧失，新出现的 IP 会全部落到未知。这套表里的类别数都在个位到十几之间，是按安全含义切的，不是按取值的自然分布切的。

## 进程与命令行字段

进程至少提取八个字段：name、path、cmdline、normalized_name、category、parent_category、cmd_flags、tree_depth。前三个是原始信息，后五个是规范值。

高价值 basename 单独保留：powershell.exe、cmd.exe、rundll32.exe、regsvr32.exe、wmic.exe、mshta.exe、python.exe、bash、sh。这份名单的共同点是它们都能被当作执行落脚点，保留原名比归成 SCRIPT_PROCESS 更有信息量。

长尾进程不给单一未知值，而是分类：UNKNOWN_SIGNED_EXE、UNKNOWN_UNSIGNED_EXE、UNKNOWN_SCRIPT、UNKNOWN_BINARY、UNKNOWN_PROC。签名与否本身带安全含义，未签名可执行文件比签名文件更值得关注，把这层区分丢进一个 UNKNOWN 就少了一个特征。

命令行的规范字段是一组布尔和分档：

- HAS_ENCODED_FLAG：带编码参数
- HAS_HIDDEN_FLAG：带隐藏窗口参数
- HAS_BYPASS_FLAG：带绕过执行策略参数
- HAS_DOWNLOAD_PATTERN：带下载模式
- HAS_URL、HAS_IP_LITERAL：带 URL 或 IP 字面量
- ARG_LENGTH_SHORT / MEDIUM / LONG / VERY_LONG：参数长度档
- BASE64_LOW / MEDIUM / HIGH：base64 内容占比档
- SCRIPT_TYPE：脚本类型

这组字段把"命令行里有没有可疑成分"从自由文本变成可枚举特征。原始命令行仍然完整保留在 raw 里，规范字段只是它的一份索引。

## point-in-time 正确性

first_seen / seen_before 这类特征不能看未来。

成因：这类特征算的是"这个值在历史上出现过没有"。如果统计口径包含了事件发生之后的记录，那么在攻击当天生成样本时，模型已经知道这个恶意域名第二天还会再出现。训练指标会很好看，上线后第一时间失效，因为真实环境里没有未来数据。

正确做法是只基于事件发生前的历史构建。这也解释了为什么 first_seen 类历史特征被列进"只能在训练集上拟合"的清单。它的约束范围不只在数据集维度上，还有时间维度上的前缀性质：对第 t 条事件，只能看 t 之前的部分。

## structured_token

structured_token 是轻量 token-id 模型和词表剪枝实验的主输入，必须从标准事件生成，不得从原始 JSON 生成。从标准事件生成，token 才和类别表绑定；从原始 JSON 生成，等于把字段名和格式差异重新引回来。

四类命名规则：

- 进程：`PROC_{ACTION}_{PROC_CATEGORY}_FROM_{PARENT_CATEGORY}_{FLAGS}`，例如 PROC_CREATE_POWERSHELL_FROM_OFFICE_ENCODED_COMMAND、PROC_CREATE_CMD_FROM_OFFICE、PROC_CREATE_WMI_FROM_SYSTEM_SERVICE
- 网络：`NET_{ACTION}_{DST_SCOPE}_{PORT_CATEGORY}`，DNS 走 `NET_DNS_{DOMAIN_CATEGORY}`，例如 NET_CONNECT_EXTERNAL_HTTPS、NET_CONNECT_EXTERNAL_HIGHPORT、NET_CONNECT_INTERNAL_SMB、NET_DNS_UNKNOWN_DOMAIN
- 文件：`FILE_{ACTION}_{PATH_CATEGORY}_{EXT_CATEGORY}`，例如 FILE_ACCESS_DOWNLOADS_EXE、FILE_WRITE_TEMP_PS1、FILE_CREATE_STARTUP_LNK
- 注册表：`REG_{ACTION}_{KEY_CATEGORY}_{HIVE}`，例如 REG_SET_VALUE_RUNKEY_HKCU、REG_CREATE_KEY_SERVICE_HKLM

命名规则本身就是特征工程。它决定了哪几个维度会被组合成一个符号。`FROM_{PARENT}` 把父子进程关系编码进去，检测 office 派生 powershell 这类异常时是关键；`_{FLAGS}` 把编码标志编码进去，让"powershell 起 cmd"和"powershell 编码起 cmd"变成两个不同的 token。

代价是组合数。每个维度取值相乘就是 token 数量上限，实际词表被高频组合占住，长尾组合落到 [UNK]。这也是词表需要按规模做取舍的直接原因。

## special token 的固定 ID

special token 的 ID 必须固定：

| token | id | 用途 |
| --- | --- | --- |
| [PAD] | 0 | padding |
| [CLS] | 1 | sequence start |
| [SEP] | 2 | sequence/group separator |
| [UNK] | 3 | 默认 unknown / pruned token |
| [MASK] | 4 | masked-message/token training |

扩展 unknown token 从 5 之后分配，例如 [UNK_PROCESS]、[UNK_PATH]、[UNK_IP]、[UNK_DOMAIN]、[UNK_REGISTRY]、[UNK_ARGUMENT]、[TRUNCATED]、[MISSING_FIELD]。主线的默认行为是 drop token 映射成 [UNK]，typed unknown 留作后续消融。

固定 ID 的理由是跨版本兼容。模型的嵌入层第 k 行对应第 k 个 token，[PAD]=0 这个约定被写进了 padding 逻辑、attention mask 逻辑和导出后的 ONNX 图。任何一处改动，旧权重就对不上新数据，而且多半不会报错，只会静默算错。
