## 一句话概括

S7comm 是西门子 S7 系列 PLC 的通信协议，运行在 ISO-on-TCP（TPKT/COTP）之上，用来读写 PLC 的 DB 块、M 区、I/Q 区，也能查询和控制 CPU 运行状态。它原生缺少强认证，所以"谁能连上，谁就几乎能做任何事"。

## 原理

### S7 与 S7comm 的定位

依据学习方案的材料：

```text
1. S7 是西门子体系协议，很多细节具有厂商专有属性。
2. 学习工程站、PLC、DB 块、读写变量、PLC 状态等概念。
3. 不同 PLC 型号和固件安全机制差异很大。
```

公开学习资料（素材指定）：

```text
Wireshark S7comm wiki
https://wiki.wireshark.org/S7comm
```

S7 在真实场景里的位置：

```text
如果公司后续使用西门子 PLC、博图、PLCSIM 或现成 PLC 仿真，可加入 S7 方向。
```

S7comm 是"厂商专有协议"这一类里最有代表性的一种：不像 Modbus 那样公开简洁，也不像 OPC UA 那样自带安全模型，它的很多行为由型号和固件决定。

### PDU 结构概览

S7comm 报文是分层的，从上到下依次是（依据 Wireshark S7comm wiki 与通用协议知识整理，非实测抓包）：

```text
┌─────────────────────────────┐
│ TPKT 头（ISO-on-TCP 传输层） │  版本、长度
├─────────────────────────────┤
│ COTP 头（连接控制）          │  CR/CC/DT 等 PDU 类型、TSAP
├─────────────────────────────┤
│ S7 header                   │  协议 ID、ROSCTR、PDU 参考、参数/数据长度
├─────────────────────────────┤
│ 参数区 Parameter             │  功能码、区域、地址、长度等
├─────────────────────────────┤
│ 数据区 Data                  │  实际读写的字节内容
└─────────────────────────────┘
```

各层作用：

```text
TPKT    给出整包长度，解决 TCP 流的分包问题
COTP    建立/维护连接，标识 Rack/Slot 对应的 TSAP
S7 header 说明这一包是"请求(Job)"还是"响应(Ack)"，以及功能类型
参数区  描述"读哪里、读多少、什么类型"
数据区  承载真正的字节内容
```

### 读写交互：Job / Ack

S7comm 是典型的请求-响应模型：

```text
主站（工程师站 / 上位机）        PLC
        Job（请求）        ->
                          <-   Ack（响应，含数据或返回码）
```

- 一次读操作：Job 携带"要读的区域 + 起始地址 + 长度"，Ack 携带数据。
- 一次写操作：Job 携带"要写的区域 + 地址 + 数据"，Ack 只返回执行结果。

### Rack / Slot 概念

Rack（机架）和 Slot（槽位）用来定位背板上的具体 CPU 模块，上位机组态时必须指定，COTP 连接建立阶段会体现出来。连错 Rack/Slot 会连不上或连到别的模块，这也是"连接超时"类排错的常见原因之一。

## 报文/字段对照

### 存储区域

S7 的变量按区域组织，S7comm 的读写请求里要指明区域：

| 区域 | 名称 | 典型用途 | 读写 |
|---|---|---|---|
| DB | Data Block 数据块 | 工艺参数、配方、状态字 | 可读可写 |
| M | Merker 标志位/位存储器 | 内部中间变量、软元件 | 可读可写 |
| I | Input 输入过程映像 | 现场输入 | 只读 |
| Q | Output 输出过程映像 | 现场输出 | 可读可写 |
| T / C | 定时器 / 计数器 | 逻辑控制 | 可读可写 |

### 符号表与变量表

工程师在博图（TIA Portal）里给变量起符号名，下载到 PLC 后，上位机可以通过符号名访问，也可以直接按绝对地址访问：

```text
符号名：   Turbine1.RunCommand
绝对地址： %DB10.DBX0.0      或   DB10.DBD0
```

符号表/变量表是理解 PLC 程序语义的钥匙：知道 DB10.DBD0 是"启停命令"还是"风速"，才知道该不该写、写什么值。

## 安全视角

以下为原理性讲解，用于理解风险与防护，不提供可复用操作步骤。

### 背景：西门子 PLC 型号差异

不同代际的 PLC 在通信与安全能力上差别很大（这部分为通用产品知识，素材只给出"型号/固件差异大"的定性结论）：

| 型号 | 代际 | 典型通信方式 | 安全能力概况 |
|---|---|---|---|
| S7-300 | 较老 | S7comm over ISO-on-TCP | 几乎无内置安全，无认证 |
| S7-400 | 较老 | S7comm over ISO-on-TCP | 同上，偏过程控制大型应用 |
| S7-1200 | 较新 | S7comm / S7comm-plus，支持 OPC UA（新固件） | 有访问级别、有保护密码概念 |
| S7-1500 | 较新 | S7comm-plus，支持 OPC UA | 访问级别更细、可设保护级别 |

注意：老型号默认无保护，新型号有"访问级别/保护"机制，但需要工程师正确配置并启用。素材中"不同型号和固件安全机制差异很大"说的就是这件事，下面几条风险在这条背景下看更清楚。

### 1. 原生缺少认证

S7comm（尤其老型号）不校验"你是谁"。只要网络可达、知道 Rack/Slot，就能建立会话并读写变量。这与 Modbus"原生没有认证和加密"是同一类问题。

### 2. 可读写任意 DB

协议层面不区分"这个 DB 是工艺参数、那个 DB 是安全联锁"，一次写操作可以落到任意 DB 的任意字节。防护必须在 PLC 侧用访问级别（新型号）、网络侧用防火墙白名单来补。

### 3. 可控制 CPU 运行状态（CPU STOP）

S7 协议支持查询和控制 CPU 的运行状态（RUN / STOP）。真实世界里这是重大风险：把 CPU 打到 STOP 意味着过程控制中断，可能造成设备损坏、生产事故，甚至人身安全后果。

原理性说明（不提供操作步骤）：

```text
协议中存在"改变 CPU 运行状态"这类功能码。
一旦被未授权使用，后果是整台 PLC 停止执行程序。
因此真实生产环境中，这类能力必须靠网络隔离、
PLC 保护级别、工程站专线接入等手段严格管控。
```

本笔记库中这类能力只作原理讲解，用于说明"为什么生产控制网不能和管理网平铺互通"（对应 NIST SP 800-82、ISA/IEC 62443 的分区分域思想）。

### 4. 工程包（博图项目）泄露的价值

依据学习方案，S7 方向的靶场化重点之一是"工程包泄露"：

```text
工程包泄露；
DB 块变量映射；
工程站凭据或项目文件误配置；
PLC 状态控制的仿真教学。
```

一个博图项目文件（含符号表、DB 定义、硬件组态）泄露后，攻击者可以：

```text
1. 知道每个 DB / M 地址对应的业务含义（变量映射）。
2. 知道 Rack/Slot、PLC 型号、固件版本。
3. 可能从项目文件里找到工程站凭据或连接配置。
4. 据此把"某地址 = 某控制功能"落到具体字节，而不是盲写。
```

这与 Modbus 靶场里"先拿点表再写寄存器"同一思路：没有点表/工程包只能猜地址，有了工程包，攻击面立刻清晰。

### 5. 防护落点

```text
网络层：S7 通信只允许工程师站/SCADA 所在网段访问，工业防火墙做白名单。
设备层：启用 S7-1200/1500 的访问级别与保护密码，限制写操作与运行状态控制。
工程层：博图项目文件、符号表按机密资料管理，禁止随意外发或存放在共享目录。
审计层：记录工程站的组态下载、变量写操作与 CPU 状态变更。
```
