## 一句话概括

魔术方法是**预先定义好、在特定时机自动触发**的方法（都以 `__` 开头）。反序列化漏洞之所以「不用攻击者手动调用任何方法」就能打通，靠的就是 **`unserialize()` 自己会触发 `__wakeup()` / `__unserialize()`，以及脚本结束时会触发 `__destruct()`**。

## 原理

### 1. 魔术方法总表（含触发时机）

| 魔术方法 | 触发时机 | 参数 | 在反序列化里的角色 |
|---|---|---|---|
| `__construct()` | `new 类名(...)` **实例化**对象时 | 有 | **反序列化不触发**；只在正常实例化时跑 |
| `__destruct()` | 对象的**所有引用被删除** / 被显式销毁 / 脚本结束时 | 无 | 链的**最常用自动入口**（脚本一定会结束） |
| `__wakeup()` | `unserialize()` 还原属性**之后**、返回对象**之前** | 无 | 常被塞进「检查逻辑」，因此是**绕过目标** |
| `__unserialize($data)` | **PHP 7.4+** 反序列化时调用，**优先级高于 `__wakeup`** | 有 | 一旦定义，`__wakeup()` 永久不再执行 |
| `__sleep()` | `serialize()` 执行**之前** | 无 | 返回「要参与序列化的属性名」数组 |
| `__toString()` | 对象被**当作字符串**使用（`echo`、`.` 拼接、`(string)`） | 无 | 链中把「对象」降级成「字符串」，用于接入字符串上下文 |
| `__invoke()` | 对象被**当作函数调用**（`$obj()`）时 | 有 | 链中的「可调用」环节 |
| `__call($name, $args)` | 调用一个**不存在 / 不可访问**的方法时 | 有 | SoapClient 的「发射点」（见 09 篇） |
| `__callStatic($name, $args)` | 以静态方式调用不存在的方法时 | 有 | `__call` 的静态版 |
| `__get($name)` | 读取**不存在 / 不可访问**的属性时 | 有 | 「读属性」被拦截时触发 |
| `__set($name, $value)` | 给**不存在 / 不可访问**的属性赋值时 | 有 | 「写属性」被拦截时触发 |
| `__isset($name)` / `__unset($name)` | 对不可访问属性 `isset()` / `unset()` 时 | 有 | 较冷门，审计时别漏 |
| `__clone()` | `clone $obj` 时 | 无 | 复制对象时触发 |
| `__debugInfo()` | `var_dump($obj)` 时 | 无 | 只影响调试输出 |

> **做题时最该先看的三行**：`__destruct()`（一定会跑）、`__wakeup()`（反序列化就跑）、`__toString()` / `__invoke()` / `__call()`（把链接起来的转接点）。

### 2. `__construct()`：实例化时触发，且只触发一次

```php
<?php
class User {
    public $username;
    public function __construct($username) {
        $this->username = $username;
        echo "触发了构造函数1次";
    }
}

$test = new User("benben");   // 这里触发一次
$ser  = serialize($test);     // 序列化不触发
unserialize($ser);            // 反序列化也不触发
?>
```

输出只有一句「触发了构造函数1次」。两个结论：

- **实例化时触发一次**，不会重复；
- **对象不是 `User` 时，构造函数根本不参与**（`unserialize` 时连类名都可能换成别的）。

> 这就是为什么在很多 payload 里，构造函数写的 `$this->x = new SomeClass();` 是**完全没用**的 —— 反序列化路径上它不执行，属性值只认 payload 里写的。

### 3. `__destruct()`：对象销毁时触发

```php
<?php
class User {
    public function __destruct() {
        echo "触发了析构函数1次<br />";
    }
}

$test = new User();
$ser  = serialize($test);
unserialize($ser);
?>
```

输出是**两遍**「触发了析构函数1次」。原因：

1. `$test = new User();` 创建**对象 1**；
2. `unserialize($ser)` 创建**对象 2**（反序列化一定会新建对象）；
3. **脚本结束时**，两个对象都被销毁，各触发一次 `__destruct()`。

时序上要记住：

```php
$test = new User("对象1");    // 只触发构造函数
$ser  = serialize($test);     // 不触发析构
$temp = unserialize($ser);    // 只新建对象，不触发析构
unset($temp);                 // 手动销毁对象2 → 触发 1 次析构
// 脚本结束 → 自动销毁对象1 → 再触发 1 次析构
```

- 对象**不是**实例化完就立刻销毁的，它活到脚本结束（或 `unset` / 引用归零）；
- **PHP 脚本结束时会自动销毁所有对象** —— 这就是「攻击者什么都不用做，`__destruct()` 也一定会跑」的原因。

### 4. `__sleep()`：序列化之前触发

```php
<?php
class User {
    public $username;
    public $nickname;
    private $password;

    public function __construct($u, $n, $p) {
        $this->username = $u;
        $this->nickname = $n;
        $this->password = $p;
    }

    public function __sleep() {
        return array('username', 'nickname');   // 只序列化这两个
    }
}

$user = new User('a', 'b', 'c');
echo serialize($user);
?>
```

要点：

- 必须**返回一个数组**，数组里是要被序列化的**属性名**；
- 上例输出里只有 `a`、`b`，**`password` 的 `c` 被挡掉了** —— 因为 `__sleep()` 先跑，`c` 没进白名单；
- 如果**不返回任何内容**，那么 `NULL` 会被序列化，并产生 `E_NOTICE` 错误。

**它为什么会成为漏洞点**：`__sleep()` 里可以直接调用别的方法 / 函数。原笔记给出的典型形态：

```php
<?php
class User {
    public $username;
    public $nickname;
    private $password;

    public function __construct($u, $n, $p) { /* 同上 */ }

    public function __sleep() {
        system($this->username);        // 序列化之前先执行命令
        return ['username', 'nickname'];
    }
}

$cmd  = $_GET['benben'];
$user = new User($cmd, 'b', 'c');
echo serialize($user);
?>
```

只要 `$username` 可控，**每次 `serialize()` 都会执行一次命令** —— 这就是「魔术方法里带危险函数」的通用形态。审计时看到 `__sleep` / `__wakeup` / `__destruct` / `__toString` 里出现 `system` / `eval` / 文件操作，就要警觉。

### 5. `__wakeup()`：反序列化时触发

- **无参数**（固定写法 `public function __wakeup() {}`，括号里不加东西）；
- **返回 void**；
- 触发位置：**对象属性被还原之后、对象被返回之前**。

它的正常用途是「恢复运行时状态」，例如重连数据库：

```php
// ✅ __wakeup() 没有参数
public function __wakeup() {
    $this->connection = new PDO("mysql:host=localhost;dbname=test", "user", "pass");
    echo "数据库连接已恢复\n";
}

// ✅ 普通方法可以有参数，与魔术方法无关
public function query($sql) {
    return $this->connection->query($sql);
}
```

**它为什么会成为绕过目标**：题目常把「检查」写在这里，例如：

```php
public function __wakeup() {
    $this->password = $this->username;   // 例如把敏感属性重置掉
}
```

因为 `__wakeup()` 是在属性还原**之后**执行的，攻击者改的属性会被它「覆盖回去」。于是解题的关键就变成「想办法让 `__wakeup()` 不执行 / 执行了也没用」—— 具体手法（属性个数不匹配、`C:` 格式、引用 `&`）见 07、08 篇。

**利用方式与 `__sleep()` 相同**：只要里面接了危险函数，就是一条命令执行 / 代码执行路径。

### 6. `__toString()`：对象被当字符串用时触发

```php
<?php
class User {
    var $benben = "this is test!!";
    public function __toString() {
        return '格式不对，输出不了！';
    }
}

$test = new User();
print_r($test);   // 正常输出对象结构（不触发）
echo $test;       // 触发 __toString() → 格式不对，输出不了！
?>
```

触发条件与约束：

| 项 | 说明 |
|---|---|
| 触发时机 | 对象被当作**字符串**使用 |
| 参数 | **无参数** |
| 返回值 | **必须返回字符串**（否则报错） |

**会触发的写法**（原笔记列举）：

```php
echo $user;              // 输出对象
print $user;
$str = (string)$user;    // 强制类型转换
$result = $user . "测试"; // 字符串拼接
```

**不会触发的写法**：

```php
print_r($user);   // 打印对象结构
var_dump($user);  // 打印详细对象信息
```

> 一句话：**「有字符串语义」才触发。** 调试函数不算。

**为什么它重要**：很多链的中间一跳就是「某处把对象拼进了字符串」，例如 `echo "hello " . $obj;` 或 `include($obj)`。攻击者只要把那个位置的属性换成自己的对象，就能把控制权接到 `__toString()` 上。

### 7. `__invoke()`：对象被当函数调用时触发

```php
<?php
class User {
    var $benben = "this is test!!";
    public function __invoke() {
        echo '它不是个函数！';
        return $this;   // 返回对象本身，支持链式调用
    }
}

$test = new User();
echo $test->benben;     // 输出：this is test!!
echo $test()->benben;   // 触发 __invoke()，再访问属性
?>
```

- 触发时机：**把对象当函数调用**（`$test()`）；
- 参数：有（就是调用时传的那些实参）；
- 上例里 `__invoke()` 返回 `$this`，所以 `$test()->benben` 还能继续访问属性 —— 这类「返回自己」的写法就是链式调用。

**它为什么会成为链的一环**：源码里出现 `$obj(...)`、或者把属性当函数调用 `$this->callback(...)`，那个属性就能被换成实现了 `__invoke()` 的对象。

### 8. `__call()`：调用不存在的方法时触发

```php
<?php
class Demo {
    public function __call($arg1, $arg2) {
        echo "方法名：{$arg1}\n";
        print_r($arg2);
    }
}

$d = new Demo();
$d->callxxx('a');   // Demo 里没有 callxxx 方法
// 输出：方法名：callxxx / Array ( [0] => a )
```

| 参数 | 含义 |
|---|---|
| `$arg1` | **被调用的、不存在的方法名** |
| `$arg2` | 调用时传进去的**参数数组** |

`__call()` 是「方法不存在时的兜底」。

### 9. 静态调用 vs 动态调用

看到 `::` 和 `->` 要分清楚，这决定了触发哪条链路：

| 特性 | 静态调用（Static） | 动态调用（Dynamic） |
|---|---|---|
| 关键字 | `::` | `->` |
| 依赖对象实例 | 不需要 | 需要 |
| 内存分配 | 类加载时分配 | 对象创建时分配 |
| 可访问范围 | 只能访问静态成员 | 可访问所有成员 |
| 兜底魔术方法 | `__callStatic()` | `__call()` |

```php
<?php
class Calculator {
    public static $static_count = 0;   // 静态属性
    public $dynamic_count = 0;         // 动态属性

    public static function staticAdd($a, $b) {   // 静态方法
        self::$static_count++;
        return $a + $b;
    }
    public function dynamicAdd($a, $b) {         // 动态方法
        $this->dynamic_count++;
        return $a + $b;
    }
}

echo Calculator::staticAdd(5, 3);   // 静态：不用 new
$calc = new Calculator();
echo $calc->dynamicAdd(5, 3);       // 动态：先 new
?>
```

**对反序列化的意义**：`$_GET['x']($arg)` 这种「变量函数」调用如果落在对象上，走的是 `__invoke()`；`$obj->$methodName()` 走的是 `__call()`。链的终点常常就是这类「动态调用」。

### 10. 反序列化漏洞成因（把魔术方法接起来的三种方式）

1. **可控的输入** —— `unserialize()` 的参数可控，攻击者能构造任意序列化数据；
2. **属性值控制** —— 通过改字符串，控制反序列化后对象的属性值；
3. **触发执行** —— 靠**魔术方法**在合适的时机自动跑起来，把「控制了的属性」送进危险函数。

```text
可控输入 → 反序列化 → 魔术方法自动触发 → 代码执行
```

## 利用条件

1. 目标类里**存在魔术方法**，且方法体内用到了属性 / 调用了别的方法；
2. 那个属性**能被 payload 控制**；
3. 触发路线走得通：
   - `__wakeup()` / `__unserialize()`：`unserialize()` 一调用就跑，**不需要额外条件**；
   - `__destruct()`：**脚本结束必跑**，最稳；
   - `__toString()`：需要代码里把对象当字符串用；
   - `__invoke()`：需要代码里把对象当函数调用；
   - `__call()`：需要代码里调用一个不存在的方法；
   - `__get()` / `__set()`：需要代码里读写不可访问的属性。

## Payload 速查

| 目的 | 写法 |
|---|---|
| 让 `__destruct` 里 `$this->x->action()` 落到自定义类 | `O:1:"A":1:{s:1:"x";O:4:"evil":1:{s:1:"c";s:13:"system('id');";}}` |
| `private` 属性 | `s:11:"\0index\0test";` |
| 触发 `__toString` 的上下文 | 代码里出现 `echo $obj;` / `$obj . "x"` / `(string)$obj` |
| 触发 `__invoke` 的上下文 | 代码里出现 `$obj()` / `$this->cb()` |
| 触发 `__call` 的上下文 | 代码里调用了一个类里**不存在**的方法 |

## 踩坑与备注

- **构造函数在反序列化路径上不执行**，这是新手最常见的误判。payload 只影响属性，不影响任何方法体的执行时机。
- **`__wakeup()` 无参数、`__sleep()` 返回数组**，两者别写反：`__sleep` 属于「序列化阶段」，`__wakeup` 属于「反序列化阶段」。
- **`__sleep()` 返回空 / 不返回会报警告**（`E_NOTICE`），并且会序列化出一个 `NULL`，做题时看到奇怪输出先怀疑这里。
- **`print_r()` / `var_dump()` 不触发 `__toString()`**，只有「字符串语义」的用法才触发。
- **对象销毁时机要用「引用计数」来想**：`unset()`、重新赋值、脚本结束都会触发 `__destruct()`；因此看到输出里析构跑了两次不要惊讶（正常对象 + 反序列化对象）。
- **`__unserialize()` 会顶掉 `__wakeup()`**（PHP 7.4+）。如果题目里两个都写了，那 `__wakeup` 里的检查形同虚设 —— 这条在 13 篇（web261）里会展开。
