## 确认、最终性、手续费与交易顺序

这一章解决四个问题：

- 交易进入区块后是否已经可靠；
- “确认”和“最终性”有什么区别；
- 手续费为什么影响交易速度；
- 谁决定交易在区块中的先后顺序。



### 交易状态

一笔交易通常经历：

```
构造交易
  ↓
签名
  ↓
广播
  ↓
进入部分节点的内存池
  ↓
被收录进区块
  ↓
执行成功或失败
  ↓
获得更多确认
  ↓
达到最终性
```

这些状态不能混为一谈。

| 状态         | 含义                                     |
| ------------ | ---------------------------------------- |
| **已签名**   | 私钥已经授权交易                         |
| **已广播**   | 交易已经发送给某个节点                   |
| **待处理**   | 交易存在于部分节点的内存池               |
| **已入块**   | 交易被某个有效区块收录                   |
| **执行成功** | 转账或合约操作按规则执行完成             |
| **执行失败** | 交易已经处理，但目标操作发生回滚         |
| **已确认**   | 交易所在区块已经成为当前主链的一部分     |
| **已最终化** | 撤销交易需要非常严重的共识攻击或协议失败 |



#### 确认状态

**确认表示交易已经进入区块，并有多少后续区块建立在它之上。**

在比特币中，交易刚进入当前主链区块时，通常算一次确认：

```
区块100：包含目标交易      → 1次确认
区块101：建立在区块100上   → 2次确认
区块102：建立在区块101上   → 3次确认
```

可以近似计算为：

```
确认数 = 当前区块高度 - 交易所在区块高度 + 1
```

尚未入块的交易是零确认交易。



### 手续费

#### 比特币手续费

比特币交易手续费来自输入和输出之间的差额：

```
手续费 = 输入UTXO总额 - 输出总额
```

例如：

```
输入：1 BTC
收款输出：0.7 BTC
找零输出：0.299 BTC

手续费：0.001 BTC
```

矿工选择交易时，通常关注**手续费率**，也就是交易占用每单位区块空间所支付的费用，而不只看手续费总额。

```
手续费率 = 手续费 ÷ 交易虚拟大小
```

交易输入和输出越多，交易占用空间通常越大，可能需要更高的总手续费才能维持相同费率。



#### 以太坊手续费

以太坊使用Gas衡量交易消耗的计算资源：

```
实际手续费 = 实际使用的Gas × 实际Gas价格
```

交易设置通常包括：

| 字段             | 作用                                 |
| ---------------- | ------------------------------------ |
| **Gas Limit**    | 最多允许交易消耗多少Gas              |
| **Base Fee**     | 当前区块的基础费用，由协议计算并销毁 |
| **Priority Fee** | 给区块提议者的小费                   |
| **Max Fee**      | 用户愿意为每单位Gas支付的最高价格    |

`Max Fee`是上限，通常不是最终一定支付的价格。没有用完的Gas额度不会按上限全部扣除。

如果交易因为Gas耗尽而失败，已经消耗的Gas仍然需要支付。



### 手续费影响速度

区块空间有限。待处理交易很多时，区块生产者通常优先选择能带来较高收益的交易。

```
待处理交易数量增加
        ↓
竞争有限的区块空间
        ↓
较高手续费交易更可能优先入块
```

手续费过低可能导致交易：

- 长时间停留在内存池；
- 只被部分节点保存；
- 被节点从内存池清除；
- 在网络拥堵缓解后才入块；
- 需要通过替换交易提高费用。

手续费高也不保证立即入块，因为还会受到网络传播、交易有效性、账户nonce和区块生产者策略影响。



### 交易会被卡住

常见原因包括：

- 手续费设置过低；
- 发送账户存在更早的待处理nonce；
- 余额不足以支付金额和手续费；
- 交易只发送给少数节点；
- RPC服务没有正常广播；
- 交易被节点内存池清除；
- 智能合约调用条件已经变化；
- 网络拥堵或区块生产暂时异常。

以太坊账户的交易需要按照nonce顺序处理。nonce较小的交易没有执行时，同一账户后续nonce交易通常也会等待。

```
nonce 7：待处理
nonce 8：等待nonce 7
nonce 9：等待nonce 7和8
```



### 加速或替换待处理交易

#### 以太坊

可以使用相同nonce重新发送一笔手续费更高的交易：

```
原交易：nonce 7，较低手续费
替换交易：nonce 7，较高手续费
```

节点通常只会让其中一笔最终执行。

所谓“取消交易”，通常是使用相同nonce向自己发送一笔金额为零、手续费更高的交易。它本质上是在竞争替换原交易，并不保证成功。



#### 比特币

比特币可以通过提高费用替换交易，例如使用RBF；也可以通过花费某个未确认输出并支付更高费用，激励矿工同时打包父子交易，这称为CPFP。

无论使用哪种方式，**已经确认的交易不能通过普通加速或取消功能撤销**。



### 交易顺序

区块生产者会从自己看到的待处理交易中选择交易，并决定区块内顺序，但必须遵守协议规则。

可能影响排序的因素包括：

- 手续费；
- 交易到达时间；
- 账户nonce；
- 交易依赖关系；
- 区块生产者自身策略；
- 私有交易通道；
- 可获得的MEV收益。

同一账户的以太坊交易通常受nonce顺序约束，但不同账户之间的交易可以被重新排列。

## 章要点

检查一笔交易时，应依次确认：

```
交易是否真正广播？
是否仍在内存池？
是否进入当前主链？
执行成功还是失败？
获得了多少确认？
是否已经最终化？
实际支付了多少手续费？
交易顺序是否影响结果？
```

**确认表示交易进入了当前认可的区块历史；最终性表示撤销它需要付出多大代价。手续费影响交易竞争区块空间的能力，区块生产者则在协议允许范围内决定交易顺序。**
