## 共识机制、PoW、PoS与分叉

> 如果不同节点看到的区块顺序不同，最终应该接受哪一份交易历史？

解决这个问题的规则统称为**共识机制**。



### 共识机制作用

区块链网络中可能出现：
• 两个区块几乎同时产生；
• 某些节点暂时掉线；
• 网络传输延迟；
• 恶意节点发送冲突区块；
• 区块生产者拒绝处理部分交易；
• 不同节点暂时拥有不同链头。

共识机制需要让正常节点最终重新选择同一条有效历史。


```
多个候选区块
      ↓
检查区块是否符合协议
      ↓
按照分叉选择规则比较
      ↓
选择共同认可的链
```



### 验证规则与共识规则

**验证规则**

判断一个交易或区块本身是否合法，例如：

- 签名是否有效；
- 是否存在双花；
- 区块奖励是否超额；
- 智能合约执行结果是否正确；
- 区块格式是否符合协议。

**共识与分叉选择规则**

当存在多个有效候选历史时，决定节点跟随哪一条。

```
无效区块
→ 直接拒绝

两个都有效的候选链
→ 使用分叉选择规则决定跟随哪条
```

矿工或验证者负责提出区块，全节点仍然会独立执行验证。



### 共识机制

如果采用“一台计算机一票”，攻击者可以低成本创建大量虚假节点，从而获得大量投票权。这就是女巫攻击问题。

区块链需要把共识影响力绑定到具有成本的资源：

| 共识机制 | 权重来自                   |
| -------- | -------------------------- |
| **PoW**  | 实际投入的计算工作         |
| **PoS**  | 锁定并可能被罚没的链上资产 |

因此，网络中节点数量多不代表一定拥有更大的共识权重。



### 工作量证明PoW

比特币使用**工作量证明（Proof of Work）**。

矿工通过哈希计算竞争产生新区块：

```
选择交易
   ↓
构造候选区块
   ↓
不断计算区块头哈希
   ↓
找到满足难度目标的结果
   ↓
广播新区块
```

其他节点检查工作量证明和区块内容。区块有效后，矿工可以获得区块补贴和交易手续费。

当网络中出现多个有效分支时，比特币节点通常选择**累计工作量最大**的有效链。

经常有人称它为“最长链”，但准确含义不是区块数量最多，而是：

> 从起点到当前链头，累计完成的有效工作量最大。

```
             ┌─ 区块B1 ─ 区块B2
共同区块 ────┤
             └─ 区块C1 ─ 区块C2 ─ 区块C3

节点比较累计工作量，而不只比较区块数量。
```

矿工通常继续在自己认可的累计工作量最大链上挖矿。某个分支继续获得新区块后，另一分支可能被放弃。



#### PoW中的临时分叉

两个矿工可能几乎同时找到有效区块：

```
                 ┌─ 区块101A
区块100 ─────────┤
                 └─ 区块101B
```

由于网络传播延迟，一部分节点先看到A，另一部分先看到B。随后某个分支先产生下一个区块：

```
区块100 ─ 区块101A ─ 区块102A
       └─ 区块101B
```

节点会切换到累计工作量更大的分支。被放弃的有效区块通常称为陈旧区块。

原先只进入被放弃区块的交易可能：

- 已经同时进入新主链；
- 返回内存池等待重新打包；
- 因为与主链交易冲突而失效。

这种切换称为**链重组**。



#### PoW只有概率最终性

比特币不会把普通区块标记为绝对不可撤销。一个区块之后累积的工作量越多，攻击者重建另一条更强链所需的成本越高。

```
确认数增加
   ↓
后续累计工作量增加
   ↓
区块被重组的概率通常降低
```

因此，比特币采用的是**概率最终性**。确认数表示风险逐渐下降，不代表达到某个数字后风险突然变成零。



#### PoW中的51%攻击

如果攻击者控制了大部分有效算力，就可能更快地构造另一条链。

攻击者可能做到：

- 重组近期区块；
- 撤销自己近期发出的付款；
- 对相同资产重新付款；
- 持续排除某些交易；
- 阻止其他矿工的区块成为主链；
- 影响近期交易顺序。

仅控制算力通常不能做到：

- 伪造其他地址的数字签名；
- 直接转走其他地址的资产；
- 创建超过协议允许数量的BTC；
- 修改全节点执行的验证规则；
- 让正常节点接受格式错误或超额奖励区块。



### 权益证明PoS

以太坊当前使用**权益证明（Proof of Stake）**。

参与共识的验证者需要质押ETH。协议根据质押权重选择区块提议者，并安排其他验证者对区块进行证明。

```
验证者质押ETH
      ↓
协议选择区块提议者
      ↓
提议者生成并广播区块
      ↓
其他验证者重新验证并投票
      ↓
节点根据证明权重选择链
```

直接运行一个以太坊验证者通常需要质押32 ETH。质押服务可以把多人的资金组合起来，但会增加服务商、智能合约或节点运营方风险。



#### 以太坊验证者工作

以太坊把时间划分为：

```
1个时隙：12秒
32个时隙：1个epoch，约6.4分钟
```

每个时隙是一次产生新区块的机会。

验证者可能承担两类任务：

| 任务           | 作用                               |
| -------------- | ---------------------------------- |
| **区块提议**   | 收集交易并提出新区块               |
| **证明或投票** | 验证区块并表达对链头和检查点的支持 |

并非每个时隙都一定产生区块。被选中的提议者离线时，该时隙可能为空。



#### PoS选择链

以太坊节点会参考验证者的最新证明和相应质押权重，选择获得支持最多的有效分支。

可以简化理解为：

```
候选分支
   ↓
统计验证者最新证明的质押权重
   ↓
按照分叉选择规则确定链头
```

实际使用的链头选择机制称为LMD-GHOST；最终性机制称为Casper FFG。现阶段先理解两者的职责：

| 机制         | 作用                                     |
| ------------ | ---------------------------------------- |
| **分叉选择** | 决定当前应该跟随哪个链头                 |
| **最终性**   | 把得到足够验证者支持的检查点标记为最终化 |



#### PoS的最终性

以太坊使用检查点和验证者投票形成最终性。当代表至少三分之二质押ETH的验证者对检查点形成规定的投票关系时，区块可以逐步成为已证明和最终化状态。

最终化意味着：

> 若要让冲突历史同时最终化，必须出现严重共识失败，并使大量验证者留下可被罚没的作恶证据。

因此，以太坊具有明确的**经济最终性**。最终化不是“密码学上绝对不可能改变”，而是改变它会触发严重的协议和经济后果。



#### 奖励、惩罚与罚没

正常参与的验证者可以获得奖励。验证者离线时可能错过奖励，并受到一定惩罚。

某些明确违反共识规则的行为会触发**罚没（slashing）**，例如：

- 同一时隙提出两个冲突区块；
- 对同一目标进行冲突投票；
- 提交相互矛盾的检查点证明。

罚没可能销毁验证者的部分质押，并将其移出验证者集合。

PoW通过计算和电力成本约束攻击者；PoS通过锁定资产和罚没风险约束攻击者。



#### PoS中的攻击能力

不同质押比例可能带来不同风险：

| 攻击者控制的质押权重 | 可能影响                                           |
| -------------------- | -------------------------------------------------- |
| 较小比例             | 延迟传播、个别时隙作恶、局部排序                   |
| 接近或超过三分之一   | 可能阻止网络正常形成最终性                         |
| 超过一半             | 可显著影响链头选择、审查和短期重组                 |
| 接近或超过三分之二   | 可能推动恶意检查点最终化，但会产生大规模可罚没行为 |

实际攻击效果还取决于网络状况、客户端行为、诚实验证者反应和社会协调。



#### 临时分叉、软分叉与硬分叉

“分叉”有不同含义。

| 类型           | 含义                                             |
| -------------- | ------------------------------------------------ |
| **临时链分叉** | 因同时出块或网络延迟出现多个候选链               |
| **链重组**     | 节点从原分支切换到更符合选择规则的分支           |
| **软分叉**     | 新规则更严格，旧节点通常仍能接受新规则产生的区块 |
| **硬分叉**     | 新旧规则不兼容，可能形成两条永久区块链           |

临时分叉属于网络正常运行中可能出现的现象。软分叉和硬分叉通常涉及协议规则升级。



### PoW与PoS对比

| 比较项         | PoW                      | PoS                        |
| -------------- | ------------------------ | -------------------------- |
| 典型网络       | 比特币                   | 以太坊                     |
| 共识资源       | 算力和能源               | 质押资产                   |
| 出块者         | 矿工                     | 验证者                     |
| 作恶成本       | 设备、电力和机会成本     | 质押被罚没                 |
| 分支选择       | 累计工作量               | 验证者证明权重             |
| 最终性         | 概率最终性               | 明确的经济最终性           |
| 主要集中化风险 | 大型矿池、矿机与能源分布 | 大型质押服务和持币集中     |
| 主要攻击方式   | 算力重组、双花、审查     | 冲突投票、最终性阻断、审查 |
