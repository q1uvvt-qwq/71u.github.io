## 一句话概括

`file://` 是 PHP 的**默认包装器**（不写前缀时系统自动补上），用于访问本地文件系统。**斜杠的个数决定路径基准**：`file:///`（三斜杠）后面接绝对路径，`file://`（两斜杠）后面接相对路径。

## 原理

### 1. `file:///`（三个斜杠）—— 绝对路径

这是最标准、最明确的格式：

```text
file:///<绝对路径>
```

**为什么是三个斜杠？** 把 URI 拆开看就清楚了：

| 部分 | 含义 |
|---|---|
| `file:` | **协议标识符** |
| `//` | 表示后面跟的是「主机名」。但在 `file://` 协议里，本地文件系统**通常省略主机名** |
| `/` | **第三个斜杠 = 文件系统根目录的起始符** |

所以 `file:///etc/passwd` 读作「本地主机 + 从根目录开始的 `etc/passwd`」：

- Linux / Unix：`file:///etc/passwd` → 解析为 `/` → `etc` → `passwd`
- Windows：`file:///C:/Windows/System32/drivers/etc/hosts` → 解析为 `C:/` → `Windows` → `System32` → …

**适用场景**：明确知道目标文件的完整路径时，用这种格式最可靠。

### 2. `file://`（两个斜杠）后直接跟文件名 —— 相对路径

```text
file://<相对路径或文件名>
```

这种写法**不推荐**，因为它的解析结果**强烈依赖当前的工作目录**。假设脚本的工作目录是 `/var/www/html/`：

| 写法 | PHP 会去找 | 说明 |
|---|---|---|
| `include('file://etc/passwd');` | `/var/www/html/etc/passwd` | 通常不是你想要的结果 |
| `include('file://../../etc/passwd');` | 从 `/var/www/html/` 向上两级 → `/var/etc/passwd` | 层数没算对，仍然不对 |

风险在于：工作目录可能因**服务器配置**、代码里的 `chdir()` 调用、甚至不同入口脚本而变化。**攻击不可靠**。

### 3. 最常用：省略 `file://` 前缀

实际利用中很少有人显式写 `file://` —— 它是 PHP 的默认协议，写不写一样。下面两组**完全等价**：

| 写法 | 说明 |
|---|---|
| `include('/etc/passwd');` | **最常用**，直接写绝对路径 |
| `include('file:///etc/passwd');` | 效果相同，但更冗长 |

路径遍历也一样：

| 写法 | 说明 |
|---|---|
| `include('../../../../etc/passwd');` | **标准做法** |
| `include('file://../../../../etc/passwd');` | 不推荐，行为可能不明确 |

## 利用条件

1. **存在可控的路径/流参数**，进了文件系统函数或包含函数；
2. **进程对目标文件有读权限**；
3. **没有被 `open_basedir` 限制**（PHP 层面最硬的限制）；
4. 目标可以是**任意本地文件**，不限于 Web 目录。

## 总结与对比

| 格式 | 示例 | 路径类型 | 解析基准 | 推荐度 |
|---|---|---|---|---|
| `file:///...` | `file:///etc/passwd` | **绝对路径** | 文件系统根目录 `/` | 明确但冗长 |
| `file://...` | `file://../../etc/passwd` | **相对路径** | 当前工作目录 | **不推荐**，行为不确定 |
| 无前缀 | `../../../../etc/passwd` | **相对路径** | 当前工作目录 | **最常用、最直接** |
| 无前缀 | `/etc/passwd` | **绝对路径** | 文件系统根目录 `/` | **最常用、最直接** |

**结论**：`file://` 唯一需要记住的差别是**三个斜杠接绝对路径、两个斜杠接相对路径**；而实战里最稳的写法是**直接省略前缀，只写路径** —— 绝对路径写全（`/etc/passwd`），相对路径写够层数（`../../../../`）。

## Payload 速查

| 目的 | Payload |
|---|---|
| 读 Linux 本地文件（绝对） | `?file=file:///etc/passwd` 或 `?file=/etc/passwd` |
| 读 Windows 本地文件 | `?file=file:///C:/Windows/System32/drivers/etc/hosts` |
| 相对路径遍历 | `?file=../../../../etc/passwd` |
| 加前缀的相对路径（不推荐） | `?file=file://../../../../etc/passwd` |

## 踩坑与备注

- **`file:///` 的三个斜杠不是笔误**：前两个来自 URI 的 `//主机名` 结构，第三个才是根目录。写成两个斜杠就变成「相对路径」了。
- **路径遍历的层数计算、编码绕过、绝对/相对路径的完整对比**，见 `01-信息收集\目录遍历.md` —— 本文只聚焦 `file://` 这一种前缀写法的差异，不重复遍历主题。
- **绝对路径要写完整**：`/flag.php` 指的是「文件系统根目录下的 `flag.php`」，它与「网站根目录下的 `flag.php`」是两个不同的文件。混淆这两者见 `05-文件包含\文件包含题解综合.md`。
- **原文里的 `file://` 曾被写成 `file///`、`file//`**（导出时的符号丢失），本文已按标准写法 `file:///` 统一。原文中个别「路径示例解析结果」的自相矛盾处（如把 `file://../../etc/passwd` 解析成 `/var/etc/passwd`）保留原样并标注为**层数算错的反例**，说明相对路径不可靠。
