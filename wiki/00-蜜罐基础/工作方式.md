## 一句话概括

漏洞专项蜜罐围绕某个具体漏洞模拟攻击者会识别和利用的特征，记录攻击请求，但不真正触发漏洞。

## 一般流程

1. 漏洞公开或 PoC 出现。
2. 分析漏洞利用前置条件和攻击请求特征。
3. 提取目标服务指纹，例如路径、Header、响应体、错误信息、版本特征。
4. 搭建仿真服务，模拟攻击者期望的响应。
5. 捕获攻击者请求和 Payload。
6. 对 Payload 进行解析、归类和 IOC 提取。
7. 生成检测规则、封禁建议或威胁情报报告。

## 以 Web RCE 为例需要模拟什么

- 框架默认静态资源路径
- 特定 API 路由
- 错误响应结构
- Server Header 或应用指纹
- 请求体解析行为
- 漏洞探测时攻击者期望看到的状态码或响应关键词

## 必须避免

- 执行命令
- 访问真实文件系统敏感路径
- 对外发起不受控连接
- 让攻击者上传并运行二进制文件
- 使用真实脆弱版本组件暴露到公网
